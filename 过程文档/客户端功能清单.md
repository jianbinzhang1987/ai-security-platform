## 1. 总体目标

客户端的目标是以低侵入、Fail-Open、高可观测的方式，把客户 AI Agent 纳入安全监控体系，覆盖以下核心能力：

- 自动接入与注册
- LLM / MCP 工具调用采集
- 本地安全处理与风险标记
- Trace 上报、缓冲与重试
- 本地健康检查与调试查询
- CLI 接入验证与运维诊断

## 6. 开发优先级建议

### P0：必须先完成

- 平台接口字段完全对齐
- OpenAI / Anthropic / MCP 插桩兼容性补齐
- 集成测试闭环

### P1：建议尽快完成

- Token 过期/吊销处理完善
- CLI 诊断增强（错误分类、结果可读性、异常分层）
- Metrics 指标丰富
- Trace 输出结构标准化
- 阻断动作细分（block / alert / shadow）
- 工具白名单与参数约束完善
- Agent 上下线事件联调验证
- OTLP HTTP 备用协议联调验证

### P2：可后续迭代

- CLI 输出表格化/摘要化
- Trace 查询分页与高级过滤
- 更多模型/工具生态兼容
- 更细粒度性能基线与压测

## 7. 验收建议

后续开发可按以下方式验收：

1. 先按功能编号逐项确认是否完成。
2. 每项功能至少有一条对应测试或联调记录。
3. 所有 P0 功能完成后再进入对外试用阶段。
4. 所有本地接口和 CLI 命令都应有最小可运行示例。

1. 平台接口协议对齐
