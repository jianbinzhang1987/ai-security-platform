# 管理端功能清单

**文档目的**  
用于沉淀管理端侧（Admin Side）后续开发范围，作为数据管道、安全检测引擎、存储查询服务、告警响应系统以及安全运营控制台的统一功能清单与阶段验收依据。

**适用范围**  
- `server/RuoYi` (Spring Boot 后端)
- `server/RuoYi-Vue3` (Vue 3 前端)
- `third_party/otel-collector` (数据采集与预处理)

## 1. 总体目标

管理端的目标是构建一个高性能、可扩展、智能化的 AI Agent 安全管理平台，覆盖以下核心能力：

- **租户与 Agent 管理**：多租户隔离与 Agent 生命周期管理。
- **高性能数据管道**：基于 OTel Collector 的 TB 级 span 数据接入与分发。
- **多维安全检测**：涵盖 Prompt 注入、工具审计、行为序列与意图对齐。
- **高并发存储查询**：基于 ClickHouse 的时序事件存储与分析。
- **闭环告警响应**：灵活规则引擎与实时阻断响应。
- **专业运营控制台**：可视化调用链追踪、风险大盘与合规报表。

## 10. 开发优先级建议

### P0：必须完成（MVP 阶段）
- 租户隔离与 Agent 配置拉取对齐
- 数据管道链路打通（SDK -> Collector -> Kafka -> ClickHouse）
- 基础 Prompt 注入与工具黑名单检测逻辑
- Trace 可视化查询与展示
- 简单的阻断通道（基于心跳响应或 WebSocket）

### P1：重要功能（完善体验）
- 行为序列分析引擎与异常评分
- 告警规则灵活配置（规则编辑器）
- 多渠道实时通知推送
- 审计日志完整性增强与操作审计记录
- 报表自动生成引擎
- 设备指纹黑名单与分环境 Token 管理
- Response 内容审计（PII 与毒性检测）

### P2：扩展功能（智能化升级）
- 意图对齐审计 (AI 判 AI)
- 数据自动冷热分层与清理
- 可观测性大盘指标下钻分析
- 自定义 Guardrail 规则沙箱
- MFA 强制认证与 SSO 集成
- 平台大规模并发性能压测与优化

## 11. 验收建议

1. **链路验证**：确保从 SDK 上报数据到控制台显示 Trace 耗时小于配置阈值。
2. **检测有效性**：构造典型攻击 Payload（如注入指令、跳板工具调用），验证风险事件是否能准确捕获。
3. **隔离性测试**：验证租户 A 绝无可能查询到租户 B 的 Trace 数据或配置。
4. **阻断一致性**：管理端下发阻断指令后，Agent 实例应在 5 秒内停止后续敏感操作并返回安全拒绝。
