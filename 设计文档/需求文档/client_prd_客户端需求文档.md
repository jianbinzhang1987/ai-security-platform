**1. 文档说明**

**1.1 文档目的**

本文档定义 AI Agent 安全监控平台客户端侧的完整产品需求，面向客户（即 AI
Agent 的开发/运营方）提供 SDK
接入、数据采集控制、安全策略配置、本地状态查询等能力。客户端的核心目标是：以最低接入成本将已有
AI Agent 纳入监控体系，并为客户研发和运维团队提供必要的本地工具与接口。

**1.2 用户角色定义**

  ------------------ ------------------------ ------------------------------------------
  **角色**           **说明**                 **主要使用场景**

  Agent 开发者       负责集成                 接入向导、SDK 安装、配置调试、接入验证
                     SDK、调整接入配置        

  Agent 运维 / SRE   负责 Agent 生产环境运行  健康检查、采样率调整、日志对接、异常排查

  客户侧安全联络员   响应平台推送的安全告警   查看本 Agent 告警、确认处置、配置阻断策略
  ------------------ ------------------------ ------------------------------------------

  ---------- ------------------------ -------------------------------------- ------------------------------

**2. 客户端整体业务流程**

**2.1 接入全生命周期（五阶段）**

客户端产品需覆盖一个 AI Agent
从\"决定接入\"到\"持续安全运营\"的完整生命周期：

+---+---------------------------------------------------------------------+
|   | **阶段 1：注册与 Token 获取**                                       |
|   |                                                                     |
|   | 客户在管理端注册账号 → 创建 Agent 记录 → 平台生成专属接入           |
|   | Token（JWT，含租户 ID + Agent ID）                                  |
|   |                                                                     |
|   | 客户下载 token.env 配置文件，保存到 Agent                           |
|   | 所在服务器的安全位置（建议存入密钥管理系统）                        |
|   |                                                                     |
|   | Token 是 SDK 与平台通信的唯一凭证，每个 Agent 独立 Token，互相隔离  |
+---+---------------------------------------------------------------------+

+---+---------------------------------------------------------------------+
|   | **阶段 2：SDK 安装与初始化**                                        |
|   |                                                                     |
|   | Agent 开发者根据语言选择接入方式：Python（opentelemetry-instrument  |
|   | 前缀命令启动）                                                      |
|   |                                                                     |
|   | SDK 启动时读取 Token 配置 → 向平台 Collector 建立 OTLP              |
|   | gRPC（TLS）连接                                                     |
|   |                                                                     |
|   | SDK 完成自检后向平台上报 agent.connected 心跳 →                     |
|   | 管理端接入状态变为\"已接入\"                                        |
+---+---------------------------------------------------------------------+

+---+---------------------------------------------------------------------+
|   | **阶段 3：配置下发与热更新**                                        |
|   |                                                                     |
|   | SDK 启动时从平台拉取采集配置（采样率、脱敏规则、工具白名单等）      |
|   |                                                                     |
|   | 此后每 30s 心跳时重新拉取配置，管理端修改配置后 30s 内在 SDK        |
|   | 侧自动生效，无需重启 Agent                                          |
|   |                                                                     |
|   | 客户可通过 agentsec-cli config show                                 |
|   | 查看当前生效配置快照，确认配置已同步                                |
+---+---------------------------------------------------------------------+

+---+---------------------------------------------------------------------+
|   | **阶段 4：运行时数据采集与上报**                                    |
|   |                                                                     |
|   | SDK 自动捕获每次 LLM 调用（prompt/response/token 用量/调用延迟）和  |
|   | MCP 工具调用（工具名/参数/返回值）                                  |
|   |                                                                     |
|   | 所有事件以 OTEL span 格式，通过 TLS 加密 OTLP gRPC 通道上报至平台   |
|   | Collector                                                           |
|   |                                                                     |
|   | PII 敏感字段在 SDK 侧脱敏后上报，原始数据不离开客户环境             |
|   |                                                                     |
|   | SDK 本地保留最近 1000 条 Trace（滚动覆盖），供本地调试查询          |
+---+---------------------------------------------------------------------+

+---+---------------------------------------------------------------------+
|   | **阶段 5：告警接收与响应**                                          |
|   |                                                                     |
|   | 平台检测到风险后，推送告警到客户配置的 Webhook（飞书/钉钉/Slack     |
|   | 等）或邮件                                                          |
|   |                                                                     |
|   | 客户侧安全联络员通过平台管理端查看告警详情和调用链，确认处置结果    |
|   |                                                                     |
|   | 若配置了阻断策略，SDK 在检测到高风险时实时拦截 LLM                  |
|   | 调用，返回配置的安全回复，Agent 业务代码无感知                      |
+---+---------------------------------------------------------------------+

**2.2 客户端与管理端交互边界**

  ------------------ --------------------- ------------------------------------
  **交互类型**       **方向**              **说明**

  OTLP gRPC 数据上报 客户端 → 管理端       持续上报 span 事件，TLS 加密，Token
                     Collector             鉴权，批量发送

  配置拉取（Pull）   客户端 → 管理端配置   SDK 启动 + 每 30s
                     API                   心跳时拉取最新配置（JSON 格式）

  告警推送（Push）   管理端 → 客户 Webhook 风险事件触发后，管理端主动推送 JSON
                                           告警到客户配置的 URL

  阻断指令（实时）   管理端检测引擎 → SDK  高风险事件触发立即阻断时，通过常连
                                           WebSocket 推送阻断指令到 SDK
  ------------------ --------------------- ------------------------------------

| **\[C-M1-03\] 接入验证与诊断 CLI 工具**                               |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+

**4. C-M2 --- 数据采集与上报控制**

**4.1 模块范围说明**

本模块控制 SDK
采集哪些数据、以什么精度采集、如何上报。所有配置由平台统一管理下发，客户通过管理端
UI 修改，SDK 热更新生效（无需重启
Agent）。客户需在\"监控覆盖度\"和\"性能开销/数据量\"之间做平衡。

+-----------------------------------------------------------------------+
| **\[C-M2-01\] 采集范围配置**                                          |
+-----------------------------------------------------------------------+
| **使用角色：**Agent 开发者                                            |
+-----------------------------------------------------------------------+
| **功能描述**                                                          |
|                                                                       |
| • 控制 SDK 采集哪些类型的事件。默认采集 LLM 调用和 MCP                |
| 工具调用，客户可按需关闭某些维度以降低性能开销                        |
+-----------------------------------------------------------------------+
| **业务场景**                                                          |
|                                                                       |
| • 场景A：生产环境资源敏感，关闭 HTTP 请求详情采集，只保留 LLM         |
| 调用采集                                                              |
|                                                                       |
| • 场景B：安全合规要求高，开启所有采集维度（含文件访问和进程调用）     |
|                                                                       |
| • 场景C：调试阶段，临时开启 response 内容完整采集（默认截断 2048      |
| 字符）                                                                |
+-----------------------------------------------------------------------+
| **详细需求**                                                          |
|                                                                       |
| • 可配置采集维度开关：LLM 调用（含 prompt/response/token/延迟）、MCP  |
| 工具调用（工具名/参数/返回值）、出站                                  |
| HTTP（URL/状态码）、数据库查询（SQL，脱敏后）                         |
|                                                                       |
| • Prompt 内容截断长度：默认 4096 字符，可配置为 0（不采集内容只采集   |
| token 数）至 unlimited                                                |
|                                                                       |
| • Response 内容截断长度：默认 2048 字符，可独立配置                   |
|                                                                       |
| • 敏感字段过滤：配置需从 span 中移除的 attribute key 列表，SDK        |
| 侧过滤（数据不上报）                                                  |
+-----------------------------------------------------------------------+
| **业务流程**                                                          |
|                                                                       |
| • 1. 客户在管理端 → Agent 配置 → 采集设置，修改各维度开关和截断长度   |
|                                                                       |
| • 2. 保存配置 → 平台将新配置写入配置服务（带版本号）                  |
|                                                                       |
| • 3. SDK 在下一次心跳（≤30s）拉取新配置并立即应用                     |
|                                                                       |
| • 4. 客户可在配置页查看\"当前生效配置版本\"和\"生效时间\"确认同步     |
+-----------------------------------------------------------------------+
| **验收标准**                                                          |
|                                                                       |
| **1.** 关闭 LLM response 采集后，新 span 中不含 gen_ai.completion     |
| 字段                                                                  |
|                                                                       |
| **2.** 配置变更后 ≤30 秒在运行中的 Agent 生效，无需重启               |
|                                                                       |
| **3.** 配置快照显示的内容与 SDK 实际执行配置一致                      |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
| **\[C-M2-02\] 采样率配置**                                            |
+-----------------------------------------------------------------------+
| **使用角色：**Agent 开发者 / 运维                                     |
+-----------------------------------------------------------------------+
| **功能描述**                                                          |
|                                                                       |
| • 控制数据上报的采样比例。高频 Agent                                  |
| 全量采集可能产生大量数据，采样率配置允许降低成本同时保证关键安全事件  |
| 100% 保留                                                             |
+-----------------------------------------------------------------------+
| **业务场景**                                                          |
|                                                                       |
| • 场景A：高并发 Agent（\>100 QPS），正常请求采样率 10%，安全事件强制  |
| 100% 保留                                                             |
|                                                                       |
| • 场景B：低频 Agent（\<10 QPS），100% 全量采集                        |
|                                                                       |
| • 场景C：费用超预算，临时调低采样率快速降低数据量                     |

|                                                                       |

|                                                                       |

|                                                                       |

| tokens）的调用强制采集                                                |
|                                                                       |
| • 采样率修改立即下发，5 秒内 SDK 侧生效（不等 30s 心跳）              |
|                                                                       |
| • 变更记录：每次采样率修改记录操作人、时间、变更前后值到 audit log    |
+-----------------------------------------------------------------------+
| **业务流程**                                                          |
|                                                                       |
| • 1. 客户在管理端 Agent 配置 → 采样率设置，输入目标采样率             |
|                                                                       |
| • 2. 系统实时预估新采样率下的月数据量和预计费用变化                   |
|                                                                       |
| • 3. 确认保存 → 配置立即下发到 SDK（优先级高于心跳拉取）              |
|                                                                       |

+-----------------------------------------------------------------------+
| **验收标准**                                                          |
|                                                                       |
| **1.** 设置采样率 0.1 后，非安全事件 span 上报量下降约 90%            |
|                                                                       |

**5. C-M3 --- 本地安全策略配置**

**5.1 模块范围说明**

本模块允许客户为自己的 Agent 配置本地安全策略：工具调用白名单定义 Agent
的\"合法行为边界\"，本地 Guardrail
规则叠加业务专属检测逻辑，阻断行为配置控制风险响应方式。平台提供框架，客户填充业务内容。

+-----------------------------------------------------------------------+
| **\[C-M3-01\] MCP 工具调用白名单配置**                                |
+-----------------------------------------------------------------------+
| **使用角色：**Agent 开发者 / 安全联络员                               |
+-----------------------------------------------------------------------+
| **功能描述**                                                          |
|                                                                       |
| • 为 Agent 声明允许调用的 MCP                                         |
| 工具列表。未在白名单中的工具调用被记录为安全事件，可配置为直接阻断    |
|                                                                       |
| • 这是 MCP 工具调用审计的基础数据，也是本平台差异化能力的核心配置项   |

| **业务场景**                                                          |
|                                                                       |
| • 场景A：Agent                                                        |
| 只应调用\"天气查询\"和\"日历查询\"，调用其他工具触发告警              |
|                                                                       |
| • 场景B：Agent 有权调用数据库工具，但参数中不允许含 DROP/DELETE       |
| 等危险关键词                                                          |
|                                                                       |
| • 场景C：多 Agent 协作场景，定义每个 Agent 可调用哪些其他 Agent       |
| 暴露的工具                                                            |
+-----------------------------------------------------------------------+
| **详细需求**                                                          |
|                                                                       |

| • 支持通配符：weather\_\* 匹配所有以 weather\_ 开头的工具名称         |
|                                                                       |
| • 未声明工具处理模式：告警（记录+放行）/ 阻断（拒绝调用+告警）/       |

|                                                                       |
| •                                                                     |
| 工具调用频率限制：每个工具可配置最大调用频率（次/分钟），超限触发告警 |
|                                                                       |
| • 版本管理：每次修改生成版本号，可查看变更历史，支持一键回滚          |
+-----------------------------------------------------------------------+
| **业务流程**                                                          |
|                                                                       |
| • 1. 客户在管理端 → Agent 配置 →                                      |
| 工具白名单，添加工具名称（支持通配符）                                |
|                                                                       |
| • 2. 为需要的工具配置参数约束和频率限制（可选）                       |
|                                                                       |
| • 3. 配置\"未声明工具\"处理策略（默认：告警放行）                     |
|                                                                       |
| • 4. 保存 → 配置下发到 MCP 网关（≤30s 生效）                          |
|                                                                       |
| • 5. Agent 调用工具时，网关对照白名单执行策略                         |
|                                                                       |
| • 6. 违规调用在管理端安全事件列表中可查，含完整调用详情和调用链上下文 |
+-----------------------------------------------------------------------+
| **验收标准**                                                          |
|                                                                       |
| **1.** 白名单外工具调用在\"阻断\"模式下被拒绝，Agent 收到明确错误信息 |
|                                                                       |
| **2.** 通配符规则正确匹配（weather\_\* 匹配 weather_query 不匹配      |
| get_weather）                                                         |
|                                                                       |
| **3.** 频率限制准确，超限后第 n+1 次调用被阻断                        |

**6. C-M4 --- 接入状态与本地查询**

**6.1 模块范围说明**

本模块提供客户端视角的轻量状态查询能力：SDK 健康检查端点、本地 Trace
抽样查询、配置同步状态。与管理端全局视图不同，本模块聚焦单个 Agent
的本地运行状态，适合在客户本地环境直接访问和集成。

+-----------------------------------------------------------------------+
| **\[C-M4-01\] SDK 健康检查端点**                                      |
+-----------------------------------------------------------------------+
| **使用角色：**Agent 运维                                              |
+-----------------------------------------------------------------------+
| **功能描述**                                                          |
|                                                                       |
| • SDK 暴露本地 HTTP 健康检查端点和 Prometheus metrics 端点，供 K8s    |
| 探针、运维监控系统、告警平台集成                                      |
+-----------------------------------------------------------------------+
| **业务场景**                                                          |
|                                                                       |
| • 场景A：K8s Liveness Probe 配置 agentsec 健康端点，SDK 异常时 Pod    |
| 自动重启                                                              |
|                                                                       |
| • 场景B：Prometheus + Grafana 接入 /agentsec/metrics 端点，展示 SDK   |
| 运行指标                                                              |
|                                                                       |
| • 场景C：告警平台订阅健康检查，SDK 断线超 5 分钟发出告警              |
+-----------------------------------------------------------------------+
| **详细需求**                                                          |
|                                                                       |
| • GET /agentsec/health → 返回 JSON：{status, collector_connected,     |
| last_span_sent_at, spans_sent_1m, config_version}                     |
|                                                                       |
| • status 取值：ok（正常）/ degraded（Collector 断线，本地缓冲中）/    |
| error（初始化失败）                                                   |
|                                                                       |
| • GET /agentsec/metrics → Prometheus                                  |
| 格式：agent                                                           |
| sec_spans_total、agentsec_collector_latency_ms、agentsec_errors_total |
|                                                                       |
| • 端口：默认 13133（标准 OTel Health Check                            |
| 端口），AGENTSEC_HEALTH_PORT 可自定义                                 |
|                                                                       |
| • 认证：健康检查端点无需认证（仅返回状态），metrics 端点支持 Basic    |
| Auth（可选）                                                          |
+-----------------------------------------------------------------------+
| **业务流程**                                                          |
|                                                                       |
| • 1. SDK 启动时在 13133 端口启动独立 HTTP 服务（不占用 Agent          |
| 业务端口）                                                            |
|                                                                       |
| • 2. K8s probe / 运维系统轮询 /agentsec/health                        |
|                                                                       |
| • 3. status=degraded 时继续运行不重启（本地缓冲），status=error       |
| 时触发重启                                                            |
+-----------------------------------------------------------------------+
| **验收标准**                                                          |
|                                                                       |
| **1.** SDK 正常运行时 /agentsec/health 返回 {status: \"ok\"} 和 HTTP  |
| 200                                                                   |
|                                                                       |
| **2.** Collector 断线时 status 变为 degraded，不影响 Agent            |
| 业务（fail-open）                                                     |
|                                                                       |
| **3.** Prometheus 能抓取 /agentsec/metrics 获取 span                  |
| 上报量和延迟分位数                                                    |
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+

**7. 非功能性需求**

**7.1 性能要求**

**7.2 可靠性要求**

-   Fail-open 原则：SDK 任何内部错误（网络断开/Token
    过期/配置拉取失败）不得导致 Agent
    业务异常，错误静默处理并记录本地日志

-   本地缓冲：Collector 不可达时 SDK 本地缓冲最近 10000 个
    span，恢复后自动重发，无数据丢失

-   数据不重复：span_id 全局唯一，重发时 Collector
    侧去重，不产生重复记录

-   配置容错：配置拉取失败时，SDK
    继续使用上一次成功拉取的配置，不降级到默认配置

**7.3 安全要求**

-   传输加密：所有 SDK → Collector 通信使用 TLS 1.2+，Token 通过 gRPC
    metadata / HTTP Authorization header 传输

-   Token 隔离：每个 Agent 独立 Token，Token 泄露只影响该 Agent
    数据，不影响其他租户和 Agent

-   本地 API 认证：健康检查端点可选认证，Trace 查询 API 强制本地 Token
    认证

-   数据不落盘：SDK 不将 span
    数据写入本地磁盘（仅错误日志和配置缓存），防止敏感数据本地泄露

-   最小权限：SDK 运行时仅读取配置和上报数据，不需要任何特权系统权限
