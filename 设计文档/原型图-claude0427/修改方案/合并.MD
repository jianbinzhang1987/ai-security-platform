# 平台 MVP 阶段功能收拢与简化整合方案

本文档整合了关于大模型安全监测平台在 MVP 阶段的功能精简、屏蔽及优化建议，供后续代码和原型修改参考。

## 1. 模块屏蔽与导航精简

在 MVP 阶段，临时隐藏部分高级管理和运营功能，使产品更聚焦于核心安全监测能力。

### 1.1 需屏蔽的全局菜单
- **工具与权限**（资产中心子菜单）
- **监控覆盖度**（资产中心子菜单）
- **租户管理**（系统管理子菜单）

**实现方式：** 
不删除任何底层代码和接口。直接在对应菜单项的 HTML/CSS 中添加 `nav-hidden-p0` 类进行隐藏。
屏蔽后，资产中心仅保留“接入应用”，系统管理保留“用户与权限”、“操作审计日志”、“数据采集器配置”。

### 1.2 屏蔽“监控覆盖度”的级联影响处理
由于屏蔽了“监控覆盖度”及“工具与权限”，需要同步清理依赖这些数据的上下游指标，避免出现“有数字但无落地页”的断链问题：
1. **应用详情页 (app-detail.html) 顶部数据卡片 (stat-cards)：** 
   - 隐藏或移除「策略覆盖率」卡片。
   - 隐藏或移除「工具声明覆盖率」卡片（可改为“资产完整度”或直接屏蔽）。
2. **仪表盘 (dashboard.html)：** 
   - 审查并隐藏安全总览页中与覆盖度相关的统计图表，可替换为“今日活跃应用数”等核心指标。
3. **应用详情页 Tab：**
   - 隐藏「策略覆盖检查」Tab（详见 2.1）。

## 2. 应用详情页面精简与重组

### 2.1 需屏蔽的 Tab 页
在应用详情页中屏蔽以下属于运维或尚未完全就绪的 Tab，使页面聚焦安全和资产本身：
- **接入配置**（运维配置，当前功能未就绪）
- **监控配置**（探针端配置，暂无配置下发能力）
- **策略覆盖检查**（依赖已屏蔽的监控覆盖度）

**优化后剩余的 Tab（按推荐优先级排列）：**
安全概览 / 智能体·节点 / 工具与资源 / 风险事件 / 运行实例

### 2.2 Skills 的类型归属
在「工具与资源」Tab 中处理 Agent Skills：
- **处理方案：** 不单独新增“Skill”类型，而是将其归入 **`Tool`（工具）** 或 **`MCP Tool`（MCP工具）** 类型中。
- **信息展示：** 在列表的“来源”字段中，明确标注为 `"agent skill 声明"`，以此与 LangChain 元数据或外部 API 区分开来。这符合从安全监测角度将其统一视为外部交互能力的逻辑。

## 3. 风险事件管理优化

### 3.1 编号规则规范化
当前系统中存在“事件编号”和“风险编号”概念混用的情况。
- **结论：** 强烈建议保留编号，因为它是跨页面（应用详情、工作台、告警记录）联动追踪的关键锚点。
- **优化方案：** 
  - 统一称为 **「事件编号」**（Event ID）。
  - 统一格式标准，建议采用纯数字序列：`EVT-{年份}-{5位自增序号}`（例如：`EVT-2026-00018`）。

### 3.2 风险事件列表字段简化
当前列表列数过多（12列），不利于快速分诊，建议精简至 9 列左右：
- **✅ 必须保留的列：** 复选框、事件编号、发生时间、关联对象（应用+工具）、风险等级、风险类型、证据要点（核心列）、状态、负责人、操作。
- **🚫 需屏蔽/隐藏的列：** 
  - **关联 Trace/Span：** 过于技术化，移入详情页展示。
  - **平台动作：** 移入详情页展示。
- **补充说明：** 列表顶部的搜索/筛选区应**保留「Trace/Span ID」搜索框**，满足高级用户定向查询的需求。

### 3.3 事件处置流程极简化
废弃当前过重的 6 个独立处置动作（派发、升级、下发限制等），合并为极简的**“处置登记”**模式。

**详情页及弹窗改造点：**
1. **统一的「处置登记」弹窗：** 
   - 包含 **「处置状态」**（必填下拉框：待处理、已处理、忽略/误报等）。
   - 包含 **「处置备注」**（必填多行文本框，记录判断依据和过程）。
2. **操作区合并：** 详情页的 6 个按钮合并为 1 个「处置登记」按钮（可保留「溯源」和「指派」快捷入口）。
3. **字段清理：** 隐藏详情中的「平台动作」；将原有的「误报原因/接受风险原因」合并为一个通用的「处置结论」字段展示。
4. **保留 Timeline：** 保留底部的处置记录时间线（Timeline），作为每次状态流转和备注的审计留痕。

## 4. 风险溯源工作台架构调整

当前“风险溯源工作台”直接进入三栏分析视图，缺乏上下文引导和筛选机制。

**架构优化建议：**
为工作台增加一层**上级列表页**。
1. **新增上级页面（溯源调查看板）：**
   - 包含时间、应用、风险等级、类型等筛选区。
   - 展示所有的独立溯源会话/Trace卡片列表（包含 trace_id、关联应用、风险等级、关联事件编号等）。
2. **当前工作台降级为详情页：**
   - 用户从上级列表点击特定 Trace 后，进入当前的三栏调查布局（Trace图谱、链路、证据区）。
   - 可将原工作台左侧简陋的 trace 列表替换为面包屑导航或返回按钮，使当前页面更专注于单条 Trace 的深度分析。
