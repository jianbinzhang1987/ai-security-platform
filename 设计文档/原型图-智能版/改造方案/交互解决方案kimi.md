# 大模型安全监测平台 — 交互解决方案

> 基于前期识别的问题（导航错位、状态过载、工作流割裂、信息层级混乱、分期边界不清、术语暴露），提出以下可落地的交互改造方案。

---

## 一、导航与信息架构重塑

### 1.1 默认首页改造

**问题**：`index.html` 默认加载 `pages/assets/app-list.html`（接入应用管理），运营人员登录后看不到待处置风险。

**方案**：
- 默认首页改为 **安全总览**（`pages/assets/dashboard.html`）
- 安全总览首屏顶部增加 **"今日待处置" 快速行动区**：
  - 未处置高风险事件数（点击直达事件列表，自动过滤 `event_status=new & risk_level=high`）
  - 平均闭环时长（点击直达事件列表，自动过滤 `event_status=resolved`）
  - AI 检测异常告警（`timeout` / `circuit_open` 聚合为 "AI 服务异常" 卡片，仅对管理员可见）

### 1.2 导航分组重组

**问题**：数据分级管理挂在"统一策略中心"下，但内容属于系统管理；AI 服务监控挂在"安全监控"下，但内容属于 AI 模型治理。

**方案**：

| 当前导航分组 | 问题页面 | 目标分组 | 理由 |
|-------------|---------|---------|------|
| 统一策略中心 → 数据分级管理 | `pages/system/data-classification.html` | **系统管理** | 数据分级是全局基础设施配置，不随策略规则变动 |
| 安全监控 → AI 服务监控 | `pages/ops/ai-service-monitor.html` | **AI 模型治理** | AI 服务监控是模型运维能力，与模型注册/版本管理同一域 |
| AI 模型治理 → 模型注册管理 | `pages/system/model-registry.html` | 保持现状，但目录统一至 `pages/ai-governance/` | 文件路径与菜单分组一致，降低维护成本 |

**交互细节**：
- 二级菜单超过 7 项时自动折叠为"更多"浮层（当前安全监控有 9 个平级子菜单）
- 高频页面（风险事件、安全总览、会话追踪）置顶并加视觉权重（图标 + 徽标数字）

### 1.3 分期可见性控制

**问题**：P1/P2/P3 页面全部可见，用户点击后进入空状态或只有标题的页面。

**方案**：引入三级可见性策略

| 期次 | 导航状态 | 视觉处理 | 点击行为 |
|-----|---------|---------|---------|
| P0.5a（当前交付） | 正常可见 | 全彩色 + 徽标数字 | 正常跳转 |
| P1（下个迭代） | **预览态** | 图标 + 文字灰色 50%，右侧标注 "P1 即将上线" | 可点击，进入页面后顶部显示黄色横幅："本功能正在开发中，当前为预览版" |
| P2/P3（远期） | **隐藏态** | 默认折叠在"更多功能"分组内 | 点击展开分组，灰色文字，不可点击，tooltip 提示 "预计 P2 开放" |

**实现方式**：
- 在 `index.html` 导航配置中增加 `phase` 字段（`p0_5a` / `p1_preview` / `p2_hidden`）
- CSS 类映射：`nav-active` / `nav-preview` / `nav-hidden`
- 避免使用 `nav-hidden-p0` 这种无业务语义的类名

## 二、状态机收敛与术语翻译层

### 2.1 三套状态机合并为"事件可信度"单一概念

**问题**：事件详情页同时展示"事件状态"、"AI 检测状态"、"AI 研判状态"，共 15 种组合，运营人员无法快速判断"这个事件的 AI 结果能不能信"。

**方案**：引入 **"AI 辅助可信度"** 统一标识，替代分散的三套状态。

| 原始状态组合 | 可信度等级 | 视觉标识 | 运营人员看到的文案 |
|-------------|-----------|---------|-----------------|
| AI检测=success + 有研判结论 + 置信度高 | **可信** | 绿色徽章 + 对勾 | "AI 辅助分析已完成，结论可信" |
| AI检测=success + 有研判结论 + 置信度低 | **待确认** | 黄色徽章 + 问号 | "AI 辅助分析已完成，置信度较低，建议人工复核" |
| AI检测=success + 研判=generated（未人工确认） | **待确认** | 黄色徽章 + 问号 | "AI 辅助分析已生成，等待人工确认" |
| AI检测=timeout / error | **不可用** | 灰色徽章 + 横线 | "AI 辅助当前不可用，已自动切换至规则检测" |
| AI检测=circuit_open | **不可用** | 灰色徽章 + 横线 | "AI 服务熔断中，已自动切换至规则检测" |
| AI检测=skipped_by_policy | **未启用** | 灰色徽章 + 斜线 | "本事件按策略配置跳过 AI 检测" |
| AI检测=not_configured | **未启用** | 灰色徽章 + 斜线 | "本策略未配置 AI 辅助" |

**交互细节**：
- 徽章放在事件标题右侧，hover 显示 tooltip 解释当前状态的具体含义
- 点击徽章展开面板，展示原始技术状态（`success`/`timeout`/`circuit_open` 等），仅对管理员/研发人员可见
- **运营人员永远看不到原始枚举值**，只看到上表中的业务语言

### 2.2 安全总览状态分布改造

**问题**：`dashboard.html` 中"AI状态分布"使用原始枚举值 `success` / `pending` / `timeout` / `circuit_open` / `skipped`。

**方案**：直接替换为业务语言标签 + 状态色块：

```
AI 辅助正常   ████████████ 72%  (绿色)
检测排队中   ██ 9%            (蓝色)
服务超时已降级 █ 6%           (橙色，hover 提示：已自动切换规则检测)
模型熔断中   ▏ 3%             (灰色，hover 提示：请联系运维团队)
策略跳过     █ 10%            (灰色)
```

**交互细节**：
- 每个色块可点击，点击后下钻到事件列表，自动带上对应的 AI 状态过滤条件
- "服务超时已降级"和"模型熔断中"增加小图标，hover 显示 1 句话解释 + 建议动作

## 三、事件详情页工作流重组（核心改造）

### 3.1 从"字段平铺"到"处置引导"的信息架构

**问题**：当前 `event-detail.html` 采用左右分栏 + 多卡片平铺，信息密度过高，用户不知道下一步该做什么。

**方案**：重组为 **"风险事实 → AI 研判 → 证据 → 处置决策"** 的垂直故事线。

#### 新布局结构（单栏垂直流）：

```
┌─────────────────────────────────────┐
│  [面包屑] 风险事件 / 事件详情 / EVT-001  │
├─────────────────────────────────────┤
│  🔴 高风险  |  AI 辅助：可信（绿色徽章）   │  ← 标题区，仅保留业务状态
│  工具能力边界越界 — external_http_post   │
│  应用：研发代码审查助手  |  时间：10:25:30 │
├─────────────────────────────────────┤
│  📋 AI 研判摘要（可展开）               │  ← 第二屏核心
│  攻击手法：工具能力边界越界              │
│  置信度：高  |  优先级：High            │
│  影响面：1个应用，3个活跃会话            │
│  [查看完整研判报告 ↓]                   │
├─────────────────────────────────────┤
│  🔍 证据与命中片段（研判报告展开后显示）    │  ← 证据紧跟结论
│  命中片段：...tool.input 包含外部URL...  │
│  判定理由：① 工具调用超出白名单范围      │
│           ② 目标域名为未授权外部服务     │
│  [缺失证据] 用户上下文未提供             │
├─────────────────────────────────────┤
│  ⚡ 处置决策                            │  ← 单一操作区
│  ┌─────────────────────────────────┐  │
│  │  确认风险，执行处置              │  │
│  │  ├─ 下发限制（推荐：限制工具频率）│  │
│  │  ├─ 加入监控名单                 │  │
│  │  └─ 指派负责人                   │  │
│  ├─────────────────────────────────┤  │
│  │  标记误报                        │  │
│  │  （弹窗：是否将本次误判反馈至     │  │
│  │   AI 样本库，帮助模型优化？）      │  │
│  ├─────────────────────────────────┤  │
│  │  接受风险                        │  │
│  │  （需关联审批编号 + 有效期）       │  │
│  └─────────────────────────────────┘  │
├─────────────────────────────────────┤
│  📜 处置历史与审计日志（折叠态）         │  ← 底部，默认折叠
├─────────────────────────────────────┤
│  🔧 技术详情（trace_id, model_version）  │  ← 最底部，仅管理员展开
│  （默认折叠，点击"展开技术详情"显示）   │
└─────────────────────────────────────┘
```

### 3.2 操作按钮合并：从三组到一组

**问题**：AI 研判卡片（确认/修正/拒绝）+ AI 处置建议（采纳/修改/拒绝/转人工）+ 处置动作（限制/误报/接受/登记）三组按钮并存，用户面临逻辑死锁。

**方案**：将"对 AI 的反馈"与"对事件的处置"合并为单一决策流。

**决策树交互**：

```
用户点击 [标记误报]
    ↓
弹窗：请选择误报原因
    ├─ 测试数据或演练数据
    ├─ 业务允许的工具调用
    ├─ 规则阈值过严
    └─ 上下文缺失导致误判
    ↓
复选框（默认勾选）：同时将本次情况反馈给 AI 样本库
    ↓
提交 → 事件标记为误报 + 自动提交 AI 反馈（rejected + 原因）
```

```
用户点击 [确认风险，执行处置]
    ↓
展开子菜单（而非弹窗）：
    ├─ 下发限制 → 选择范围/时长/审批编号 → 执行
    ├─ 加入监控名单 → 选择监控时长 → 执行
    └─ 指派负责人 → 选择负责人 → 执行
    ↓
同时自动提交 AI 反馈（confirmed）
```

**关键原则**：
- **处置动作自动携带 AI 反馈**：只要用户做出了处置决策（确认风险 / 标记误报 / 接受风险），系统自动推断对应的 AI 反馈，无需用户在两处分别操作
- **例外情况**：如果用户想"修正 AI 研判"（如 AI 判为高风险，用户认为中风险但不完全误报），在处置前增加一步"是否调整 AI 研判等级？"，将"修正"内嵌进处置流
- **AI 处置建议卡片降级为提示**：不再作为独立操作区，而是在"下发限制"子菜单中以高亮提示形式出现："AI 建议：限制工具调用频率（预计误伤率 < 2%）"

### 3.3 移除 P3 能力卡片（分期隔离）

**问题**：P0.5a 页面混入了 P3 的 AI 处置建议卡片、自动执行台账、动作与审批台账。

**方案**：
- **P0.5a 事件详情页仅保留**：事件基本信息、AI 研判摘要、证据命中片段、人工处置决策区、处置历史（手动操作记录）
- **P3 元素移除或灰态化**：
  - AI 处置建议卡片 → 移除，改为处置子菜单中的文本提示
  - 自动执行台账 → 移除（P3 才具备自动执行能力）
  - 动作与审批台账 → 保留但简化，仅展示人工操作记录（移除 `action_id`、`approval_id` 等工程字段）

## 四、信息层级重构与首屏简化

### 4.1 首屏只保留"风险事实"

**问题**：首屏被 `trace_id`、`span_id`、`source_field`、`model_version` 等开发态术语占领。

**方案**：首屏黄金区域仅保留 4 个要素：

| 要素 | 示例 | 理由 |
|-----|------|------|
| **主体** | 应用：研发代码审查助手 | 谁引发了风险 |
| **客体** | 工具：external_http_post | 访问了什么 |
| **风险事实** | 工具能力边界越界（高风险） | 发生了什么 |
| **AI 可信度** | 可信 / 待确认 / 不可用 | AI 辅助是否可靠 |

其余字段按优先级下沉：

| 字段 | 原位置 | 新位置 | 可见权限 |
|-----|--------|--------|---------|
| `trace_id` / `span_id` | 首屏标题下方 | 底部"技术详情"折叠面板 | 管理员/研发 |
| `model_version` / `prompt_template_version` | 右侧 AI 研判卡片 | 底部"技术详情"折叠面板 | 管理员/研发 |
| `evidence_offset` | 证据 Tab 内 | 命中片段内联标注（小字灰色） | 全部 |
| `source_field` | 首屏 | 证据区块内 | 全部 |
| `detection_source` | 首屏标签 | 保留但简化：仅显示"规则检出" / "AI 辅助检出" / "联合检出" | 全部 |

### 4.2 证据与结论合并为"AI 研判报告"单一区块

**问题**：证据在左侧 Tab 内，结论在右侧卡片，视线左右跳跃。

**方案**：
- 取消左侧"证据工作区"的多 Tab 设计（原始会话 / AI 检测结果 / 关联规则 / 上下文）
- 改为 **"AI 研判报告" 单一可展开区块**，内部按信息层级组织：

```
📋 AI 研判摘要（默认展开前 2 行，点击展开完整报告）
  ├── 攻击手法：工具能力边界越界
  ├── 置信度：高  |  优先级：High  |  模型版本：sec-judge-v1.2（小字灰色）
  ├── 影响面评估：1 个应用，3 个活跃会话，预计误伤率 < 2%
  ├── [展开完整报告 ↓]
  │   ├── 🔍 命中片段（原始会话中触发检测的关键段落，高亮标红）
  │   ├── 📝 判定理由（结构化列表：① ② ③）
  │   ├── ❓ 不确定性（缺失证据 / 需人工补充的问题）
  │   └── 📚 相似事件参考（3 条历史相似事件，可点击跳转）
```

**交互细节**：
- "命中片段"直接引用原始会话文本，用红色高亮标注触发段落，无需切换 Tab
- "判定理由"用编号列表，每条理由下可展开"对应证据"（点击理由 → 自动滚动到命中片段的对应位置）
- "缺失证据"用黄色背景提示，引导用户补充上下文

## 五、分期边界隔离与灰态方案

### 5.1 事件详情页分期元素灰态处理

对于 P0.5a 页面中必须占位（但后端未实现）的功能：

| 功能 | 当前实现 | 改造方案 |
|-----|---------|---------|
| AI 处置建议"采纳并执行"按钮 | 可点击，toast 提示"已采纳" | 按钮改为 **纯文本提示**（不可点击）："P3 阶段将支持一键采纳 AI 建议自动执行" |
| 自动执行台账 | 展示 L1/L2/L3 动作记录 | **移除该卡片**，P3 再引入 |
| 动作与审批台账 | 展示 `action_id`、`rollback_status` | 简化为"操作审计日志"，仅展示：时间、操作人、操作类型、备注 |

### 5.2 知识库页面（P1）引导式改造

**问题**：`security-qa.html` 只有一个输入框，首次使用不知道问什么；`source-ref` 以纯文本展示，可信度不明。

**方案**：

```
┌─────────────────────────────────────┐
│  安全知识问答                          │
│  "基于安全知识库的 AI 问答助手..."      │
├─────────────────────────────────────┤
│  ┌─────────────────────────────────┐  │
│  │ 🔍 输入问题...              [提问] │  │
│  └─────────────────────────────────┘  │
│                                      │
│  💡 常见问题快捷入口（可点击直接提问）   │
│  ┌────────┐ ┌────────┐ ┌────────┐  │
│  │ 如何配置 │ │ 提示词注入 │ │ 数据分级 │  │
│  │ 提示词攻击│ │ 攻击手法 │ │ 管理规范 │  │
│  │ 防护策略？│ │ 有哪些？ │ │ 是什么？ │  │
│  └────────┘ └────────┘ └────────┘  │
│                                      │
│  📚 热门知识库条目（最近 7 天高频查询）  │

│  ───────────────────────────────────  │
│  💬 问答历史                           │
│  Q: 提示词注入攻击有哪些常见手法？       │
│  A: ...（来源：知识库条目 #128，可信度：高）│
│     [查看原文 →]                       │
└─────────────────────────────────────┘
```

**交互细节**：
- 首次进入页面（问答历史为空）时，自动展开"常见问题快捷入口"和"热门知识库条目"
- 问答结果中的 `source-ref` 改为结构化卡片：
  - 来源条目名称（可点击跳转）
  - 可信度标签："高"（来自官方知识库）/ "中"（来自社区贡献）/ "低"（来自模型生成，未匹配知识库）
  - 关联度百分比
- 答案底部增加反馈按钮："有帮助 👍 / 无帮助 👎 / 信息过时"，用于持续优化 RAG 效果

## 六、图表交互与 AI 标识统一

### 6.1 安全总览图表升级

**问题**：`dashboard.html` 中趋势图用 CSS 模拟柱状图，无 tooltip、无下钻、无联动。

**方案**：
- 引入 ECharts（注释掉的脚本启用），实现：
  - **Tooltip**：hover 柱状图显示具体数值 + 占比
  - **点击下钻**：点击某天柱状图 → 事件列表自动过滤该日期
  - **联动筛选**：时间范围切换（今日/近7天/近30天）时，所有图表同步更新
  - **异常标注**：自动标记 AI 检测异常峰值（如 `circuit_open` 突增），hover 显示异常原因
- 风险趋势图增加图例说明：蓝色=规则检出，紫色=AI 检出，红色=联合检出，灰色=AI 跳过

### 6.2 AI 结论全局统一标识体系

**问题**：有些页面有"AI 分析"标签（`correlation-analysis.html`），有些只标"预测"（`soc-dashboard.html`），不一致。

**方案**：建立全局 AI 标识规范：

| 场景 | 标识样式 | 说明 |
|-----|---------|------|
| AI 分析结论（已确认） | 🟢 绿色角标 "AI·已确认" | 人工已复核 |
| AI 分析结论（未确认） | 🟡 黄色角标 "AI·待确认" | 需人工复核 |
| AI 预测/推测 | 🟠 橙色角标 "AI·预测" | 仅供参考，不作为决策依据 |
| AI 辅助生成（文本/摘要） | 🔵 蓝色角标 "AI·生成" | 内容来自模型生成 |
| AI 服务异常 | ⚪ 灰色角标 "AI·不可用" | 服务熔断/超时 |

**交互细节**：
- 所有带 AI 角标的内容 hover 显示 tooltip："本内容/结论由 AI 模型生成，[可信度状态]"
- "AI·预测"和"AI·生成"的内容区域增加半透明水印底纹，强化"非事实"认知
- SOC 驾驶舱中的预测链路（`soc-dashboard.html`）统一使用 "AI·预测" 角标，而非纯文本"预测"

## 七、L4 强控制约束显性化

**问题**：自动响应页 L4"不可自动执行、必须审批/MFA/可回滚"的约束仅在页面说明中，未形成强约束交互。

**方案**：

### 7.1 配置区风险等级色块

在自动响应规则配置页（`pages/policy/auto-response.html`）中：
- 动作级别选择器改为 **色块分段滑块**：
  - L1（蓝色）：自动执行，无需审批
  - L2（绿色）：自动执行，通知管理员
  - L3（黄色）：自动执行，需二次确认
  - L4（红色）：**不可自动执行**，必须审批 + MFA + 可回滚
- 当用户拖动到 L4 时：
  - 滑块区域抖动一次（视觉警示）
  - 下方自动展开审批配置面板（审批人、MFA 方式、回滚 TTL）
  - 顶部出现红色横幅："L4 动作将阻断业务流量，请确认审批流程已就绪"

### 7.2 执行确认弹窗强制约束

当用户尝试执行 L4 动作时：
- **阻断弹窗**（不可绕过）：
  ```
  ⚠️ 高危动作确认
  动作级别：L4（不可自动执行）
  该动作将 [阻断应用访问 / 注销用户会话 / 隔离数据源]
  
  请完成以下确认：
  □ 我已获得业务负责人书面审批（审批编号：________）
  □ 我已确认 MFA 验证码（6 位数字）
  □ 我已确认回滚策略（TTL：________ 小时）
  
  [确认执行]（仅当以上全部勾选时可用）
  [取消]
  ```
- 审批编号输入框增加实时校验（格式 + 数据库查询是否存在）
- MFA 验证码输入后增加倒计时（60 秒），超时需重新获取
