## 一、分期边界修复：导航可见性控制系统

### 方案：基于 `data-phase` 的分期标记 + 全局开关

**实现思路**：为每个导航项增加 `data-phase` 属性，通过全局开关控制可见性。

```html
<!-- index.html 导航项增加分期标记 -->
<div class="nav-item" data-phase="P0.5a" data-page="pages/events/event-list.html">风险事件</div>
<div class="nav-item" data-phase="P1" data-page="pages/knowledge/knowledge-item.html">知识条目管理</div>
<div class="nav-item" data-phase="P2a" data-page="pages/monitor/soc-dashboard.html">SOC分析驾驶舱</div>
<div class="nav-item" data-phase="P3" data-page="pages/policy/auto-response-rules.html">自动响应规则</div>
```

**交互规则**：

- 顶部栏增加分期切换器：`[P0.5a 当前] [P0.5b] [P1] [P2] [P3]`，当前激活期次高亮
- 仅展示 `<= 当前期次` 的导航项，后续期次自动隐藏
- 后续期次的导航项在隐藏态增加半透明占位 + "P1 开放" 标签，让评审者知道有规划但不承诺当前交付
- [event-detail.html](cci:7://file:///E:/code/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%AE%89%E5%85%A8%E7%9B%91%E6%B5%8B%E5%B9%B3%E5%8F%B0/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/%E5%8E%9F%E5%9E%8B%E5%9B%BE-%E6%99%BA%E8%83%BD%E7%89%88/pages/events/event-detail.html:0:0-0:0) 同理：AI处置建议卡片和自动执行台账用 `data-phase="P3"` 标记，P0.5a模式下折叠为"P3 将提供自动响应能力"占位卡片

**验收效果**：切换期次开关，导航和页面内容随之变化，评审时一目了然。

## 三、事件详情页重构 —— 核心改造

### 3.1 渐进式信息披露

将当前8个卡片区域重组为三层结构：

```
┌─────────────────────────────────────────────────────────────┐
│ 第一层：决策摘要区（始终可见，不折叠）                        │
│ ┌─────────────────────┐ ┌─────────────────────────────────┐ │
│ │ 风险判定             │ │ AI研判结论                       │ │
│ │ 工具能力边界越界     │ │ 攻击手法: 工具越界               │ │
│ │ 高风险 · 置信度 0.91 │ │ 影响面: 单应用，3个活跃会话       │ │
│ │ 规则+AI联合检出      │ │ 建议: 限制工具调用频率           │ │
│ │                      │ │ 置信等级: 高                    │ │
│ │ [确认风险] [标记误报]│ │ [采纳并处置] [转人工审核]        │ │
│ └─────────────────────┘ └─────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│ 第二层：证据与分析区（可折叠）                                │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ [证据链] [AI检测详情] [相似事件(3)] [处置历史]            │ │
│ │                                                         │ │
│ │ 当前Tab内容...                                           │ │
│ └─────────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│ 第三层：技术详情（默认折叠）                                  │
│ ▼ 元数据与调试信息                                          │
│   trace_id / span_id / model_version / evidence_offset ...  │
└─────────────────────────────────────────────────────────────┘
```

**关键变化**：

- **AI研判卡片从右侧提升到首屏核心位置**，与风险判定并列，成为决策摘要区
- **操作按钮从3套合并为2个核心动作**："确认风险" / "标记误报"，点击后弹出统一处置面板
- **证据与AI检测结果合并到同一Tab区域**，不再左右拆分
- **技术字段全部沉入第三层**，默认折叠

### 3.2 统一处置面板（合并三套操作区）

点击"确认风险"或"标记误报"后，弹出统一处置面板：

```
┌──────────────────────────────────────────┐
│ 处置: EVT-2026-00018                      │
├──────────────────────────────────────────┤
│ 处置结论:                                 │
│ ○ 确认风险，需要处置                      │
│ ○ 标记为误报                              │
│ ○ 接受风险（需审批）                       │
│                                          │
│ 处置动作:                                 │
│ ☑ 限制工具 external_http_post 调用频率    │
│    TTL: [6小时 ▼]  级别: L3软限制        │
│ □ 通知应用负责人                          │
│ □ 加入监控名单                            │
│                                          │
│ 反馈AI（帮助改进检测）:                    │
│ ☑ 将此事件作为样本反馈                    │
│    样本类型: [命中样本 ▼]                 │
│    补充说明: [_______________]            │
│                                          │
│ [取消]              [提交处置]            │
└──────────────────────────────────────────┘
```

**交互逻辑**：

- 处置结论和处置动作合并在一个面板中，线性步骤
- "反馈AI"作为面板中的一个可选区域，默认勾选，不强制用户单独操作
- 选择"标记误报"时，处置动作区自动禁用，样本类型自动切换为"误报样本"

### 3.3 证据→结论连贯布局

将AI检测详情Tab与研判结论放在同一视觉流中：

```
证据工作区
├── Tab: 证据摘要    ← 原始证据
├── Tab: AI检测详情  ← AI为什么命中（命中片段 + 判断理由 + 反例提示）
└── Tab: 规则解释

↓ 紧接下方

AI研判结论卡片       ← AI对全局的判断（攻击手法 + 影响面 + 处置建议）
```

用户从上到下自然阅读：原始证据 → AI检测依据 → AI综合研判，形成完整证据链。

## 四、AI状态术语用户化

### 4.1 状态映射表

建立工程状态到用户语言的映射，在UI层统一转换：

| 工程值                | 用户语言                   | 视觉表达        |
| --------------------- | -------------------------- | --------------- |
| `success`           | AI分析完成                 | 绿色对勾        |
| `pending`           | AI分析中...                | 蓝色加载动画    |
| `timeout`           | AI响应超时，已切换规则检测 | 黄色提示        |
| `error`             | AI服务异常，请人工研判     | 红色提示        |
| `circuit_open`      | AI服务熔断保护中           | 灰色 + 问号图标 |
| `skipped_by_policy` | 按策略未启用AI检测         | 灰色标签        |
| `generated`         | AI研判已完成               | 绿色标签        |
| `confirmed`         | 已确认（人工）             | 蓝色标签        |
| `modified`          | 已修正（人工）             | 橙色标签        |
| `rejected`          | 已拒绝（人工）             | 灰色标签        |

### 4.2 状态精简

将15种状态组合收敛为用户关心的3个维度：

```
┌────────────────────────────────────────────┐
│ AI辅助状态                                 │
│                                            │
│ 检测: ✅ 已完成  │ 研判: ✅ 已完成         │
│ 综合可信度: 高   │ 需要人工复核: 否        │
└────────────────────────────────────────────┘
```

异常态时展开详情：

```
│ 检测: ⚠️ 服务熔断  │ 研判: — 未执行        │
│ 当前仅展示规则检测结果，AI恢复后将自动补充  │
│ [查看技术详情]                              │
```
