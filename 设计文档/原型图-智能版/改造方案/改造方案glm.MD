## 一、设计文档与原型实现的对齐问题

### 1. 期次边界在原型中模糊，P0.5a/P0.5b/P1/P2/P3内容混装

概要设计明确定义了严格的分期交付边界（P0→P0.5a→P0.5b→P1→P2→P3→P4），但原型HTML页面**未做期次标识**：

- `@E:\code\大模型安全监测平台\设计文档\原型图-智能版\pages\events\event-detail.html` 同时包含了P0.5a的AI检测结果Tab、P3的AI处置建议面板和自动执行台账
- `@E:\code\大模型安全监测平台\设计文档\原型图-智能版\pages\policy\auto-response-rules.html` 是P3功能，但已完整实现
- `@E:\code\大模型安全监测平台\设计文档\原型图-智能版\pages\monitor\soc-dashboard.html` 是P2功能，也已完整实现

**后果**：开发团队无法从原型中区分"这期必须做"和"后续才做"，容易导致P0.5a阶段就试图实现P3功能，拖延交付。

**建议**：每个页面/Tab/卡片区域标注期次标签（如 `[P0.5a]` `[P3]`），未到期次的内容用灰色占位或折叠区标注"XX期次交付"。

| 设计文档定义                                                                                                       | 原型实现状态                                                            | 问题                                                   |

### 3. 服务接口路径在原型说明中定义但HTML未实现交互

08-AI模型与服务治理原型说明定义了9个接口路径（`/model-registries` CRUD等），但 [model-registry.html](cci:7://file:///E:/code/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%AE%89%E5%85%A8%E7%9B%91%E6%B5%8B%E5%B9%B3%E5%8F%B0/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/%E5%8E%9F%E5%9E%8B%E5%9B%BE-%E6%99%BA%E8%83%BD%E7%89%88/pages/system/model-registry.html:0:0-0:0) 是纯静态展示，无任何API交互模拟。同样，09-数据分级定义了 `/data-classification-rules/{id}/evaluate` 测试接口，但原型中"执行预览"按钮无实际效果。

## 二、信息架构结构性问题

### 4. "知识库管理"模块职责越界

导航结构将"模型效果评估"放在"知识库管理"下：

```
知识库管理
  ├── 知识条目管理
  ├── 样本库管理
  ├── 策略模板库
  ├── 安全知识问答
  └── 模型效果评估  ← ML运维概念，不属于知识库
```

但设计文档 `@E:\code\大模型安全监测平台\设计文档\智能化改造\概要设计\系统设计\01-总体架构改造.md:72-76` 明确定义 `ai-model-service` 负责模型调用管理/评分融合/熔断器/**评测**，`knowledge-service` 负责知识库/RAG/样本库。模型评测应归属AI模型治理域而非知识库域。

**建议**：将"模型效果评估"移至系统管理下的"AI模型治理"子组（与模型注册、Prompt模板、AI服务监控同组）。

### 5. 安全监控9个平级子菜单缺少分组

[index.html](cci:7://file:///E:/code/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%AE%89%E5%85%A8%E7%9B%91%E6%B5%8B%E5%B9%B3%E5%8F%B0/%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3/%E5%8E%9F%E5%9E%8B%E5%9B%BE-%E6%99%BA%E8%83%BD%E7%89%88/index.html:0:0-0:0) 中安全监控下9个入口完全平铺，但使用频率差异极大：

- **日常高频**：风险溯源工作台、会话风险追踪、会话列表
- **分析低频**：SOC驾驶舱、人员风险分析、风险关联分析、行为基线管理、组织风险态势
- **运维入口**：AI服务监控（应归系统管理）

**建议**：分为"日常监控"和"高级分析"两组，AI服务监控移至系统管理。

### 6. 策略中心按"网关/探针"技术分类而非业务场景分类

设计文档 `@E:\code\大模型安全监测平台\设计文档\智能化改造\概要设计\系统设计\03-场景1-风险识别增强.md:171-179` 中原型改造建议明确提到"内容安全策略增加AI检测配置Tab"，但导航仍按"网关策略→探针策略"组织。安全运营人员关心"防什么"而非"跑在哪"。

**建议**：增加"按防护对象"视图（提示词防护、数据防泄露、工具管控），作为技术分类的补充入口。

## 三、交互流程断裂问题

### 7. 事件详情页三套操作区无流程引导（最严重的交互问题）

event-detail.html 右侧存在三套并列操作区：

| 操作区     | 操作                                              | 期次  |
| ---------- | ------------------------------------------------- | ----- |
| AI研判卡片 | 确认/修正/拒绝                                    | P0.5a |
| AI处置建议 | 采纳/修改后执行/拒绝/转人工                       | P3    |
| 处置动作   | 指派/下发限制/标记误报/接受风险/处置登记/生成摘要 | 现有  |

用户不知道先做哪个。设计文档 `@E:\code\大模型安全监测平台\设计文档\智能化改造\概要设计\系统设计\04-场景2和3-研判与处置增强.md` 定义了明确的流程：**研判→处置建议→执行**，但原型未体现这个步骤依赖。

**建议**：设计为向导式流程 Step1确认研判 → Step2选择处置 → Step3执行，而非三个并列操作区。

### 8. 反馈回流路径在原型中不完整

设计文档定义的反馈闭环：

```
人工确认 → 样本入候选集 → 复核 → 分流到训练集/评测集/回归集 → 支撑模型评测/规则优化
```

但原型中：

- event-detail.html 的修正弹窗有"是否加入样本候选集"开关，但**拒绝操作没有此选项**
- sample-library.html 有候选集/训练集/评估集/回收站Tab，但**缺少设计文档定义的"争议集"和"回归集"**
- 设计文档明确"争议集"是人工与AI判断不一致的边界样本，优先进入下一轮评测，这是样本治理的核心机制

**建议**：补充争议集和回归集Tab；拒绝操作也应支持入样本候选集。

### 9. 页面间跳转缺少上下文传递

- 安全总览点击AI检出指标卡 → 事件列表，但事件列表不知道筛选条件来自哪里
- 人员风险分析点击关联事件 → 事件详情，但事件详情不知道用户是从哪个分析路径来的
- SOC驾驶舱点击五维指标卡 → 对应分析页，但未携带时间范围

**建议**：跳转携带来源上下文参数，目标页提供面包屑或"返回分析"快捷入口。

## 四、数据一致性问题

### 10. AI状态枚举在原型中不完整

设计文档 `@E:\code\大模型安全监测平台\设计文档\智能化改造\概要设计\系统设计\99-评审修复总结.md:82-98` 修复后定义了完整的9状态枚举：

| ai_analysis_status | 原型展示                  |
| ------------------ | ------------------------- |
| pending            | ✅ 有                     |
| generated          | ✅ 有                     |
| confirmed          | ✅ 有                     |
| modified           | ✅ 有                     |
| rejected           | ✅ 有                     |
| timeout            | ❌ 原型未展示研判超时状态 |

**建议**：AI研判卡片区域需覆盖全部9种 `ai_analysis_status`，特别是异常状态下的降级提示。

### 11. 评分融合逻辑在原型中不可验证

设计文档定义了 `composite_risk_score = max(rule_risk_score, ai_risk_score)`（AI置信度>阈值时），但event-detail.html只展示了一个综合评分，用户无法看到：

- 规则评分是多少
- AI评分是多少
- 融合策略是什么
- AI是否导致了等级上升（触发二次告警）

**建议**：评分区域拆分展示规则评分/AI评分/融合策略/综合评分，并标注"AI导致等级上升"的情况。

### 12. 样本集分类与设计文档不一致

设计文档 `@E:\code\大模型安全监测平台\设计文档\智能化改造\概要设计\系统设计\02-三大底座设计.md:253-263` 定义了5类样本集：**候选集、训练集、评测集（固定）、回归集、争议集**。

差异：

- 缺少"回归集"（用于规则/模型变更前回放验证）
- 缺少"争议集"（人工与AI判断不一致的边界样本）
- "回收站"是原型自行添加的，设计文档未定义
