# 大模型安全监测平台原型交互改造方案（汇总版）

> 基于多模型反馈交叉分析，剔除不合理或过度设计的方案，保留可落地、高价值的交互改造项。

---

## 一、问题域总览（按优先级排列）

### P0 — 阻断级：运营人员无法正常工作

| 编号 | 问题域 | 核心痛点 | 来源 |
|------|--------|---------|------|
| P0-1 | **事件详情页工作流断裂** | 三套操作区（AI研判/AI处置建议/处置动作）并列，用户不知先做哪个；"确认研判"与"处置登记"逻辑关系不明 | kimi / deepseek / glm |
| P0-2 | **术语过载与状态机爆炸** | 首屏同时展示事件状态、AI检测状态（`success`/`timeout`/`circuit_open`）、AI研判状态（`generated`/`confirmed`），15种组合无法快速判断"能不能信" | kimi / deepseek / glm |
| P0-3 | **分期边界混在一起** | P1知识库、P2 SOC分析、P3自动响应与P0.5a页面同权展示，开发团队和验收方无法区分交付范围 | CODEX / deepseek / glm |
| P0-4 | **AI状态枚举不完整** | `timeout`/`error`/`circuit_open`/`skipped` 等异常状态在事件详情页无UI表达，降级场景不可验证 | glm |

### P1 — 高优级：严重影响效率或存在合规风险

| 编号 | 问题域 | 核心痛点 | 来源 |
|------|--------|---------|------|
| P1-1 | **信息架构错位** | 数据分级管理挂在"统一策略中心"下、AI服务监控挂在"安全监控"下，文件路径与导航分组不一致 | kimi / deepseek / glm |
| P1-2 | **首屏被开发态术语占领** | `trace_id`/`span_id`/`model_version`/`prompt_template_version` 占据首屏黄金位置，运营人员日均处理几百告警时视觉噪音严重 | kimi / deepseek |
| P1-3 | **证据与结论物理拆散** | AI命中片段藏在左侧"证据工作区→AI检测结果Tab"，AI研判结论放在右侧卡片，用户必须左右跳跃阅读 | kimi / deepseek |
| P1-4 | **反馈回流路径断裂** | 样本库缺少"争议集"和"回归集"Tab；拒绝AI研判时不支持入样本候选集；设计文档定义的"人工→样本→训练/评测/回归"闭环在原型中断裂 | glm |
| P1-5 | **评分融合逻辑不可验证** | `composite_risk_score = max(rule_risk_score, ai_risk_score)` 只展示综合评分，无法看到规则评分、AI评分、融合策略、是否AI导致等级上升 | glm |
| P1-6 | **数据分级交互约束未体现** | 选择L2级别却配置Cloud部署模式、选择L3却用Webhook发送——原型未校验和阻断违规配置 | glm |
| P1-7 | **页面间跳转无上下文** | 安全总览点击AI检出指标→事件列表，筛选条件丢失；人员风险分析跳转事件详情，不知来源路径 | deepseek / glm |

### P2 — 优化级：体验打磨与能力补齐

| 编号 | 问题域 | 核心痛点 | 来源 |
|------|--------|---------|------|
| P2-1 | **默认首页不合理** | 默认加载"接入应用管理"，运营人员首屏看不到待处置风险 | kimi / deepseek |
| P2-2 | **安全监控导航膨胀** | 9个平级子菜单无分组，高频操作（溯源、会话追踪）与低频分析（SOC驾驶舱、组织态势）混杂 | deepseek / glm |
| P2-3 | **图表交互能力不足** | ECharts脚本被注释，趋势图用CSS模拟，无tooltip、下钻、联动、导出 | CODEX / deepseek |
| P2-4 | **AI结论标识不全局一致** | 关联分析页有"AI分析"标签，SOC驾驶舱只标"预测"，无统一"AI分析/需人工确认"表达 | CODEX / deepseek |
| P2-5 | **L4强控制约束不够显性** | "不可自动执行、必须审批/MFA/可回滚"仅在页面说明中，未形成阻断式交互约束 | CODEX / deepseek / glm |
| P2-6 | **熔断器操作缺少二次确认** | "手动恢复"/"强制熔断"无二次确认弹窗，无审计提示，无渐进流量恢复模拟 | glm |
| P2-7 | **成本超限降级体验缺失** | 80%告警→100%限流→仅规则引擎运行，但原型无超限后的降级状态展示 | glm |
| P2-8 | **知识库缺乏引导** | `security-qa.html` 只有输入框，无常见问题快捷入口、无来源可信度标识 | kimi |

## 二、交互解决方案

### 2.1 事件详情页工作流重组（P0-1）

**现状**：右侧同时存在三组操作卡片——AI研判（确认/修正/拒绝）、AI处置建议（采纳并执行/修改后执行/拒绝并记录/转人工）、处置动作（下发限制/标记误报/接受风险/处置登记）。用户面临逻辑死锁："该先确认研判，还是直接处置？"

**方案**：将"对AI的反馈"与"对事件的处置"合并为单一决策流，采用**向导式三步**替代三列并列：

```
Step 1: 查看AI研判摘要（默认展开）
  └── 攻击手法 / 置信度 / 影响面 / 判定理由（命中片段内联展示）
  └── [我认为研判准确] → 进入Step 2
  └── [我认为研判有误] → 弹窗：调整风险等级 + 填写原因（同时勾选"反馈至样本库"）→ 进入Step 2

Step 2: 选择处置方向（三选一，单选）
  ┌─ A. 确认风险，执行处置 ──┐
  │  ├─ 下发限制（范围/时长/审批编号）      │
  │  ├─ 加入监控名单（时长）                │
  │  └─ 指派负责人                          │
  ├─ B. 标记误报 ───────────┤
  │  ├─ 选择误报原因                        │
  │  └─ ☑ 同时反馈给AI样本库（默认勾选）    │
  └─ C. 接受风险 ───────────┘
     └─ 关联审批编号 + 有效期

Step 3: 执行确认
  └── 摘要确认弹窗（动作/范围/影响评估）→ 二次确认 → 提交
```

**关键原则**：
- **处置即反馈**：用户做出任何处置决策（确认风险/标记误报/接受风险），系统自动推断对应的AI反馈（confirmed/rejected/accepted），无需在两处分别操作
- **AI处置建议降级为提示**：不再作为独立操作区，而是在"下发限制"子菜单中以高亮文本出现："AI建议：限制工具调用频率（预计误伤率<2%）"
- **移除P3元素**：AI处置建议卡片、自动执行台账、动作与审批台账（`action_id`/`approval_id`/`rollback_status`）在P0.5a阶段移除或灰态化

### 2.2 状态机收敛：引入"AI辅助可信度"（P0-2 + P0-4）

**现状**：三套独立状态机（事件状态、AI检测状态、AI研判状态）共15种组合，运营人员无法快速判断"这个事件的AI结果能不能信"。

**方案**：合并为单一**"AI辅助可信度"**标识，替换原始枚举值。

| 原始状态组合 | 可信度等级 | 视觉标识 | 运营人员看到的文案 |
|-------------|-----------|---------|-----------------|
| AI检测=success + 有研判 + 置信度高 | **可信** | 🟢 绿色徽章 + 对勾 | "AI辅助分析已完成，结论可信" |
| AI检测=success + 有研判 + 置信度低 | **待确认** | 🟡 黄色徽章 + 问号 | "AI辅助分析已完成，置信度较低，建议人工复核" |
| AI检测=success + 研判=generated（未确认） | **待确认** | 🟡 黄色徽章 + 问号 | "AI辅助分析已生成，等待人工确认" |
| AI检测=timeout / error | **不可用** | ⚪ 灰色徽章 + 横线 | "AI辅助当前不可用，已自动切换至规则检测" |
| AI检测=circuit_open | **不可用** | ⚪ 灰色徽章 + 横线 | "AI服务熔断中，已自动切换至规则检测" |
| AI检测=skipped_by_policy | **未启用** | ⚪ 灰色徽章 + 斜线 | "本事件按策略配置跳过AI检测" |
| AI检测=not_configured | **未启用** | ⚪ 灰色徽章 + 斜线 | "本策略未配置AI辅助" |

**交互细节**：
- 徽章放在事件标题右侧，hover显示tooltip解释当前状态含义
- 点击徽章展开面板，展示原始技术状态（仅对管理员/研发人员可见）
- **运营人员永远看不到原始枚举值**（`success`/`timeout`/`circuit_open`/`skipped` 等）

### 2.3 分期可见性控制（P0-3）

**现状**：P1/P2/P3页面与P0.5a同权展示，用户点击后可能进入空状态页面。

**方案**：引入三级可见性策略

| 期次 | 导航状态 | 视觉处理 | 点击行为 |
|-----|---------|---------|---------|
| P0.5a（当前交付） | 正常可见 | 全彩色 + 徽标数字 | 正常跳转 |
| P1（下个迭代） | **预览态** | 图标+文字灰色50%，右侧标注"P1即将上线" | 可点击，页面顶部显示黄色横幅："本功能正在开发中，当前为预览版" |
| P2/P3（远期） | **隐藏态** | 默认折叠在"更多功能"分组内 | 点击展开分组，灰色文字，不可点击，tooltip提示"预计P2开放" |

---

### 2.4 信息架构归位（P1-1 + P2-2）

**现状**：数据分级管理挂在"统一策略中心"下，AI服务监控挂在"安全监控"下，安全监控9个子项平铺无分组。

**方案**：

| 页面 | 当前分组 | 目标分组 | 理由 |
|-----|---------|---------|------|
| 数据分级管理 | 统一策略中心 | **系统管理** | 数据分级是全局基础设施配置，不随策略规则变动 |
| AI服务监控 | 安全监控 | **AI模型治理** | AI服务监控是模型运维能力，与模型注册/版本管理同域 |
| 模型注册管理 / Prompt模板 | 系统管理 | **AI模型治理**（目录统一至`pages/ai-governance/`） | 文件路径与菜单分组一致 |

**安全监控子菜单重组**：
```
安全监控
├── 日常监控（高频）
│   ├── 风险溯源工作台
│   ├── 会话风险追踪
│   └── 会话列表
├── 高级分析（低频，P2能力预览态）
│   ├── SOC分析驾驶舱
│   ├── 人员风险分析
│   ├── 风险关联分析
│   ├── 行为基线管理
│   └── 组织风险态势
```

### 2.5 首屏简化与技术元数据下沉（P1-2 + P1-3）

**现状**：首屏被`trace_id`/`span_id`/`model_version`占领；证据在左侧Tab内，结论在右侧卡片，视线左右跳跃。

**方案**：

**首屏仅保留4要素**：
- **主体**：应用：研发代码审查助手
- **客体**：工具：external_http_post
- **风险事实**：工具能力边界越界（高风险）
- **AI可信度**：可信 / 待确认 / 不可用

**其余字段下沉**：

| 字段 | 原位置 | 新位置 | 可见权限 |
|-----|--------|--------|---------|
| `trace_id` / `span_id` | 首屏标题下方 | 底部"技术详情"折叠面板 | 管理员/研发 |
| `model_version` / `prompt_template_version` | 右侧AI研判卡片 | 底部"技术详情"折叠面板 | 管理员/研发 |
| `evidence_offset` | 证据Tab内 | 命中片段内联标注（小字灰色） | 全部 |
| `detection_source` | 首屏标签 | 保留但简化为"规则检出"/"AI辅助检出"/"联合检出" | 全部 |

**证据与结论合并为"AI研判报告"单一区块**：
- 取消左侧"证据工作区"多Tab设计
- 改为可展开的单一区块，内部按信息层级组织：
  - 攻击手法 + 置信度/优先级（首行）
  - [展开完整报告 ↓]
    - 🔍 命中片段（原始会话高亮标红）
    - 📝 判定理由（结构化列表，点击自动滚动到对应证据位置）
    - ❓ 不确定性（缺失证据/需人工补充的问题，黄色背景提示）
    - 📚 相似事件参考（3条历史事件，可点击跳转）

### 2.6 反馈回流路径补全（P1-4）

**现状**：样本库只有候选集/训练集/评估集/回收站4个Tab，缺少"争议集"和"回归集"；拒绝AI研判时无"入样本候选集"选项。

**方案**：
- 样本库Tab重构为5类：**候选集、训练集、评测集、回归集、争议集**（移除原型自行添加的"回收站"）
- **争议集**机制：人工与AI判断不一致的边界样本自动归入，优先进入下一轮评测——这是样本治理的核心差异化能力
- **拒绝操作弹窗**增加"☑ 同时加入样本候选集（默认勾选）"，与"标记误报"保持一致
- 事件详情页处置完成后，toast提示："处置已记录，相关证据已回流至样本候选集"

---

### 2.7 评分融合可视化（P1-5）

**现状**：只展示综合评分，无法验证`max(rule, ai)`的融合逻辑。

**方案**：评分区域拆分为结构化展示：
```
风险评分
├── 规则评分：72（高风险阈值：60）         [蓝色进度条]
├── AI评分：85（置信度：高）               [紫色进度条]
├── 融合策略：取最大值（AI置信度 > 阈值）    [小字灰色]
└── 综合评分：85（高风险）                  [红色进度条]
    ⚠️ AI导致等级上升：规则评分72（中风险）→ 综合评分85（高风险）
```

---

### 2.8 数据分级强约束交互（P1-6）

**现状**：选择L2级别+Cloud部署、L3级别+Webhook发送时原型未校验。

**方案**：
- **选择L2 + Cloud部署**：弹出警告弹窗"L2级别数据禁止部署至云端，请切换至本地或私有部署模式"，阻断提交
- **选择L3 + Webhook输出**：直接禁止并标红，提示"L3级别数据仅允许本地模型处理，禁止任何外部传输"
- 在模型注册页、策略配置页、外部集成页统一植入该校验逻辑

---

### 2.9 页面间上下文传递（P1-7）

**现状**：下钻后筛选条件丢失，返回路径不清晰。

**方案**：
- 跳转URL携带`from`参数和筛选上下文：`event-list.html?detection_source=ai_model&from=dashboard`
- 目标页面包屑增加返回来源："安全总览 > AI检出统计 > 风险事件列表"
- 事件详情页顶部增加"返回分析"快捷按钮（仅当`from=persona-analysis`或`from=soc-dashboard`时显示）

---

### 2.10 安全总览改造（P2-1 + P2-3）

**现状**：默认首页为"接入应用管理"；ECharts脚本被注释；AI状态分布使用原始枚举值。

**方案**：
- **默认首页改为安全总览**，首屏顶部增加"今日待处置"快速行动区
- 启用ECharts，趋势图增加：tooltip、点击下钻到事件列表、时间范围联动、异常点标注
- AI状态分布标签替换为业务语言：
  - "AI辅助正常" 72%（绿色）
  - "检测排队中" 9%（蓝色）
  - "AI服务超时，已降级" 6%（橙色）
  - "模型熔断中，纯规则运行" 3%（灰色）
  - "策略跳过AI检测" 10%（灰色）

---

### 2.11 AI结论全局统一标识（P2-4）

**现状**：关联分析页有"AI分析"标签，SOC驾驶舱只标"预测"，无统一表达。

**方案**：建立5级全局角标规范

| 场景 | 标识样式 | 说明 |
|-----|---------|------|
| AI分析结论（已人工确认） | 🟢 "AI·已确认" | 人工已复核 |
| AI分析结论（未确认） | 🟡 "AI·待确认" | 需人工复核 |
| AI预测/推测 | 🟠 "AI·预测" | 仅供参考，不作为决策依据 |
| AI辅助生成（文本/摘要） | 🔵 "AI·生成" | 内容来自模型生成 |
| AI服务异常 | ⚪ "AI·不可用" | 服务熔断/超时 |

- "AI·预测"和"AI·生成"的内容区域增加半透明水印底纹
- 所有带角标内容hover显示tooltip："本内容由AI模型生成，[可信度状态]"

---

### 2.12 L4强控制约束显性化（P2-5 + P2-6）

**现状**：L4"不可自动执行"仅在页面说明中，无阻断式交互。

**方案**：
- **配置区**：动作级别选择器改为色块分段滑块（L1蓝色→L2绿色→L3黄色→L4红色）
- **拖动到L4时**：滑块区域抖动一次（视觉警示），自动展开审批配置面板，顶部红色横幅："L4动作将阻断业务流量，请确认审批流程已就绪"
- **执行确认弹窗**（不可绕过）：
  ```
  ⚠️ 高危动作确认 — L4（不可自动执行）
  该动作将 [阻断应用访问 / 注销用户会话]
  □ 我已获得业务负责人书面审批（审批编号：________）
  □ 我已确认MFA验证码（6位数字）
  □ 我已确认回滚策略（TTL：________小时）
  [确认执行]（仅当全部勾选时可用）  [取消]
  ```
- **熔断器操作**："强制熔断"/"手动恢复"增加二次确认弹窗 + 审计日志提示

---

### 2.13 成本超限降级提示（P2-7）

**现状**：成本看板只有预算进度条，无超限后的系统状态提示。

**方案**：
