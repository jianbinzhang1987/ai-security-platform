## 4. 数据输出范围控制

### 4.1 字段过滤规则

| 字段 | L0可发送 | L1可发送 | L2可发送 | L3可发送 |
|------|----------|----------|----------|----------|
| 事件ID | ✅ | ✅ | ✅ | ✅ |
| 风险类型 | ✅ | ✅ | ✅ | ✅ |
| 风险等级 | ✅ | ✅ | ✅ | ✅ |
| 时间 | ✅ | ✅ | ✅ | ✅ |
| 应用名 | ✅ | ✅ | ✅ | ✅ |
| 检测来源 | ✅ | ✅ | ✅ | ✅ |
| 处置状态 | ✅ | ✅ | ✅ | ✅ |
| 用户标识 | ❌ | 脱敏后 | 脱敏后 | ✅ |
| AI研判摘要 | ❌ | ✅ | ✅ | ✅ |
| 命中片段 | ❌ | ❌ | 脱敏后 | ✅ |
| Prompt原文 | ❌ | ❌ | ❌ | ✅ |
| Response原文 | ❌ | ❌ | ❌ | ✅ |
| 统计指标 | ✅ | ✅ | ✅ | ✅ |

### 4.2 数据过滤流程

```
事件/日志产生
→ 查询匹配的集成通道 (按过滤条件匹配)
→ 读取通道的最高数据级别 (max_data_level)
→ 从 data_classification_rule 获取各字段的数据级别
→ 字段级别 > max_data_level → 脱敏或移除
→ 字段级别 <= max_data_level → 保留
→ 构造发送内容 (按通道格式)
→ 异步发送 (Syslog/Webhook)
→ 写入 external_delivery_log
```

## 6. Webhook协议说明

### 6.1 请求格式

```
POST {target_url}
Headers:
  Content-Type: application/json
  X-Platform-Signature: sha256={hmac_sha256(payload, secret)}
  X-Platform-Event: risk_event / audit_log / statistics
  X-Platform-Delivery: {delivery_id} (幂等键)

Body:
  (按上述JSON格式发送)
```

### 6.2 响应与重试

| 响应 | 处理 |
|------|------|
| 2xx | 发送成功 |
| 非2xx | 发送失败，进入重试队列 |

**重试策略:**
- 最多3次
- 间隔: 1s → 5s → 30s
- 超过3次标记为failed，告警通知

## 8. 安全约束

1. **数据级别硬约束**: 发送内容严格按通道`max_data_level`过滤，不可绕过
2. **L3发送白名单**: L3数据仅发送到经安全负责人审批的白名单地址
3. **签名验证**: Webhook发送必须携带HMAC-SHA256签名
4. **TLS强制**: L2/L3数据必须通过TLS传输，禁止明文
5. **审计全量记录**: 所有外部数据输出写入`external_delivery_log`
6. **失败告警**: 连续3次发送失败触发告警通知
