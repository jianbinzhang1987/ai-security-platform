### 5.3 Trace 瀑布图组件设计（核心差异化组件）

这是管理端最复杂的组件，需要单独设计：

```/dev/null/TraceWaterfall.tsx#L1-40
// 数据结构设计
interface SpanNode {
  spanId: string;
  parentSpanId: string | null;
  operationName: string;          // 'llm.chat' | 'mcp.tool_call' | 'http.request'
  startTime: number;              // Unix timestamp ms
  duration: number;               // ms
  attributes: {
    'llm.model'?: string;
    'llm.prompt'?: string;        // 脱敏后
    'llm.response'?: string;      // 脱敏后
    'mcp.tool_name'?: string;
    'mcp.input_params'?: object;
    'security.risk_level'?: 'critical' | 'high' | 'medium' | 'low';
    'security.risk_type'?: string;
    'security.risk_detail'?: string;
  };
  children: SpanNode[];           // 树形结构（前端重建）
}

// 渲染策略：
// 1. 根据 parentSpanId 将扁平 Span 列表构建为树
// 2. 用 ECharts 自定义序列图或纯 CSS + 绝对定位渲染时间轴
// 3. 高风险 Span 节点红色高亮，点击展开右侧详情面板
// 4. 支持全屏模式和时间轴缩放
```

## 七、关键设计决策总结

| 决策点 | 选择 | 核心理由 |
|---|---|---|
| Python SDK 脱敏方案 | `Presidio`（客户端本地执行）| PII 绝不出用户环境，隐私保障最优 |
| Java SDK LLM 捕获 | 自研 HttpBody Extension | OTel JavaAgent 原生不解析 HTTP body，必须自研 |
| 管理端组件库 | `Ant Design` | 企业级复杂组件（Table/Form/Tree）开箱即用，减少重复开发 |
| 图表库 | `ECharts`（非 Recharts/Victory）| 热力图、关系图、大数据集渲染性能优于 SVG 方案 |
| 实时方案 | `WebSocket`（非 SSE/轮询）| 双向通信，后端可主动推送高优先级告警 |
| 状态管理 | `Zustand`（非 Redux）| 实时告警场景下 reducer 样板代码过重，Zustand 更灵活 |
| Trace 可视化 | `Langfuse 集成 + 自研瀑布图` | Langfuse 负责标准 OTel 存储展示，自研部分负责安全标注和深度定制 |
| 规则编辑器 | `Monaco Editor` | 支持 Sigma 规则语法高亮和智能提示，与 VS Code 一致的体验 |
