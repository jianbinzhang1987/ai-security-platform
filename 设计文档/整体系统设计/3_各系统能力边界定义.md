# 各系统能力边界定义

## 1. SUP 平台 (Static & Authorization Unified Platform)

### 1.1 职责范围

**核心职责：**
- 管理所有静态资源（大模型、Agent、Skills、知识库、MCP）的授权信息
- 管理用户/应用的身份信息和权限
- 提供授权查询服务

**不负责：**
- 不实现具体的安全检测逻辑（由网关和安全平台负责）
- 不处理请求的具体转发（由网关负责）
- 不监测客户端行为（由安全平台负责）
- 不处理静态资源的托管和运行（资源由各自系统托管）

### 1.2 输入接口

| 接口 | 来源 | 描述 |
|------|------|------|
| 授权查询 | AI智能网关(Higress扩展) | 查询某身份是否有权限使用某资源 |
| 身份认证 | AI智能网关 | 验证用户/应用身份 |
| 资源列表查询 | 智能体应用 | 查询可用的资源列表 |
| 授权规则配置 | SUP管理UI | 配置新的授权规则 |
| 身份信息查询 | 内部服务 | 查询身份详细信息 |

### 1.3 输出接口

| 接口 | 目标 | 描述 |
|------|------|------|
| 授权决策 | AI智能网关(Higress) | 返回允许/拒绝 |
| 身份信息 | AI智能网关 | 返回身份验证结果 |
| 资源列表 | 智能体应用 | 返回授权的资源列表 |
| 权限规则 | Higress扩展缓存 | 推送授权规则更新 |
| 审计日志 | AI安全平台 | 推送授权相关审计日志 |

### 1.4 与其他系统的边界

#### 1.4.1 SUP ↔ AI智能网关

```
网关接收请求
    ↓
调用SUP身份认证接口 (HTTP API)
    ↓
SUP返回身份信息
    ↓
网关调用SUP授权检查接口 (via Higress扩展)
    ↓
SUP返回权限结果
    ↓
网关允许/拒绝请求

集成方式：
- 认证：同步HTTP API调用
- 授权检查：Higress扩展插件（高性能）
- 缓存策略：Higress缓存授权规则（TTL 5-10分钟）
```

#### 1.4.2 SUP ↔ 智能体应用

```
应用需要获取资源列表
    ↓
调用SUP资源查询接口 (HTTP API)
    ↓
SUP返回该身份有权限的资源列表
    ↓
应用展示资源列表供用户选择

集成方式：
- 异步HTTP API调用
- 结果在客户端缓存
```

### 1.5 关键设计原则

- **职责单一**：只负责授权和身份，不涉及具体业务逻辑
- **高性能**：通过Higress缓存实现快速授权检查
- **安全第一**：所有授权决策通过明确的服务接口
- **灵活配置**：支持RBAC和ABAC两种模式

## 2. AI 智能网关 (AI Gateway with Security)

### 2.1 职责范围

**核心职责：**
- 接收和转发用户请求
- 执行身份认证和权限检查（通过SUP）
- 检测和阻止安全威胁（输入/输出侧）
- 记录安全事件并上报到安全平台
- 实施访问控制和速率限制

**不负责：**
- 不管理授权规则（由SUP负责）
- 不分析安全事件（由安全平台负责）
- 不决策安全策略（由安全平台决策并下发）
- 不运行用户代码（代码由各应用系统运行）
- 不存储用户数据（由后端系统存储）

### 2.2 输入接口

| 接口 | 来源 | 描述 |
|------|------|------|
| 用户请求 | 客户端/应用 | 调用大模型/Agent/Skills等的请求 |
| 授权规则 | SUP | 通过Higress获取授权规则 |
| 安全策略 | AI安全平台 | 接收安全检测策略的更新 |
| 黑白名单 | SUP/安全平台 | 接收IP/身份黑白名单 |
| 系统配置 | 管理员 | 网关配置参数 |

### 2.3 输出接口

| 接口 | 目标 | 描述 |
|------|------|------|
| 转发请求 | 后端服务 | 转发验证通过的请求 |
| 响应 | 客户端/应用 | 返回处理结果或错误信息 |
| 安全事件 | AI安全平台 | 推送检测到的安全事件 |
| 访问日志 | 日志系统 | 记录所有请求和响应 |

### 2.4 分层设计

#### 2.4.1 第一层：Higress 扩展层 (高性能实时检查)

**职责：**
- 实时身份认证
- 权限检查（通过缓存的授权规则）
- 速率限制
- 基础黑白名单检查

**特点：**
- 在请求处理前执行
- 非常快速（内存中缓存规则）
- 缓存授权规则（定期同步）

**与SUP的关系：**
```
Higress扩展缓存授权规则
    ↓
定期（如5分钟）从SUP同步最新规则
    ↓
请求时直接查询缓存，做出快速决策
    ↓
缓存失效时回源到SUP
```

#### 2.4.2 第二层：网关后端层 (业务逻辑处理)

**职责：**
- 请求验证和预处理
- 输入安全检测
- 请求转发
- 输出安全检测
- 响应处理

**工作流：**
```
请求经过Higress层 (权限检查)
    ↓
网关后端接收请求
    ↓
[输入安全检测]
  ├─ 提示词注入检测
  ├─ SQL注入检测
  ├─ 内容合规检查
  └─ 格式校验
    ↓
安全？是 → 转发到后端服务
      ↓ 否 → 拒绝请求，记录事件
    ↓
接收后端响应
    ↓
[输出安全检测]
  ├─ 有害内容检测
  ├─ 信息泄露检测
  ├─ 法规合规检查
  └─ 格式校验
    ↓
安全？是 → 返回给用户
      ↓ 否 → 脱敏/拒绝，记录事件
```

#### 2.4.3 第三层：网络层 (网络部负责)

**职责：**
- 网络级别的安全策略
- 协议级检查
- VPN/加密隧道

### 2.5 与其他系统的边界

#### 2.5.1 网关 ↔ SUP

```
实时交互：
请求到达 → Higress扩展检查权限
         → 查询本地缓存的授权规则
         → 规则过期？从SUP同步

同步周期：
SUP授权规则变更 → 推送更新到Higress
                或
Higress定期轮询SUP获取最新规则
```

#### 2.5.2 网关 ↔ AI安全平台

```
实时事件推送：
网关检测到安全事件
    ↓
记录到日志
    ↓
通过异步消息队列推送到安全平台
    ↓
安全平台分析和聚合
    ↓
决定是否触发告警/自动响应

策略下发：
安全平台决定需要新的安全策略
    ↓
推送策略到网关（通过配置管理或消息队列）
    ↓
网关加载新策略
    ↓
后续请求按新策略执行

缓冲隔离：
网关与安全平台之间通过消息队列解耦
确保网关性能不受安全平台影响
```

#### 2.5.3 网关 ↔ 后端服务

```
网关作为反向代理
    ↓
维护到后端服务的连接池
    ↓
转发请求到后端
    ↓
接收响应
    ↓
返回给客户端

关键设计点：
- 请求/响应不修改内容（除安全检测外）
- 支持流式响应
- 连接复用和优化
```

### 2.6 关键设计原则

- **责任分离**：业务授权(SUP) vs 安全检测(网关) vs 安全分析(安全平台)
- **高性能**：Higress缓存 + 异步处理
- **隔离隔断**：网关异常不影响后端，安全平台异常不影响网关
- **可观测**：完整的日志、追踪和指标

## 3. AI 安全管理中心 (AI Security Management Platform)

### 3.1 职责范围

**核心职责：**
- 收集各端的安全事件（网关、Agent、客户端）
- 分析和聚合安全事件
- 评估威胁等级
- 定义和管理安全策略
- 执行自动化或人工安全响应
- 向各端推送安全策略

**不负责：**
- 不实现实时安全检测（由网关负责实时检测）
- 不执行权限检查（由SUP和网关负责）
- 不管理用户身份（由SUP负责）
- 不存储业务数据（仅存储安全相关数据）

### 3.2 输入接口

| 接口 | 来源 | 描述 |
|------|------|------|
| 网关安全事件 | AI智能网关 | 检测到的各类安全事件 |
| Agent异常事件 | Agent中心/SDK | Agent运行时异常 |
| 客户端行为事件 | 客户端SDK | 客户端端侧行为和威胁 |
| 网关授权规则 | SUP | 查询当前授权规则 |
| 第三方威胁情报 | 外部服务 | 威胁情报信息 |
| 策略配置 | 管理员 | 安全策略配置 |

### 3.3 输出接口

| 接口 | 目标 | 描述 |
|------|------|------|
| 安全策略 | AI智能网关 | 下发安全检测策略 |
| 安全策略 | Agent中心 | 下发应用层安全策略 |
| 安全策略 | 客户端SDK | 下发客户端安全策略 |
| 告警通知 | 管理员/值班人员 | 发送安全告警 |
| 自动响应 | 各系统 | 执行自动化安全响应 |
| 安全报表 | 管理员 | 定期安全报表 |
| 审计日志 | 日志系统 | 记录安全操作 |

### 3.4 与网关的集成边界

```
明确分工：

AI智能网关负责：
├─ 实时安全检测 (在请求处理中)
├─ 快速阻止 (非法请求直接拒绝)
├─ 原始事件记录
└─ 事件推送

AI安全平台负责：
├─ 事件聚合和关联
├─ 深度威胁分析
├─ 趋势识别
├─ 策略决策
└─ 长期审计记录
```

**集成模式：**

```
[离线分析模式]
网关事件推送 → 消息队列 → 安全平台
                          ↓
                    事件聚合和分析
                          ↓
                    识别异常模式
                          ↓
                    生成报警
                          ↓
                    决策响应方案
                          ↓
                    推送新策略 → 网关加载

[关键特点]
- 网关和安全平台完全异步
- 网关故障不影响应用
- 安全平台可以补偿检测
- 策略下发有版本控制
```

### 3.5 端侧安全监测的独立性

```
端侧监测不依赖网关：
客户端SDK直接收集本地数据
    ↓
与网关事件独立上报
    ↓
安全平台在收集端侧和网关事件后关联分析

优点：
- 检测本地威胁
- 用户行为分析
- 客户端性能监控
```

### 3.6 关键设计原则

- **事件驱动**：基于事件的实时响应
- **关联分析**：多源事件关联分析提高准确性
- **自适应**：根据检测结果动态调整策略
- **低延迟**：事件到告警的时间要短
- **可追溯**：完整的审计链路

## 4. 智能体生态系统

### 4.1 职责范围

**Agent中心职责：**
- 管理Agent的生命周期和运行时
- 为普通用户提供Agent应用访问
- 性能监控和统计
- 调用Agent权限检查（通过网关）

**开发平台职责：**
- 为开发者提供Agent编排工具
- 集成各类能力（大模型、Skills、KB等）
- 支持Agent的开发、测试和发布
- 为产品部提供二次开发能力

**都不负责：**
- 不管理授权规则（由SUP负责）
- 不执行安全检测（由网关负责）
- 不进行威胁分析（由安全平台负责）
- 不存储大模型凭证（由SUP或专门凭证系统管理）

### 4.2 输入接口

| 接口 | 来源 | 描述 |
|------|------|------|
| 用户请求 | 用户 | 执行Agent应用 |
| 权限检查 | AI智能网关 | 通过网关检查权限后才能执行 |
| 安全策略 | AI安全平台 | 执行安全策略 |
| 后端能力 | 大模型/Skills/KB等 | 调用各种能力 |
| 开发命令 | 开发者 | 在开发平台上配置Agent |

### 4.3 输出接口

| 接口 | 目标 | 描述 |
|------|------|------|
| 执行结果 | 用户 | 返回Agent执行结果 |
| 网关请求 | AI智能网关 | 通过网关调用后端能力 |
| 安全事件 | AI安全平台 | 上报异常和安全相关事件 |
| 发布信息 | Agent中心 | 发布新的Agent版本 |
| API/SDK | 第三方开发者 | 提供接入能力 |

### 4.4 与其他系统的集成边界

#### 4.4.1 应用层权限检查

```
用户请求 → Agent中心/开发平台
         ↓
应用确认身份 (来自网关认证)
         ↓
应用端检查用户是否有权限使用此Agent
         ↓
有权限 → 执行Agent
      → 需要调用后端服务
      → 通过网关调用
         ↓
网关进行第二次权限检查(Higress层)
确保即使应用被破坏，也能保护后端
```

**分层防护：**
```
第一道防线：应用层权限检查 (应用自己检查)
第二道防线：网关权限检查 (Higress扩展)
第三道防线：网关安全检测 (后端处理)
第四道防线：安全平台分析 (异常检测)
```

#### 4.4.2 开发平台与Dify的关系

```
智能体开发平台 (AI部门实现)
    ↓
基于Dify核心引擎
    ↓
扩展功能：
├─ 与SUP集成 (配置能力权限)
├─ 与网关集成 (转发请求)
├─ 与安全平台集成 (执行安全策略)
├─ 发布管理 (灰度、金丝雀)
└─ 第三方API支持 (给外部开发者)

设计原则：
- Dify提供工作流编排的核心
- 我们扩展认证、授权、安全相关功能
- 不修改Dify核心逻辑，通过插件和包装
```

### 4.5 关键设计原则

- **多层防护**：应用层 + 网关层 + 安全平台层
- **最小权限**：默认拒绝，明确授权
- **事件上报**：所有异常都上报安全平台
- **独立性**：应用异常不影响网关，网关异常不影响后端
- **可扩展**：支持第三方开发和产品部的定制化

## 5. 跨系统边界总结表

| 边界 | 交互类型 | 通信机制 | 特点 |
|-----|--------|--------|-----|
| SUP ↔ 网关(Higress) | 授权查询 | HTTP API + 缓存 | 高性能、低延迟 |
| 网关 ↔ 安全平台 | 事件推送 | 异步消息队列 | 异步、解耦、可靠 |
| 安全平台 → 网关 | 策略下发 | 配置管理/推送 | 版本控制、灰度 |
| 应用 ↔ 网关 | 功能调用 | HTTP/gRPC | 同步、即时 |
| 应用 → 安全平台 | 事件上报 | 异步API | 异步、非阻塞 |
| SUP ↔ 应用 | 资源查询 | HTTP API | 同步、实时 |
| 网关 ↔ 后端 | 请求转发 | HTTP/gRPC | 同步、直通 |
