## ❌ 缺失功能（对照需求文档 P0 级）

### 1. **PII 检测与脱敏策略** — 完全缺失

需求文档 GW-FR-24~27（全部 P0）要求网关支持输入侧 PII 快速识别、脱敏放行、拦截/告警、输出侧替换。技术设计文档有独立 `<span>pii-detector</span>` 插件，支持手机号/身份证/邮箱/银行卡/IP/自定义正则，输出 `<span>x-pii-detected</span>` / `<span>x-pii-types</span>` / `<span>x-pii-action</span>` 上下文字段。

 **现状** ：

content-security.html 的输入/输出 Tab 仅在检测维度标签中提到"PII 外发"和"PII 泄露"，但 **没有独立的 PII 检测与脱敏策略配置页面** ，无法配置：

* PII 类型开关（手机号/身份证/邮箱/银行卡/IP/自定义正则）
* 各 PII 类型的处置动作（脱敏放行 / 拦截 / 告警放行）
* 输出侧 PII 替换文案
* 自定义正则规则

### 2. **MCP 路由与运行时拦截策略** — 完全缺失

需求文档 GW-FR-28~31（P0/P1）要求网关支持 MCP 工具调用统一路由分发、MCP 调用前统一权限决策、参数摘要采集、结果风险打标。技术设计有独立 `<span>mcp-router</span>` 插件和 `<span>ext-auth</span>` 集成。

 **现状** ：5 个页面中 **没有任何 MCP 路由策略管理入口** ，无法配置：

* MCP 工具路由规则
* MCP 调用前权限决策接入
* MCP 参数摘要采集开关
* MCP 返回结果风险打标规则

### 3. **WAF 防护策略** — 完全缺失

需求文档 GW-FR-14~15（P0）要求网关具备 WAF 防护能力（SQL 注入、XSS、协议攻击）和 HTTPS/TLS 传输加密。技术设计有 `<span>waf</span>` 插件。

 **现状** ：

access-control.html 覆盖了认证和授权，但 **没有 WAF 规则配置入口** ，无法管理：

* WAF 规则启停
* WAF 规则类型（SQL 注入 / XSS / 协议攻击 / 自定义规则）
* WAF 命中动作配置
* TLS/HTTPS 传输安全配置

### 4. **路由规划与管理** — 完全缺失

需求文档 GW-FR-03~04（P0）要求网关按路由区分 LLM/MCP/开放 API/管理接口流量，并统一透传上下文。技术设计定义了 4 条路由（`<span>/api/chat/**</span>`, `<span>/api/mcp/**</span>`, `<span>/api/open/**</span>`, `<span>/api/admin/**</span>`）及其插件链。

 **现状** ： **没有路由管理页面** ，无法配置：

* 路由定义与路径匹配规则
* 各路由挂载的插件链编排
* 路由级上下文透传字段
* 路由级策略覆盖（全局默认 vs 路由级策略）

> 对比：`<span>@e:\code\大模型网关\原型图\pages\gateway\ai-route.html</span>` 已有路由管理原型，且网关原型每个策略页面都有"默认策略 / 路由级策略"分层 Tab。

## ⚠️ 不完善之处

### 5. **内容安全策略页面职责过重，缺少分层设计**

content-security.html 将 4 个安全域（提示词攻击 / 输入安全 / 输出安全 / 会话安全）压缩在一个页面的 4 个 Tab 中，每个 Tab 仅展示策略列表表格。

 **对比网关原型** （`<span>@e:\code\大模型网关\原型图\pages\policy\</span>`）的做法：

* 提示词攻击、输入安全、输出安全各自独立页面
* 每个页面有 **"默认策略 / 路由级策略"** 分层 Tab
* 默认策略 Tab 以**表单配置**为主（审核服务、风险阈值、规则包、兜底动作），而非列表
* 路由级策略 Tab 管理路由覆盖策略

 **当前问题** ：

* 缺少"全局默认策略"表单配置区（当前只有策略列表，无法直观配置兜底策略）
* 缺少"路由级策略"分层（所有策略平铺在列表中，无法区分全局兜底和路由覆盖）
* 输出安全 Tab  **缺少流式处理模式配置** （GW-FR-22，网关原型 `<span>output-security.html:60</span>` 有"流结束后检测 / 分段检测"选项）
* 缺少 **检测模式配置** （同步/异步，GW-FR-18）
* 缺少 **降级动作配置** （安全引擎超时时的 PASS/BLOCK 降级，GW-FR-19，技术设计 `<span>fallback_action</span>` 字段）

### 6. **会话安全与审计策略职责边界模糊**

content-security.html 的"会话安全" Tab 和

session-audit.html 存在职责重叠：

* 前者管理"敏感词双向会话防护"和"高危连续会话拦截"
* 后者管理"会话镜像转发"和"审计留存"

两者都涉及"会话"概念，用户难以区分在哪个页面配置会话级安全规则 vs 会话级审计规则。建议：

* 将

  content-security.html 的"会话安全" Tab 移入

  session-audit.html，或
* 明确命名区分："会话安全防护" vs "会话审计采集"

### 7. **策略版本管理缺失**

gateway-distribution.html 展示了版本号（v1.3, v0.9 等），但：

* "查看版本"按钮仅弹出 toast，无实际版本详情页
* 无版本历史列表
* 无版本对比（diff）能力
* 无版本回滚操作
* 无版本变更日志

> 对比：网关原型 `<span>distribution-status.html:30</span>` 有"查看发布原则"和"查看发布记录"按钮。

### 8. **绑定与下发页面功能单薄**

当前

gateway-distribution.html 仅支持单条绑定 CRUD，缺少：

* 批量下发 / 批量停用
* 发布原则说明（网关原型有此功能）
* 发布记录时间线（网关原型有此功能）
* 下发异常的节点级详情（当前"失败节点"仅 toast）
* 下发回执的详细状态追踪

### 9. **流量与服务治理缺少 Token 级配额维度**

需求 GW-FR-09~11 要求用户级、API Key 级、部门/应用级 Token 配额控制。当前

traffic-governance.html 的限流策略表格和表单仅以"QPS / 并发 / 日配额"粗粒度展示，缺少：

* Token 配额维度选择（用户 / API Key / 部门 / 应用）
* Token 配额单位配置（input tokens / output tokens / total tokens）
* 配额周期配置（日 / 周 / 月）

### 10. **访问控制策略缺少 TLS/传输安全配置**

GW-FR-14（P0）要求 HTTPS/TLS 传输加密，但

access-control.html 仅覆盖身份认证、资源授权和黑白名单， **缺少传输安全配置 Tab 或字段** 。
