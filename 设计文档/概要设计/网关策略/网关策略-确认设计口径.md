# 网关策略确认设计口径

> 适用范围：`访问控制策略`、`流量与服务治理`、`内容安全策略`、`会话审计`、`绑定与下发`
>
> 目的：沉淀当前讨论后已确认的页面定位、字段口径和边界约束，作为后续原型修改依据。

## 一、会话审计

### 1. 页面定位

- `会话审计` 是简单查询页。
- 主要用于按访问用户、时间、应用、路由、会话 ID 查询会话。
- 主要查看经过网关的 Prompt 信息、命中策略、网关动作、关联风险事件。
- 不承担风险事件的闭环处置。

### 2. 页面职责

负责：

- 查会话
- 看 Prompt 信息
- 看命中策略
- 看网关动作
- 看关联风险事件
- 看会话详情

不负责：

- 风险评分
- 研判结论编辑
- 用户画像运营分析
- 指派 / 确认 / 误报 / 接受风险 / 关闭
- 风险事件正式闭环

### 3. 查询条件

建议保留：

- 时间范围
- 访问用户
- 应用 / 路由
- 会话 ID
- 是否命中策略
- 网关动作
- 是否关联风险事件

不建议保留：

- 风险等级
- 研判状态
- 处置结果

### 4. 列表字段

建议保留：

- 会话 ID
- 访问用户
- 应用 / 路由
- Prompt 信息
- 命中策略
- 网关动作
- 开始时间
- 结束时间
- 关联风险事件
- 操作

补充约束：

- `Prompt 信息` 默认显示 1 至 2 行
- 命中敏感内容时展示经过网关后的 Prompt 摘要
- `关联风险事件` 显示事件编号链接，没有则显示 `--`

### 5. 网关动作枚举

统一使用中文：

- 放行
- 拦截
- 脱敏
- 改写
- 仅记录

不建议在会话审计列表直接展示英文动作码。

### 6. 会话详情

建议包含：

- 基础信息
- 经过网关的 Prompt 信息
- 网关处置结果
- 命中策略
- 网关动作
- 会话时间线
- 关联风险事件编号

可以提供“查看关联风险事件”入口，但不在本页做事件闭环动作。

### 7. 与风险事件中心的边界

- `会话审计`：看用户、看会话、看上下文、看线索
- `风险事件中心`：做正式事件主档与闭环处置

因此：

- 会话审计页允许跳转查看风险事件
- 会话审计页不提供事件指派、误报、关闭等动作

## 二、风险事件中心

### 1. 页面定位

- `风险事件中心` 是正式事件闭环主档页面。

### 2. 页面职责

负责：

- 指派
- 确认
- 误报
- 接受风险
- 关闭
- 审计留痕

不负责：

- 展示完整会话输入输出上下文
- 替代会话查询页

### 3. 与会话审计的关系

- 事件中心可跳转会话审计查看对应上下文
- 跳转时允许携带 `userId`、`sessionId`、`eventType`、`tab`
- 会话审计加载后应自动定位对应上下文

## 三、版本管理

### 1. 是否单独开页

- 不单独开版本管理页面
- 在当前策略页和绑定与下发页内闭环实现

### 2. 版本状态

统一只有 3 个：

- 草稿
- 已发布
- 已停用

### 3. 引用规则

- 只有 `已发布` 版本允许被绑定与下发引用
- `草稿` 版本不可引用
- `已停用` 版本不可直接引用
- 回滚应基于历史版本重新生成一个新的已发布版本

### 4. 策略页最小版本能力

每个策略页至少支持：

- 查看当前版本
- 查看版本状态
- 保存为草稿
- 发布新版本
- 查看版本历史
- 查看版本差异
- 回滚版本

### 5. 绑定与下发最小版本能力

绑定与下发页至少支持：

- 选择引用的已发布版本
- 查看当前绑定引用版本
- 查看该版本下发状态
- 重新下发指定版本

## 四、内容安全中的会话安全

### 1. 当前归属

- `会话安全` 暂时保留在 `内容安全策略` 页面内

### 2. 概念边界

- `输入安全`：单次请求内容检测
- `输出安全`：单次响应内容检测
- `会话安全`：多轮对话上下文中的连续风险检测

因此：

- 会话安全不是输入安全与输出安全的简单合集
- 它强调跨轮次、上下文和连续行为

## 五、访问控制

### 1. 字段表达

- `Issuer` 应改为中文表达，如 `签发方（Issuer）`
- `Audience` 应改为中文表达，如 `受众（Audience）`

### 2. 字段联动

不同认证方式下字段应联动变化：

- `API Key`：不展示签发方、受众、JWKS 等字段
- `JWT`：展示签发方、受众、JWKS、有效期校验
- `OIDC`：展示签发方、受众、授权端点、Token 端点、JWKS 等字段

## 六、流量与服务治理

### 1. 治理对象表达

- 需要区分 `治理对象分类` 与 `具体治理对象`
- 例如：
  - 治理对象分类：应用 / 路由 / 模型服务 / 网关节点
  - 具体治理对象：`finance-app`、`finance-model-route`、`llm-core-service`

### 2. 恢复条件表达

- `服务熔断` 的恢复条件不应只用自然语言承担配置职责
- 核心条件应结构化表达，例如：
  - 连续成功次数
  - 健康检查通过阈值
  - 半开探测窗口
  - 恢复观察期

自然语言仅作为补充说明。

## 七、通用约束

- 查询页优先展示客观事实，不混入运营结论
- 策略页优先展示配置与版本，不承载过多运行态分析入口
- 日志、命中记录、原文上下文等入口，应按页面职责放置，避免同一能力在多个页面重复承担
