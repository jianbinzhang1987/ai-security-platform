# 网关策略管理原型修改执行清单

> 来源：合并 `网关策略-sonnet.md` 的审核意见与本轮原型走查补充意见。  
> 范围：当前导航下的 5 个页面：访问控制策略、流量与服务治理、内容安全策略、会话审计、绑定与下发。  
> 说明：其中“会话审计”已重新定义为审计分析功能，不再按“策略管理页”设计。

## 一、执行原则

1. 先补齐可走查闭环，再做视觉和体验打磨。
2. 优先改当前导航中已暴露的 5 个页面，不先扩展大而全的新模块。
3. 对 `prompt-attack.html`、`input-security.html`、`output-security.html`、`gateway-policies.html` 等未入导航页面，先做信息架构取舍，不并行维护两套重复页面。
4. 弹窗、抽屉、确认框可以先用静态原型实现，但必须让用户能看到关键字段、状态变化入口和操作后果。

## 五、建议实施顺序

1. 先改信息架构与通用组件：确认孤儿页面处理方式，增加确认弹窗、详情抽屉、分页、批量操作样式。
2. 修改四类策略配置弹窗：访问控制、流量治理、内容安全、会话审计。
3. 修改绑定与下发：策略/版本/对象联动，下发历史、回执、失败节点、回滚。
4. 补诊断入口：日志、命中记录、会话链路、模拟预演、敏感词库。
5. 做体验补强：统计下钻、排序、空状态、状态开关、样式统一。

## 七、暂不直接采纳但保留评估的扩展项

以下来自其他分析意见或外部网关能力，方向有价值，但需要先确认是否属于当前“安全监测平台”的网关策略管理边界：

| 候选项 | 暂缓原因 | 后续判断标准 |
| --- | --- | --- |
| 独立 WAF 策略页面 | 当前原型主要围绕 AI 安全策略，WAF/TLS 可能属于基础网关或运维配置 | 若需求明确网关策略中心承担入口 WAF，则加入访问控制或单独页面 |
| TLS/证书配置 | 更像系统/网关运维配置，不一定属于策略管理 | 若用户按租户/路由配置 TLS，则纳入 |
| MCP 路由策略页面 | 平台已有 Tool/MCP 资产和审计能力，是否放入网关策略需定边界 | 若网关实际承担 MCP 请求路由和前置拦截，则新增 |
| 路由规划与插件链编排页面 | 可能属于“大模型网关控制台”，不是安全监测平台本模块 | 若本项目要统一管理网关路由，则新增路由管理入口 |
