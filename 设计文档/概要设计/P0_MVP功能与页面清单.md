# AI Agent 安全监控平台 - P0 MVP 功能与页面清单

**文档版本**：v1.0
**日期**：2026-04-16
**状态**：评审中
**关联文档**：管理端 PRD v1.1 / 管理端技术概要设计 v1.1 / 安全可观测性设计概念规范 v1.1 / claude 分析视角 v1.1

---

## 1. 文档目的

本文档用于把当前 PRD、概要设计和原型调整意见收敛为 P0 MVP 可交付范围，明确：

- P0 必须闭环的产品主线
- P0 页面清单、页面目标、核心字段和核心操作
- P0 数据对象和字段边界
- 当前原型需要优先调整的页面
- P0 不承诺的能力，避免设计和研发范围继续发散

本平台主要面向企业内网与私有化客户。产品页面、报告和审计记录统一使用"风险、合规、异常、越界、证据、处置、能力边界、风险链路、风险溯源"等表达，不使用"攻击、武器、杀伤链"等强对抗字眼。

## 2. P0 MVP 核心判断

### 2.1 产品定位

P0 阶段不把平台做成通用 LLM APM，也不追求完整性能可观测性，而是先做成"智能体运行安全证据平台"。

P0 必须回答三个问题：

1. 当前哪些应用、智能体、工具和资源已经被纳入监控？
2. 智能体运行过程中是否出现了风险、异常或合规越界？
3. 为什么判定为风险，证据在哪里，应该如何处置？

### 2.2 P0 主链路

P0 只围绕一条安全运营闭环建设：

```text
探针采集
  -> Span / Trace 归一化
  -> 安全检测
  -> 风险事件
  -> 证据面板
  -> 风险溯源
  -> 人工确认
  -> 处置 / 忽略 / 报告留痕
```

### 2.3 P0 设计原则

| 原则 | P0 要求 |
|---|---|
| Trace 优先 | `trace_id` 是默认调查入口；`session_id` 只作为多轮聚合增强，不作为 P0 强依赖 |
| Span 锚定证据 | `span_id` 是最小证据锚点，所有风险事件必须能回到原始 Span |
| 应用承载治理 | `app_id` 是接入、租户、凭证、策略和责任归属主键 |
| 智能体承载分析 | Agent / Workflow Node 是安全分析主体，P0 可以先在应用详情中展示 |
| 工具承载能力边界 | Tool / MCP / Skill 是重点风险面，P0 必须能发现已观测工具和影子工具 |
| 证据优先于评分 | P0 先做证据、事件、溯源和处置；安全评分、雷达图放到 P1 |
| 低误操作处置 | 高影响范围处置必须有二次确认、TTL、审批记录和回滚入口 |

## 3. P0 范围

### 3.1 P0 必须交付

| 编号 | 能力 | 说明 | 主要页面 |
|---|---|---|---|
| P0-01 | 应用接入与 Token 管理 | 创建接入应用、生成 App Token、查看接入状态 | 应用列表、应用详情、Token 管理 |
| P0-02 | Span / Trace 数据接入 | 接收 OTLP 数据，归一化 LLM、Tool、MCP、Skill 相关 Span | 接入配置、采集健康 |
| P0-03 | 资产自动发现 | 基于上报数据发现应用、智能体、工具、MCP、Skill、资源 | 资产中心、应用详情、工具与权限 |
| P0-04 | 工具能力边界审计 | 展示已观测工具、声明状态、调用来源、风险事件 | 工具与权限 |
| P0-05 | 基础安全检测 | Prompt 风险、敏感数据、工具越界、异常调用序列的基础检测 | 规则策略、风险事件 |
| P0-06 | 风险事件生成 | 统一生成 `risk_event`，包含风险类型、等级、置信度、证据 | 风险事件 |
| P0-07 | 证据面板 | 展示 Prompt、Response、Tool I/O、命中规则、证据位置、脱敏状态 | 风险事件详情、风险溯源 |
| P0-08 | 风险溯源工作台 | 以 Trace 为入口，还原一次 Agent run 的风险路径和上下文 | 风险溯源 |
| P0-09 | 基础安全大盘 | 展示待处置风险、风险趋势、高风险应用/工具、采集健康、覆盖缺口 | 安全总览 |
| P0-10 | 事件处置闭环 | 新建、确认、忽略、误报标记、处置、关闭、审计留痕 | 风险事件 |
| P0-11 | 阻断与熔断基础能力 | 支持 Session / Tool / Agent / App 范围处置，App 级需保护机制 | 风险事件、应用详情 |
| P0-12 | 规则配置与干跑 | 支持规则启停、版本、样本预览和干跑结果 | 规则策略 |
| P0-13 | 权限与审计 | RBAC、操作审计、租户隔离 | 系统管理 |

### 3.2 P0 明确不做

| 能力 | 放入阶段 | 原因 |
|---|---|---|
| 完整安全态势评分模型 | P1 | P0 先积累稳定指标和处置反馈 |
| 风险向量雷达图 | P1 | 需要稳定风险分类和权重 |
| 独立智能体中心 | P1 | P0 可先在应用详情中展示 Agent / Workflow Node |
| 完整 Agent -> Tool -> Resource 权限图谱 | P1 | P0 先做已观测工具发现和声明差异 |
| 参数级权限越界分析 | P2 | 依赖工具 Schema 和业务资源建模 |
| 复杂风险路径推演 | P2 | P0 先做 Trace 级风险剧本和证据链 |
| 自动化处置编排 | P2 | P0 以人工确认和审计留痕为主 |
| 全部业务方法自动追踪 | 不承诺 | 受 SDK、框架和探针能力限制 |
| 全部三方 Agent 框架同等成熟支持 | 不承诺 | MVP 优先围绕已验证的 LangChain 遥测能力 |

## 4. P0 导航与页面清单

### 4.1 推荐导航

```text
安全总览
风险溯源
风险事件
资产中心
  - 应用
  - 工具与权限
  - 监控覆盖度
规则策略
处置与审计
报告中心
系统管理
```

P0 阶段不建议把服务器、Pod、主机作为一级安全运营导航。运行环境信息可放在应用详情或采集健康中，作为影响范围和运维辅助信息展示。

### 4.2 页面清单

| 页面 | 路由建议 | P0/P1 | 页面目标 | 核心操作 | 主要数据来源 |
|---|---|---|---|---|---|

## 5. P0 页面设计要点

### 5.1 安全总览

P0 首屏应优先展示：

| 区域 | P0 内容 |
|---|---|
| 核心卡片 | 未处置高风险事件、今日新增风险、已处置风险、采集异常应用、规则覆盖缺口 |
| 风险趋势 | 近 7 / 30 天风险事件趋势，按风险等级堆叠 |
| 高风险排行 | 高风险应用 TOP5、高风险工具 TOP5、高风险智能体 TOP5 |
| 监控覆盖 | 已接入应用数、活跃 Agent 数、Trace 完整率、黑盒工具调用数 |
| 快速入口 | 查看风险事件、查看风险溯源、查看工具与权限、查看采集健康 |

P0 不展示或弱化 Token 成本、平均延迟、P95/P99 等性能指标。此类指标可作为采集健康或运维辅助信息，不应占据安全总览首屏。

### 5.2 风险溯源工作台

P0 风险溯源工作台面向 1920x1080 企业安全运营场景，采用“顶部横向筛选 + 证据优先三栏”的调查工作台结构。页面目标不是复刻 APM Trace 瀑布图，而是帮助用户快速完成风险链路理解、证据判断和处置闭环。

| 区域 | 内容 | 设计要求 |
|---|---|---|
| 顶部横向筛选 | 默认显示时间范围、接入应用、风险等级、Trace ID / Span ID；更多筛选中放置风险类型、事件状态、Agent / 节点、工具 / MCP | 使用全站统一筛选栏样式，高频条件首屏可见，低频条件默认折叠，避免 1920 宽度下仍显得拥挤 |
| 左侧 Trace 列表 | Trace ID、应用、风险等级、Span 数、风险摘要、时间 | 独立列表列，支持连续分诊和快速切换 |
| 中间风险链路 | 按 Span 顺序展示意图输入、上下文检索、模型推理、工具调用、响应输出、处置状态 | 作为风险节点导航，点击节点后右侧证据工作区联动 |
| 右侧证据工作区 | 风险摘要、证据锚点、命中规则、格式化 JSON、Raw Payload、脱敏状态、处置操作 | 使用主宽度，优先保证 Prompt、Tool I/O、Raw Payload 可读 |

右侧证据工作区至少包含：

- 风险结论摘要：先解释为什么有风险，再展示原始证据。
- 结构化证据字段：`event_id`、`trace_id`、`span_id`、`source_field`、`evidence_offset`、`risk_stage`、`rule_version`、`raw_ref`。
- 证据 Tab：证据摘要、格式化 JSON、Raw Payload、规则解释，并能随当前 Span 切换内容。
- 固定操作区：确认风险、建议处置、标记误报、创建或关联风险事件。

Trace 视图的默认排序应以风险优先，而不是耗时优先。耗时字段可以保留在详情中，但不作为主视觉重点。P0 先采用固定大屏布局；拖拽分栏、证据对比和复杂查询放入 P1。

### 5.3 风险事件

风险事件必须支持完整处置闭环：

```text
New -> Confirmed -> In Progress -> Resolved -> Closed
       \-> False Positive
       \-> Accepted Risk
```

事件详情必须展示：

- 风险类型、等级、置信度、标准风险阶段
- 关联应用、智能体、工具、资源
- `trace_id`、`span_id`、发生时间
- 上下文预览：触发前文、模型计划、工具/资源、响应输出
- 证据面板：证据摘要、格式化 JSON、Raw Payload、规则解释
- 命中规则和规则版本
- 处置动作、审批记录和审计日志
- 误报原因或接受风险原因

事件列表必须支持安全运营分诊：

| 能力 | P0 要求 |
|---|---|
| 筛选降噪 | 默认展示时间范围、状态、风险等级、负责人、Trace / Span；更多筛选中放置接入应用、所属部门、风险类型、平台动作 |
| 信息密度 | 独立展示发生时间；证据摘要采用标签化要点；展示平台动作，如仅记录、已通知、已建议限制、已下发限制、已恢复 |
| 责任归属 | 支持认领 / 指派负责人，支持批量指派 |
| 审计留痕 | 批量确认、批量误报、接受风险、下发限制都必须填写原因、审批或备注 |
| 证据联动 | 从列表、详情、处置记录跳转风险溯源时携带 `trace_id / span_id` |

告警与处置记录页必须支持按时间、动作类型、操作人、审批状态、回滚状态、事件 / Trace 查询，并保留回滚入口。

### 5.4 应用详情

应用详情不再以服务器和性能指标为主，应调整为安全治理视角：

| Tab | P0 内容 |
|---|---|
| 安全概览 | 应用风险趋势、未处置风险、采集状态、规则覆盖缺口 |
| 智能体 / 节点 | 已观测 Agent / Workflow Node、来源、置信度、关联风险 |
| 工具与资源 | 已观测工具、MCP、Skill、资源、声明状态、影子工具提示 |
| 风险事件 | 当前应用下的风险事件列表 |
| 接入配置 | App Token、SDK 配置、采样率、脱敏策略 |
| 运行实例 | SDK 实例、主机/Pod、版本、心跳，仅作为辅助信息 |

### 5.5 工具与权限

P0 先交付工具发现和工具风险面，不强求完整权限图谱：

| 能力 | P0 要求 |
|---|---|
| 工具列表 | 展示工具名称、类型、来源、调用次数、关联 Agent 数、风险事件数 |
| 声明差异 | 标记"已声明 / 未声明但已观测 / 已声明但未使用" |
| 影子工具 | 对未声明但被调用的工具进行风险提示 |
| 工具详情 | 展示调用 Agent、典型参数、关联 Trace、历史风险事件 |
| 名单管理 | 支持加入允许名单、关注名单、限制名单 |

## 6. P0 数据对象最小字段

### 6.1 接入应用 `applications`

| 字段 | 说明 |
|---|---|
| `id` / `app_id` | 接入治理主键 |
| `tenant_id` | 租户 |
| `name` | 应用名称 |
| `owner` | 责任人或责任部门 |
| `environment` | 生产、测试、开发 |
| `status` | 正常、未接入、采集异常、停用 |
| `policy_id` | 绑定策略 |
| `created_at` / `updated_at` | 时间 |

### 6.2 Span `agent_spans`

| 字段 | 说明 |
|---|---|
| `tenant_id` / `app_id` | 归属 |
| `trace_id` / `span_id` / `parent_span_id` | Trace 关系 |
| `span_kind` | LLM、Tool、MCP、Skill、Retriever、Chain |
| `agent_name` / `node_name` | 智能体或工作流节点标签 |
| `tool_name` / `mcp_server` / `skill_name` | 工具能力标签 |
| `resource_type` / `resource_name` | 访问资源标签 |
| `input` / `output` | 脱敏后的输入输出摘要 |
| `raw_ref` | 原始证据对象存储引用 |
| `started_at` / `ended_at` | 时间 |
| `security_tags` | Processor 或检测引擎写入的安全标签 |

### 6.3 风险事件 `risk_events`

| 字段 | 说明 |
|---|---|
| `id` | 风险事件 ID |
| `tenant_id` / `app_id` | 归属 |
| `trace_id` / `span_id` | 证据锚点 |
| `risk_type` | 风险类型 |
| `risk_level` | 高、中、低、提示 |
| `confidence` | 置信度 |
| `status` | 事件状态 |
| `detector_id` | 检测器 |
| `rule_version` | 规则版本 |
| `risk_stage` | 标准风险阶段 |
| `source_field` | 证据来源字段 |
| `evidence_offset` | 证据位置 |
| `redaction_state` | 脱敏状态 |
| `subject_type` / `subject_id` | 分析主体，如 Agent / Workflow Node |
| `tool_id` / `resource_id` | 关联工具和资源 |
| `block_action` / `block_reason` | 处置动作和原因 |
| `false_positive_reason` | 误报原因 |
| `created_at` / `updated_at` | 时间 |

### 6.4 证据 `evidence`

P0 可作为 `risk_events.evidence` JSON 字段或独立表实现，至少包含：

| 字段 | 说明 |
|---|---|
| `evidence_id` | 证据 ID |
| `risk_event_id` | 关联事件 |
| `span_id` | 关联 Span |
| `field` | Prompt、Response、Tool Input、Tool Output 等 |
| `excerpt` | 脱敏后的证据片段 |
| `offset_start` / `offset_end` | 证据位置 |
| `matcher` | 命中规则、模型或检测器 |
| `confidence` | 证据置信度 |
| `raw_ref` | 原始数据引用 |

### 6.5 处置动作 `response_actions`

| 字段 | 说明 |
|---|---|
| `id` | 处置动作 ID |
| `risk_event_id` | 关联事件 |
| `scope` | Session、Tool、Agent、App |
| `subject_id` | 被处置对象 |
| `action_type` | 通知、限制、阻断、熔断、恢复 |
| `ttl` | 有效期 |
| `approval_id` | 审批记录 |
| `rollback_state` | 回滚状态 |
| `operator` | 操作人 |

## 8. P0 验收标准

### 8.1 端到端闭环验收

P0 验收时至少完成以下场景：

1. 创建应用并获取接入 Token。
2. 客户端 SDK 上报一次包含 LLM 调用和 Tool 调用的 Trace。
3. 管理端成功归一化 Span，并能按 `trace_id` 查询完整 Span 树。
4. 检测引擎识别一个风险事件，写入 `risk_events`。
5. 风险事件详情能展示证据片段、命中规则、置信度和关联 Span。
6. 风险溯源工作台能按 Trace 展示风险路径和证据面板。
7. 安全总览能统计该风险事件，并显示待处置数量。
8. SOC 用户能确认、处置、关闭事件，并留下审计记录。
9. 高影响处置动作具备二次确认、TTL 和回滚入口。
10. 监控覆盖度能提示未接入、Trace 断链或黑盒工具调用中的至少一类问题。

### 8.2 页面评审标准

| 标准 | 要求 |
|---|---|
| 安全优先 | 页面首屏回答风险、证据、处置问题，而不是性能成本问题 |
| 证据可追溯 | 每个风险事件都能追到 `trace_id` 和 `span_id` |
| 操作可审计 | 所有确认、忽略、阻断、恢复动作都有审计记录 |
| 误报可沉淀 | 误报必须记录原因，后续可用于规则优化 |
| 覆盖可见 | 用户能知道哪些应用、智能体、工具没有被有效监控 |
| 术语一致 | 页面避免强对抗字眼，使用风险治理和合规口径 |
