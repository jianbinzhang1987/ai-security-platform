# 风险溯源流程设计

## 1. 文档目标

本文档定义平台从风险线索进入调查，到形成调查结论和事件输出的完整风险溯源流程。

---

## 2. 流程目标

风险溯源流程的目标是：

1. 基于 `trace_id` 和 `span_id` 快速定位风险。
2. 还原风险发生路径。
3. 展示最小证据单元。
4. 形成可复核的人工判断。
5. 将结论输出给风险事件模块。

---

## 3. 流程参与对象

1. 风险线索
2. Trace
3. Span
4. 证据引用
5. 安全运营
6. 安全管理员
7. 风险事件
8. 规则项

---

## 4. 主流程

```text
风险规则识别
→ 生成风险线索
→ 进入风险溯源工作台
→ 查询并定位 Trace
→ 选中关键 Span
→ 阅读证据摘要 / JSON / Raw / 规则解释
→ 形成调查判断
→ 输出为：
   1. 创建事件
   2. 关联事件
   3. 标记误报
   4. 提出处置建议
```

---

## 5. 流程步骤设计

## 5.1 风险线索生成

触发来源：

1. Prompt 风险命中
2. 输入安全命中
3. 输出安全命中
4. 工具边界命中
5. 会话安全命中
6. 人工从会话审计发起调查

输出数据：

1. `clue_id`
2. `trace_id`
3. `span_id`
4. `risk_type`
5. `risk_level`
6. 风险摘要
7. `source_field`
8. `evidence_offset`
9. 命中规则 ID / 版本

状态要求：

1. 新生成线索进入 `detected`。
2. 人工进入调查后变更为 `under_review`。
3. 创建或关联正式事件后变更为 `linked_event`。
4. 判定误报或无需形成事件后变更为 `dismissed`。

## 5.2 Trace 定位

调查人员进入工作台后，通过以下条件定位目标：

1. 时间范围
2. 应用
3. 风险等级
4. 风险类型
5. Agent / 节点
6. 工具 / MCP
7. `trace_id / span_id`
8. `source_field`

## 5.3 风险链路阅读

工作台中应按安全语义展示链路：

1. 意图输入
2. 上下文检索
3. 模型推理
4. 工具调用
5. 输出结果
6. 处置状态

调查重点：

1. 风险发生在哪一段
2. 风险是否跨段扩散
3. 是否存在多处命中

## 5.4 Span 证据确认

调查人员选中关键 Span 后，需要查看：

1. 证据摘要
2. 格式化 JSON
3. 原始载荷
4. 规则解释
5. 关联资源
6. 脱敏状态
7. 命中规则版本
8. `raw_ref`

Raw 查看要求：

1. 默认展示脱敏证据。
2. 查看 Raw 必须校验高敏证据权限。
3. Raw 访问必须记录 `trace_id`、`span_id`、`raw_ref`、访问原因和访问人。

## 5.5 调查结论输出

可输出的结论类型：

1. 确认为真实风险
2. 需继续观察
3. 判定为误报
4. 需立即限制或处置

---

## 6. 分支流程

## 6.1 创建事件分支

适用条件：

1. 风险真实存在
2. 需要进入正式闭环

输出内容：

1. `trace_id`
2. `span_id`
3. 风险等级
4. 风险类型
5. 风险摘要
6. `source_field`
7. `evidence_offset`
8. `clue_id`
9. 命中规则 ID / 版本

状态变化：

1. 风险线索从 `under_review` 变更为 `linked_event`。
2. 风险事件创建后进入 `new`。

## 6.2 关联既有事件分支

适用条件：

1. 当前线索属于已知事件扩展
2. 同一事件存在多个相关 Span

关键要求：

1. 一个事件应支持关联多个风险线索。
2. 关联动作必须记录审计。
3. 事件证据关系应写入 `event_evidence_rel`。

## 6.3 误报分支

适用条件：

1. 规则误判
2. 风险不成立

关键要求：

1. 必须填写误报原因。
2. 误报样本可回流规则优化。

## 6.4 处置建议分支

适用条件：

1. 风险成立
2. 需要立即限制、降级或恢复

建议填写内容：

1. 动作类型
2. 建议作用范围
3. 建议目标对象
4. TTL
5. 影响说明
6. 推荐审批级别
7. 审批备注

关键要求：

1. 处置建议不等同于正式处置动作。
2. 正式动作必须在风险事件模块中创建 `event_action`。

---

## 7. 关键字段要求

风险溯源流程至少应保留以下字段：

1. `trace_id`
2. `span_id`
3. `session_id`
4. `app_id`
5. 风险类型
6. 风险等级
7. `source_field`
8. `evidence_offset`
9. 规则 ID / 规则版本
10. 置信度
11. `mask_status`
12. `raw_ref`
13. `clue_status`

---

## 8. 权限与审计要求

1. 查看脱敏证据需基础调查权限。
2. 查看 Raw 证据需额外授权。
3. 创建事件、误报标记、处置建议必须审计。
4. 导出证据必须审计。
5. 线索状态变化必须写入状态变更日志。

---

## 9. 后续详细设计重点

3. 规则解释展示模型

5. 高敏证据访问审批机制
