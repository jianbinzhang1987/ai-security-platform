# 大模型安全监测平台总体业务架构

## 1. 文档目标

本文档用于定义大模型安全监测平台的总体业务架构，明确平台定位、核心对象、模块边界、主业务闭环及模块间关系，作为后续模块设计、接口设计和数据模型设计的统一业务基线。

本文档范围以当前原型 `index.html` 中实际展示的功能菜单为准。

---

## 2. 平台定位

大模型安全监测平台是一个面向大模型应用、Agent、网关和探针双侧的安全监测与处置平台，负责承接以下核心能力：

1. 对大模型输入、输出、会话、工具调用和运行行为进行持续监测。
2. 对风险行为进行识别、证据提取和链路还原。
3. 将风险线索沉淀为正式安全事件并推动处置闭环。
4. 通过网关策略和探针策略对风险进行治理、限制、阻断和恢复。
5. 对所有策略变更、风险处置和证据访问形成审计留痕。
6. 对采集链路、策略下发链路和运行组件健康进行统一观测。

---

## 3. 业务架构总览

平台整体业务可以抽象为六个一级业务域：

1. 安全总览
2. 资产中心
3. 安全监控
4. 风险事件
5. 统一策略中心
6. 系统管理

其核心业务闭环如下：

```text
应用 / Agent 运行
    ↓
网关 / 探针采集
    ↓
安全规则识别风险
    ↓
Trace / Span 证据还原
    ↓
形成风险事件
    ↓
执行处置动作
    ↓
策略优化与版本治理
    ↓
审计留痕与运行复盘
```

---

## 4. 核心对象模型

### 4.1 平台核心对象

平台后续设计建议统一围绕以下对象展开：

1. 应用 `app`
2. Agent / 工作流节点 `agent / node`
3. 工具 / MCP / 外部资源 `tool / resource`
4. 会话 `session`
5. 调用链 `trace`
6. 证据单元 `span / observation`
7. 风险事件 `event`
8. 处置动作 `action`
9. 网关策略 `gateway policy`
10. 探针策略包 `probe package`
11. 高级规则项 `rule`
12. 通知渠道 `channel`
13. 采集器 / 运行组件 `collector / service`
14. 用户 / 角色 / 审批主体 `user / role / approval`

### 4.2 对象关系

建议采用如下对象关系：

```text
租户 / 组织
└── 应用 App
    ├── Agent / 工作流节点
    ├── 工具 / MCP / 外部资源
    ├── 会话 Session
    │   └── Trace
    │       └── Span / Observation
    ├── 风险事件 Event
    │   └── 处置动作 Action
    └── 策略绑定关系
        ├── 网关策略
        └── 探针策略包
```

### 4.3 业务锚点定义

后续系统设计中，建议统一使用如下业务锚点：

1. `app_id` 作为治理归属边界。
2. `session_id` 作为多轮上下文聚合边界。
3. `trace_id` 作为默认调查入口。
4. `span_id` 作为最小证据锚点。
5. `event_id` 作为正式闭环对象。
6. `action_id` 作为处置动作留痕对象。

## 5. 六大业务域设计

## 5.1 安全总览

### 业务定位

安全总览是平台首屏，负责展示安全态势、风险分布、待办事项、覆盖情况和运行健康，并承接下钻入口。

### 核心职责

1. 展示风险总量与趋势。
2. 展示高风险对象排行。
3. 展示采集健康和覆盖缺口。
4. 展示待处理事项。
5. 将用户快速引导到事件、溯源、资产和采集器等工作区。

## 5.2 资产中心

### 业务定位

资产中心以“接入应用”为唯一正式资产入口，统一承接应用安全概览、Agent 识别、工具资源、风险事件、接入配置、运行实例和策略覆盖。

### 核心职责

1. 管理接入应用和责任归属。
2. 管理接入信息与配置。
3. 聚合应用相关 Agent、工具、实例和风险。
4. 展示策略绑定、生效与覆盖缺口。

## 5.3 安全监控

### 业务定位

安全监控以“风险溯源工作台”为正式调查入口，围绕 Trace 和 Span 证据完成风险还原和调查判断。

### 核心职责

1. 查询和筛选风险 Trace。
2. 展示风险链路。
3. 展示 Span 证据。
4. 输出调查结论。
5. 关联或创建风险事件。

## 5.4 风险事件

### 业务定位

风险事件模块是正式闭环中心，负责把线索转化为可管理、可处置、可审计的安全事件。

### 核心职责

1. 接收风险线索和调查结论。
2. 形成正式事件。
3. 指派责任人。
4. 完成确认、误报、接受风险、关闭等处置流程。
5. 记录全部响应动作、审批和回滚信息。

## 5.5 统一策略中心

### 业务定位

统一策略中心负责平台的风险治理能力配置，覆盖网关侧安全策略、探针侧策略包、高级规则项以及通知渠道。

### 核心职责

1. 配置网关访问、流量、Prompt、输入、输出、会话策略。
2. 配置探针侧策略包和高级规则项。
3. 管理绑定、下发、灰度、回滚。
4. 管理通知渠道和联动动作。
5. 支撑事件处置与策略优化闭环。

## 5.6 系统管理

### 业务定位

系统管理负责平台级用户权限、操作审计和采集器配置，是平台安全治理和运行保障的基础域。

### 核心职责

1. 管理用户和角色。
2. 管理对象级权限能力。
3. 提供完整的操作审计。
4. 监控采集链路健康。
5. 管理采集配置发布与同步。

## 6. 平台主业务闭环

## 6.1 运行监测闭环

```text
应用 / Agent 运行
→ 网关 / 探针采集
→ 规则识别
→ 生成 Trace / Span 风险标记
→ 安全总览聚合展示
```

## 6.2 调查处置闭环

```text
风险线索
→ 风险溯源工作台调查
→ 创建 / 关联风险事件
→ 指派负责人
→ 执行处置
→ 审批 / 回滚
→ 事件关闭
→ 审计留痕
```

## 6.3 策略治理闭环

```text
风险识别
→ 事件处置
→ 策略优化需求
→ 规则 / 策略 / 策略包调整
→ 绑定与下发
→ 灰度验证
→ 生效监控
→ 版本沉淀
```

## 6.4 运行保障闭环

```text
采集器运行
→ 健康状态监控
→ 队列 / 写入 / QPS / 错误率观测
→ 异常告警
→ 运维处置
→ 配置优化
```

## 7. 模块间依赖关系

### 7.1 安全总览与其他模块

1. 从风险事件获取待办数量。
2. 从安全监控获取风险趋势数据。
3. 从资产中心获取应用与工具排行。
4. 从系统管理获取采集健康数据。

### 7.2 资产中心与其他模块

1. 从策略中心获取策略绑定和下发状态。
2. 从风险事件获取应用风险聚合信息。
3. 从安全监控获取 Trace / Span 风险证据汇总。

### 7.3 安全监控与其他模块

1. 从采集链路获取 Trace / Span 数据。
2. 从策略中心获取命中规则与规则解释。
3. 向风险事件输出调查结果。

### 7.4 风险事件与其他模块

1. 从安全监控获取证据和调查链路。
2. 从会话审计获取上下文原文和网关动作。
3. 反向驱动策略中心产生治理优化动作。

### 7.5 统一策略中心与其他模块

1. 为网关和探针提供治理能力。
2. 向风险事件提供处置动作执行基础。
3. 向系统管理输出发布与审计动作。

### 7.6 系统管理与其他模块

1. 为所有模块提供用户权限与角色控制。
2. 为所有模块提供审计能力。
3. 为总览和资产提供采集健康支撑。

## 8. 总体业务边界

### 8.1 本平台负责

1. 安全数据采集后的治理与监测。
2. 风险识别、证据还原、事件闭环。
3. 网关和探针侧策略治理。
4. 安全处置、审批、回滚与审计。
5. 采集链路和策略链路的运行观测。

### 8.2 本平台不直接负责

1. 大模型业务本身的业务功能实现。
2. 非安全类的普通 APM 性能分析。
3. 外部审批平台、外部工单平台的业务实现本体。
4. 第三方 IM / 邮件 / 短信系统本体。

本平台可以与上述系统集成，但不取代其业务职责。

## 9. 当前架构收敛结论

### 9.1 必须统一的产品口径

1. 资产入口统一为“接入应用”。
2. 调查入口统一为“风险溯源工作台”。
3. 闭环入口统一为“风险事件”。
4. 治理入口统一为“统一策略中心”。
5. 平台基础能力入口统一为“系统管理”。

### 9.2 后续设计优先级

后续模块设计建议优先展开以下三个复杂域：

1. 风险事件
2. 安全监控
3. 统一策略中心

原因如下：

1. 这三块决定平台是否真正形成安全闭环。
2. 这三块也是对象、状态、流程最复杂的区域。
3. 资产中心和总览更多依赖这三块能力完成聚合。
