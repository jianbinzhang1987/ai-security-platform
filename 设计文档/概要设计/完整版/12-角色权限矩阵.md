# 大模型安全监测平台角色权限矩阵

## 1. 文档目标

本文档用于定义平台的角色体系、职责边界、功能权限和对象级敏感权限，为后续页面权限控制、接口鉴权、审批流和审计设计提供依据。

---

## 2. 设计原则

角色权限设计遵循以下原则：

1. 最小权限原则。
2. 读写分离原则。
3. 查看权限与处置权限分离原则。
4. 策略配置权限与事件处置权限分离原则。
5. 敏感证据访问单独授权原则。
6. 高危操作必须支持审批或双人校验。

---

## 3. 角色定义

## 3.1 平台管理员

### 角色定位

负责平台级配置、用户权限、审计管理和系统运行保障。

### 主要职责

1. 管理用户、角色和平台级权限。
2. 查看和导出操作审计。
3. 管理采集器配置和平台运行组件。
4. 处理平台级异常和运维治理。

## 3.2 安全管理员

### 角色定位

负责平台安全规则、策略体系、处置机制和高危操作审批。

### 主要职责

1. 管理网关策略和探针策略。
2. 审批高危策略发布和高危处置动作。
3. 管理通知渠道。
4. 查看和处理跨应用安全事件。

## 3.3 安全运营

### 角色定位

负责日常风险监测、风险溯源、事件研判和处置闭环执行。

### 主要职责

1. 查看总览和告警。
2. 进行风险溯源调查。
3. 创建、指派、确认和关闭风险事件。
4. 提出处置建议。

## 3.4 审计只读

### 角色定位

负责查看平台风险、事件和审计留痕，不执行变更和处置。

### 主要职责

1. 查看安全总览。
2. 查看风险事件和告警记录。
3. 查看审计日志。
4. 查看策略与配置结果，但不可修改。

## 3.5 应用负责人

### 角色定位

负责自己所属应用的接入、风险查看、配置确认和协同处理。

### 主要职责

1. 查看所负责应用的详情、风险和策略绑定情况。
2. 协同确认应用相关事件。
3. 查看应用接入和配置状态。
4. 无权操作跨应用和平台级资源。

## 6. 对象级敏感权限

除页面级权限外，以下敏感对象建议单独控制。

### 6.1 原始证据访问权限

控制对象：

1. Prompt 原文
2. Response 原文
3. Tool Input 原文
4. Tool Output 原文
5. Raw Payload 引用内容

建议权限规则：

1. 安全管理员默认可查看。
2. 安全运营默认查看脱敏后内容，申请后可看 Raw。
3. 审计只读默认仅看脱敏内容。
4. 应用负责人默认仅看所属应用脱敏内容。

### 6.2 高危处置权限

高危动作包括：

1. 全应用阻断
2. Agent 级限制
3. 大范围策略切换
4. 高危策略发布
5. 接受风险
6. 大范围回滚

建议规则：

1. 执行人可以发起。
2. 安全管理员或被授权审批人批准后生效。
3. 必须保留审批单号和操作原因。

### 6.3 导出权限

控制导出对象：

1. 事件列表导出
2. 会话审计导出
3. 原始证据导出
4. 审计日志导出

建议规则：

1. 普通查看角色默认不可导出 Raw。
2. 审计日志导出应仅限平台管理员和授权审计角色。
3. 原始证据导出必须记录审计。

## 7. 审批与双人校验建议

以下操作建议进入审批流或双人校验：

1. 接受风险
2. 发布高危策略
3. 回滚生产策略
4. 查看高敏原始证据
5. 导出高敏原始证据
6. 批量关闭高风险事件
7. 批量执行限制类动作

建议审批字段：

1. `approval_id`
2. 发起人
3. 审批人
4. 审批类型
5. 审批状态
6. 审批意见
7. 生效时间

## 8. 权限控制落地建议

### 8.1 前端控制

1. 控制菜单可见性。
2. 控制按钮显隐。
3. 控制字段是否脱敏展示。
4. 控制详情区域是否可见。

### 8.2 后端控制

1. 控制接口是否可调用。
2. 控制查询结果是否过滤到授权范围。
3. 控制 Raw 数据访问。
4. 控制跨应用、跨租户访问。

### 8.3 数据权限控制

1. 按租户控制。
2. 按应用控制。
3. 按事件所属范围控制。
4. 按敏感级别控制。

## 9. 当前建议结论

### 9.1 最终角色建议

本轮建议保留五类正式角色：

1. 平台管理员
2. 安全管理员
3. 安全运营
4. 审计只读
5. 应用负责人

### 9.2 后续详细设计必须补齐

1. 角色与菜单映射表
2. 角色与接口权限映射表
3. 数据权限规则表
4. 敏感对象脱敏查看规则
5. 审批流与角色映射关系
