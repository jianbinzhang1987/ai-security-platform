# 资产中心模块概要设计

## 1. 文档目标

本文档定义大模型安全监测平台“资产中心”模块的业务定位、页面范围、核心对象、功能设计和关键设计要求。

当前原型中资产中心正式展示的一级页面仅为“接入应用”，因此本轮资产中心设计以“应用”为唯一正式资产入口，其他资产维度作为应用详情中的子域能力承载。

---

## 2. 模块定位

### 2.1 业务定位

资产中心是平台的治理对象中心，负责统一管理平台接入的应用，并从应用视角聚合 Agent、工具、资源、风险、接入配置、运行实例和策略覆盖状态。

### 2.2 核心职责

1. 统一管理接入应用。
2. 承载应用责任归属和业务边界。
3. 展示应用相关的 Agent / 节点、工具和资源。
4. 聚合应用相关的风险和事件。
5. 管理应用接入配置、运行实例和策略覆盖。

### 2.3 模块边界

资产中心负责：

1. 应用主档管理。
2. 应用接入信息和配置管理。
3. 应用视角的安全态势聚合。
4. 应用级策略绑定和覆盖检查。

资产中心不直接负责：

1. 风险事件闭环。
2. Trace / Span 深度调查。
3. 策略规则本体配置。
4. 平台级用户和角色管理。

---

## 3. 页面范围

当前正式页面建议包括：

1. 接入应用列表
2. 应用详情

说明：

1. 工具、Agent、实例等内容不再独立为一级菜单。
2. 这些能力统一收敛到应用详情内部视图。

---

## 4. 核心对象

## 4.1 应用 `app`

应用是平台的正式治理归属对象。

### 核心属性

1. `app_id`
2. 应用名称
3. 所属租户 / 组织
4. 所属业务线
5. 应用负责人
6. 运行环境
7. 接入状态
8. 当前策略版本
9. 最近上报时间
10. 采集健康状态

## 4.2 应用实例 `instance`

应用实例是应用运行时的承载对象。

### 核心属性

1. `instance_id`
2. 所属应用
3. hostname
4. IP
5. 容器 / 进程信息
6. `service.name`
7. SDK 版本
8. 策略同步版本
9. 心跳状态
10. 最后上报时间

## 4.3 Agent / 节点 `agent / node`

Agent / 节点是应用内逻辑执行主体。

### 核心属性

1. `agent_id` 或节点唯一标识
2. 名称
3. 识别来源
4. 识别等级
5. 所属应用
6. 工具集合
7. 风险画像

## 4.4 工具 / 资源 `tool / resource`

### 核心属性

1. 工具名称
2. 工具类型
3. 声明状态
4. 来源
5. 风险级别
6. 关联资源
7. 最近使用时间

## 5. 接入应用列表设计

## 5.1 页面目标

统一承接平台接入应用的查询、查看、创建、批量治理和详情下钻。

## 5.2 页面结构

建议页面结构如下：

1. 页面头部
2. 查询筛选区
3. 列表工具栏
4. 应用列表区
5. 批量操作区
6. 创建应用弹窗

## 5.3 查询条件

建议支持：

1. 应用名称
2. `app_id`
3. 业务线
4. 负责人
5. 环境
6. 接入状态
7. 风险等级
8. 采集健康状态
9. 当前策略版本

## 5.4 列表字段

建议字段如下：

1. 应用名称
2. `app_id`
3. 业务线
4. 负责人
5. 环境
6. 接入状态
7. 最近 24h 调用量
8. 风险数
9. 高风险数
10. 采集健康
11. 最近上报时间
12. 操作

## 5.5 页面功能

1. 查看应用详情
2. 创建应用
3. 批量绑定策略
4. 批量变更状态
5. 导出列表
6. 查看接入指引

## 5.6 关键设计要求

1. 点击不同应用必须带上真实 `app_id`。
2. 应用列表是资产治理主列表，不再展示服务器式资产主入口。
3. 批量操作应有审批或二次确认能力。

## 6. 应用详情设计

## 6.1 页面目标

从单个应用视角，统一承载应用安全概览、逻辑主体、工具资源、风险事件、接入配置、运行实例和策略覆盖。

## 6.2 视图结构建议

建议应用详情按以下顺序组织：

1. 安全概览
2. Agent / 节点
3. 工具与资源
4. 风险事件
5. 接入配置
6. 运行实例
7. 策略覆盖检查
8. 接入指引

## 6.3 安全概览

### 页面目标

快速展示应用当前的整体安全状态。

### 建议展示内容

1. 应用状态
2. 风险总量
3. 高风险数
4. 最近事件
5. 误报率
6. 当前生效策略
7. 策略同步情况

## 6.4 Agent / 节点视图

### 业务目标

展示应用内部的逻辑执行主体及其安全画像。

### 建议展示内容

1. Agent / 节点名称
2. 来源类型
3. 识别等级
4. 工具集合
5. 风险数量
6. 关联事件

## 6.5 工具与资源视图

### 业务目标

展示应用内已声明、已观测和高风险的工具与资源。

### 建议展示内容

1. 工具名称
2. 工具类型
3. 声明状态
4. 风险级别
5. 关联资源
6. 最近使用时间
7. 关联事件

## 6.6 风险事件视图

### 业务目标

从应用视角查看当前应用相关的事件聚合情况。

### 建议展示内容

1. 关联事件列表
2. 风险类型分布
3. 事件状态分布
4. 高风险事件数
5. 跳转事件详情和溯源

## 6.7 接入配置

### 业务目标

管理应用接入时的采集、脱敏和工具治理配置。

### 建议配置项

1. 采集开关
2. 采样率
3. Prompt / Response / Tool I/O 采集项
4. 脱敏规则
5. 工具白名单 / 黑名单
6. 告警绑定
7. 策略包绑定

## 6.8 运行实例

### 业务目标

展示应用运行实例和实例级同步、心跳、版本情况。

### 建议字段

1. `instance_id`
2. hostname
3. IP
4. 容器 / 进程
5. `service.name`
6. SDK 版本
7. 策略版本
8. 心跳状态
9. 最后上报时间
10. 操作

## 6.9 策略覆盖检查

### 业务目标

展示当前应用绑定的策略及其生效覆盖状态。

### 建议内容

1. 当前策略包
2. 当前版本
3. 发布状态
4. 同步进度
5. 覆盖缺口
6. 配置变更历史
7. 回滚记录

## 6.10 接入指引

### 业务目标

为应用接入和运维提供标准接入指导。

### 建议内容

1. OTLP Endpoint
2. App Token / 接入凭证
3. 环境变量示例
4. SDK 配置示例
5. 首次激活判断逻辑

## 7. 核心流程设计

## 7.1 应用接入流程

```text
创建应用
→ 生成接入信息
→ 应用配置 SDK / 探针
→ 首次上报
→ 激活应用
→ 进入资产中心治理范围
```

## 7.2 应用风险聚合流程

```text
Trace / Span 风险识别
→ 归属到 app_id
→ 汇总到应用风险统计
→ 展示在应用详情和总览排行
```

## 7.3 应用策略绑定流程

```text
选择策略包
→ 绑定应用
→ 下发到实例
→ 实例同步
→ 展示覆盖与缺口
```

## 7.4 应用配置变更流程

```text
修改采集或治理配置
→ 生成配置新版本
→ 发布
→ 应用实例拉取
→ 生效校验
```

## 8. 与其他模块关系

### 8.1 与安全总览

1. 总览中的高风险应用排行来自资产中心聚合结果。
2. 总览点击应用应能下钻到应用详情。

### 8.2 与安全监控

1. 应用详情可跳转到应用范围内的风险溯源工作台。
2. 安全监控中的 Trace 归属到应用。

### 8.3 与风险事件

1. 应用详情中的风险事件视图消费事件模块数据。
2. 事件详情可反向回跳应用详情。

### 8.4 与统一策略中心

1. 应用详情展示绑定策略和版本信息。
2. 策略绑定和下发结果反映到应用覆盖状态。

### 8.5 与系统管理

1. 采集健康状态由系统管理提供。
2. 用户权限控制应用查看和变更范围。

## 9. 数据与权限要求

## 9.1 最低数据要求

应用主档至少必须具备：

1. `app_id`
2. 应用名称
3. 所属业务线
4. 负责人
5. 环境
6. 接入状态
7. 最近上报时间

## 9.2 权限要求

1. 平台管理员可创建和管理所有应用。
2. 安全管理员可查看和管理安全配置相关内容。
3. 安全运营可查看，不建议修改接入配置。
4. 应用负责人只能查看所属应用，部分变更建议走申请式流程。

## 9.3 审计要求

以下动作必须审计：

1. 创建应用
2. 修改接入配置
3. 变更策略绑定
4. 回滚应用配置
5. 导出应用数据
