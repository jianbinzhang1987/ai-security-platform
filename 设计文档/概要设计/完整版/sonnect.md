## 二、P0 可见模块 — 未完善问题（按严重程度）

### 🔴 P0 阻塞级问题（影响评审演示）

**1. 风险事件详情页存在 JS 运行时错误**

`event-detail.html` 中 `renderEvent()` 调用了 `document.getElementById('platformAction').innerHTML`，但该 HTML 元素已被注释掉，导致打开任意事件详情时均**抛出空指针错误**，3 个演示事件全部无法正常渲染。

**2. 应用列表跳转逻辑断链**

`app-list.html` 的 `goDetail()` 函数**未传入 `app_id` 参数**，点击 5 个不同应用的「详情」按钮，全部跳转到同一个硬编码「智能客服 Copilot」详情页，无法区分应用。

**3. 应用详情核心 Tab 被整体注释**

`app-detail.html` 中「接入配置」和「接入指引」两个 Tab 的 HTML 内容整块被注释，包含**采集开关、采样率、工具白黑名单、PII 脱敏规则、配置变更历史**等核心功能，对外完全不可见。同时「规则覆盖」Tab 有内容 div 但无导航入口。

**4. 风险溯源工作台 Span 证据数据混淆**

`trace-list.html` 中 6 个 Span 里，`sp_01_input`、`sp_02_retriever`、`sp_06_action` 三个 Span 在 `evidenceProfiles` 中无对应数据，点击后**静默 fallback 到 `sp_04_tool` 的证据**，产生严重的展示混淆，且无任何提示。Trace 列表也仅有 1 条演示记录，无法演示切换效果。

**5. 检测规则配置定位模糊、核心能力缺失**

`policy-list.html` 页面混合了采集策略、脱敏策略、处置响应规则，导航标签写的是「检测规则配置」但内容更像「安全策略库」。缺少：规则版本管理入口、版本历史查看、绑定应用列表可展开、误报样本跳转。干跑结果完全硬编码，无法演示真实能力。

**6. 告警规则页编辑回填错误**

`alert-rules.html` 中 `openAlertRuleModal(name)` 只传入名称，编辑任何一条规则时，表单始终**回填第一条「Collector 心跳离线」的数据**，不会动态切换，且缺少删除按钮、批量操作、告警历史入口。

---

### 🟠 P0 重要缺陷（影响关键业务流程）

**7. 安全总览监控覆盖卡片被注释**

`dashboard.html` 中「监控覆盖概况」和「规则覆盖缺口」两个卡片被整块注释，造成首页信息密度不足，且覆盖度数据与 `coverage.html` 的下钻路径断开。高风险排行榜（应用/工具/智能体）三列数据均为硬编码，应用名和工具名**点击无跳转**，无法下钻到对应详情页。

**8. 风险事件闭环路径不完整**

- 「接受风险」有状态但无独立操作 Modal（事件列表和详情页均缺失）
- 「平台动作」筛选项在列表页被代码注释掉
- 批量操作缺少「批量关闭」
- 处置时间线硬编码（第2条时间戳写死），无审计留痕写入逻辑
- 详情页无「误报标记」和「指派」快捷按钮，需回列表操作

**9. 数据采集器配置与应用列表断链**

`collector-config.html` 采集健康指标（Kafka Lag、实例状态等）已有展示，但与 `app-list.html` 中「采集异常应用」卡片（7个异常）**无任何双向跳转入口**，形成信息孤岛。缺少配置版本历史和实例级下发状态。

**10. 监控覆盖度操作按钮为空**

`coverage.html` 中覆盖缺口清单的「查看规则」和「绑定规则」两个按钮**无 `onclick` 处理函数**，是空按钮，覆盖度→策略规则的引导路径断开。

---

### 🟡 P0 可增强问题（影响演示体验）

**11. 全模块搜索/查询实际均无效**

所有列表页面（事件列表、应用列表、告警记录、Trace 工作台等）的「查询」按钮一律只触发 `toastSuccess`，不执行实际数据过滤。高级筛选展开后条件也不与数据联动。

**12. 应用详情 Tab 顺序不符合信息优先级**

「运行实例」Tab 位置靠前，「风险事件」Tab 缺失，「接入配置」被注释。建议顺序：安全概览 → 智能体/节点 → 工具与资源 → 风险事件 → 接入配置 → 运行实例。

**13. 告警与处置记录（alert-log）缺少页面标题和部分字段**

无 `page-header` 区域，缺少审批记录的跳转链接（APR 编号为纯文本）、缺少批量处置、缺少手动触发动作的入口。

**14. 工具详情面板关联事件无跳转**

`tool-exposure.html` 右侧安全档案中关联事件（如 `EVT-2026-A018`）为纯文本，**未链接到 `event-detail.html`**，工具→事件的调查链路断开。

**15. 面包屑未在关键页面初始化**

多个页面未调用 `setBreadcrumb()`，切换页面后面包屑可能停留在上一个状态。

## 四、横向缺失能力汇总

以下是跨模块、在整个平台层面缺失的能力：

### 4.1 数据流链路断链

```/dev/null/chain-gaps.txt#L1-15
【已连通】
event-list   → event-detail（携带 id）       ✅
event-list   → trace-list（携带 trace_id）    ✅
event-detail → trace-list（携带 trace_id+span_id）✅
app-detail   → event-detail（带参数）         ✅
coverage     → event-detail（带参数）         ✅

【断开 / 缺失】
dashboard    ✗→ app-detail（排行榜应用名无点击）
dashboard    ✗→ tool-exposure（高风险工具无点击）
app-list     ✗→ app-detail（未传 app_id，所有应用跳同一页）
tool-exposure✗→ event-detail（关联事件为纯文本）
coverage     ✗→ policy/shared-rules（查看规则按钮为空）
prompt-search✗→ trace-list（追踪按钮只 toast）
alert-log    ✗→ 审批详情（APR 编号为纯文本）
collector    ✗→ app-list（采集异常应用无下钻）
```

### 4.2 功能性空白

| 缺失能力                   | 影响范围                                                           |
| -------------------------- | ------------------------------------------------------------------ |
| 自定义时间范围日期选择器   | 所有列表页「自定义」选项无响应                                     |
| 编辑弹窗不回填当前数据     | `app-list`、`tenant-list`、`notify-channel`、`alert-rules` |
| 批量操作确认弹窗           | 事件列表批量确认/误报只 toast，无原因填写                          |
| API Key 创建后展示完整 Key | `api-keys.html` 缺少安全弹框设计                                 |
| 接受风险操作路径           | 事件列表和详情页均无此 Modal                                       |
| 规则版本历史查看           | `policy-list` 和 `guardrails` 均缺失                           |
| 拓扑图真实图形引擎         | `topology.html` 为 CSS 硬编码坐标                                |
| 自动刷新机制               | 运维类页面（service-status）无实时刷新                             |
| 报告时间范围字段           | `report-new.html` 缺失核心字段                                   |
