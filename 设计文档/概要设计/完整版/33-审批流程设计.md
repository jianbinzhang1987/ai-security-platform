# 审批流程设计

## 1. 文档目标

本文档定义平台中高危操作、风险接受、策略发布和证据访问的审批流程设计。

---

## 2. 审批目标

1. 对高风险动作形成前置控制。
2. 保证高危操作有责任归属。
3. 保证审批过程可追溯。
4. 支撑事件、策略、证据访问三类审批。

---

## 3. 审批对象分类

建议审批对象分为三类：

1. 事件类审批
2. 策略类审批
3. 证据访问类审批
4. 系统配置类审批

## 3.1 事件类审批

包括：

1. 接受风险
2. 高危处置动作
3. App 级限制
4. 批量关闭高风险事件
5. 回滚已生效动作

## 3.2 策略类审批

包括：

1. 高危策略发布
2. 生产环境全量下发
3. 高危策略回滚
4. 大范围灰度切换

## 3.3 证据访问类审批

包括：

1. 查看高敏 Raw
2. 导出高敏证据
3. 批量导出会话原文

## 3.4 系统配置类审批

包括：

1. 生产采集配置发布
2. 采集配置恢复默认
3. 高风险用户权限变更

---

## 4. 审批流程主模型

```text
发起审批申请
→ submitted 已提交
→ in_review 审批中
→ approved / rejected / canceled / expired
→ 输出审批结果
```

---

## 5. 流程步骤设计

## 5.1 发起申请

申请时至少需要填写：

1. 审批类型
2. 关联对象类型
3. 关联对象 ID
4. 申请原因
5. 影响范围
6. 期望生效时长
7. 回滚方案
8. `request_id`

## 5.2 审批中

审批人需要查看：

1. 申请摘要
2. 风险背景
3. 关联事件 / 策略 / 证据
4. 影响范围
5. 发起人说明

## 5.3 审批通过

通过后：

1. 触发业务动作执行
2. 记录审批人和审批时间
3. 更新关联对象状态

回写规则：

1. 风险接受审批通过后，事件可从 `confirmed/in_progress` 变更为 `accepted_risk`。
2. 高危处置审批通过后，处置动作可从 `pending` 变更为 `approved`。
3. 策略发布审批通过后，策略或策略包可进入 `gray` 或 `enabled`。
4. 回滚审批通过后，可创建回滚 `deployment` 或将动作变更为 `rollback_pending`。

## 5.4 审批驳回

驳回后：

1. 业务动作不得执行
2. 记录驳回原因
3. 通知申请人

回写规则：

1. 风险接受审批驳回后，事件保持原状态。
2. 高危处置审批驳回后，动作变更为 `canceled`。
3. 策略发布审批驳回后，策略保持原状态。
4. Raw 访问审批驳回后，不允许读取原始载荷。

## 5.5 审批超时

超时策略建议：

1. 默认不执行高危动作
2. 标记为超时失效
3. 通知发起人与管理员

---

## 6. 审批状态定义

统一使用 `approval_status` 字段，枚举如下：

1. `submitted`
2. `in_review`
3. `approved`
4. `rejected`
5. `canceled`
6. `expired`

---

## 7. 审批角色建议

1. 安全管理员
2. 平台管理员
3. 指定审批人

审批人选择规则建议：

1. 事件类优先安全管理员
2. 策略类可由安全管理员或平台管理员审批
3. 高敏证据访问可由安全管理员审批

---

## 8. 与其他模块关系

1. 风险事件中的接受风险依赖审批流程。
2. 策略中心中的发布和回滚依赖审批流程。
3. 安全监控中的 Raw 证据访问依赖审批流程。
4. 系统管理中的审计日志记录全部审批行为。

## 10. 关键字段与接口引用

关键字段：

1. `approval_id`
2. `approval_status`
3. 关联对象类型
4. 关联对象 ID
5. `event_id`
6. `action_id`
7. `policy_id`
8. `package_id`
9. `deployment_id`
10. `trace_id`
11. `span_id`

关键接口：

1. `GET /approvals`
2. `GET /risk-events/{eventId}/approvals`
3. `GET /event-actions/{actionId}/approvals`
4. `POST /risk-events/{eventId}/accept-risk`
5. `POST /event-actions/{actionId}/rollback`
6. `POST /policies/{policyId}/publish`
7. `POST /deployments/{deploymentId}/rollback`
