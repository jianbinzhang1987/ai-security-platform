## 3. 产品定位收敛

基于当前原型，后续系统设计应统一为：

**一个面向大模型应用、Agent、网关与探针双侧的安全监测与处置平台。**

平台主线应收敛为：

1. 发现风险
2. 还原证据
3. 形成事件
4. 执行处置
5. 策略治理
6. 审计留痕
7. 运行保障

对应的核心对象模型建议统一为：

1. 应用 `app`
2. Agent / 工作流节点 `agent / node`
3. 会话 `session`
4. 调用链 `trace`
5. 证据单元 `span / observation`
6. 风险事件 `event`
7. 处置动作 `action`
8. 安全策略 `policy / package / rule`
9. 通知渠道 `channel`
10. 采集器与运行组件 `collector / gateway / service`

## 4. 完整系统功能设计清单

## 4.1 安全总览

### 4.1.1 页面目标

为安全运营、管理员和负责人提供平台安全态势首屏，支持从总览快速下钻到资产、溯源、事件、策略和采集健康页面。

### 4.1.2 功能清单

1. 风险态势总览卡片
   - 未处置高风险数
   - 今日新增风险数
   - 今日拦截/告警/降级/恢复数量
   - 采集异常应用数
   - 待处理事件数
2. 风险趋势分析
   - 按日/周/月展示风险趋势
   - 支持按风险类型、应用、环境筛选
3. 高风险对象排行
   - 高风险应用 TOP
   - 高风险工具 TOP
   - 高风险 Agent / 工作流 TOP
4. 今日待办
   - 待确认事件
   - 待审批处置
   - 下发失败任务
   - 采集异常告警
5. 覆盖与健康概览
   - 应用接入覆盖率
   - 工具声明覆盖率
   - 规则覆盖率
   - 会话审计覆盖率
   - 采集器健康概况
6. 下钻联动
   - 跳转风险事件
   - 跳转风险溯源工作台
   - 跳转接入应用
   - 跳转数据采集器配置

### 4.1.3 设计要求

1. 所有卡片与排行必须可下钻。
2. 首页不只展示统计值，还要能承接调查入口。
3. 排行必须分对象展示，不能再混排。

## 4.3 安全监控

#### 功能清单

1. Trace 列表查询
   - 时间范围
   - 接入应用
   - 风险等级
   - 风险类型
   - 事件状态
   - Agent / 节点
   - 工具 / MCP
   - `trace_id`
   - `span_id`
2. Trace 调查列表
   - Trace 基本信息
   - 风险等级
   - 应用
   - 风险摘要
   - Span 数量
   - 关联事件
3. 风险链路视图
   - 意图输入
   - 上下文检索
   - 模型推理
   - 工具调用
   - 输出结果
   - 处置状态
4. Span 证据工作区
   - 证据摘要
   - 格式化 JSON
   - 原始载荷
   - 规则解释
   - 原始证据引用
5. 证据元数据
   - `event_id`
   - `trace_id`
   - `span_id`
   - 风险阶段 `risk_stage`
   - 风险类型
   - 置信度
   - 证据来源字段 `source_field`

   - 关联资源
6. 调查动作
   - 确认风险

   - 创建 / 关联风险事件

### 4.3.2 设计要求

1. 工作台必须优先服务“证据阅读与判断”，不是性能链路看板。
2. 不同 Trace、不同 Span 切换时，左中右三个区域必须联动刷新。
3. 原始载荷展示必须考虑授权和脱敏。
