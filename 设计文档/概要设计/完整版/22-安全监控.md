# 安全监控模块概要设计

## 1. 文档目标

本文档定义平台“安全监控”模块的业务定位、页面范围、核心对象、功能设计和主流程。

当前安全监控模块在原型中以“风险溯源工作台”为核心承载页面，因此本轮设计以风险溯源工作台为主，不扩展隐藏页面。

---

## 2. 模块定位

### 2.1 业务定位

安全监控模块是平台的正式调查入口，负责对风险 Trace、Span 证据、工具调用、模型推理和上下文信息进行还原与分析。

### 2.2 核心职责

1. 查询风险 Trace。
2. 还原风险链路。
3. 展示 Span 级证据。
4. 输出人工调查结论。
5. 关联或创建风险事件。

### 2.3 模块边界

安全监控模块负责：

1. Trace / Span 调查。
2. 风险证据展示。
3. 调查结果记录。

安全监控模块不直接负责：

1. 正式事件闭环。
2. 策略规则配置。
3. 用户与权限管理。

---

## 3. 页面范围

当前纳入设计的正式页面：

1. 风险溯源工作台

建议保留“单页工作台 + 二级抽屉/弹窗”的模式，不再拆成多菜单页。

---

## 4. 核心对象

## 4.1 Trace

Trace 是一次完整运行链路的调查入口。

### 关键属性

1. `trace_id`
2. 所属应用
3. 所属会话
4. 风险等级
5. 风险类型
6. 开始时间
7. 结束时间
8. Span 数量
9. 关联事件

## 4.2 Span / Observation

Span 是最小证据锚点。

### 关键属性

1. `span_id`
2. `parent_span_id`
3. `trace_id`
4. 风险阶段
5. 风险类型
6. 证据来源字段
7. 原始载荷引用
8. 脱敏状态
9. 命中规则
10. 置信度
11. 证据位置偏移

### 证据字段规范

Span 证据建议拆分为结构化证据、原始引用和展示脱敏三层：

1. 结构化证据
   - `risk_stage`
   - `risk_type`
   - `subject_type`
   - `subject_id`
   - `resource_type`
   - `resource_id`
   - `source_field`
   - `evidence_offset`
   - `confidence`
2. 原始引用
   - `raw_ref`
   - `payload_hash`
   - `storage_type`
   - `retention_expire_at`
3. 展示脱敏
   - `mask_status`
   - `mask_rule_id`
   - `raw_access_required`
   - `raw_access_audit_id`

风险事件模块引用证据时，应优先引用 `trace_id + span_id + source_field + evidence_offset`，不得复制完整 Raw Payload 作为事件主档字段。

## 4.3 调查视图

调查视图用于沉淀查询条件和分析上下文。

### 关键属性

1. 视图名称
2. 查询条件
3. 关注字段
4. 默认证据页签
5. 创建人

---

## 5. 风险溯源工作台设计

## 5.1 页面目标

以 `trace_id` 为默认调查入口，帮助安全运营快速看懂风险发生过程、定位证据、形成判断并推动后续事件闭环。

## 5.2 页面结构

建议工作台采用三栏结构：

1. 左侧 Trace 调查列表
2. 中间风险链路区
3. 右侧证据工作区

### 布局目标

1. 左侧适合连续分诊和快速切换。
2. 中间适合阅读链路和定位节点。
3. 右侧优先承载证据与操作，是核心工作区。

## 5.3 查询与筛选设计

### 基础筛选

1. 时间范围
2. 接入应用
3. 风险等级
4. `trace_id / span_id`

### 高级筛选

1. 风险类型
2. 事件状态
3. Agent / 节点
4. 工具 / MCP
5. 会话 ID
6. 关联事件 ID

## 5.4 左侧 Trace 列表设计

每条 Trace 建议展示：

1. `trace_id`
2. 风险等级
3. 应用名称
4. 风险摘要
5. Span 数量
6. 发生时间
7. 关联事件状态

### 支持操作

1. 切换当前 Trace
2. 快速查看摘要
3. 跳转相关事件

## 5.5 中间风险链路设计

风险链路建议按照安全语义分段，而不是纯性能链路。

建议阶段：

1. 意图输入
2. 上下文检索
3. 模型推理
4. 工具调用
5. 输出结果
6. 处置状态

### 每个节点建议展示

1. 阶段名称
2. 节点标题
3. `span_id`
4. 关联资源或工具
5. 风险说明
6. 是否命中风险

## 5.6 右侧证据工作区设计

### 证据摘要区

展示以下内容：

1. 事件编号
2. 风险阶段
3. 风险等级
4. 置信度
5. 证据来源字段
6. 证据位置
7. 命中规则版本
8. 脱敏状态

### 证据页签

建议提供以下页签：

1. 证据摘要
2. 格式化 JSON
3. 原始载荷
4. 规则解释

### 证据元数据

1. 分析主体
2. 关联资源
3. `trace_id`
4. `span_id`
5. Raw 引用地址

### 证据操作

1. 确认风险
2. 标记误报
3. 创建 / 关联事件
4. 提出处置建议

### 证据操作输出

从证据工作区输出到事件或审批流程时，必须携带：

1. `trace_id`
2. `span_id`
3. `risk_stage`
4. `risk_type`
5. `source_field`
6. `evidence_offset`
7. 命中规则 ID / 版本
8. 风险摘要
9. 调查结论
10. 操作人

## 6. 关键交互设计

## 6.1 Trace 切换联动

切换 Trace 后，必须联动刷新：

1. 左侧当前选中状态
2. 中间风险链路
3. 右侧证据摘要
4. 页签内容

## 6.2 Span 切换联动

切换 Span 后，必须联动刷新：

1. 当前 Span 标识
2. 风险阶段
3. 证据字段
4. 规则解释
5. Raw 引用

## 6.3 页签切换联动

切换页签后，应保持：

1. 当前 Trace 不变
2. 当前 Span 不变
3. 只切换右侧展示内容

## 6.4 事件联动

从工作台发起事件时，必须自动带出：

1. `trace_id`
2. `span_id`
3. 风险类型
4. 风险摘要
5. 证据来源字段

### 事件联动规则

1. 同一 Trace 中多个 Span 命中同类风险时，允许合并创建一个事件。
2. 同一 Span 命中多个风险类型时，默认按风险类型拆分事件，但允许人工合并。
3. 已有关联事件的证据再次创建事件时，应优先提示“关联现有事件”。
4. 标记误报时，应同时记录误报原因，并可回流到规则优化样本池。
5. 创建事件成功后，工作台应展示事件编号和事件状态。

## 7. 核心流程设计

## 7.1 风险调查流程

```text
进入风险溯源工作台
→ 筛选目标 Trace
→ 选中 Trace
→ 查看风险链路
→ 选中关键 Span
→ 阅读证据和规则解释
→ 输出调查结论
```

## 7.2 创建事件流程

```text
调查发现真实风险
→ 点击关联 / 创建事件
→ 自动带入关键字段
→ 生成事件主档
→ 跳转风险事件模块继续闭环
```

## 7.3 误报处理流程

```text
调查发现误报
→ 标记误报
→ 记录误报原因
→ 可同步进入规则优化池
```

## 7.4 处置建议流程

```text
调查发现需要限制或阻断
→ 选择处置范围
→ 设置 TTL
→ 填写审批备注
→ 提交至事件或审批流程
```

### 处置建议字段

1. 建议动作类型
2. 建议作用范围
3. 建议目标对象
4. TTL
5. 影响说明
6. 推荐审批级别
7. 证据摘要
8. 关联 `trace_id / span_id`

处置建议不等同于正式处置动作，正式动作应由风险事件模块创建 `action` 后执行。

---

## 8. 与其他模块关系

### 8.1 与资产中心

1. 从应用详情跳入工作台时，应自动带入 `app_id`。
2. 工作台中的应用信息应能回跳应用详情。

### 8.2 与风险事件

1. 工作台是事件创建前的调查入口。
2. 事件模块消费工作台输出的证据与结论。

### 8.3 与会话审计

1. 对于多轮上下文风险，可从工作台跳转会话审计查看会话原文和网关动作。

### 8.4 与统一策略中心

1. 规则解释依赖策略中心提供命中规则和版本信息。
2. 调查结果反向驱动策略优化。

---

## 9. 数据与权限要求

## 9.1 最低数据要求

每条可调查 Trace 至少必须具备：

1. `trace_id`
2. 所属应用
3. 风险等级
4. 风险类型
5. 时间范围
6. 关联 Span 列表

每个可调查 Span 至少必须具备：

1. `span_id`
2. `trace_id`
3. 风险阶段
4. 证据来源字段
5. 风险摘要
6. 命中规则
7. 置信度

如果 Span 需要作为正式事件证据，还必须具备：

1. `source_field`
2. `evidence_offset`
3. `raw_ref`
4. `mask_status`
5. 命中规则版本
6. 风险主体对象
7. 关联资源对象

## 9.2 权限要求

1. 安全管理员可查看全部证据。
2. 安全运营默认可查看脱敏证据。
3. 应用负责人仅可查看所属应用的授权范围内容。
4. Raw 内容访问应支持单独授权和审计。

## 9.3 审计要求

以下动作必须审计：

1. 查看高敏证据
2. 创建事件
3. 标记误报
4. 提出处置建议
5. 导出证据

Raw 内容访问审计必须记录：

1. 访问人
2. 访问时间
3. 访问原因
4. `trace_id`
5. `span_id`
6. `raw_ref`
7. 脱敏状态
8. 导出标记
