# 通知联动流程设计

## 1. 文档目标

本文档定义平台风险事件、审批、策略下发、采集异常等场景下的通知联动流程，保证通知规则、通知渠道、发送记录和失败处理具备统一口径。

---

## 2. 通知触发场景

平台至少支持以下通知触发场景：

1. 高危风险事件创建。
2. 事件待确认超时。
3. 事件被指派或转派。
4. 接受风险审批发起、通过、驳回。
5. 高危处置动作审批发起、通过、驳回。
6. 策略发布、下发失败、回滚完成。
7. Collector 离线、队列积压、存储写入异常。
8. 通知渠道自身异常。

---

## 3. 主流程

```text
业务事件触发
→ 匹配通知规则
→ 选择通知渠道
→ 渲染通知内容
→ 发送通知
→ 记录 channel_delivery
→ 成功结束 / 失败重试 / 标记渠道异常
```

---

## 4. 关键对象

## 4.1 通知渠道 `notify_channel`

关键字段：

1. `channel_id`
2. 渠道名称
3. 渠道类型
4. 通知范围
5. 鉴权信息引用
6. `channel_status`
7. 最近测试结果

## 4.2 通知发送记录 `channel_delivery`

关键字段：

1. `delivery_id`
2. `channel_id`
3. 触发对象类型
4. 触发对象 ID
5. 发送状态
6. 错误码
7. 错误信息
8. 发送时间

---

## 5. 通知规则设计

通知规则建议包含：

1. 触发对象类型
2. 触发条件
3. 聚合窗口
4. 抑制窗口
5. 通知渠道
6. 通知模板
7. 升级通知规则
8. 是否自动创建事件

业务风险告警建议支持：

1. 高危 Prompt / 越狱事件聚合告警。
2. 工具越界调用频次超阈值告警。
3. 敏感数据输出持续发生告警。
4. 同一用户或应用短时间多次触发高危规则告警。
5. 高危事件超时未确认告警。
6. 高危审批超时告警。

---

## 6. 通知内容要求

通知内容应避免携带 Raw 证据原文。建议包含：

1. 事件或审批标题。
2. 风险等级。
3. 风险类型。
4. 关联应用。
5. `event_id` / `approval_id` / `deployment_id`。
6. 证据摘要。
7. 当前状态。
8. 处理入口链接。

高敏内容只展示摘要，详情通过平台权限控制查看。

---

## 7. 失败处理

通知失败后建议按以下规则处理：

1. 网络或限流失败：进入重试队列。
2. 鉴权失败：标记渠道 `abnormal`。
3. 部分渠道失败：保留失败记录，不影响其他渠道。
4. 连续失败达到阈值：通知平台管理员或切换备用渠道。
5. 重试仍失败：记录最终失败原因。

---

## 8. 权限与审计要求

1. 创建、编辑、启停通知渠道必须审计。
2. 测试通知渠道必须审计。
3. 通知发送记录应保留触发对象和发送结果。
4. 密钥、Webhook、SMTP 密码仅保存密钥引用，不返回明文。

---

## 9. 关键接口引用

1. `GET /notify-channels`
2. `POST /notify-channels`
3. `PUT /notify-channels/{channelId}`
4. `POST /notify-channels/{channelId}/status`
5. `POST /notify-channels/{channelId}/test`
6. `GET /notify-channels/{channelId}/deliveries`

---

## 10. 后续详细设计重点

1. 通知规则配置模型。
2. 通知模板字段。
3. 聚合窗口与抑制窗口。
4. 失败重试策略。
5. 多渠道升级通知策略。
