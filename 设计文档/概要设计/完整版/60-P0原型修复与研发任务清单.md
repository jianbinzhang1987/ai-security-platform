# P0 原型修复与研发任务清单

## 1. 文档目标

本文档用于把概要设计、接口设计、数据模型和字段字典转化为 P0 阶段可执行的原型修复任务与研发任务。

本文档重点回答：

1. 哪些页面必须修。
2. 每个页面修什么。
3. 修完如何验收。
4. 需要引用哪些字段、状态和接口。
5. 哪些任务属于 P0 阻塞、P0 重要和 P0 增强。

---

## 2. 任务分级

## 2.1 P0 阻塞

影响核心演示、核心闭环或导致页面不可用的问题。

必须在 P0 评审前完成。

## 2.2 P0 重要

不一定导致页面不可用，但会影响业务闭环完整性、专业性或下钻链路。

建议在 P0 评审前完成，至少给出可演示方案。

## 2.3 P0 增强

提升体验、补充完整度、减少后续返工的问题。

可在 P0 评审后紧接补齐。

---

## 3. 全局验收口径

P0 原型修复完成后，应满足以下全局要求：

1. 所有 P0 可见菜单页面可正常打开，无 JS 运行时错误。
2. 首页、资产、溯源、事件、策略、系统管理之间的关键下钻链路可走通。
3. 事件、动作、策略、下发、审批状态字段引用统一字段名。
4. 所有风险事件至少能回溯到 `trace_id` 和 `span_id`。
5. 所有处置动作展示 `action_id`、`action_status`、`rollback_status`、TTL 和审批信息。
6. 策略体系统一为 `rule → policy → package → binding → deployment → runtime_effect`。
7. Raw 证据只展示引用和授权入口，不在普通页面直接暴露完整 Raw。
8. 页面文案保持企业级、专业化表达。

## 4. P0 阻塞任务

## 4.1 修复风险事件详情页运行错误

### 涉及页面

1. `pages/events/event-detail.html`

### 问题

事件详情页存在已注释元素仍被 JS 调用的风险，可能导致详情页渲染失败。

### 修复要求

1. 检查详情页所有 `getElementById` 和 DOM 操作。
2. 移除对不存在元素的直接调用，或恢复对应元素。
3. 事件详情必须展示：
   - `event_id`
   - `event_status`
   - `trace_id`
   - `span_id`
   - 证据摘要
   - 处置记录
   - 审批记录
   - 状态变更记录

### 验收标准

1. 3 个以上不同事件详情均可正常打开。
2. 浏览器控制台无阻塞性 JS 错误。
3. 从事件详情可跳转风险溯源工作台，并携带 `trace_id` 和 `span_id`。

## 4.2 修复应用列表到应用详情的 app_id 断链

### 涉及页面

1. `pages/assets/app-list.html`
2. `pages/assets/app-detail.html`

### 问题

应用列表进入详情时必须携带 `app_id`，不能所有应用进入同一硬编码详情。

### 修复要求

1. `app-list.html` 的详情按钮携带当前行 `app_id`。
2. `app-detail.html` 根据 `app_id` 切换应用基础信息、风险统计、实例、策略覆盖等内容。
3. 统一字段：
   - `app_id`
   - `app_name`
   - `business_line`
   - `owner_id`
   - `access_status`
   - `health_status`

### 验收标准

1. 点击不同应用进入详情，页面展示内容不同。
2. URL 或页面状态中能看到当前 `app_id`。
3. 从应用详情可跳转该应用的风险事件列表。

## 4.3 恢复应用详情核心 Tab

### 涉及页面

3. 工具与资源
4. 风险事件
5. 接入配置
6. 接入指引

风险事件 Tab 至少展示：

1. `event_id`
2. 风险等级
3. 风险类型
4. `event_status`
5. `trace_id`
6. `span_id`
7. 负责人
8. 操作入口

### 验收标准

1. 所有 Tab 可见且可切换。
2. 风险事件 Tab 可跳转事件详情和风险溯源。
3. 接入配置区展示采样率、采集范围、脱敏规则、工具黑白名单。

## 4.4 修复风险溯源 Span 证据混淆

### 涉及页面

1. `pages/monitor/trace-list.html`
2. `pages/monitor/trace-board.html`
3. `index.html`

### 问题

风险溯源应使用完整调查工作台，Trace 和 Span 切换时证据不得 fallback 到错误 Span。

### 修复要求

1. 导航中的“风险溯源工作台”指向完整工作台页面。
2. 至少准备 3 条 Trace 示例数据。
3. 每条 Trace 至少包含 4 个 Span。
4. 每个风险 Span 都有独立证据数据。
5. 证据字段使用：
   - `trace_id`
   - `span_id`
   - `risk_stage`
   - `risk_type`
   - `source_field`
   - `evidence_offset`
   - `mask_status`
   - `raw_ref`

### 验收标准

1. 切换 Trace 后，链路和证据同步变化。
2. 切换 Span 后，证据摘要、JSON、规则解释同步变化。
3. 无证据的 Span 应展示空态，不得显示其他 Span 的数据。

## 4.5 修复安全总览覆盖卡片和下钻

### 涉及页面

1. `pages/assets/dashboard.html`

### 问题

安全总览缺少覆盖与健康入口，高风险排行和采集异常无法下钻。

### 修复要求

1. 恢复或补充覆盖与健康概览区。
2. 高风险排行拆分为：
   - 高风险应用
   - 高风险工具
   - 高风险 Agent / 节点
3. 所有卡片和排行项支持下钻。
4. 下钻目标：
   - 风险事件列表
   - 风险溯源工作台
   - 应用详情
   - 数据采集器配置
   - 策略中心

### 验收标准

1. 首页指标点击后能进入对应页面。
2. 下钻参数包含 `app_id`、`risk_type`、`event_status` 或时间范围。
3. 采集异常可进入 Collector 健康或异常应用列表。

## 5.3 策略中心统一规则、策略、策略包层级

### 涉及页面

1. `pages/policy/access-control.html`
2. `pages/policy/traffic-governance.html`
3. `pages/policy/prompt-attack.html`
4. `pages/policy/input-security.html`
5. `pages/policy/output-security.html`
6. `pages/policy/session-security.html`
7. `pages/policy/unified-protection.html`
8. `pages/policy/shared-rules.html`
9. `pages/policy/probe-policies.html`
10. `pages/policy/gateway-distribution.html`
11. `pages/policy/distribution-status.html`
12. `pages/policy/notify-channel.html`

### 修复要求

策略中心统一展示以下层级：

```text
rule → policy → package → binding → deployment → runtime_effect
```

关键页面能力：

1. 规则项支持启停、版本、风险类型、命中统计。
2. 规则项支持干跑验证和命中样本预览。
3. 策略支持测试、灰度、发布、回滚。
4. 策略包支持版本、绑定范围、下发状态。
5. 下发页支持实例级同步状态。
6. 通知渠道支持测试、启停、发送记录。

### 验收标准

1. 页面文案不再把检测规则、网关策略、探针策略割裂成三套概念。
2. 下发状态使用 `dispatch_status`。
3. 实例级生效使用 `runtime_effect` 口径。

## 5.4 告警规则从运维告警扩展为业务风险告警

### 涉及页面

1. `pages/policy/alert-rules.html`
2. `pages/policy/notify-channel.html`

### 修复要求

补充业务风险告警规则：

1. 高危 Prompt / 越狱事件聚合告警。
2. 工具越界调用频次超阈值告警。
3. 敏感数据输出持续发生告警。
4. 同一用户或应用短时间多次高危触发告警。
5. 事件超时未确认告警。
6. 高危审批超时告警。

### 验收标准

1. 告警规则可以配置聚合窗口、抑制窗口、通知渠道。
2. 支持是否自动创建事件。
3. 支持测试或历史样本回放入口。

## 10. P0 验收清单

P0 评审前建议逐项检查：

1. 首页能下钻到事件、溯源、应用、采集器、策略。
2. 应用详情能看到风险事件和策略覆盖。
3. 风险溯源能切换 Trace 和 Span，证据同步变化。
4. 风险事件能完成确认、误报、接受风险、处置、关闭。
5. 告警与响应记录能看到动作台账和回滚状态。
