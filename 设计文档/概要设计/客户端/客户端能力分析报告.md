# 客户端能力分析报告 (Client Capabilities Analysis Report)

## 1. 概述
本报告旨在分析"大模型安全监测平台"当前客户端（Go CLI 及 Python SDK）的实现细节，梳理其信息采集能力与功能边界。该分析将作为后续管理端设计（如策略下发、告警配置、资产管理等）的基础依据。

**代码来源**:
- Python SDK: `client/agentsec-python-sdk/agentsec/`
- Go CLI: `client/agentsec-cli/`

---

## 2. 采集信息分析 (What can be collected?)

客户端采集的信息涵盖了从底层基础设施到应用层 LLM 交互的全过程，主要分为以下六个维度：

### 2.1 基础设施与环境指纹 (Host Fingerprinting)
用于在管理端唯一识别并管理每一个接入的 Agent。来源：`utils/registration.py` + `internal/api/platform_client.go`
- **主机信息**: 主机名 (Hostname)、操作系统 (OS)、处理器架构 (Arch)。
- **操作系统版本**: OS Release 信息（Python SDK 额外采集 `platform.release()`）。
- **网络标识**: 局域网 IP 地址 (Local IP)，支持多 IP 列表 (`ips`)。
- **唯一标识**: 机器 ID (Machine ID，Python SDK 基于 UUID5 + 主机名，Go CLI 基于 SHA1 + 主机名)。
- **组件版本**: SDK 版本号 + Agent 版本号，用于版本兼容性控制。
- **实例标识**: Instance ID（`hostname-uuid8` 格式），用于区分同一主机上的多个 SDK 实例。

### 2.2 LLM 交互深度观测 (LLM Observability)
通过自动插桩 (Auto-instrumentation) 捕获模型调用的核心上下文。来源：`instrumentation/openai_v2.py` + `instrumentation/anthropic.py`
- **供应商与模型**: 识别厂商（OpenAI, Anthropic）及具体模型版本（如 gpt-4）。
- **内容捕获**:
    - **Prompt 内容**: 发送给模型的原始提示词（默认截断至 4096 字符）。
    - **Completion 内容**: 模型生成的响应文本（默认截断至 2048 字符）。
- **资源消耗**:
    - 提示词 Token 数 (Prompt Tokens)。
    - 生成内容 Token 数 (Completion Tokens)。
    - 总 Token 数 (Total Tokens)。
- **运行元数据**: 开始/结束时间戳、异常类型 (`error.type`) 及异常堆栈。
- **Span 类型标记**: `agentsec.span_type = "llm_call"`，区分 LLM 调用与其他类型。

### 2.3 工具调用监控 (Tool Call/MCP Monitoring)
针对 AI Agent 调用的外部工具进行监控（支持 MCP 协议）。来源：`instrumentation/mcp_client.py`
- **工具身份**: 被调用工具的名称 (`mcp.tool_name`)。
- **调用参数**: 工具执行时的输入参数（JSON 序列化后捕获，截断至 2048 字符）。
- **执行结果**: 工具返回的原始输出内容（截断至 2048 字符）。
- **策略判定结果**: 工具调用的策略动作 (`agentsec.tool.policy.action`) 和原因 (`agentsec.tool.policy.reason`)。
- **Span 类型标记**: `agentsec.span_type = "tool_call"`。

### 2.4 安全与风险元数据 (Security Metadata)
在数据采集阶段同步生成的风险标签。来源：`processors/security_tagger.py` + `processors/otel_processors.py`
- **风险等级**: 动态评估的风险分级（None, Low, Medium, High, Critical）。
- **异常标识**:
    - 注入检测标识 (`security.injection_detected`)。
    - 密钥泄露标识 (`security.secret_detected`)。
    - 限流标识 (`security.rate_limited`)。
    - 阻断原因 (`security.block_reason`)。
- **租户与应用标签**: `agentsec.tenant_id`、`agentsec.app_id`、`agentsec.session_id`。
- **采样决策**: `agentsec.sampled` 标记该 Span 是否被采样导出。

### 2.5 运行时状态与心跳数据 (Runtime State & Heartbeat)
客户端持续上报的运行状态信息。来源：`utils/runtime_state.py` + `heartbeat/service.py`
- **连接状态**: Collector 连接状态 (`collector_connected`)。
- **流量统计**: 已发送 Span 总数 (`spans_sent_total`)、已丢弃 Span 总数 (`spans_dropped_total`)、缓冲区中 Span 数 (`spans_buffered`)。
- **时间指标**: 最近 Span 发送时间、运行时长 (`uptime_seconds`)。
- **配置状态**: 当前配置版本号 (`config_version`)、配置拉取成功/失败状态。
- **Token 状态**: 认证 Token 有效性状态 (`missing/valid/expired/invalid`)。
- **心跳数据**: SDK 版本、实例 ID、近 1 分钟 Span 发送量 (`spans_sent_1m`)。

### 2.6 生命周期事件 (Lifecycle Events)
来源：`utils/platform_events.py`
- **上线事件** (`agent-connected`): 实例 ID、SDK 版本、SDK 语言、主机名、OS、架构、配置版本、连接时间。
- **下线事件** (`agent-disconnected`): 实例 ID、下线原因、运行时长、断开时间。

## 3. 核心功能能力 (What are the capabilities?)

客户端不仅仅是数据采集器，还具备主动安全管控和数据治理能力。

### 3.1 自动管控与防御 (Active Enforcement)
- **工具白名单 (Tool Whitelisting)**: 支持基于名称模式（Glob/Fnmatch）的工具调用准入控制。来源：`processors/tool_policy.py`
- **参数约束校验 (Parameter Constraints)**: 强制校验工具调用的参数键值对 (`allowed_keys`)、必填项 (`required_keys`) 以及字符串最大长度 (`max_string_length`)。
- **实时阻断 (Active Blocking)**: 能够在恶意工具调用或违规调用发生前，通过抛出 `MCPToolBlockedException` 直接中断执行。
- **阻断策略分级**: 支持三种动作模式——`alert`（仅告警）、`block`（阻断）、`shadow`（影子模式，标记但不阻断）。
- **会话级阻断 (Session Blocking)**: 通过 WebSocket 接收管理端下发的会话阻断指令 (`blocked_session_ids`)，支持 TTL 过期机制。来源：`blocking/watcher.py` + `processors/block_checker.py`
- **双向限流 (Rate Limiting)**:
    - 支持按工具调用频率限流 (`max_calls_per_minute`)。
    - 支持按总 Token 预算 (`token_budget_limit`) 进行全局配额管控。来源：`processors/rate_limiter.py`
- **高风险/严重等级自动响应**: `block_action_high`（默认 alert）和 `block_action_critical`（默认 block）可配置。来源：`config/models.py`
- **阻断回复模板**: `block_reply_template` 支持自定义拦截提示语。

### 3.2 数据脱敏与合规 (Data Governance)
- **PII 敏感数据脱敏**: 内置 Regex 引擎，支持对 Email、手机号、API Key 等进行掩码 (Masking)、哈希 (Hashing) 或移除 (Removal) 处理。来源：`processors/pii_redactor.py`
- **PII 规则可配置**: 每条规则支持 `name`、`pattern`、`action`、`scope`（作用域过滤）、`enabled` 开关。来源：`config/models.py`
- **内置 PII 规则**: Email 掩码、中国手机号掩码、OpenAI API Key 移除、Anthropic API Key 移除、AWS Access Key 哈希。
- **密钥扫描 (Secret Scanning)**: 实时扫描 Prompt、Completion 和工具输入中的敏感凭据（OpenAI Key、AWS Key）。来源：`processors/secret_scanner.py`
- **注入防御 (Injection Guard)**: 基于启发式规则检测常见 Prompt 注入攻击（"ignore previous instructions"、"system prompt"、"reveal hidden instructions"）。来源：`processors/injection_guard.py`
- **审计日志**: 支持 `audit_log_path` 配置本地审计日志文件路径。来源：`config/models.py`

### 3.3 智能化观测流水线 (Observability Pipeline)
- **智能采样 (Intelligent Sampling)**: 来源：`processors/sampling_processor.py` + `processors/otel_processors.py`
    - 默认按比例采样 (`sampling_rate`) 以节省流量。
    - **强制采样**: 对高风险事件（high/critical）或高成本调用（超过 `force_sample_token_threshold`，默认 4000 tokens）进行 100% 采集。
- **租户隔离与打标**: 自动为所有 Span 注入 Tenant ID、App ID 和 Instance ID。来源：`processors/security_tagger.py`
- **双协议导出**: 支持 OTLP/gRPC 和 OTLP/HTTP+Protobuf 两种导出协议，自动根据 Collector URL 协议选择。来源：`exporters/otlp_exporter.py`
- **断线缓冲与重试**: Span 导出失败时自动缓存在本地 `LocalBuffer`（容量可配，默认 10000），后台 `RetryExporter` 线程以指数退避（1s→16s，最多 5 次）持续重试。来源：`exporters/local_buffer.py` + `exporters/retry_exporter.py`
- **本地文件导出**: `LocalFileExporter` 支持将 Span JSONL 格式写入本地文件。来源：`exporters/local_file_exporter.py`

### 3.4 配置管理 (Configuration Management)
- **远程配置拉取**: 后台线程按 `config_poll_interval`（默认 30s）轮询管理端 `/internal/sdk-config`，支持 304 Not Modified 缓存协商。来源：`config/manager.py`
- **配置订阅机制**: 支持订阅者回调 (`subscribe`)，配置变更时实时通知各组件。
- **环境变量覆盖**: 所有核心配置项均可通过 `AGENTSEC_*` 环境变量覆盖。
- **配置版本追踪**: `config_version` + `config_schema_version` 双版本号，支持配置兼容性管理。
- **Fail-Open 模式**: 注册失败时 SDK 以 fail-open 模式运行，不阻断业务流量。

### 3.5 本地 API 服务 (Local API Server)
客户端在本地启动一个 HTTP API 服务（默认 `127.0.0.1:13133`），供 CLI 和本地工具查询状态。来源：`local_api/server.py`
- **健康检查** (`GET /agentsec/health`): 返回初始化状态、连接状态、Token 状态、流量统计、运行时长。来源：`local_api/health.py`
- **指标暴露** (`GET /agentsec/metrics`): Prometheus 格式指标（采样率、连接状态、缓冲数、发送数、丢弃数、Token 状态、配置拉取状态）。来源：`local_api/metrics.py`
- **Trace 查询** (`GET /agentsec/traces`): 本地内存中的 Trace 列表，支持按类型、风险等级、安全事件过滤和分页。来源：`local_api/traces.py` + `local_api/trace_store.py`
- **Trace 详情** (`GET /agentsec/traces/{trace_id}`): 单条 Trace 完整 Span 详情。
- **配置状态** (`GET /agentsec/config/status`): 当前配置版本、同步状态、阻断会话列表。来源：`local_api/config_status.py`
- **阻断状态** (`GET /agentsec/block/status`): 当前活跃阻断列表、WebSocket 连接状态。来源：`local_api/block_status.py`
- **认证保护**: 除 `/agentsec/health` 和 `/agentsec/metrics` 外，所有接口需 Bearer Token 认证。

### 3.6 Go CLI 命令集 (CLI Commands)
来源：`client/agentsec-cli/cmd/`
- **`register`**: 自动注册当前机器并缓存 Agent Token。
- **`verify`**: 模拟发送测试 Span 验证 Collector 连通性和 Platform 数据接收。
- **`diagnose`**: 诊断本地环境（Platform URL、Collector URL、Token 格式/过期、Collector TCP/TLS/认证可达性）。
- **`status`**: 查询本地 API 健康状态。
- **`traces list`**: 查询本地 Trace 列表，支持类型/风险等级/安全事件过滤。
- **`traces get`**: 查询单条 Trace 详情。
- **`block`**: 查看本地阻断状态（活跃阻断数、WebSocket 连接、最近消息时间）。
- **`config status`**: 查看配置同步状态。

### 3.7 心跳与实时指令通道 (Heartbeat & Command Channel)
- **心跳上报**: 按 `heartbeat_interval`（默认 30s）向管理端发送心跳，携带运行状态数据。来源：`heartbeat/service.py`
- **指令下发**: 心跳响应中可携带 `block_commands`，实现管理端→客户端的实时指令推送。
- **WebSocket 阻断通道**: 客户端通过 WebSocket (`/ws/block`) 接收管理端的实时阻断指令，支持自动重连（5s 退避）。来源：`blocking/watcher.py`
- **Token 失效处理**: 心跳返回 401 时自动触发 Token 失效和重新注册流程。

### 5.2 实现层面的缺失与待完善项

| 缺失项 | 严重度 | 说明 |
|---|---|---|
| **`blocked_keywords` 未被消费** | 高 | `AgentSecConfig.blocked_keywords` 已定义但无 Processor 消费，管理端若下发此配置将无效 |
| **`collect_http_calls` / `collect_db_queries` 未实现** | 中 | 配置项已预留但无对应插桩实现，管理端界面应标记为"规划中"或移除 |
| **`audit_log_path` 未被消费** | 中 | 配置项已定义但无代码写入审计日志文件，`LocalFileExporter` 存在但未接入流水线 |
| **Anthropic 异常捕获缺失** | 中 | `anthropic.py` 的 `_wrap_sync` 未包裹 try/except，异常时不会记录 `error.type`，与 OpenAI 插桩行为不一致 |
| **Injection Guard 规则不可远程配置** | 中 | `injection_guard.py` 的检测模式硬编码，管理端无法远程增删注入检测规则 |
| **Secret Scanner 规则不可远程配置** | 中 | `secret_scanner.py` 的密钥模式硬编码，与 PII 规则的可配置性不一致 |
| **Rate Limiter 无重置/时间窗口** | 中 | `rate_limiter.py` 的 Token 预算是全局累加无重置，长时间运行后将永久阻断 |
| **PII scope 字段未被消费** | 低 | `PIIRule.scope` 已定义但 `PIIRedactor` 未使用此字段做作用域过滤 |
| **Go CLI 与 Python SDK 指纹算法不一致** | 低 | Go 用 SHA1，Python 用 UUID5，跨语言注册可能导致同一机器生成不同 Machine ID |
| **Local API 无 TLS** | 低 | 本地 API 仅 HTTP，在多租户共享主机场景下存在 Token 窃听风险 |
| **心跳 block_commands 直接调用内部方法** | 低 | `heartbeat/service.py:63` 直接调用 `block_watcher._handle_message()`，绕过了封装 |

### 5.3 管理端设计补充建议

基于上述遗漏，在原有 4 条建议基础上补充：

5. **实时指令中心**: 管理端需同时支持心跳响应指令和 WebSocket 推送两种通道，前者为低频保底，后者为高频实时。
6. **实例级管理**: 管理端资产模型应区分"主机"和"实例"，同一主机可运行多个 SDK 实例（不同 app_id/tenant_id），需以 `instance_id` 为管理单元。
7. **配置项灰度下发**: 利用 `config_version` + `config_schema_version` 支持按租户/应用灰度下发配置，避免全量变更风险。
8. **客户端健康看板**: 聚合心跳数据（spans_sent_1m、buffered、collector_connected、token_status、uptime），构建客户端健康度视图，识别离线/异常 Agent。
9. **未实现配置项标记**: 管理端界面应将 `collect_http_calls`、`collect_db_queries`、`blocked_keywords`、`audit_log_path` 标记为"规划中/暂未生效"，避免用户误配。
10. **安全规则远程管理**: 注入检测规则和密钥扫描规则应纳入策略下发中心，与 PII 规则保持一致的可配置性。
