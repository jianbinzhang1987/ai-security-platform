# 原型与探针能力对比及修改建议

## 概述
基于对客户端（探针）底层代码能力分析与当前完整版原型中探针策略相关页面（`probe-policies.html`、`unified-protection.html`、`shared-rules.html`、`distribution-status.html`）的逐页对比，发现当前原型设计与实际底层 SDK 代码实现存在"能力错位"。原型中包含部分当前架构不支持的特性，同时遗漏了底层已实现的若干核心安全控制能力。本建议旨在指导后续原型及管理端的迭代设计，使其与底层能力完全对齐。

**对比范围**：
- 原型页面：探针运行时策略 (`probe-policies.html`)、策略包管理 (`unified-protection.html`)、高级规则项 (`shared-rules.html`)、绑定与下发 (`distribution-status.html`)
- 底层代码：Python SDK (`agentsec/`) + Go CLI (`agentsec-cli/`)
- 能力基线：`客户端能力分析报告.md`

**本次原型修改执行口径（已确认）**：
- **删除旧页**：`probe-policies.html` 为旧版探针运行时策略页面，本次直接删除，不做重定向，不再保留两套入口。
- **保留三页结构**：暂不拆分为四个专属页签，所有探针策略能力补齐到现有三页：`unified-protection.html`、`shared-rules.html`、`distribution-status.html`。
- **暂不做二期能力展示**：探针当前不支持的审批流、模型规则、外部服务规则、HTTP/DB 采集、RAG/Memory/Lifecycle 插桩等二期或网关侧能力，本次不在原型中展示禁用态，原则上从探针策略管理页面移除。
- **示例值先行设定**：缺少产品确认的字段默认值、示例数据和统计口径，先按本文第七节“本次原型默认值与示例数据口径”执行，后续评审再调整。

## 二、 探针已具备但原型中缺失的配置项（需补充到原型设计中）

当前探针的配置实体是 `AgentSecConfig`，管理端应能下发对应策略。原型中缺失了以下 7 大核心管控面板：

### 2.1 数据脱敏与合规策略 (PII & Data Governance)
探针内置了 `PIIRedactor`，支持在数据导出前进行脱敏。来源：`processors/pii_redactor.py` + `config/models.py`
- **原型需补充设计**：
  - **全局脱敏开关** (`pii_redaction_enabled`)。
  - **规则配置列表**：每条规则支持配置：
    - `name`: 规则名称
    - `pattern`: 匹配正则表达式
    - `action`: 处置动作（掩码 Mask、哈希 Hash、直接移除 Remove）
    - `scope`: 作用域（prompt / completion / tool_input / tool_output）——**注意：此字段已定义但 SDK 未消费，管理端应预留但标记为"增强中"**
    - `enabled`: 启停开关
  - **内置规则展示**：Email 掩码、中国手机号掩码、OpenAI API Key 移除、Anthropic API Key 移除、AWS Access Key 哈希——应展示但建议锁定不可删除
- **原型现有覆盖情况**：`shared-rules.html` 的"数据防泄露"类型面板有部分重叠（敏感类型、脱敏模板），但模型不匹配 SDK 的 `PIIRule` 结构，且缺少 Regex 自定义和 action 三选一

### 2.2 威胁检测策略 (Threat Detection)
探针支持本地实时的安全合规扫描。
- **原型需补充设计**：
  - **注入防御开关** (`injection_guard_enabled`)：开启/关闭对常见 Prompt 注入攻击的侦测拦截。
  - **注入检测规则管理**：当前 SDK 硬编码了 3 条注入检测规则（`injection_guard.py`），**建议 SDK 升级为可配置后，管理端提供规则增删界面**，与 PII 规则保持一致的可配置性。
  - **密钥扫描开关** (`secret_scan_enabled`)：开启/关闭对 Prompt、Completion 中敏感凭据的扫描。
  - **密钥扫描规则管理**：当前 SDK 硬编码了密钥检测规则（`secret_scanner.py`），**同上建议升级为可配置**。
- **原型现有覆盖情况**：`shared-rules.html` 的"内容安全"类型面板有"风险类别→注入"选项，但仅为标签选择，非规则管理

### 2.3 工具调用白名单与参数约束策略 (Tool Constraints)
探针目前不依赖复杂的条件表达式拦截工具，而是基于"白名单+强约束"。来源：`processors/tool_policy.py`
- **原型需补充设计**：
  - **工具白名单录入**：配置允许运行的工具名称（支持通配符 `*`）。不在白名单内的工具触发 `tool_unknown_action`。
  - **参数强校验机制**：针对允许的工具，细化配置其安全约束：
    - `allowed_keys`: 允许传入的参数名列表。
    - `required_keys`: 必填参数校验。
    - `max_string_length`: 防止参数超长造成的拒绝服务或缓冲区注入。
  - **未知工具默认动作** (`tool_unknown_action`)：alert / block / shadow 三选一。
- **原型现有覆盖情况**：`shared-rules.html` 的"工具管控"类型面板有"工具范围"和"调用频率上限"，但缺少参数约束配置，且"工具范围"是逗号分隔列表而非 Glob 模式

### 2.4 限流与全局配额策略 (Rate Limit & Token Budget)
探针具备基于调用量和计费单位的双向控制能力。来源：`processors/rate_limiter.py` + `processors/tool_policy.py`
- **原型需补充设计**：
  - **工具频控**：为单一工具配置 `max_calls_per_minute`。
  - **全局大模型配额**：配置该 Agent 实例的大模型 Token 消耗总上限 (`token_budget_limit`)，超额后探针将在本地阻断后续请求。
- **⚠️ 已知缺陷**：`rate_limiter.py` 的 Token 预算是全局累加无重置机制，长时间运行后将永久阻断。管理端应在界面上提示此限制，或推动 SDK 增加时间窗口重置逻辑。
- **原型现有覆盖情况**：`shared-rules.html` 的"工具管控"面板有"调用频率上限"，但缺少 Token 预算配置

### 2.5 全局动作模式与响应配置 (Global Actions & Responses)
探针支持更精细的处置模式，不只有"阻断"这一种。来源：`config/models.py`
- **原型需补充设计**：
  - **动作模式选择**：探针支持三种模式，应在界面中供用户选择：
    - `Alert`: 仅打标签并告警上报，不影响业务流。
    - `Block`: 真实阻断，抛出异常阻断业务流。
    - `Shadow`: 影子模式，标记但不阻断，常用于规则上线前的灰度观察。
  - **基于风险等级的默认动作**：分别设置高风险 (`block_action_high`) 和严重风险 (`block_action_critical`) 触发时的默认动作。
  - **自定义拦截话术**：补充配置项 `block_reply_template`，阻断时用于向前端返回友好的阻断提示语。
- **原型现有覆盖情况**：`unified-protection.html` Step2 的"阻断策略"有"高风险阻断/高风险+中风险/仅告警不阻断"选项，部分覆盖但未区分 high/critical，且无 Shadow 模式和拦截话术

### 2.6 会话级实时阻断策略 (Session Blocking)
探针支持基于 session_id 的实时阻断，这是与工具白名单阻断完全不同的维度。来源：`blocking/watcher.py` + `processors/block_checker.py`
- **原型需补充设计**：
  - **阻断会话列表** (`blocked_session_ids`)：管理端可下发需要阻断的会话 ID 列表。
  - **实时阻断指令推送**：管理端通过 WebSocket (`/ws/block`) 实时推送阻断指令，支持 TTL 过期。
  - **阻断关键词列表** (`blocked_keywords`)：**⚠️ 此配置项已定义但 SDK 未消费**，管理端应预留但标记为"规划中"。
  - **阻断状态查看**：当前活跃阻断数、WebSocket 连接状态、最近消息时间。
- **原型现有覆盖情况**：`probe-policies.html` 有"探针死循环熔断触发 34 次"统计，但无会话级阻断管理界面

### 2.7 遥测与采集控制策略 (Telemetry & Collection Control)
探针具备精细的遥测采集控制能力。来源：`processors/sampling_processor.py` + `exporters/otlp_exporter.py`
- **原型需补充设计**：
  - **采样率配置** (`sampling_rate`)：0.0~1.0 浮点数。
  - **强制采样阈值** (`force_sample_token_threshold`)：超过此 Token 数的调用 100% 采集，默认 4000。
  - **采集开关**：`collect_llm_calls`、`collect_tool_calls`（已实现），`collect_http_calls`、`collect_db_queries`（**⚠️ 未实现，标记为规划中**）。
  - **导出协议选择** (`otlp_protocol`)：gRPC / HTTP+Protobuf 二选一。
  - **缓冲区容量** (`buffer_capacity`)：断线缓冲上限，默认 10000。
  - **内容截断长度**：`prompt_max_length`（默认 4096）、`response_max_length`（默认 2048）。
  - **本地 Trace 存储上限** (`local_trace_max_size`)：默认 1000。
- **原型现有覆盖情况**：`shared-rules.html` 的"采集控制"类型面板有采样率和时间窗口，但缺少强制采样阈值、导出协议、截断长度等关键配置

## 四、 原型交互架构重组建议

为确保管理端操作逻辑与底层架构（OpenTelemetry Processors 体系）一致，降低用户理解成本，长期建议将"探针运行时策略"页面由目前的单列表形态拆分（或重组）为以下四个专属配置页签：

1. **脱敏与合规策略** (对应探针 `SensitiveFieldSpanProcessor` + `PIIRedactor`)
2. **安全基线与审计策略** (对应探针 `SecurityTagSpanProcessor` + `InjectionGuard` & `SecretScanner` & Audit)
3. **工具管控与限制策略** (对应探针 `ToolPolicyEnforcer` + `BlockChecker` & `RateLimiter`)
4. **遥测熔断与配额管理** (对应探针 `SamplingDecisionSpanProcessor` + `RateLimitSpanProcessor` & Token Budget 熔断 & 全局动作模式)

按此逻辑重构原型，将能实现管理端 UI 与底层代码能力的 100% 契合。

**本次执行口径**：暂不实施四页签重组，仍在现有三页内补齐字段与交互：
- `unified-protection.html`：作为策略包入口，补充模板、动作模式、关键参数摘要和实例灰度选择。
- `shared-rules.html`：作为规则项编辑入口，补充 PII、注入防御、密钥扫描、工具白名单、参数约束、Token 预算和遥测采集控制字段。
- `distribution-status.html`：作为绑定、下发和运行回执入口，补充实例级状态、版本差异、WebSocket 阻断通道和心跳指标。

## 五、 原型与 SDK 术语映射表

为降低管理端开发时的理解成本，以下为原型术语 → SDK 实际概念的映射：

| 原型术语 | SDK 实际概念 | 对齐建议 |
|---|---|---|
| 挂载点 (Hook Point) | OpenTelemetry SpanProcessor | 保留"挂载点"面向用户，但内部映射到 SpanProcessor |
| 探针处理节点 | SpanProcessor 类名 | 对齐：pii-redactor / security-tagger / sampler / rate-limiter / trace-recorder |
| 显式规则 | Regex 正则匹配 | 改名"正则规则" |
| 阈值规则 | 数值比较 + 时间窗口 | 保留 |
| 模型规则 | 无对应实现 | 标为二期规划 |
| 外部服务规则 | 无对应实现 | 标为二期规划 |
| 流程规则 (审批流) | 无对应实现 | 移除 |
| 中止并转人工审批 | 无对应实现 | 移除 |
| 修改传入的参数变量 | 无对应实现 | 移除 |
| 灰度比例 | 无对应实现 | 改为"选择灰度实例" |
| 工具范围 (逗号分隔) | `ToolWhitelistEntry.name_pattern` (Glob) | 改为 Glob 模式输入 |
| 脱敏模板 (局部掩码/哈希化/固定替换) | `PIIRule.action` (mask/hash/remove) | 对齐为 mask/hash/remove 三选一 |
| 阻断策略 (高风险阻断/高风险+中风险/仅告警) | `block_action_high` + `block_action_critical` | 拆分为 high 和 critical 两个独立选择 |
| 审批策略 | 无对应实现 | 移除 |
| Fallback 策略 (告警/放行/阻断) | `tool_unknown_action` (alert/block/shadow) | 对齐为 alert/block/shadow，增加 shadow |
