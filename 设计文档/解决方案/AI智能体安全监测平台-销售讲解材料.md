# AI 智能体安全监测平台 · 销售讲解材料

> **适用对象**：售前工程师、销售代表、客户技术决策者
> **目标**：在 10-15 分钟内，向客户清晰传递平台定位、核心能力、产品功能与差异化优势
> **基于**：原型图-智能版设计文档 + AI 产品博览会讲解稿

---

## 一、一句话定位（开场 30 秒）

**"别人管大模型，我们管智能体。"**

当前市面上的 AI 安全产品几乎只聚焦大模型输入输出安全。但企业真正部署上线的是**智能体（Agent）**——它能调用工具、读写数据库、发送 HTTP 请求、跨多轮对话自主编排任务。攻击面从一条线变成了一张网，传统方案根本管不住。

**我们专注 AI 智能体运行安全，覆盖从 Prompt 到工具到数据到行为的全链路风险识别与闭环处置。**

---

## 二、平台核心能力概览（1 分钟）

平台采用**"网络侧 + 端侧"双层协同架构**，提供**"静态扫描 + 动态监控"全生命周期防护**：

```
┌─────────────────────────────────────────────────────────────┐
│                      AI 智能体安全监测平台                    │
├─────────────────────────────────────────────────────────────┤
│  网络侧：AI 安全网关              │  端侧：SDK 安全探针       │
│  · 部署在流量入口，无侵入         │  · 嵌入 Agent 进程内部    │
│  · 管"请求进出边界"               │  · 管"运行时行为"         │
│  · 毫秒级拦截                     │  · 秒级深度监测           │
├─────────────────────────────────────────────────────────────┤
│              统一策略中心（一次配置，双线生效）               │
├─────────────────────────────────────────────────────────────┤
│  资产中心 → 安全扫描 → 安全监控 → 风险处置 → 报告中心        │
│  （摸清家底）  （上线前安检） （运行时盯防）（闭环解决）（输出汇报）│
└─────────────────────────────────────────────────────────────┘
```

**核心闭环**：AI 检测 → AI 研判 → 人工反馈 → 样本回流 → 模型优化，能力持续进化。

## 三、产品功能详解（5-8 分钟）

### 3.1 资产中心——先摸清家底，再谈安全

安全的前提是知道有哪些资产。资产中心帮企业统一管理：

| 功能 | 价值 |
|------|------|
| **接入应用管理** | 把企业内部所有接入 AI 能力的应用全部登记入库，明确每款应用归谁负责、运行状态是否正常、绑定了哪些安全策略 |
| **智能体管理** | 对企业里使用的各种 AI 智能体（对话助手、检索增强型、流程编排型等）分类纳管，做到心中有数 |
| **工具暴露面管理** | 自动梳理每个智能体调用了哪些工具，识别未声明工具和权限范围过宽的风险 |
| **资产拓扑视图** | 一张可视化大图，看清"应用 → 智能体 → 工具"之间的调用关系，哪里有风险一目了然 |

**销售话术**：
> "很多客户上线 AI 应用后，连自己有多少个 Agent、调了多少个工具都说不清楚。资产中心就是帮您把 AI 家底摸清楚，安全治理才有抓手。"

---

### 3.2 安全扫描——上线前的"安检"

智能体上线前，平台会做一次全面的"安全检查"，就像飞机起飞前必须过安检一样。

| 安检项目 | 检查对象 | 查什么 |
|----------|----------|--------|
| **Prompt 检查** | 智能体的指令模板 | 指令里是否夹带恶意内容、是否暴露了不该说的信息 |
| **Skill 检查** | 智能体配置的技能与权限 | 技能绑定的工具权限是否合理、数据流向是否安全 |
| **MCP 工具检查** | 第三方工具的声明与配置 | 工具声明是否完整、参数配置是否安全、是否存在越权风险 |

检查完成后，平台输出检查报告，告诉管理员哪里有问题、该怎么修。**只有检查通过，才能允许上线。**

**销售话术**：
> "安全不能只靠运行时堵。很多风险是配置阶段就埋下的——比如 Prompt 里写了不该写的系统指令、工具权限配得过宽。上线前扫一遍，把隐患消灭在摇篮里。"

---

### 3.3 安全监控——运行时的"安全摄像头"

智能体上线运行后，平台开启 7×24 实时监控，发现问题立刻告警。

#### 核心监控能力

| 监控能力 | 通俗理解 | 销售亮点 |
|----------|----------|----------|
| **风险溯源工作台** | 一旦发生安全事件，平台能像看监控回放一样，完整还原整个攻击过程 | "从用户说了什么 → AI 怎么理解 → 调用了哪些工具 → 做了什么操作 → 最终输出了什么，全链路可追溯" |
| **会话风险追踪** | 把一段多轮对话当作整体来看，画出风险变化曲线，标出第几轮是"危险转折点" | "专门对付多轮诱导攻击——单轮看正常，合起来就是攻击，传统方案根本发现不了" |
| **SOC 分析驾驶舱** | 企业安全总览大屏，一眼看到：今天有多少风险、哪个智能体最危险、高风险事件集中在哪些场景 | "给安全负责人一张全局视图，不用翻日志就能掌握整体态势" |
| **意图分片逃逸检测** | 专门识破一种高级攻击手法：坏人把恶意目的拆成好几句话，单句话都正常，合起来却是在偷数据 | **独有能力**，"这是高级攻击手法，市面上几乎只有我们能检测" |
| **行为异常检测** | 记录每个智能体的正常行为规律，一旦发现"今天突然变了"立即告警 | "不只是看内容，还要看行为——调用次数暴涨、用了不该用的工具，马上告警" |
| **人员风险画像** | 给每个用户打安全分，跨应用、跨会话积累风险记录，揪出可疑人员 | "从'事件'视角升级到'人'视角，发现内部威胁和高级持续攻击" |
| **风险关联分析** | 跨应用风险传播图、工具传播链、攻击链路可视化 | "看清攻击是怎么在企业内部扩散的，一处发现、全网排查" |

#### AI 增强检测（核心卖点）

平台不是简单的规则匹配，而是**"规则引擎 + AI 语义分析"双引擎驱动**：

- **规则检出**：传统关键词、正则、阈值匹配，快速、确定性强
- **AI 检出**：大模型语义理解，能识别变形攻击、上下文关联风险、新型攻击模式
- **联合检出**：规则 + AI 同时命中，**大幅降低误报、提升检出率**
- **降级保护**：AI 超时/错误/熔断时，自动降级为纯规则检测，**绝不漏检**

**销售话术**：
> "传统规则引擎只能抓已知攻击，遇到变形、绕过就失效。纯 AI 检测又担心误报和稳定性。我们是规则 + AI 联合检测——规则抓确定性的，AI 抓语义层面的，两者互补。AI 出问题了还能自动降级到规则，**业务不中断、安全不降级**。*"

---

### 3.4 风险事件闭环处置——发现即闭环

发现风险只是第一步，关键是把问题解决掉。平台提供**完整的事件处置流程**：

```
风险发现 → AI 检测与研判 → 人工确认/修正/拒绝 → 自动/人工处置 → 样本回流 → 模型优化
     ↑_________________________________________________________________________________↓
```

| 能力 | 说明 |
|------|------|
| **AI 检测可解释** | 不是给出一个结论，而是告诉您：命中了哪段文本、为什么判定为风险、有没有可能是误报、置信度多少 |
| **AI 研判摘要** | 自动分析攻击手法、影响面评估、处置优先级建议，帮安全运营人员快速决策 |
| **人工反馈闭环** | 安全运营人员可以"确认、修正、拒绝"AI 研判结果，反馈自动进入样本库，持续优化模型 |
| **自动响应规则** | 支持分级自动处置：L1 通知 → L2 观察标记 → L3 软限制（需审批） → L4 强控制（必须人工审批+MFA） |
| **急停控制** | 全局急停、单规则急停、单租户急停，**任何时候都能一键刹车** |
| **处置动作记录** | 谁在什么时间做了什么处置，全部留痕，满足合规审计要求 |

**销售话术**：
> "很多安全产品只管'发现'，不管'解决'。我们是从发现到处置的完整闭环——AI 先帮您分析，您确认后自动执行处置动作，处置结果还能反哺模型优化。**越用越准。**"

### 3.5 统一策略中心——策略配一次，全网生效

企业的安全策略在这里统一编排、统一下发，不需要跑到每个应用、每个智能体上单独配置。

| 策略类型 | 具体内容 |
|----------|----------|
| **网关侧策略** | 访问控制（API Key / JWT 认证）、内容安全（输入/输出双向检测）、流量治理（限流、路由、超时降级）、会话审计 |
| **探针侧策略** | 场景化策略包（内置高危工具审批、外联访问约束、数据脱敏等模板）、细粒度规则（工具调用权限、参数约束、行为基线） |
| **自动响应规则** | 触发条件、动作分级、白名单、熔断阈值、TTL 自动恢复、灰度发布 |
| **通知渠道** | 邮件、短信、Webhook 等多种方式推送给安全管理员 |

**销售话术**：
> "没有统一策略中心，安全策略就是各管各的，一个应用配一遍，十个应用配十遍，还容易配错、漏配。我们的策略中心一次配置，网关和探针两侧同时生效，**统一管理、统一审计、统一版本控制。**"

## 四、产品优势总结（2 分钟）

### 4.1 与竞品的差异化对比

| 对比维度 | 传统大模型安全产品 | 传统应用安全产品 | **我们的平台** |
|----------|-------------------|-----------------|---------------|
| **防护对象** | 只管网模型输入输出 | 只管网应用流量 | **智能体全链路**：Prompt → LLM → Tool → 数据库 → 外部 API |
| **防护层次** | 单层（内容审核） | 单层（WAF/API 网关） | **双层协同**：网关管边界 + 探针管运行时 |
| **检测手段** | 规则匹配或纯 AI | 签名/规则/行为基线 | **规则 + AI 联合检测**，可解释、可降级 |
| **生命周期** | 运行时 | 运行时 | **静态扫描 + 动态监控**，上线前 + 运行中全闭环 |
| **处置能力** | 告警或阻断 | 阻断/限流 | **分级自动响应 + 人工审批 + 急停控制** |
| **持续优化** | 人工更新规则 | 人工更新规则 | **AI 自进化**：样本回流 → 模型评测 → 规则优化 |
| **可见范围** | 请求/响应文本 | 网络流量 | **工具调用细节、进程行为、文件操作、命令执行** |

### 4.2 五大核心优势

**优势一：唯一专注"智能体安全"的平台**

- 不是大模型内容审核，不是传统 WAF/API 网关
- 专门解决智能体特有的风险：工具越界、意图偏移、多轮诱导、行为异常
- **竞品盲区 = 我们的核心战场**

**优势二：网络侧 + 端侧双层协同，无侵入 + 深可见**

- **网关**：部署在流量入口，**零代码改造**，流量指向即生效
- **探针**：嵌入 Agent 进程，**看见网关看不见的运行时行为**
- 两侧联动：网关发现异常 → 通知探针拦截；探针发现异常 → 更新网关策略
- **一次配置，双线生效**

**优势三：规则 + AI 联合检测，准确与稳定兼得**

- 规则引擎抓确定性风险（快、稳、可解释）
- AI 语义分析抓变形和新型攻击（聪明、灵活、覆盖面广）
- 联合检出**降低误报、提升检出率**
- AI 故障时**自动降级**，业务不中断

**优势四：从发现到处置的完整闭环，越用越准**

- 不是只发现问题，而是**发现问题 → 分析研判 → 处置解决 → 反哺优化**
- AI 研判 + 人工反馈 → 样本回流 → 模型评测 → 规则优化
- **能力持续进化，而不是一成不变**

**优势五：静态扫描 + 动态监控，全生命周期守护**

- **上线前**：Prompt / Skill / MCP 配置检查，排除配置风险
- **运行时**：7×24 实时监控，全链路风险识别与处置
- 两道关卡，**安全前置 + 持续守护**

## 五、典型客户场景（1 分钟）

### 场景一：金融企业智能客服安全

**痛点**：智能客服能查余额、能转账、能发送短信，一旦被诱导调用转账接口，损失巨大。

**我们的方案**：
- 网关层：拦截包含"绕过安全验证""忽略指令"等注入攻击的 Prompt
- 探针层：监控客服 Agent 的工具调用，发现未声明的转账接口调用立即告警
- 策略中心：统一配置转账类工具的审批规则，超过一定金额必须人工确认

### 场景二：研发代码审查 Agent 数据外泄

**痛点**：代码审查 Agent 能访问内部仓库，攻击者通过多轮对话诱导其外传代码片段。

**我们的方案**：
- 意图分片逃逸检测：识别多轮对话中逐步偏离原始意图的攻击模式
- PII 脱敏：探针端识别并脱敏响应中的敏感信息，原始数据不离开客户环境
- 行为基线：建立正常审查行为基线，发现"今天突然开始大量外传数据"立即告警

### 场景三：企业内部知识库问答安全

**痛点**：员工用 AI 查询内部文档，但文档有分级（公开/内部/机密），担心 AI 把机密信息泄露给不该看的人。

**我们的方案**：
- 数据分级分类：文档分 L0-L3 级别，驱动安全策略精细化
- RAG Prompt 安全沙盒：预览知识被引用时的风险等级
- 网关层：根据用户身份和数据级别，动态控制 AI 响应内容的脱敏粒度

## 附录：客户常见问题应答（FAQ）

### Q1：你们和传统 WAF/API 网关有什么区别？

**答**：传统 WAF 管的是通用 Web 攻击（SQL 注入、XSS），API 网关管的是接口认证和限流。它们都不理解 AI 语义，也看不见 Agent 内部的行为。我们专门解决 AI 智能体特有的风险——提示词注入、工具越界、意图偏移、行为异常，这是传统安全产品根本看不到的攻击面。

### Q2：部署需要改造现有系统吗？

**答**：网关侧**零代码改造**，只需要把 AI 流量指向网关即可。探针侧需要在 Agent 进程中嵌入轻量 SDK（Python，一行代码初始化），对现有业务逻辑无侵入。

### Q3：AI 检测会不会很慢？会不会影响业务？

**答**：AI 检测是**旁路异步执行**的，不会阻塞主请求链路。同时平台有完善的降级机制：AI 超时/错误/熔断时，自动降级为纯规则检测，**业务不中断、安全不降级**。

### Q4：误报率高吗？

**答**：我们采用**规则 + AI 联合检出**机制，只有当规则或 AI 一方命中时才会进入研判流程，两者联合命中时置信度最高。同时 AI 研判结果会给出置信等级，低置信事件会明确标记"需人工复核"。平台还支持人工反馈闭环，误报样本会回流优化，**越用越准**。

### Q5：数据安全吗？会不会把我们的数据传给第三方？

**答**：平台支持私有化部署。探针侧的 PII 脱敏在本地完成，敏感数据不离开客户环境。模型调用支持接入客户自研模型或私有化部署的大模型，数据不出域。

### Q6：能和我们现有的安全体系对接吗？

**答**：支持。平台提供标准 Webhook 和 API 接口，可对接企业现有的 SIEM、SOAR、工单系统、自研审核服务等安全基础设施。
