## 一、背景与挑战

### 1.1 智能体安全：被忽视的新战场

当前企业正快速从"使用大模型"向"部署 AI 智能体（Agent）"演进。与传统大模型仅完成文本生成不同，智能体具备调用工具、读写数据库、发送外部请求、跨多轮对话自主编排任务等能力。这一演进使得 AI 系统的攻击面从单一的"输入-输出"链路，扩展为覆盖 Prompt、LLM、工具调用、数据访问、外部 API 及响应输出的全链路网络。

现有安全产品主要存在以下局限：

- **大模型安全产品**：仅聚焦输入输出内容审核，无法理解智能体内部的行为逻辑与工具调用链；
- **传统应用安全产品**（如 WAF、API 网关）：基于签名和规则检测通用 Web 攻击，不具备 AI 语义理解能力，也无法感知 Agent 进程内部的运行时行为。

智能体特有攻击形态——如工具越界调用、意图分片逃逸、多轮诱导攻击、行为基线偏离——在传统安全方案的盲区中持续存在。

### 1.2 核心挑战

| 挑战维度 | 具体表现 |
|----------|----------|
| **攻击面扩展** | 从单条文本链路扩展为多链路交叉（Prompt→LLM→Tool→数据库→外部API→响应），任一环节都可能成为突破口 |
| **检测手段滞后** | 基于关键词和正则的规则引擎无法识别语义变形、上下文关联、新型攻击模式 |
| **可见性缺失** | 网关层看不到 Agent 内部的工具调用细节和进程行为；探针层看不到流量层面的请求响应全貌 |
| **策略管理分散** | 安全策略在各应用、各 Agent 上分别配置，缺乏统一编排、版本控制和审计追溯 |
| **处置能力不足** | 多数方案止步于"发现风险"，缺乏从研判到处置再到反馈优化的完整闭环 |
| **合规与审计压力** | 企业需要完整的安全事件证据链、操作审计记录和定期安全报告 |

## 二、平台概述

### 2.1 定位

**AI 智能体安全监测平台**专注于 AI 智能体运行安全，覆盖从 Prompt 到工具到数据到行为的全链路风险识别、分析研判与闭环处置。

平台采用**"网络侧 + 端侧"双层协同架构**，结合**"规则引擎 + AI 语义分析"双引擎检测机制**，实现静态扫描与动态监控的全生命周期安全防护。

### 2.2 架构总览

```
┌─────────────────────────────────────────────────────────────────────┐
│                     AI 智能体安全监测平台                             │
├─────────────────────────────────────────────────────────────────────┤
│  网络侧：AI 安全网关                  │  端侧：SDK 安全探针          │
│  · 部署于流量入口，无侵入             │  · 嵌入 Agent 进程内部       │
│  · 负责请求/响应边界防护               │  · 负责运行时行为深度监测     │
│  · 毫秒级拦截响应                     │  · 秒级采样与判定             │
├─────────────────────────────────────────────────────────────────────┤
│                    统一策略中心（统一下发、双线生效）                  │
├─────────────────────────────────────────────────────────────────────┤
│  资产中心 → 安全扫描 → 安全监控 → 风险处置 → 报告中心               │
│  （摸清家底）  （上线前安检）  （运行时盯防） （闭环解决） （输出汇报）│
├─────────────────────────────────────────────────────────────────────┤
│  知识库与评测治理 │ AI 模型与服务治理 │ 操作审计与合规               │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 双层协同机制

**网络侧（AI 安全网关）**与**端侧（SDK 探针）**并非独立运行，而是通过统一策略中心实现联动：

- **网关 → 探针**：网关识别异常请求后，通过阻断通道向探针下发实时拦截指令；
- **探针 → 网关**：探针上报工具调用异常后，管理端自动更新网关访问控制策略，后续同类请求在网关层直接拒绝；
- **统一策略中心**：同时编排网关策略与探针策略，一次配置，双线生效，避免漏配、错配。

### 2.4 检测融合机制

平台检测引擎采用三层融合策略：

| 检测模式 | 机制 | 特点 |
|----------|------|------|
| **规则检出** | 基于关键词、正则表达式、阈值匹配 | 速度快、确定性高、可解释性强 |
| **AI 检出** | 基于大模型语义理解 | 可识别变形攻击、上下文关联风险、新型攻击模式 |
| **联合检出** | 规则与 AI 同时命中 | 误报率更低、检出率更高、置信度更强 |

同时，平台内置完善的降级机制：当 AI 服务出现超时、错误或熔断时，系统自动降级为纯规则检测，确保业务不中断、安全不降级。

## 三、核心能力体系

### 3.1 资产中心

安全治理的前提是全面的资产可见性。资产中心帮助企业统一管理 AI 相关资产：

- **接入应用管理**：登记企业所有接入 AI 能力的应用，明确归属、运行状态及绑定的安全策略；
- **智能体管理**：对企业内各类 AI 智能体（对话助手、RAG 型、流程编排型等）进行分类纳管；
- **工具暴露面管理**：自动梳理每个智能体声明及实际调用的工具，识别未声明调用和权限过宽风险；
- **资产拓扑视图**：可视化展示"应用 → 智能体 → 工具"的调用关系，直观呈现风险分布。

### 3.2 安全扫描（静态检测）

在智能体上线前，平台执行全面的配置安全检查，提前消除配置阶段埋下的安全隐患：

| 检查项 | 检查对象 | 检查内容 |
|--------|----------|----------|
| Prompt 检查 | 智能体指令模板 | 指令中是否夹带恶意内容、是否暴露敏感系统信息 |
| Skill 检查 | 智能体配置的技能与权限 | 技能绑定工具的权限合理性、数据流向安全性 |
| MCP 工具检查 | 第三方工具的声明与配置 | 工具声明完整性、参数配置安全性、越权风险 |

检查完成后输出结构化报告，明确问题位置、风险等级及修复建议，**检查通过方可允许上线**。

### 3.3 安全监控（动态检测）

智能体上线后，平台开启 7×24 实时监控，核心监控能力包括：

| 能力模块 | 功能描述 |
|----------|----------|
| **风险溯源工作台** | 完整还原安全事件全链路：用户输入 → LLM 理解 → 工具调用 → 操作执行 → 最终输出，形成可追溯的证据链 |
| **会话风险追踪** | 将会话内多轮对话作为整体分析，绘制风险累积曲线，标注关键转折点，识别多轮诱导攻击 |
| **SOC 分析驾驶舱** | 企业级安全态势总览，聚合展示风险数量、高危智能体、攻击趋势、异常行为等核心指标 |
| **意图分片逃逸检测** | 识别恶意意图被拆分到多轮对话的攻击手法——单轮无害、聚合危险的隐蔽攻击模式 |
| **行为异常检测** | 建立应用/Agent 行为基线，实时监测调用频率、工具种类、响应时长等指标的偏离情况 |
| **人员风险画像** | 聚合用户跨应用、跨会话的风险记录，生成用户级安全评分，辅助识别内部威胁与高级持续攻击 |
| **风险关联分析** | 可视化展示跨应用风险传播路径、工具传播链和攻击链路关联，支持全网排查与溯源 |

### 3.4 风险事件闭环处置

发现风险后，平台提供从检测到处置的完整闭环流程：

```
风险生成 → 规则检测命中 → AI 检测旁路执行 → 评分融合 → AI 研判摘要生成
    → 风险事件详情页展示 → 人工确认/修正/拒绝 → 处置执行 → 样本回流 → 模型优化
```

**关键能力**：

- **AI 检测结果可解释**：展示命中文本片段、判定理由、反例提示、置信度、模型版本等信息，辅助人工研判；
- **AI 研判摘要**：自动分析攻击手法、影响面评估、处置优先级建议、缺失证据及需人工补充的问题；
- **人工反馈闭环**：支持对 AI 研判结果执行确认、修正、拒绝三类操作，反馈自动进入样本候选集，持续优化检测模型；
- **分级自动响应**：L1 通知 → L2 观察标记 → L3 软限制（需白名单与审批） → L4 强控制（必须人工审批 + MFA），高等级动作不可自动执行；
- **急停控制**：支持全局急停、单规则急停、单租户急停，确保任何情况下均可一键刹车；
- **处置审计**：所有处置动作全程留痕，满足合规审计要求。

### 3.5 统一策略中心

企业的安全策略在统一策略中心集中编排、版本化管理、统一下发：

**网关侧策略**：
- 访问控制策略（API Key / JWT 身份认证、路由级访问控制）
- 内容安全策略（输入侧：提示词注入、PII 外发、保密检查；输出侧：敏感信息泄露、违规输出拦截）
- 流量与服务治理（限流、路由分发、超时降级）
- 会话审计（完整记录请求与响应，留痕备查）

**探针侧策略**：
- 场景化策略包（内置高危工具审批、外联访问约束、数据脱敏等常用模板）
- 细粒度规则（工具调用权限控制、参数约束、行为基线配置）

**自动响应规则**：
- 触发条件配置（风险类型、风险等级、检测来源、置信度阈值、时间窗口、触发次数）
- 动作分级（L1-L4）
- 白名单、熔断阈值、TTL 自动恢复、灰度发布

**通知渠道**：支持邮件、短信、Webhook 等多种告警推送方式。

### 3.6 知识库与评测治理

平台建立完整的 AI 检测能力管理体系，确保检测模型可持续迭代优化：

- **知识条目管理**：安全知识库 CRUD、版本控制、审核流程、RAG Prompt 安全沙盒预览（防止知识被恶意利用）；
- **样本库管理**：误报/命中/攻击/边界样本的分类治理，支持 AI 辅助标注，训练集/评估集/回收站全生命周期管理；
- **模型效果评估**：评测集管理、模型版本对比、准确率/召回率/F1 指标看板、上线门禁建议（达标才允许上线）；
- **AI 优化建议**：基于样本积累自动生成规则调优建议（调整阈值、补充关键词、改用 AI 增强），支持干跑验证。

### 3.7 AI 模型与服务治理

- **模型注册管理**：统一管理企业接入的各类大模型（LLM、分类器、Embedding），记录状态、版本、部署模式及数据级别；
- **Prompt 模板管理**：对智能体使用的指令模板进行版本化管理，配合上线前检查；
- **AI 服务监控**：实时展示模型调用量、响应时间、错误率、熔断状态；
- **成本看板**：Token 消耗统计、月度预算控制、成本趋势分析。

### 3.8 安全报告

- **AI 自动生成**：基于平台运行数据，自动生成周/月安全报告；
- **人工审核**：报告生成后走人工审核流程，确保内容准确性；
- **定时推送**：支持定时自动推送给管理层；
- **自定义报告**：灵活选择模板、填充内容，按需定制。

## 四、产品优势

### 4.1 竞品对比分析

| 对比维度 | 传统大模型安全产品 | 传统应用安全产品 | **本平台** |
|----------|-------------------|-----------------|------------|
| **防护对象** | 仅模型输入输出 | 仅应用流量 | **智能体全链路**：Prompt→LLM→Tool→数据库→外部API→响应 |
| **防护层次** | 单层（内容审核） | 单层（WAF/API网关） | **双层协同**：网关管边界 + 探针管运行时 |
| **检测手段** | 规则匹配或纯 AI | 签名/规则/行为基线 | **规则 + AI 联合检测**，可解释、可降级 |
| **生命周期** | 运行时 | 运行时 | **静态扫描 + 动态监控**，上线前 + 运行中 |
| **处置能力** | 告警或阻断 | 阻断/限流 | **分级自动响应 + 人工审批 + 急停控制** |
| **持续优化** | 人工更新规则 | 人工更新规则 | **AI 自进化**：样本回流 → 模型评测 → 规则优化 |
| **可见范围** | 请求/响应文本 | 网络流量 | **工具调用细节、进程行为、文件操作、命令执行** |

### 4.2 五大核心优势

**优势一：唯一专注"智能体安全"的平台**

区别于大模型内容审核和传统应用安全网关，本平台专门解决智能体特有的安全风险——工具越界、意图偏移、多轮诱导、行为异常。竞品盲区即本平台的核心战场。

**优势二：网络侧 + 端侧双层协同，无侵入 + 深可见**

- **网关层**：部署于流量入口，**零代码改造**，流量指向即可生效；
- **探针层**：轻量 SDK 嵌入 Agent 进程，**看见网关不可见的运行时行为**；
- **统一策略**：一次配置，网关与探针双线生效，避免漏配、错配。

**优势三：规则 + AI 联合检测，准确与稳定兼得**

- 规则引擎抓确定性风险（快速、稳定、可解释）；
- AI 语义分析抓变形与新型攻击（智能、灵活、覆盖面广）；
- 联合检出降低误报、提升检出率；
- AI 故障时自动降级，业务不中断。

**优势四：从发现到处置的完整闭环，越用越准**

平台不止于风险发现，更提供完整的"发现 → 研判 → 处置 → 优化"闭环：
- AI 研判 + 人工反馈 → 样本回流 → 模型评测 → 规则优化；
- 检测能力持续进化，而非一成不变。

**优势五：静态扫描 + 动态监控，全生命周期守护**

- **上线前**：Prompt / Skill / MCP 配置检查，排除配置风险；
- **运行时**：7×24 实时监控，全链路风险识别与处置；
- 两道关卡，安全前置 + 持续守护。

## 五、典型应用场景

### 场景一：金融企业智能客服安全

**场景描述**：智能客服系统具备查询余额、转账、发送短信等能力，一旦被诱导调用转账接口，将造成直接资金损失。

**解决方案**：
- 网关层拦截包含注入攻击特征的 Prompt（如"绕过安全验证""忽略系统指令"）；
- 探针层监控客服 Agent 的工具调用链，识别未声明的转账接口调用；
- 策略中心配置转账类工具的审批规则，大额转账强制人工确认。

### 场景二：研发代码审查 Agent 数据外泄防护

**场景描述**：代码审查 Agent 可访问内部代码仓库，攻击者通过多轮对话诱导其外传代码片段或仓库路径。

**解决方案**：
- 意图分片逃逸检测识别多轮对话中逐步偏离原始意图的攻击模式；
- 探针端 PII 脱敏在本地完成，敏感数据不离开客户环境；
- 行为基线监测发现异常数据外传行为（如调用次数突增、外传数据量异常）。

### 场景三：企业内部知识库问答安全

**场景描述**：企业员工使用 AI 查询内部文档，但文档按敏感度分级（公开/内部/机密/绝密），需防止高密级信息泄露给低权限用户。

**解决方案**：
- 数据分级分类体系驱动安全策略精细化；
- RAG Prompt 安全沙盒预览知识被引用时的风险等级；
- 网关层根据用户身份与数据级别动态控制 AI 响应内容的脱敏粒度。

## 六、技术特性与部署

### 6.1 技术特性

| 特性 | 说明 |
|------|------|
| **旁路检测** | AI 检测异步旁路执行，不阻塞主请求链路 |
| **自动降级** | AI 超时/错误/熔断时自动降级为纯规则检测 |
| **私有化部署** | 支持私有化部署，数据不出域 |
| **多模型兼容** | 支持 GPT、Claude、通义千问、自研模型等多种大模型接入 |
| **开放集成** | 提供标准 Webhook 和 API 接口，可对接 SIEM、SOAR、工单系统等 |
| **多租户隔离** | 支持租户级数据隔离与策略隔离 |

### 6.2 部署方式

| 组件 | 部署方式 | 侵入性 |
|------|----------|--------|
| AI 安全网关 | 部署于流量入口，作为统一代理层 | **无侵入**：仅需将 AI 流量指向网关 |
| SDK 探针 | 以 Python SDK 形式嵌入 Agent 进程 | **轻量侵入**：一行代码初始化，对业务逻辑无影响 |
| 管理控制台 | 支持容器化部署或传统服务器部署 | 无侵入 |

### 6.3 常见问题

**Q1：与传统 WAF/API 网关的区别？**

传统 WAF 针对通用 Web 攻击（SQL 注入、XSS），API 网关针对接口认证与限流，两者均不具备 AI 语义理解能力，也无法感知 Agent 内部行为。本平台专门解决智能体特有的全链路风险。

**Q2：AI 检测是否影响业务性能？**

AI 检测采用旁路异步执行，不阻塞主请求链路。平台内置完善的降级机制，AI 服务异常时自动降级为纯规则检测，确保业务连续性。

**Q3：误报率如何控制？**

采用规则 + AI 联合检出机制，联合命中时置信度最高。AI 研判结果标注置信等级，低置信事件明确标记"需人工复核"。平台支持人工反馈闭环，误报样本回流优化，检测准确率持续提升。

**Q4：数据安全性如何保障？**

平台支持私有化部署。探针侧 PII 脱敏在本地完成，敏感数据不离开客户环境。模型调用支持接入自研模型或私有化部署大模型。

**Q5：能否对接现有安全基础设施？**

支持。平台提供标准 Webhook 和 API 接口，可对接企业现有的 SIEM、SOAR、工单系统、自研审核服务等安全基础设施。
