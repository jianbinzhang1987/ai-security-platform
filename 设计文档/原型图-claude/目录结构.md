# 大模型安全监测平台 — 管理端功能目录树

> 本版目录按运维人员和安全运营人员的真实调查路径重构。核心原则：`app_id` 是平台侧主资产对象，`span_id` 是安全证据锚点，`trace_id` 是默认调查入口，`session_id` 是跨轮聚合视角。服务器、进程、工具、RAG、网络、数据库等不再作为独立菜单，而作为接入应用详情或调用观测工作台中的分析维度。

---

## 一、统一对象模型

```text
租户 tenant_id
└── 接入应用 app_id                         平台侧主资产对象
    ├── 接入凭证 App Token                  用于 SDK 上报鉴权与归属
    ├── 运行实例 instance_id                主机 / 容器 / 进程 / SDK 心跳
    ├── 逻辑智能体 / 工作流节点              可选标签，不默认作为强资产
    └── 运行观测数据
        ├── Trace trace_id                  默认调查入口，一次 Agent run / 请求链路
        ├── Span span_id                    最小证据单元
        └── Session session_id              多轮会话 / 长任务聚合，MVP 可选
```

### 1.1 主资产对象

主资产对象为平台注册的接入应用 `app_id`，而不是 `OTEL_SERVICE_NAME`。

| 对象 | 定位 | 菜单呈现 |
|---|---|---|
| `app_id` / 接入应用 | 策略、责任、凭证、统计归属主体 | 资产管理 > 接入应用管理 |
| `OTEL_SERVICE_NAME` / `service.name` | OTel Resource Attribute，描述服务进程名 | 应用详情 > 运行实例维度 |
| 服务器 / 主机 | 运行环境属性，如 `host.name`、`host.ip` | 应用详情 > 运行实例维度 |
| 应用进程 / 容器 / Pod | 运行实例属性，如 `process.pid`、容器 ID | 应用详情 > 运行实例维度 |
| 逻辑智能体 / Agent 角色 | 可选业务标签，取决于注册或框架元数据质量 | 应用详情 > 逻辑智能体 / 工作流节点 |

### 1.2 智能体识别分级

| 分级 | 来源 | 可用能力 | 边界 |
|---|---|---|---|
| 强识别 | 平台注册 + App Token / agent_id | 策略绑定、阻断、SLA、责任归属 | 可进入资产详情 |
| 中识别 | LangChain node、tool、class、method、OTel/框架属性 | 调用链着色、筛选、风险聚合 | 不作为强策略主体 |
| 弱识别 | Prompt hash、工具集合、调用图聚类 | 显示疑似 Agent / 未命名工作流，标注置信度 | 不进入资产列表，不做阻断主体 |
| 一次性 Agent | 单次 Trace 内的临时节点 | Trace 内展示 | 不进入资产管理 |

当前 LangChain SDK 已经能稳定采集 `agentsec.node.display_name`、`agentsec.node.class_name`、`agentsec.node.method_name`、`agentsec.tool.name` 等字段，因此 MVP 阶段主要支撑中识别视图。

### 1.3 调查对象层级

| 层级 | 作用 | MVP 优先级 |
|---|---|---|
| Span / Observation | 最小证据单元，承载 Prompt、Response、Tool 输入输出、风险等级、阻断原因 | P0 |
| Trace | 默认调查入口，通过 `parent_span_id` 还原执行链路 | P0 |
| Session | 多轮会话、长任务、跨轮攻击聚合 | P1 / 可选 |

MVP 阶段不强制所有数据都有 `session_id`。当无稳定 `session_id` 时，平台按 `trace_id` 展示单次调用链，不伪造真实会话。

## 四、菜单收敛说明

| 原菜单 / 页面 | 新位置 | 调整理由 |
|---|---|---|
| 服务器管理 | 应用详情 > 运行实例 | 服务器是运行属性，不是平台主资产 |
| 应用进程管理 | 应用详情 > 运行实例 | 进程是实例属性，可由 OTel Resource/Process 属性支撑 |
| 接口令牌管理 | 应用详情 > 接入凭证 | Token 与 `app_id` 强绑定 |
| 智能体列表 | 应用详情 > 逻辑智能体 / 工作流节点 | 仅强/中识别对象展示；弱识别和一次性 Agent 只在 Trace 中出现 |
| 智能体类型字典 | 系统字典或监控配置内部项 | 纯配置，不作为独立菜单 |
| 调用链分析 | 安全监控 > 调用观测工作台 > Trace 视图 | Trace 是默认调查入口 |
| 会话列表 | 安全监控 > 调用观测工作台 > Session 视图 | Session 是聚合视角，MVP 可选 |
| 提示词检索 | 安全监控 > 内容检索 | 检索范围扩展到 Prompt、Response、Tool Input、Tool Output |
| 告警日志 / 阻断日志 | 安全事件 > 告警与响应记录 | 阻断是响应动作，与通知、降级、放行统一展示 |
| 平台运维一级菜单 | 系统管理 > 平台运维 | 仅 SA / 私有化运维角色可见 |

## 五、核心页面功能清单

### 5.1 安全大盘

| 页面区域 | 功能说明 |
|---|---|
| 风险总览卡 | 今日高危 Trace 数、未处置事件数、阻断次数、误报率趋势 |
| 接入覆盖卡 | 接入应用数、活跃实例数、Collector 在线率、Span 上报量 |
| 采集健康卡 | Collector QPS、丢弃率、Kafka Lag、检测队列延迟 |
| 高风险排行 | 按 `app_id`、工具、风险类型、模型、Trace 异常分排行，可下钻 |
| 风险趋势图 | 24h / 7d 事件趋势、异常分走势、Token 异常量 |
| 今日待办 | 未处置事件、失败告警、离线实例、策略覆盖空缺 |

所有指标必须能一键下钻到调用观测工作台、事件详情或接入应用详情。

### 5.2 资产管理

#### 接入应用管理

| 页面区域 | 功能说明 |
|---|---|
| 应用列表 | 以 `app_id` 为中心展示应用名称、状态、业务线、负责人、近 24h 调用量、风险数 |
| 概览 | 运行状态、近 7 日风险趋势、活跃告警、调用统计 |
| 运行实例 | hostname、IP、容器、进程、`service.name`、SDK 版本、心跳、最后上报时间 |
| 接入凭证 | App Token 创建、轮换、吊销、最后使用时间 |
| 监控配置 | 采样率、脱敏规则、采集开关、工具白黑名单、告警规则绑定 |
| 工具与资源声明 | MCP 工具、外部 API、数据库、知识库权限声明；MVP 先展示已观测工具 |
| 逻辑智能体 / 工作流节点 | 展示强识别和中识别对象，标注来源和置信度 |
| 策略覆盖检查 | 策略是否生效、版本是否滞后、是否存在冲突 |

#### 接入审批

| 页面区域 | 功能说明 |
|---|---|
| 注册申请 | 待审批、已通过、已拒绝列表，展示设备指纹 |
| 审批策略 | 自动通过 / 人工审批模式 |
| 黑名单 | 设备指纹黑名单，命中后自动拒绝 |

#### 资产拓扑（第一轮迭代）

第一轮迭代交付基础资产拓扑：以接入应用为根节点，展示应用 -> 运行实例 -> 逻辑智能体 / 工作流节点 -> 已观测工具 / 已声明资源的关系图。拓扑节点来源包括 app_id、instance_id、LangChain node/tool 元数据、工具与资源声明；对弱识别或推断关系需标注来源和置信度。第一轮不承诺跨系统全自动资源图谱和复杂攻击路径推演。

### 5.3 安全监控

#### 调用观测工作台

| 区域 | 功能说明 |
|---|---|
| Trace 视图 | 默认视图，展示一次 Agent run / 请求链路，支持瀑布图 |
| Span 视图 | 最小证据列表，适合按风险、工具、状态批量筛查 |
| Session 视图 | 多轮会话或长任务聚合；仅有稳定 `session_id` 时启用 |
| 详情面板 | Prompt、Response、Tool 输入、Tool 输出、风险证据、阻断原因 |
| 过滤维度 | `app_id`、`trace_id`、`span_id`、`session_id`、`span_kind`、`status`、风险等级、模型、工具、框架、时间 |

#### 内容检索

检索范围不再局限于 Prompt，应覆盖：

1. Prompt / LLM 输入
2. LLM Response / Completion
3. Tool Input
4. Tool Output

支持关键词、正则、语义搜索，并能跳转到对应 Span 和 Trace。

#### 保存的调查模板

高危注入调查、敏感信息泄露调查、工具越权调查、异常 Tool 调用阻断、Token 激增调查等常用过滤视图。

### 5.4 安全事件

| 页面 | 功能说明 |
|---|---|
| 事件处置中心 | 事件列表、详情、认领、确认威胁、误报、关闭、根因分析 |
| 告警与响应记录 | 通知、阻断、降级、放行等响应动作统一列表 |

事件详情必须以 `span_id` 为主证据锚点，并向上提供 `trace_id`、`session_id`、`app_id` 的跳转。

### 5.5 策略中心

| 页面 | 功能说明 |
|---|---|
| 检测规则配置 | Prompt 检测、工具审计、行为分析、意图对齐阈值 |
| 告警规则 | 条件树、窗口聚合、响应动作、规则测试沙箱 |
| 自定义 Guardrail | 关键词、正则、LLM 评分、触发动作 |
| 通知渠道 | 飞书、钉钉、企微、邮件、短信、PagerDuty、SIEM |

### 5.6 系统管理

平台运维收敛到系统管理，仅 SA / 私有化部署运维角色可见，包括服务运行状态、采集器配置、平台路由与部署。

## 六、当前 LangChain SDK 能力对菜单的约束

当前研发提供的 LangChain SDK 遥测说明表明，MVP 已经具备如下主证据：

| 能力 | 当前字段 |
|---|---|
| LLM 调用 | `agentsec.span_type=llm_call`、`gen_ai.framework=langchain`、`gen_ai.prompt`、`gen_ai.completion`、`agentsec.llm.input`、`agentsec.llm.output` |
| Tool / Skill 调用 | `agentsec.span_type=tool_call`、`agentsec.tool.kind=skill`、`agentsec.tool.name`、`agentsec.tool.input`、`agentsec.tool.output` |
| 风险与阻断 | `security.risk.level`、`security.block_reason`、`agentsec.block.action`、`status=ok/blocked/error` |
| 调用关系 | `trace_id`、`span_id`、`parent_span_id` |
| 节点展示 | `agentsec.node.display_name`、`agentsec.node.class_name`、`agentsec.node.method_name` |

因此 MVP 默认建设重点为 Trace 视图、Span 详情、内容检索、事件证据，不强依赖 Session。

## 七、数据字段与证据锚点口径

### 7.1 Span / Observation 归一化字段

| 管理端字段 | 来源或说明 |
|---|---|
| `span_kind` | 归一化字段：`llm` / `tool` / `retriever` / `network` / `db` / `guardrail` / `internal` |
| `agentsec_span_type` | SDK 原始字段：如 `llm_call`、`tool_call` |
| `framework` | 如 `gen_ai.framework=langchain` |
| `node_display_name` | `agentsec.node.display_name` |
| `tool_name` | `agentsec.tool.name` |
| `tool_input` / `tool_output` | 工具真实入参 / 出参 |
| `prompt_text` / `completion_text` | LLM 输入 / 输出，需按策略脱敏与截断 |
| `status` | `ok` / `blocked` / `error` |
| `block_action` / `block_reason` | 阻断动作与原因 |
| `error_type` | 异常类型 |

### 7.2 风险事件锚点

`risk_events` 需要统一包含：

```text
id
tenant_id
app_id
session_id        可空，跨轮聚合时使用
trace_id          建议冗余，便于直达 Trace
span_id           建议非空；Session 级事件可指向 root span 或 analysis span
span_kind         建议冗余，便于筛选和统计
risk_type
risk_level
confidence
status
block_action
block_reason
evidence          JSONB，含 source_fields、snippet、redaction_state、offset
detected_at
```

告警和事件调查链路：

```text
告警 / 事件
  -> span_id       最小证据
  -> trace_id      完整调用链
  -> session_id    多轮上下文
  -> app_id        责任主体
```

## 八、MVP 与后续边界

### 8.1 MVP 可承诺

1. LangChain LLM 调用自动采集
2. LangChain Tool / Skill 调用自动采集
3. Prompt、Response、Tool 输入、Tool 输出展示
4. Trace / Span 父子关系还原
5. `ok` / `blocked` / `error` 状态展示
6. 风险等级、阻断动作、阻断原因展示
7. 基于 `span_id` 的证据定位和事件下钻
8. 接入应用、运行实例、Token、策略覆盖检查
9. 基础资产拓扑（接入应用 -> 运行实例 -> 逻辑智能体/工作流节点 -> 已观测工具/已声明资源）

### 8.2 暂不承诺

1. 任意 Python 方法全量自动追踪
2. 所有三方框架同等成熟支持
3. 稳定识别任意业务智能体角色
4. 跨系统完整资产拓扑自动推断和复杂攻击路径推演
5. 完整多轮 Session 攻击链分析
