# 平台MVP阶段功能收拢与简化方案

## 1. 功能屏蔽策略

### 1.1 临时屏蔽模块
在MVP阶段，临时屏蔽以下高级管理和运营功能，以聚焦核心安全监测能力：
- 工具与权限
- 监控覆盖度
- 租户管理

**实现方案：**
不删除任何底层代码和接口，仅在前端路由（Router）或菜单配置中隐藏入口（如设置 `hidden: true`），以便未来随时开放。

### 1.2 监控覆盖度屏蔽影响评估
**评估结果：** 影响极小。
- **原因：** “监控覆盖度”主要用于展示探针接入情况的大盘（预期接入 vs 实际接入）。屏蔽后不影响核心的“风险发现、拦截和溯源”能力。
- **替代方案：** 仪表盘（Dashboard）上的相关覆盖率统计图表可临时隐藏或替换为“今日活跃应用数”等核心指标。

## 2. 应用详情页面精简

### 2.1 Tab页屏蔽
应用详情页中屏蔽以下Tab页信息，使页面更聚焦：
- 接入配置
- 监控配置
- 策略覆盖检查

### 2.2 Skills 的归属
**处理方案：**
- 建议将 Skills 归类为 **MCP工具 (MCP Tools)** 或统称为 **声明工具 (Declared Tools)**，放置在“工具与资源” Tab 下。
- **原因：** 在大模型（特别是Claude）语境下，Skill 本质上是对外交互的“能力”，包含特定的输入参数和预期的执行动作，这与 MCP 暴露本地或远程工具的理念完全一致。

## 3. 风险事件管理优化

### 3.1 编号规则保留与定义
**评估结果：** 强烈建议保留“事件编号（Event ID）”和“风险编号（Risk ID）”。
- **原因：** 安全人员协作沟通或在外部系统（如工单系统）记录追踪时，必须依赖唯一标识，否则极易混淆。
- **编号定义建议：** 采用 `业务前缀 + 时间戳 + 流水号` 格式，如：
  - 事件编号：`EVT-20260417-0001`
  - 风险编号：`RSK-260417-0001`

### 3.2 风险事件列表字段简化
**简化方案：**
- **屏蔽字段：** “平台动作（Platform Action）”、“关联 trace/span”等深度技术细节字段。
- **保留核心字段：** 风险/事件编号、发生时间、所属应用、风险类型、严重程度、处置状态。

### 3.3 事件处置流程简化
将复杂的工单化流转改为极简的“状态+备注”模式。

**详情页需要修改的内容梳理：**
1. **移除复杂操作区：** 移除“派发”、“升级”、“自动阻断/联动执行”等复杂操作按钮。
2. **状态流转精简：** 改为简单的下拉框或单选组，状态包含：`待处理`、`已处理`、`忽略/误报`。
3. **增加备注功能：** 提供多行文本框，供安全人员记录判定理由或处置说明。
4. **历史流转日志（可选）：** 仅展示简化的变更记录（如“某人于某时将状态修改为某状态，备注：xxx”）。

## 4. 风险溯源工作台架构优化

**讨论建议：** 中长期来看，非常有必要增加一层上级页面。
- **当前现状：** 当前“风险溯源工作台”只有一层，像是一个全局单次的分析沙箱。
- **未来理想架构：**
  - **上级页面（新增）：** “溯源任务列表”或“调查看板”，展示所有独立的溯源会话（任务名称、关联事件、调查人、创建时间）。
  - **当前页面定位：** 作为特定调查任务的**详情页**，内部保存该特定调查的 Trace 图谱、上下文对话和分析记录，支持持续性的调查任务。
