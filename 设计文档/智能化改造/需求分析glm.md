# 大模型安全监测平台智能化改造需求分析

## 1. 文档目标

基于当前平台概要设计，从四个维度梳理智能化改造需求：

1. **大模型引入**：安全专用模型 + 通用大模型增强AI能力
2. **高级SOC分析**：从基础规则分析升级为多维度高维安全分析
3. **知识库安全能力**：引入知识库并构建安全防护体系
4. **智能体方案**：引入AI Agent提升自主化、自动化和智能化水平

---

## 2. 现状分析

### 2.1 当前风险识别链路

```text
网关/探针采集 → 规则匹配 → 风险打分 → 风险线索 → 人工调查 → 事件闭环
```

**核心特征：** 风险识别依赖静态规则，研判依赖人工，分析停留在单条Trace/Span级别。

### 2.2 能力瓶颈

| 环节 | 当前能力 | 瓶颈 |
|---|---|---|
| 风险识别 | 规则匹配+关键词/正则 | 无法识别语义级注入、隐式越狱、多轮累积风险 |
| 风险研判 | 人工查看证据→人工判断 | 效率低，依赖经验，误报率高 |
| 证据分析 | 展示结构化证据/JSON/Raw | 缺乏自动摘要、攻击链还原、影响面评估 |
| 策略优化 | 误报标记→人工调整规则 | 优化周期长，缺乏自动调优 |
| SOC分析 | 单条Trace/Span维度统计 | 缺乏人员/组织/时序等高维分析 |
| 处置决策 | 人工选择动作和范围 | 缺乏智能建议和自动响应 |

## 3. 大模型引入需求

### 3.1 模型分层架构

```text
┌──────────────────────────────────┐
│     通用大模型（研判层）           │
│  研判分析、报告生成、处置建议、     │
│  攻击链还原、知识问答              │
├──────────────────────────────────┤
│    安全专用模型（检测层）           │
│  Prompt注入检测、越狱识别、        │
│  敏感内容识别、工具边界判定         │
├──────────────────────────────────┤
│      规则引擎（基础层）            │
│  关键词/正则/条件表达式匹配        │
└──────────────────────────────────┘
```

**分层原则：** 基础层保证低延迟确定性检测，检测层提升语义级检出率，研判层增强复杂推理。三层并行运行，结果融合输出综合风险评分。

### 3.2 安全专用模型引入场景

#### 3.2.1 Prompt注入检测增强

- **当前问题：** 规则只能识别已知注入模式，无法检测语义级隐式注入
- **增强方案：** 安全专用模型对输入进行语义分析，覆盖直接/间接/上下文/多轮累积注入
- **输出：** 风险标签 + 置信度 + 攻击类型 + 攻击片段定位
- **数据模型影响：** `span_observation`增加`ai_detection_result`字段；`risk_clue`增加`detection_source`枚举（`rule`/`ai_model`/`rule_and_ai`）

#### 3.2.2 越狱攻击识别增强

- 覆盖角色扮演越狱、编码绕过、多轮诱导、指令覆盖等新型模式
- 输出越狱类型分类 + 置信度 + 诱导路径还原

#### 3.2.3 敏感内容识别增强

- 对模型输出进行语义级敏感分类：个人隐私/商业秘密/合规违规/有害内容/内部泄露
- 输出敏感类型 + 置信度 + 敏感片段定位

#### 3.2.4 工具边界判定增强

- 分析工具调用意图与声明范围的匹配度
- 识别意图偏移调用、参数篡改、级联越权、资源越界访问

### 3.3 通用大模型引入场景

#### 3.3.1 智能研判辅助

- 基于Trace/Span证据自动生成风险研判摘要（攻击手法、影响面、相似历史事件、处置优先级）
- 安全运营可确认/修正/补充
- **数据模型影响：** `risk_event`增加`ai_analysis`字段和`ai_analysis_status`枚举

#### 3.3.2 攻击链自动还原

- 基于完整Span序列自动还原攻击链路，标注攻击阶段、意图推断、关键转折点
- 在溯源工作台增加"攻击链视图"

#### 3.3.3 处置建议生成

- 基于风险类型、影响面、历史处置记录自动生成处置建议
- 运营可一键采纳或修改
- **数据模型影响：** `event_action`增加`ai_suggested`布尔字段

#### 3.3.4 规则优化建议

- 分析误报/命中样本，自动生成规则调整建议（条件修改、阈值调整、新增规则）
- 支持干跑验证闭环

#### 3.3.5 安全报告自动生成

- 基于事件数据、风险趋势、处置记录自动生成周报/月报/专项报告
- 支持自定义模板

### 3.4 模型接入架构

```text
规则引擎(同步) ──┐
安全专用模型(近同步) ──┼── 风险评分融合引擎 ──→ 现有业务服务层
通用大模型(异步) ────┘
```

**关键要求：**

1. 模型调用采用**旁路模式**，不可用时不影响规则引擎运行
2. 安全专用模型延迟 < 200ms，通用大模型允许异步1-5s
3. 所有模型输入输出必须审计留痕
4. 模型结果必须可解释、可追溯、可覆盖
5. 模型版本管理纳入策略版本体系

### 3.5 各环节大模型引入审视

| 系统环节 | 可引入的模型能力 | 优先级 |
|---|---|---|
| 风险识别层 | 安全专用模型语义检测、多轮风险累积识别 | **P0** |
| 风险溯源层 | AI攻击链还原、证据摘要生成、相似事件关联 | **P0** |
| 事件研判层 | AI研判摘要、处置建议生成、影响面评估 | **P0** |
| 策略治理层 | AI规则优化建议、自动干跑验证、策略效果预测 | P1 |
| 安全总览层 | AI态势摘要、风险预测、安全评分 | P1 |
| 接入采集层 | AI辅助数据质量评估、异常采集模式识别 | P2 |
| 通知联动层 | AI告警聚合、智能降噪、告警优先级排序 | P2 |
| 审计分析层 | AI异常行为识别、审计异常检测 | P2 |

## 4. 高级SOC分析需求

### 4.1 当前分析局限

当前分析停留在**单点检测+人工串联**，缺乏：人员维度跨会话风险累积、组织维度风险态势聚合、时序维度风险演化趋势、关联维度跨应用风险传播、行为基线维度异常识别。

### 4.2 人员维度分析

1. **用户风险画像** — 聚合同一用户标识下所有风险事件/线索/命中记录，输出风险等级/类型分布/趋势
2. **用户行为基线** — 建立正常行为基线（调用频率/工具使用/Prompt模式），检测偏离
3. **用户风险累积** — 识别多轮会话中低风险行为的累积升级，输出累积评分和关键转折点
4. **高风险用户排行** — 按用户维度聚合风险评分

**新增实体：** `user_risk_profile`、`user_behavior_baseline`、`user_risk_accumulation`

### 4.3 组织/业务线维度分析

1. **业务线风险态势** — 按业务线聚合应用风险、事件数量、处置效率
2. **租户级风险聚合** — 按租户聚合全量风险数据，识别跨应用风险传播
3. **组织内风险热点** — 识别风险集中应用和高风险Agent/工具

**新增实体：** `org_risk_profile`

### 4.4 时序与趋势分析

1. **风险趋势预测** — 基于历史数据预测未来趋势，识别拐点和季节性模式
2. **攻击周期识别** — 识别周期性攻击模式（特定时段高峰）
3. **风险演化追踪** — 追踪风险类型从出现到爆发的演化过程

### 4.5 关联与传播分析

1. **跨应用风险关联** — 识别共享工具/资源/模型的应用间风险传播
2. **工具/资源风险传播** — 追踪高风险工具被多Agent/应用调用的风险扩散
3. **攻击链路关联** — 将分散在不同Trace中的攻击行为关联为完整攻击链

### 4.6 行为基线与异常检测

1. **应用行为基线** — 建立应用级正常行为基线，检测偏离
2. **Agent行为基线** — 建立Agent级正常行为基线，检测行为偏移
3. **全局异常检测** — 统计模型检测全局异常模式（突发流量、新型攻击、未知风险类型）

### 4.7 高级分析引擎架构

```text
┌──────────────────────────────────────────┐
│              高级分析引擎                  │
├──────────┬──────────┬──────────┬─────────┤
│ 人员分析  │ 组织分析  │ 时序分析  │ 关联分析 │
├──────────┴──────────┴──────────┴─────────┤
│         行为基线与异常检测模块              │
├──────────────────────────────────────────┤
│         分析任务调度与结果存储              │
├──────────────────────────────────────────┤
│    数据聚合层（Trace/Span/Event/Session）  │
└──────────────────────────────────────────┘
```

**关键要求：** 异步批处理不影响实时检测；分析结果独立存储；支持定时调度和手动触发；结果可下钻到原始数据；行为基线支持自动更新和人工审核。

### 4.8 安全总览增强

基于高级分析能力，安全总览需增加：人员风险视图（高风险用户排行）、组织风险视图（业务线态势）、风险预测视图（趋势预测曲线）、关联视图（风险传播图）、异常视图（基线偏离告警）。

## 5. 知识库安全能力需求

### 5.1 知识库引入目的

1. 安全运营知识检索（攻击手法库、处置预案库、合规要求库）
2. AI研判领域知识支撑（安全知识增强研判准确性）
3. 规则优化样本库（误报/命中/攻击样本）
4. 策略配置最佳实践库（策略模板、场景化配置）

### 5.2 知识库自身安全

#### 5.2.1 知识内容安全

- 入库前安全审核：检测敏感信息、注入内容、有害内容
- 知识版本管理：版本化存储，支持回滚和变更审计
- 来源可信验证：标记来源（人工/AI生成/外部导入），按来源设信任等级
- 过期与失效管理：设置有效期，过期自动标记降级

#### 5.2.2 知识访问安全

- 知识分级访问控制：按敏感级别设置访问权限
- 检索审计：记录检索人、检索内容、检索时间
- 导出控制：知识导出需审批和审计
- 防泄露：知识内容脱敏展示，完整内容需授权

#### 5.2.3 知识更新安全

- 变更审批：新增/修改/删除需审批
- AI生成知识审核：AI生成条目需人工审核后才可发布
- 冲突检测：检测新旧知识矛盾
- 影响面评估：变更前评估对依赖规则/策略的影响

### 5.3 知识库赋能安全

#### 5.3.1 安全知识检索增强研判

- 安全运营调查时可检索相关攻击手法、历史案例、处置预案
- AI研判引用知识库内容，增强准确性和可解释性

#### 5.3.2 RAG增强AI检测与研判

- 安全知识库作为RAG外部知识源
- 安全专用模型检测时检索相关攻击模式知识
- 通用大模型研判时检索历史案例和处置预案

#### 5.3.3 样本库支撑规则优化

- **误报样本库**：沉淀误报样本，支撑干跑验证和阈值调优
- **命中样本库**：沉淀确认命中样本，支撑规则效果评估
- **攻击样本库**：沉淀已知攻击样本，支撑新规则开发和模型微调
- **AI辅助样本标注**：减少人工标注成本

#### 5.3.4 策略模板库加速治理

- 场景化策略模板（防注入、防越狱、工具边界控制）
- 行业最佳实践库
- 合规要求映射库

#### 5.3.5 知识驱动安全问答

- 自然语言提问获取安全知识、处置指引、历史案例
- 问答结果引用知识来源，可追溯可验证
- 支持知识缺口识别：无法匹配时标记缺口

### 5.4 知识库核心对象

```text
knowledge_base        知识库
├── knowledge_entry   知识条目（内容/元数据/版本/安全标记）
├── knowledge_relation 知识关系（相似/依赖/冲突）
├── sample_library     样本库（误报/命中/攻击）
└── policy_template    策略模板库（场景模板/最佳实践）
```

**新增实体：**

- `knowledge_base`：`kb_id`、名称、类型、状态、条目数
- `knowledge_entry`：`entry_id`、`kb_id`、标题、内容、嵌入向量、来源类型、信任等级、敏感级别、审核状态、有效期、版本号
- `knowledge_version`：`version_id`、`entry_id`、版本号、内容快照、变更说明、发布人、发布时间
- `knowledge_access_log`：`access_id`、`entry_id`、访问人、访问动作、访问时间、访问原因
- `sample_entry`：`sample_id`、类型（误报/命中/攻击）、关联规则ID、关联事件ID、样本内容、标注状态、标注人

### 5.5 知识库安全风险与防护

| 风险类型 | 描述 | 防护措施 |
|---|---|---|
| 知识投毒 | 恶意知识条目影响AI判断 | 入库审核+AI内容安全检测+信任等级分级 |
| 知识泄露 | 敏感知识被未授权访问 | 分级访问控制+检索审计+脱敏展示 |
| 知识过时 | 过期知识导致错误判断 | 有效期管理+自动降级+定期审核 |
| 知识冲突 | 矛盾知识导致判断不一致 | 冲突检测+优先级排序+人工裁决 |
| RAG注入 | 通过知识库间接注入AI | 知识内容安全扫描+检索结果过滤+来源可信验证 |
| 依赖失效 | 知识变更导致依赖规则/策略失效 | 影响面评估+变更审批+灰度发布 |

## 6. 智能体方案需求

### 6.1 智能体引入定位

智能体（AI Agent）比单次模型调用更高阶，具备**感知-推理-行动-反馈**闭环能力。在安全监测平台中按自主度分三层：

```text
┌─────────────────────────────────────────────┐
│              智能体分层架构                    │
├─────────────────────────────────────────────┤
│  L3: 自主运营Agent — 长周期自主安全运营       │
│      周期性风险巡检、策略效果评估、报告生成     │
├─────────────────────────────────────────────┤
│  L2: 处置响应Agent — 事件驱动的自动响应       │
│      自动研判、处置建议、受限自动响应执行       │
├─────────────────────────────────────────────┤
│  L1: 分析辅助Agent — 任务驱动的分析辅助       │
│      证据分析、攻击链还原、知识检索            │
└─────────────────────────────────────────────┘
```

### 6.2 L1: 分析辅助Agent

#### 6.2.1 证据分析Agent

- **触发：** 新风险线索生成时自动激活
- **能力：** 自动读取Trace/Span证据，调用安全专用模型和通用大模型分析
- **输出：** 证据摘要、攻击手法分析、风险评分建议、相似历史事件
- **边界：** 仅分析建议，不执行任何处置动作，结果需人工确认

#### 6.2.2 攻击链还原Agent

- **触发：** 安全运营在溯源工作台请求攻击链还原
- **能力：** 自动串联跨Span攻击行为，生成攻击链路图和意图推断
- **输出：** 攻击链路图、攻击阶段标注、关键转折点、攻击者画像
- **边界：** 仅还原展示，不改变任何数据状态

#### 6.2.3 知识检索Agent

- **触发：** 安全运营提问或研判时自动检索
- **能力：** 基于自然语言查询知识库，返回相关攻击手法、历史案例、处置预案
- **输出：** 知识检索结果列表、相关性评分、知识来源引用
- **边界：** 仅检索展示，不修改知识库内容

### 6.3 L2: 处置响应Agent

#### 6.3.1 自动研判Agent

- **触发：** 新事件创建时自动激活
- **能力：** 综合证据分析、知识检索、历史案例，生成研判结论
- **输出：** 研判结论（确认风险/误报/需观察）、置信度、研判依据、处置建议
- **边界：** 研判结论为建议性质，高危事件必须人工确认后才可采纳

#### 6.3.2 处置建议Agent

- **触发：** 事件确认后自动激活
- **能力：** 基于风险类型、影响面、历史处置效果，生成处置方案
- **输出：** 推荐动作类型、建议范围、TTL建议、影响评估、审批级别推荐
- **边界：** 建议性质，高危处置必须人工确认和审批

#### 6.3.3 自动响应Agent（受限模式）

- **触发：** 满足预定义自动响应规则的事件
- **可自动执行的动作：** 通知发送、低风险会话限制（TTL自动过期）、告警升级
- **不可自动执行的动作：** 应用降级、工具禁用、主体阻断、策略变更（必须人工审批）
- **关键约束：**
  - 自动响应动作必须有明确的规则前置条件
  - 所有自动执行动作必须写入审计日志
  - 自动响应动作默认带TTL，到期自动恢复
  - 自动响应规则需审批后启用，支持灰度模式
  - 自动响应执行失败必须告警并转人工

**新增数据对象：**

- `auto_response_rule`：`rule_id`、触发条件、动作类型、动作范围、TTL、审批状态、启用状态、灰度比例
- `auto_response_execution`：`execution_id`、`rule_id`、`event_id`、执行动作、执行结果、执行时间、是否自动恢复

### 6.4 L3: 自主运营Agent

#### 6.4.1 风险巡检Agent

- **触发：** 定时调度（每日/每周）
- **能力：** 自动扫描全量风险数据，识别异常模式、风险热点、覆盖缺口
- **输出：** 巡检报告、异常告警、优化建议
- **边界：** 仅报告建议，不自动执行任何变更

#### 6.4.2 策略效果评估Agent

- **触发：** 策略发布后定时评估（如发布后7天/30天）
- **能力：** 评估策略命中效果、误报率、覆盖率，与干跑结果对比
- **输出：** 效果评估报告、优化建议、是否建议回滚
- **边界：** 评估建议性质，策略变更必须走正式审批流程

#### 6.4.3 安全报告Agent

- **触发：** 定时调度或事件触发
- **能力：** 自动聚合数据生成安全报告（周报/月报/专项报告）
- **输出：** 格式化安全报告
- **边界：** 报告发布前需人工审核

### 6.5 智能体安全约束

```text
┌─────────────────────────────────────────────┐
│            智能体安全约束层                   │
├─────────────────────────────────────────────┤
│  1. 动作边界约束 — 明确可执行/不可执行动作     │
│  2. 审批前置约束 — 高危动作必须人工审批        │
│  3. TTL约束 — 自动动作默认带过期时间           │
│  4. 灰度约束 — 新规则/策略先灰度后全量          │
│  5. 审计约束 — 所有Agent动作必须审计留痕       │
│  6. 回滚约束 — 自动动作必须支持回滚            │
│  7. 失败约束 — 执行失败必须告警并转人工        │
│  8. 降级约束 — Agent不可用时降级为人工流程     │
└─────────────────────────────────────────────┘
```

**新增核心实体：**

- `agent_definition`：`agent_def_id`、名称、类型（L1/L2/L3）、能力描述、工具集合、约束规则、版本号、状态
- `agent_execution`：`execution_id`、`agent_def_id`、触发类型、触发对象、执行步骤JSON、执行结果、执行耗时、是否人工确认
- `agent_tool`：`tool_id`、工具名称、工具类型（API调用/数据查询/模型调用/知识检索）、权限级别、审批要求

### 6.6 智能体与现有模块集成

```text
┌──────────┐    触发     ┌──────────┐    分析     ┌──────────┐
│ 风险线索  │ ──────────→ │ 分析辅助  │ ──────────→ │ 处置响应  │
│ 生成事件  │            │  Agent   │            │  Agent   │
└──────────┘            └──────────┘            └──────────┘
                              │                      │
                         知识检索                  处置建议
                         攻击链还原                自动响应
                              │                      │
                              ▼                      ▼
┌──────────────────────────────────────────────────────┐
│                    现有业务服务层                       │
│  安全监控 ←→ 风险事件 ←→ 统一策略中心 ←→ 系统管理     │
└──────────────────────────────────────────────────────┘
                              ▲
                              │ 巡检/评估/报告
```

**集成原则：**

1. Agent通过现有API与业务服务交互，不绕过权限和审批
2. Agent执行记录纳入现有审计体系
3. Agent不可用时自动降级为人工流程，不影响业务连续性
4. Agent的自动响应规则纳入策略中心统一管理

## 8. 实施优先级与路线图

### 8.1 分期实施建议

```text
第一期（P0 — 核心AI能力）
├── 安全专用模型接入（Prompt注入检测、越狱识别）
├── 通用大模型研判辅助（事件研判摘要）
├── 风险评分融合引擎
└── 模型旁路调用架构

第二期（P1 — 分析与知识增强）
├── 高级SOC分析引擎（人员维度、关联分析）
├── 行为基线与异常检测
├── 知识库基础能力（知识条目管理、RAG检索）
├── 样本库建设
└── AI规则优化建议

第三期（P2 — 智能体与自动化）
├── L1分析辅助Agent（证据分析、攻击链还原）
├── L2处置响应Agent（自动研判、处置建议）
├── 自动响应Agent（受限模式）
├── 知识驱动安全问答
└── 安全报告自动生成

第四期（P3 — 自主运营）
├── L3自主运营Agent（风险巡检、策略评估）
├── 组织维度分析
├── 时序趋势预测
├── 策略模板库完善
└── 智能体管理平台
```

### 8.2 关键依赖关系

```text
安全专用模型接入 ←── 模型旁路架构（先建）
通用大模型研判  ←── 风险评分融合引擎（先建）
知识库RAG检索   ←── 向量数据库（先建）
高级SOC分析     ←── 数据聚合层（先建）
智能体调度      ←── 模型服务+知识服务+分析服务（先建）
自动响应        ←── 自动响应规则管理+审批流程（先建）
```

### 8.3 风险与注意事项

1. **模型幻觉风险** — AI研判和处置建议可能产生错误结论，必须保留人工确认环节，不可完全替代人工判断
2. **模型延迟风险** — 安全专用模型调用增加检测延迟，需设定超时降级策略
3. **知识投毒风险** — 知识库可能被恶意内容污染，需建立入库审核和定期巡检机制
4. **智能体失控风险** — Agent自动执行可能产生意外动作，需严格动作边界约束和审批前置
5. **数据隐私风险** — 模型调用需传输证据数据，需评估数据出境和隐私合规要求
6. **成本控制** — 大模型调用产生Token成本，需设定调用频率限制和成本预算

## 9. 总结

本需求分析从四个维度梳理了平台智能化改造需求，核心结论如下：

- **大模型引入**是智能化改造的基础，采用安全专用模型+通用大模型双层架构，以旁路模式接入，优先增强风险识别和研判环节（P0）
- **高级SOC分析**将分析维度从单条Trace/Span扩展到人员、组织、时序、关联和行为基线五个维度，显著提升安全分析深度
- **知识库安全能力**需同时建设知识库自身安全（内容安全、访问安全、更新安全）和知识库赋能安全（RAG增强、样本库、策略模板），并防范知识投毒和RAG注入等新型风险
- **智能体方案**按自主度分三层（L1分析辅助→L2处置响应→L3自主运营），每层都有明确的动作边界约束，确保AI自主性与安全可控性的平衡

四者之间形成协同关系：大模型提供基础AI能力，知识库为大模型提供领域知识支撑，高级分析为智能体提供分析输入，智能体将大模型、知识库和分析能力编排为自动化工作流。
