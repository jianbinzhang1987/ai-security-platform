# 大模型安全监测平台 — 智能化改造需求分析

## 执行摘要

本文档基于当前大模型安全监测平台的业务架构和技术架构，梳理了三大智能化增强方向的具体需求和实现路径：
1. **大模型能力引入** — 在分析、研判、风险评估等关键环节引入安全专用模型和通用大模型
2. **高阶SOC分析能力** — 从单维度事件检测升级到多维度、跨对象的关联分析
3. **知识库体系建设** — 构建安全知识库、规则库、案例库，并融合大模型能力形成智能分析闭环

---

## 第一部分：大模型能力集成规划

### 1.1 整体策略

大模型集成遵循"**渐进式融合**"原则：从低门槛、高收益的分析环节开始，逐步深化到策略优化和自适应检测。

#### 1.1.1 两类模型选型

| 模型类型 | 典型代表 | 使用场景 | 优势 | 劣势 |
|---------|--------|--------|------|------|
| **安全专用模型** | GLM-Security, Qwen-Security | Prompt检测、代码分析、恶意payload识别 | 领域精度高、推理成本低、可离线部署 | 需要专门微调、通用能力弱 |
| **通用大模型** | GPT-4, Claude, GLM-4, Qwen | 风险研判、推荐决策、报告生成、意图理解 | 理解能力强、支持多模态、可处理复杂推理 | 推理成本高、隐私风险、依赖外部API |

**建议混合策略**：
- 高频、实时检测环节 → 安全专用模型/本地部署
- 低频、离线分析环节 → 通用大模型/云端API
- 关键决策环节 → 同时支持两类模型对比

### 1.2 大模型集成的七大场景

#### **场景1：Prompt/输入智能分析与分类**（HIGH优先级）

**当前现状**：
- 规则引擎对Prompt进行词法、语法检测
- 缺乏对"隐性意图"和"变形攻击"的理解

**大模型增强方案**：
```
数据流：原始Prompt → 分词器(本地) → 安全专用模型 → 分析维度(意图、类型、风险信号)

分析维度：
  ✓ 显式恶意意图识别（prompt injection、jailbreak）
  ✓ 隐性意图识别（变形问法、迂回请求）
  ✓ 意图分类（正常查询、数据探测、权限提升、应用滥用）
  ✓ 相似性计算（与历史Prompt的相似度、变种检测）
  ✓ 上下文关联（多轮会话中的隐性演进）
```

**实现建议**：
- 轻量化模型（参数<7B）部署在网关侧，实时分析
- 复杂分析（多轮关联）离线处理，异步反馈

**输出指标**：
```json
{
  "prompt_id": "xxx",
  "intent_classification": "permission_escalation",  // 意图分类
  "risk_signals": [
    {"signal": "sql_injection_pattern", "confidence": 0.92},
    {"signal": "privilege_escalation_intent", "confidence": 0.85}
  ],
  "llm_risk_score": 8.5,           // LLM评分 0-10
  "rule_risk_score": 7.2,          // 规则评分 0-10
  "combined_risk_score": 8.8,      // 综合评分
  "similar_historical_events": [   // 相似历史事件
    {"event_id": "evt_123", "similarity": 0.94}
  ]
}
```

#### **场景2：输出安全性智能评估**（HIGH优先级）

**当前现状**：
- 检测输出中的敏感信息泄露（基于关键词、正则、模式）
- 无法理解"隐含泄露"（如间接推导的机密信息）

**大模型增强方案**：
```
数据流：模型输出 → 分词器 → 安全专用模型 → 语义理解与风险评估

评估维度：
  ✓ 直接敏感信息泄露（数据库密钥、API Key、用户隐私）
  ✓ 间接信息泄露（可被推导的机密、业务逻辑暴露）
  ✓ 异常输出检测（过长输出、循环输出、注入结果）
  ✓ 语义毒性检测（仇恨言论、骚扰、虚假信息）
  ✓ 合规性评估（GDPR、行业隐私法规）
  ✓ 内容真实性检查（幻觉检测、事实性验证）
```

**实现建议**：
- 在数据处理层增加"输出分析组件"
- 支持流式输出分析（token级别的实时评分）
- 可配置的风险阈值和动作（标记、阻断、脱敏）

**输出指标**：

    "compliance_flags": ["gdpr_violation"]

#### **场景3：风险关联与证据智能链接**（MEDIUM优先级）

**当前现状**：
- Trace/Span证据通过时间戳和ID关联
- 缺乏语义级别的风险关联（同一攻击者、同一活动、同一根因）

**大模型增强方案**：
```
数据流：多条风险Trace → 特征向量化 → 向量化匹配 → LLM关联分析

关联维度：
  ✓ 攻击者身份关联（IP、User Agent、行为特征）
  ✓ 活动链关联（多步骤、跨时间的同一活动）
  ✓ 根因分析（多条看似独立事件的共同原因）
  ✓ 攻击阶段识别（侦察→入侵→权提→数据窃取）
  ✓ IoC（Indicators of Compromise）抽取（IP、Domain、Hash）
```

**实现建议**：
- 建立"证据向量化引擎"，将Span特征转换为向量
- 使用向量数据库（Milvus/Weaviate）进行相似性匹配
- LLM用于复杂的语义关联和解释

**输出指标**：
```json
{
  "correlation_result": {
    "related_events": [
      {
        "event_id": "evt_456",
        "relation_type": "same_attacker",
        "confidence": 0.94,
        "reasoning": "相同的User-Agent和IP段，操作模式一致"
      }
    ],
    "attack_chain": [
      {"phase": "reconnaissance", "events": ["evt_123"]},
      {"phase": "exploitation", "events": ["evt_456"]},
      {"phase": "privilege_escalation", "events": ["evt_789"]}
    ],
    "ioc_extraction": [
      {"type": "ip", "value": "192.168.1.100", "context": "attacker_ip"},
      {"type": "hash", "value": "abc123...", "context": "malicious_payload"}
    ]
  }
}
```

#### **场景4：事件调查与根因分析自动化**（MEDIUM优先级）

**当前现状**：
- 安全监控模块依赖人工查看Trace/Span，形成调查结论
- 调查过程费时，标准化程度低

**大模型增强方案**：
```
数据流：风险Trace+Session上下文 → 多模态理解 → 自动化调查 → 结论推荐

自动化能力：
  ✓ 事件摘要生成（自动从Trace生成人类可读的风险描述）
  ✓ 上下文还原（将分散的Span信息整合为完整故事）
  ✓ 影响范围评估（本次事件可能波及的应用、用户、数据）
  ✓ 根因推荐（基于行为特征推荐可能的根本原因）
  ✓ 处置建议生成（自动推荐处置动作、优先级、TTL）
  ✓ 相似案例召回（从历史案例库检索相似事件）
```

**实现建议**：
- 调查工作台集成"AI辅助调查"模式
- 提供"一键生成调查报告"功能
- 支持安全人员的"同意/修改/驳回"反馈循环

#### **场景5：风险评分与优先级智能调整**（MEDIUM优先级）

**当前现状**：
- 风险等级由规则命中置信度决定，不考虑业务背景和历史信息

**大模型增强方案**：
```
数据流：事件特征 + 应用背景 + 历史数据 → 多因子评分 → 动态优先级

动态评分因子：
  ✓ 规则置信度（当前）
  ✓ 目标敏感度（目标应用/数据的重要性）
  ✓ 攻击者历史（是否为已知恶意行为者）
  ✓ 时间异常性（是否在异常时间段）
  ✓ 行为异常性（与用户历史行为的偏离程度）
  ✓ 扩散风险（该类攻击在行业内的传播速度）
  ✓ 应急容量（当前是否有余力处置）
```

**实现建议**：
- 在风险事件生成层，添加"评分调整引擎"
- 支持配置权重和调整规则
- 定期基于处置效果进行模型微调

**示例输出**：
```json
{
  "risk_scoring": {
    "base_score": 7.2,                    // 规则置信度

      {"factor": "attacker_history", "adjustment": +1.2, "reason": "用户有3次历史攻击"},
      {"factor": "time_anomaly", "adjustment": +0.8, "reason": "发生在非工作时间"},
      {"factor": "organizational_capacity", "adjustment": -0.5, "reason": "当前安全团队工作饱和"}

    "final_score": 10.2,
    "dynamic_severity": "critical",
    "recommendation": "立即处置，可触发高级审批"
  }
}
```

**大模型增强方案**：

数据流：历史误报+命中样本+领域知识 → 规则生成 → 规则优化建议

优化能力：

#### 1.3.2 关键组件设计

**1. LLM路由与调度模块**

```
决策树：
  ├─ 实时性要求高？
  │   ├─ 是 → 本地轻量模型（优先）或规则
  │   └─ 否 → 云端API
  ├─ 需要多模态理解？
  │   ├─ 是 → 云端通用大模型
  │   └─ 否 → 安全专用模型
  └─ 成本敏感性？
      ├─ 高 → 缓存命中 → 本地模型
      └─ 低 → 直接调用高精度模型
```

**2. 向量化与相似度匹配**

```
向量化流程：
  原始Span/事件 
    → 特征提取（IP、User Agent、操作、返回值等）
    → Embedding生成（使用sentence-transformer或专用模型）
    → 向量数据库存储（Milvus/Weaviate）
    → 相似度查询（计算距离，返回Top-K）
    → LLM语义验证（确认相似性的有效性）
```

**3. 提示词管理**

```
提示词分类：
  ├─ 系统提示词（角色定义、安全约束）
  ├─ 任务提示词（分析维度、输出格式）
  ├─ 示例提示词（Few-shot示例）
  └─ 约束提示词（禁止输出、敏感词过滤）

版本管理：
  └─ 提示词版本控制（Git）
  └─ A/B测试（验证提示词效果）
  └─ 性能指标追踪（准确率、延时、成本）
```

**4. 结果验证与质量控制**

```
验证层次：
  ├─ 输出格式验证（JSON Schema）
  ├─ 内容安全验证（无敏感信息泄露）
  ├─ 逻辑一致性验证（不自相矛盾）
  ├─ 业务规则验证（符合安全策略）
  └─ 人工复核（标签、反馈）
```

## 第二部分：高级SOC分析能力建设

### 2.1 当前SOC分析能力现状

**现有能力**：
- ✓ 单事件规则检测（Prompt/输出/工具调用违规）
- ✓ Trace级调查分析（证据链路还原）
- ✓ 应用维度的风险聚合（某应用有多少事件）

**缺失能力**：
- ✗ 用户维度的行为分析（User123在整个平台的活动风险）

#### **能力1：用户行为基线建立与异常检测**

**目标**：在用户维度建立正常行为基线，检测偏离基线的异常行为。

**核心指标**：
```
用户行为基线：
  ├─ 访问频率（日均访问次数、访问时段分布）
  ├─ 常用工具（频繁调用的工具集合）
  ├─ 数据访问范围（通常访问的应用、数据库、字段）
  ├─ 查询特征（查询复杂度、数据量范围）
  ├─ 时间特征（常见活跃时间、非工作时间活动）
  └─ 协作网络（常见协作者、通常的多人活动）

异常检测维度：
  ├─ 频率异常（突发高频访问）
  ├─ 时间异常（非常见时间段访问）
  ├─ 工具异常（使用陌生工具）
  ├─ 数据范围异常（访问超出历史范围的数据）
  ├─ 权限异常（使用权限外的工具/资源）
  └─ 行为演进异常（短期内行为大幅变化）
```

**实现方案**：

2. 特征工程：计算滑动窗口内的统计特征

3. 基线建立：使用统计或机器学习方法

   - 方法2：基于时间序列分解的动态基线（考虑周期性）
   - 方法3：基于聚类的用户分组基线（相似用户群体）
   
4. 异常检测：
   - 方法1：孤立森林（Isolation Forest）
   - 方法2：局部异常因子（LOF）
   - 方法3：自适应阈值（结合深度学习）
   
5. 告警生成：
   - 异常度评分 + 风险等级分类
   - 关联历史事件，确认是否为已知风险

  ├─ 时间关联（紧密的时间序列活动）
  ├─ 数据关联（操作同一数据对象）
  └─ 意图关联（多步活动组成的完整攻击链）

  ├─ 侦察阶段（枚举应用、权限探测）

4. 攻击链的端到端还原
   - 起点识别（初始可疑活动）
   - 中间节点连接（通过身份、数据、时间关联）
   - 终点识别（最终目标或成果）

#### **能力3：图谱化分析 — 用户/应用/工具/数据网络**

**目标**：构建和分析用户、应用、工具、数据之间的多维关联网络，发现异常模式。

**核心图谱**：
```
图谱节点类型：
  ├─ User（用户）
  ├─ App（应用）
  ├─ Tool（工具/MCP）
  ├─ Resource（数据/资源）
  └─ Permission（权限）

边的类型：
  ├─ User -[调用]-> Tool
  ├─ User -[访问]-> Resource
  ├─ User -[协作]-> User
  ├─ App -[包含]-> Tool
  ├─ Tool -[访问]-> Resource
  ├─ User -[拥有]-> Permission
  └─ Permission -[关联]-> Resource

异常图谱模式（网络异常检测）：
  ├─ 星型模式（一个用户集中访问多个资源）
  ├─ 路径异常（用户走了不寻常的访问路径）
  ├─ 子图异常（一个用户集群内的异常互动）
  ├─ 权限异常（权限使用不匹配）
  └─ 孤立异常（突然出现的新节点或边）
```

**实现方案**：
```
1. 图数据库存储（Neo4j/ArangoDB）
   - 实时更新用户、应用、工具、资源的关系
   
2. 图特征计算
   - 节点中心性（degree, betweenness, closeness, eigenvector）
   - 社区检测（用户协作团体、应用集群）
   - 子图模式挖掘（高频访问模式）
   
3. 异常检测
   - 基于中心性的异常（节点的关系数异常）
   - 基于路径的异常（最短路径、跳数异常）
   - 基于权限的异常（权限使用违规）
   - 时间动态的异常（图随时间的演化异常）
   
4. 可视化与查询
   - 图遍历API（查询某用户的所有访问路径）
   - 子图抽取（提取关联子图用于分析）
   - 路径推荐（对于某目标，最可能的访问路径）

#### **能力4：集群化分析 — 协同攻击与内鬼检测**

**目标**：识别多个用户间的协同行为，检测内鬼、组织性攻击等。

**核心方法**：
```
协同行为检测维度：
  ├─ 时间同步性（多个用户的活动时间高度一致）
  ├─ 行为同步性（多个用户执行相同的操作序列）
  ├─ 数据同步性（多个用户访问同一数据对象）
  ├─ 目标一致性（多个用户的最终目标相同）
  └─ 身份特征同步性（IP段、User-Agent相似）

内鬼检测特征：
  ├─ 高权限滥用（特定权限的异常使用激增）
  ├─ 敏感数据访问（历史不访问的数据被批量导出）
  ├─ 时间反常（工作时间外的频繁访问）
  ├─ 行为变化（突然的行为模式转变）
  └─ 通道隐蔽性（利用多个身份掩盖痕迹）
```

**实现方案**：
```
1. 用户聚类
   - 基于行为特征的聚类（K-means、DBSCAN）
   - 动态时间规整（DTW）计算行为序列相似度
   
2. 协同强度评分
   - 时间同步强度（时间序列相关系数）
   - 行为同步强度（操作序列相似度）
   - 数据访问同步强度（访问相同资源的频率）
   
3. 威胁群体识别
   - 聚类后的高协同强度群体
   - 群体规模、活动持续时间、目标对象
   
4. 内鬼评分
   - 权限滥用指数（使用高权限的频率）
   - 敏感访问指数（访问敏感资源的频率）
   - 异常变化指数（行为与历史的偏离度）
   - 隐蔽性指数（是否使用多个身份）
```

## 第三部分：知识库体系建设

### 3.1 知识库体系概览

**定义**：知识库是系统积累的安全专业知识、历史案例、规则经验和行业威胁情报的集合。通过融合大模型能力，提升分析、检测和决策的智能化程度。

**知识库分类**：
```
┌─ 安全知识库
│  ├─ 规则库（检测规则、告警规则）
│  ├─ 威胁情报库（IoC、攻击TTP、CVE）
│  ├─ 防御方案库（处置动作、缓解策略）
│  └─ 最佳实践库（配置示例、案例分享）
