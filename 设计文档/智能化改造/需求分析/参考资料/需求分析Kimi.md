# 大模型安全监测平台智能化改造需求分析

> 基于当前系统架构，梳理三大增强方向：大模型引入、SOC分析能力提升、知识库安全能力建设

---

## 一、大模型引入需求分析

### 1.1 引入策略与模型选型

#### 模型分层架构

```
┌─────────────────────────────────────────────┐
│           通用大模型（研判层）                │
│  • 研判分析  • 报告生成  • 处置建议           │
│  • 攻击链还原  • 知识问答  • 风险预测         │
├─────────────────────────────────────────────┤
│          安全专用模型（检测层）               │
│  • Prompt注入检测  • 越狱识别              │
│  • 敏感内容识别  • 工具边界判定             │
├─────────────────────────────────────────────┤
│            规则引擎（基础层）                │
│  • 关键词/正则/条件表达式匹配               │
└─────────────────────────────────────────────┘
```

#### 两类模型选型建议

| 模型类型 | 典型代表 | 使用场景 | 接入方式 | 性能要求 |
|---------|---------|---------|---------|---------|
| **安全专用模型** | GLM-Security、Qwen-Security、内部安全模型 | Prompt检测、越狱识别、恶意payload识别 | 本地化部署/私有化API | 延迟<200ms |
| **通用大模型** | GPT-4、Claude、GLM-4、Kimi | 风险研判、攻击链还原、报告生成、处置建议 | API调用/混合部署 | 允许异步1-5s |

**核心原则**：
- 基础层保证低延迟确定性检测
- 检测层提升语义级检出率（覆盖隐式攻击）
- 研判层增强复杂推理和综合分析
- 三层并行运行，结果融合输出综合风险评分

---

### 1.2 安全专用模型引入场景（P0优先级）

#### 场景1: Prompt注入检测增强

**当前瓶颈**：规则只能识别已知注入模式，无法检测语义级隐式注入、多轮累积注入

**增强方案**：
- 安全专用模型对输入进行语义级分析
- 覆盖直接注入、间接注入、上下文注入、多轮累积注入
- 输出：风险标签 + 置信度 + 攻击类型 + 攻击片段定位

**数据模型影响**：
- `span_observation` 增加 `ai_detection_result` (JSON) 字段
- `risk_clue` 增加 `detection_source` 枚举（`rule`/`ai_model`/`rule_and_ai`）

**输出示例**：
```json
{
  "prompt_id": "xxx",
  "ai_detection": {
    "risk_labels": ["sql_injection_pattern", "privilege_escalation_intent"],
    "confidence": 0.92,
    "attack_type": "direct_injection",
    "evidence_offset": [125, 140],
    "severity": "high"
  },
  "detection_source": "rule_and_ai"
}
```

#### 场景2: 越狱攻击识别增强

**当前瓶颈**：规则难以识别新型越狱模式（角色扮演越狱、编码绕过、多轮诱导、指令覆盖）

**增强方案**：
- 语义级越狱识别
- 越狱类型分类（角色扮演、编码绕过、多轮诱导、指令覆盖）
- 输出越狱类型 + 置信度 + 诱导路径还原

#### 场景3: 敏感内容识别增强

**当前瓶颈**：无法理解"隐性泄露"（如间接推导的机密信息）

**增强方案**：
- 对模型输出进行语义级敏感分类
- 检测类型：个人隐私、商业秘密、合规违规、有害内容、内部泄露、间接信息泄露
- 输出敏感类型 + 置信度 + 敏感片段定位

#### 场景4: 工具边界判定增强

**当前瓶颈**：仅能通过规则匹配判断工具调用合规性

**增强方案**：
- 分析工具调用意图与声明范围的匹配度
- 识别意图偏移调用、参数篡改、级联越权、资源越界访问
- 输出：越界类型 + 置信度 + 建议动作

### 1.3 通用大模型引入场景（P0-P1优先级）

#### 场景5: 智能研判辅助（P0）

**应用环节**：风险事件模块

**功能描述**：
- 基于Trace/Span证据自动生成风险研判摘要
- 包含：攻击手法分析、影响面评估、相似历史事件关联、处置优先级建议
- 安全运营可确认、修正或补充

**数据模型影响**：
- `risk_event` 增加 `ai_analysis` (JSON) 字段
- `risk_event` 增加 `ai_analysis_status` 枚举（`pending`/`generated`/`confirmed`/`revised`）

**输出示例**：
```json
{
  "ai_analysis": {
    "event_summary": "检测到用户User123通过提示词注入尝试越权访问数据库信息",
    "attack_technique": "SQL注入变形 — 利用上下文绕过输入验证",
    "impact_scope": {
      "affected_apps": ["app_a"],
      "affected_resources": ["user_table", "config_table"],
      "data_exposure_risk": "medium"
    },
    "similar_events": ["evt_456", "evt_789"],
    "recommended_priority": "high",
    "disposition_suggestions": [
      {"action": "limit_tool_permissions", "scope": "user_123", "ttl": "7d"}
    ]
  },
  "ai_analysis_status": "confirmed"
}
```

#### 场景6: 攻击链自动还原（P0）

**应用环节**：安全监控 — 风险溯源工作台

**功能描述**：
- 基于完整Span序列自动还原攻击链路
- 标注攻击阶段（侦察→入侵→权提→数据窃取）
- 意图推断和关键转折点标记
- 在溯源工作台增加"AI攻击链视图"

#### 场景7: 处置建议生成（P0）

**应用环节**：风险事件 — 处置动作创建

**功能描述**：
- 基于风险类型、影响面、历史处置记录自动生成处置建议
- 包含：推荐动作类型、建议范围、TTL建议、影响评估、审批级别推荐
- 运营可一键采纳或修改

**数据模型影响**：
- `event_action` 增加 `ai_suggested` (bool) 字段

#### 场景8: 规则优化建议（P1）

**应用环节**：统一策略中心

**功能描述**：
- 分析误报/命中样本，自动生成规则调整建议
- 包含：条件修改建议、阈值调整建议、新增规则建议
- 支持干跑验证闭环

**数据模型影响**：
- `rule` 增加 `ai_optimized` (bool) 和 `optimization_source` 字段

#### 场景9: 安全报告自动生成（P1）

**应用环节**：安全总览

**功能描述**：
- 基于事件数据、风险趋势、处置记录自动生成周报/月报/专项报告
- 支持多角色视图（管理层/运营层/技术层）
- 支持自定义模板

### 1.4 模型接入架构设计

#### 融合评分引擎

```
规则引擎(同步) ──┐
                ├── 风险评分融合引擎 ──→ 现有业务服务层
安全专用模型(近同步) ──┤
                │
通用大模型(异步) ────┘
```

#### 关键设计要求

1. **旁路模式**：模型调用采用旁路模式，不可用时规则引擎独立运行
2. **降级策略**：安全专用模型延迟>200ms时降级到规则引擎；通用大模型失败时标记为待人工分析
3. **审计留痕**：所有模型输入输出必须审计留痕（`model_audit_log`）
4. **可解释性**：模型结果必须可解释、可追溯、可人工覆盖
5. **版本管理**：模型版本纳入策略版本体系，支持灰度切换

### 1.5 各环节大模型引入审视汇总

| 系统环节 | 可引入的模型能力 | 优先级 | 模型类型 | 部署模式 |
|---------|-----------------|-------|---------|---------|
| **风险识别层** | 语义级Prompt检测、越狱识别、多轮风险累积识别 | **P0** | 安全专用模型 | 本地化 |
| **风险溯源层** | AI攻击链还原、证据摘要生成、相似事件关联 | **P0** | 通用大模型 | API异步 |
| **事件研判层** | AI研判摘要、处置建议生成、影响面评估 | **P0** | 通用大模型 | API异步 |
| **策略治理层** | AI规则优化建议、自动干跑验证、策略效果预测 | P1 | 混合 | 本地+API |
| **安全总览层** | AI态势摘要、风险预测、安全评分 | P1 | 通用大模型 | API异步 |
| **通知联动层** | AI告警聚合、智能降噪、告警优先级排序 | P2 | 安全专用模型 | 本地化 |
| **审计分析层** | AI异常行为识别、审计异常检测 | P2 | 通用大模型 | API异步 |

## 二、高级SOC分析能力建设需求

### 2.1 当前分析能力现状

**现有能力**：
- ✓ 单事件规则检测（Prompt/输出/工具调用违规）
- ✓ Trace级调查分析（证据链路还原）
- ✓ 应用维度的风险聚合（某应用有多少事件）

**核心瓶颈**：分析停留在**单点检测+人工串联**，缺乏：
- ✗ 人员维度跨会话风险累积
- ✗ 组织维度风险态势聚合
- ✗ 时序维度风险演化趋势
- ✗ 关联维度跨应用风险传播
- ✗ 行为基线维度异常识别

---

### 2.2 人员维度分析能力（P0优先级）

#### 功能1: 用户风险画像

**目标**：聚合同一用户标识下所有风险事件/线索/命中记录

**输出内容**：
- 用户风险等级综合评分
- 风险类型分布（Prompt注入、越狱、工具越界等）
- 风险趋势（近7天/30天变化）
- 高风险行为模式识别

**新增实体**：`user_risk_profile`

```json
{
  "user_id": "user_123",
  "risk_profile": {
    "composite_score": 8.5,
    "risk_level": "high",
    "risk_distribution": {
      "prompt_injection": 12,
      "jailbreak": 3,
      "tool_boundary_violation": 8
    },
    "trend_7d": "increasing",
    "trend_30d": "stable"
  }
}
```

#### 功能2: 用户行为基线建立与异常检测

**目标**：在用户维度建立正常行为基线，检测偏离基线的异常行为

**基线指标**：
```
用户行为基线：
  ├─ 访问频率（日均访问次数、访问时段分布）
  ├─ 常用工具（频繁调用的工具集合）
  ├─ 数据访问范围（通常访问的应用、数据库、字段）
  ├─ 查询特征（查询复杂度、数据量范围）
  ├─ 时间特征（常见活跃时间、非工作时间活动）
  └─ 协作网络（常见协作者、通常的多人活动）
```

**异常检测维度**：
- 频率异常（突发高频访问）
- 时间异常（非常见时间段访问）
- 工具异常（使用陌生工具）
- 数据范围异常（访问超出历史范围的数据）
- 权限异常（使用权限外的工具/资源）
- 行为演进异常（短期内行为大幅变化）

**技术实现**：
- 基线建立：统计分位数 / 时间序列分解 / 聚类分组基线
- 异常检测：孤立森林（Isolation Forest）/ LOF / 自适应阈值

**新增实体**：`user_behavior_baseline`、`user_anomaly_detection`

#### 功能3: 用户风险累积识别

**目标**：识别多轮会话中低风险行为的累积升级

**输出内容**：
- 累积评分和关键转折点
- 从低风险试探到高风险攻击的演进路径
- 预警提示（累积评分达到阈值时告警）

**新增实体**：`user_risk_accumulation`

#### 功能4: 高风险用户排行

**目标**：按用户维度聚合风险评分，识别需要重点关注的用户

**应用场景**：安全总览增加"人员风险视图"

---

### 2.3 组织/业务线维度分析（P1优先级）

#### 功能5: 业务线风险态势

**目标**：按业务线聚合应用风险、事件数量、处置效率

**输出内容**：
- 业务线级风险评分
- 风险类型分布
- MTTD（平均检测时间）/ MTTR（平均响应时间）
- 环比/同比趋势

**新增实体**：`org_risk_profile`

#### 功能6: 租户级风险聚合

**目标**：按租户聚合全量风险数据，识别跨应用风险传播

**应用场景**：多租户环境下的全局风险视图

#### 功能7: 组织内风险热点识别

**目标**：识别风险集中应用和高风险Agent/工具

**输出内容**：
- 风险集中度热力图
- 高风险Agent排行榜
- 高风险工具调用趋势

---

### 2.4 时序与趋势分析（P1优先级）

#### 功能8: 风险趋势预测

**目标**：基于历史数据预测未来趋势，识别拐点和季节性模式

**应用场景**：安全总览增加"风险预测视图"

#### 功能9: 攻击周期识别

**目标**：识别周期性攻击模式（特定时段高峰）

#### 功能10: 风险演化追踪

**目标**：追踪风险类型从出现到爆发的演化过程

---

### 2.5 关联与传播分析（P0-P1优先级）

#### 功能11: 跨应用风险关联（P0）

**目标**：识别共享工具/资源/模型的应用间风险传播

**应用场景**：
- 某工具出现漏洞时，快速识别所有受影响应用
- 跨应用攻击链追踪

#### 功能12: 工具/资源风险传播分析（P0）

**目标**：追踪高风险工具被多Agent/应用调用的风险扩散

**输出内容**：
- 工具风险传播路径图
- 受影响应用清单
- 建议处置范围

#### 功能13: 攻击链路关联（P1）

**目标**：将分散在不同Trace中的攻击行为关联为完整攻击链

**技术实现**：
- 基于身份、IP、时间、行为模式的关联
- 使用向量数据库进行相似性匹配
- LLM用于复杂语义关联和解释

**输出示例**：
```json
{
  "attack_chain": {
    "chain_id": "chain_001",
    "phases": [
      {"phase": "reconnaissance", "events": ["evt_123"], "time": "2024-01-15 13:00"},
      {"phase": "exploitation", "events": ["evt_456"], "time": "2024-01-15 13:30"},
      {"phase": "privilege_escalation", "events": ["evt_789"], "time": "2024-01-15 14:00"}
    ],
    "estimated_attacker": "user_123",
    "confidence": 0.92
  }
}
```

### 2.6 行为基线与异常检测（P1优先级）

#### 功能14: 应用行为基线

**目标**：建立应用级正常行为基线，检测偏离

**基线指标**：
- 调用频率分布
- 常用工具集合
- 典型响应时间
- 异常错误率阈值

#### 功能15: Agent行为基线

**目标**：建立Agent级正常行为基线，检测行为偏移

#### 功能16: 全局异常检测

**目标**：统计模型检测全局异常模式

**检测类型**：
- 突发流量异常
- 新型攻击模式识别
- 未知风险类型发现

### 2.7 高级分析引擎架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    高级分析引擎                          │
├──────────────┬──────────────┬──────────────┬────────────┤
│    人员分析    │    组织分析   │    时序分析   │   关联分析  │
├──────────────┴──────────────┴──────────────┴────────────┤
│              行为基线与异常检测模块                       │
├─────────────────────────────────────────────────────────┤
│              分析任务调度与结果存储                       │
├─────────────────────────────────────────────────────────┤
│     数据聚合层（Trace/Span/Event/Session）              │
└─────────────────────────────────────────────────────────┘
```

**关键设计要求**：
1. 异步批处理不影响实时检测
2. 分析结果独立存储，支持高效查询
3. 支持定时调度（每小时/每天）和手动触发
4. 结果可下钻到原始数据
5. 行为基线支持自动更新和人工审核

## 三、知识库安全能力建设需求

### 3.1 知识库引入目的

1. **安全运营知识检索**：攻击手法库、处置预案库、合规要求库
2. **AI研判领域知识支撑**：安全知识增强研判准确性和可解释性
3. **规则优化样本库**：误报/命中/攻击样本沉淀
4. **策略配置最佳实践库**：策略模板、场景化配置

---

### 3.2 知识库自身安全能力建设

#### 3.2.1 知识内容安全（P0优先级）

| 安全能力 | 描述 | 实现方式 |
|---------|-----|---------|
| **入库前安全审核** | 检测敏感信息、注入内容、有害内容 | AI内容安全检测 + 人工审核 |
| **知识版本管理** | 版本化存储，支持回滚和变更审计 | Git式版本控制 |
| **来源可信验证** | 标记来源（人工/AI生成/外部导入），按来源设信任等级 | 来源标签 + 信任评分 |
| **过期与失效管理** | 设置有效期，过期自动标记降级 | 有效期字段 + 定时巡检 |

#### 3.2.2 知识访问安全（P0优先级）

| 安全能力 | 描述 | 实现方式 |
|---------|-----|---------|
| **知识分级访问控制** | 按敏感级别设置访问权限 | RBAC + 敏感级别标签 |
| **检索审计** | 记录检索人、检索内容、检索时间 | `knowledge_access_log` |
| **导出控制** | 知识导出需审批和审计 | 导出审批流程 |
| **防泄露** | 知识内容脱敏展示，完整内容需授权 | 脱敏规则 + 授权访问 |

#### 3.2.3 知识更新安全（P1优先级）

| 安全能力 | 描述 | 实现方式 |
|---------|-----|---------|
| **变更审批** | 新增/修改/删除需审批 | 工作流审批 |
| **AI生成知识审核** | AI生成条目需人工审核后才可发布 | 待审核状态 + 人工确认 |
| **冲突检测** | 检测新旧知识矛盾 | 相似度检测 + 规则冲突检测 |
| **影响面评估** | 变更前评估对依赖规则/策略的影响 | 依赖关系图 + 影响分析 |

### 3.3 知识库赋能安全能力（P0-P1优先级）

#### 3.3.1 安全知识检索增强研判（P0）

**应用场景**：安全运营在风险溯源工作台调查时

**功能描述**：
- 基于当前风险特征自动检索相关攻击手法、历史案例、处置预案
- AI研判引用知识库内容，增强准确性和可解释性
- 展示知识来源引用，可追溯可验证

**实现方式**：RAG（检索增强生成）

#### 3.3.2 RAG增强AI检测与研判（P0）

**架构设计**：
```
查询/检测请求
    ↓
向量化检索 ──→ 向量数据库 ──→ Top-K相关知识
    ↓                              ↓
安全专用模型/通用大模型 ←── 检索结果增强
    ↓
检测/研判输出（带知识引用）
```

**应用场景**：
- 安全专用模型检测时检索相关攻击模式知识
- 通用大模型研判时检索历史案例和处置预案

#### 3.3.3 样本库支撑规则优化（P1）

| 样本库类型 | 用途 | 数据模型 |
|-----------|-----|---------|
| **误报样本库** | 沉淀误报样本，支撑干跑验证和阈值调优 | `sample_entry` (type=`false_positive`) |
| **命中样本库** | 沉淀确认命中样本，支撑规则效果评估 | `sample_entry` (type=`true_positive`) |
| **攻击样本库** | 沉淀已知攻击样本，支撑新规则开发和模型微调 | `sample_entry` (type=`attack`) |

**AI辅助样本标注**：
- 自动标注建议
- 减少人工标注成本

#### 3.3.4 策略模板库加速治理（P1）

**模板类型**：
- 场景化策略模板（防注入、防越狱、工具边界控制）
- 行业最佳实践库
- 合规要求映射库

**应用场景**：策略中心创建策略时，提供模板推荐

#### 3.3.5 知识驱动安全问答（P2）

**应用场景**：安全运营自然语言提问

**功能描述**：
- 自然语言提问获取安全知识、处置指引、历史案例
- 问答结果引用知识来源，可追溯可验证
- 支持知识缺口识别：无法匹配时标记缺口

### 3.5 知识库安全风险与防护矩阵

| 风险类型 | 描述 | 防护措施 | 优先级 |
|---------|-----|---------|-------|
| **知识投毒** | 恶意知识条目影响AI判断 | 入库审核 + AI内容安全检测 + 信任等级分级 | P0 |
| **知识泄露** | 敏感知识被未授权访问 | 分级访问控制 + 检索审计 + 脱敏展示 | P0 |
| **知识过时** | 过期知识导致错误判断 | 有效期管理 + 自动降级 + 定期审核 | P1 |
| **知识冲突** | 矛盾知识导致判断不一致 | 冲突检测 + 优先级排序 + 人工裁决 | P1 |
| **RAG注入** | 通过知识库间接注入AI | 知识内容安全扫描 + 检索结果过滤 + 来源可信验证 | P0 |
| **依赖失效** | 知识变更导致依赖规则/策略失效 | 影响面评估 + 变更审批 + 灰度发布 | P1 |

## 四、智能体方案（可选增强方向）

### 4.1 智能体分层架构

```
┌─────────────────────────────────────────────┐
│              智能体分层架构                    │
├─────────────────────────────────────────────┤
│  L3: 自主运营Agent — 长周期自主安全运营       │
│      周期性风险巡检、策略效果评估、报告生成     │
├─────────────────────────────────────────────┤
│  L2: 处置响应Agent — 事件驱动的自动响应       │
│      自动研判、处置建议、受限自动响应执行       │
├─────────────────────────────────────────────┤
│  L1: 分析辅助Agent — 任务驱动的分析辅助       │
│      证据分析、攻击链还原、知识检索            │
└─────────────────────────────────────────────┘
```

### 4.2 L1: 分析辅助Agent（P1优先级）

| Agent | 触发条件 | 能力 | 输出 | 边界 |
|-------|---------|-----|-----|-----|
| **证据分析Agent** | 新风险线索生成 | 自动读取证据，调用模型分析 | 证据摘要、攻击手法、风险评分、相似事件 | 仅分析建议，不执行处置 |
| **攻击链还原Agent** | 溯源工作台请求 | 串联跨Span攻击行为 | 攻击链路图、阶段标注、意图推断 | 仅还原展示，不改变数据状态 |
| **知识检索Agent** | 运营提问或研判 | 自然语言检索知识库 | 知识结果、相关性评分、来源引用 | 仅检索展示，不修改知识库 |

### 4.3 L2: 处置响应Agent（P2优先级）

| Agent | 触发条件 | 能力 | 边界 |
|-------|---------|-----|-----|
| **自动研判Agent** | 新事件创建 | 综合证据、知识、历史案例生成研判结论 | 建议性质，高危事件需人工确认 |
| **处置建议Agent** | 事件确认后 | 生成处置方案（动作、范围、TTL、影响评估） | 建议性质，高危处置需人工审批 |
| **自动响应Agent**（受限） | 满足预定义自动响应规则 | 执行通知发送、低风险限制 | 仅可执行白名单动作，必须人工审批高危动作 |

**自动响应安全约束**：
- 可自动执行：通知发送、低风险会话限制（TTL自动过期）、告警升级
- 不可自动执行：应用降级、工具禁用、主体阻断、策略变更
- 所有自动执行动作必须写入审计日志
- 自动响应规则需审批后启用，支持灰度模式


### 5.6 风险与注意事项

| 风险类型 | 描述 | 缓解措施 |
|---------|-----|---------|
| **模型幻觉** | AI研判和处置建议可能产生错误结论 | 保留人工确认环节，不可完全替代人工判断 |
| **模型延迟** | 安全专用模型调用增加检测延迟 | 设定超时降级策略（>200ms降级到规则） |
| **知识投毒** | 知识库可能被恶意内容污染 | 入库审核 + 定期巡检 + 信任等级 |
| **智能体失控** | Agent自动执行可能产生意外动作 | 严格动作边界约束和审批前置 |
| **数据隐私** | 模型调用需传输证据数据 | 评估数据出境和隐私合规要求 |
| **成本控制** | 大模型调用产生Token成本 | 设定调用频率限制和成本预算 |

## 六、总结

本需求分析从三个核心维度梳理了平台智能化改造需求：

### 核心结论

1. **大模型引入**是智能化改造的基础
   - 采用安全专用模型+通用大模型双层架构
   - 以旁路模式接入，优先增强风险识别和研判环节（P0）
   - 关键价值：提升语义级检出率、减少人工研判时间、增强复杂推理能力

2. **高级SOC分析**将分析维度从单条Trace/Span扩展到多维度
   - 人员维度：用户风险画像、行为基线、风险累积
   - 组织维度：业务线态势、租户级聚合
   - 关联维度：跨应用风险传播、攻击链路还原
   - 关键价值：从被动响应转向主动防御，提前发现高级威胁

3. **知识库安全能力**需同时建设自身安全和赋能安全
   - 自身安全：内容安全、访问安全、更新安全
   - 赋能安全：RAG增强检测研判、样本库支撑规则优化、策略模板加速治理
   - 关键价值：知识沉淀与复用，持续提升AI能力和运营效率

### 三者协同关系

```
┌─────────────┐    领域知识支撑    ┌─────────────┐
│   大模型     │ ←──────────────→ │   知识库     │
│  (推理能力)  │                   │  (知识沉淀)  │
└──────┬──────┘                   └──────┬──────┘
       │                                  │
       │    分析输入    ┌─────────────┐   │
       └──────────────→ │  高级SOC分析 │ ←─┘
                        │  (多维度洞察)│
                        └──────┬──────┘
                               │
                               ↓
                        ┌─────────────┐
                        │   智能体     │
                        │ (自动化编排) │
                        └─────────────┘
```

- **大模型**提供基础AI能力
- **知识库**为大模型提供领域知识支撑
- **高级分析**为智能体提供分析输入
- **智能体**将大模型、知识库和分析能力编排为自动化工作流
