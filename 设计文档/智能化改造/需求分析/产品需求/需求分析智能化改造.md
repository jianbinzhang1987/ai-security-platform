# 大模型安全监测平台智能化改造需求规格

## 1. 文档说明

### 1.1 目标

基于当前平台概要设计和现有原型图，以**核心闭环+基础底座+增强能力**的结构梳理智能化改造需求，确保方案可交付、可验收、可控风险。

### 1.2 需求拆解原则

- **核心闭环优先**：先跑通一条端到端价值链路，再扩展增强能力
- **业务场景为主维度**：需求按业务场景拆解，不按技术组件拆解
- **大模型引入不区分专用/通用**：需求阶段仅描述"需要大模型增强什么能力"
- **智能体是跨场景实现机制**：Agent的L1/L2/L3分层归入架构设计而非独立需求章节
- **端到端完整性**：每个场景从输入到输出完整描述，避免重复
- **可验收**：每个AI能力必须配验收指标和门禁值
- **可控风险**：数据隐私、模型幻觉、成本爆炸等风险必须在需求层明确约束

## 2. 现状与差距

### 2.1 当前风险识别链路

```text
网关/探针采集 → 规则匹配 → 风险打分 → 风险线索 → 人工调查 → 事件闭环
```

核心特征：风险识别依赖静态规则，研判依赖人工，分析停留在单条Trace/Span级别。

### 2.2 能力瓶颈

| 环节 | 当前能力 | 瓶颈 |
|---|---|---|
| 风险识别 | 规则匹配+关键词/正则 | 无法识别语义级注入、隐式越狱、多轮累积风险 |
| 风险研判 | 人工查看证据→人工判断 | 效率低，依赖经验，误报率高 |
| 证据分析 | 展示结构化证据/JSON/Raw | 缺乏自动摘要、攻击链还原、影响面评估 |
| 策略优化 | 误报标记→人工调整规则 | 优化周期长，缺乏自动调优 |
| SOC分析 | 单条Trace/Span维度统计 | 缺乏人员/组织/时序等高维分析 |
| 处置决策 | 人工选择动作和范围 | 缺乏智能建议和自动响应 |

### 2.3 原型图功能覆盖现状

| 模块 | 已有页面 | 功能范围 |
|---|---|---|
| 安全总览 | dashboard | 5指标卡、7日趋势、高风险对象排行、监控覆盖概况 |
| 资产中心 | app/agent/server/tool/coverage/topology等 | 接入应用、智能体、网关探针、工具暴露面、覆盖度 |
| 安全监控 | trace-list/board, prompt-search, saved-views, session-list | 风险溯源工作台、内容检索、意图偏离分析 |
| 风险事件 | event-list, event-detail | 事件列表、详情(概况/证据/处置/审批台账) |
| 策略中心 | 网关策略4类+探针策略3类+通知渠道 | 访问控制/流量治理/提示词防护/会话审计/策略包/规则项 |
| 报告中心 | report-list/new/subscriptions | 报告列表、自定义报告、订阅 |
| 系统管理 | user/audit/apikey/tenant/service/collector/deploy | 用户权限、审计、租户、服务状态、采集器 |

**缺失模块：** 知识库管理、高级SOC多维分析、自动响应规则、智能体管理。
**需AI增强的现有模块：** 内容安全策略（AI检测配置）、高级规则项（AI增强实现方式）。

## 3. 核心闭环与基础底座

### 3.1 核心闭环

智能化改造的最短价值路径——从检测到反馈的端到端闭环：

```text
采集证据 → 规则初判 → AI语义补判 → 风险线索/事件 → AI研判摘要 → 人工确认/修正 → 样本沉淀 → 规则/模型评估
```

闭环约束：每个环节必须有可观测的输出和验收标准；人工确认/修正的反馈必须回流到样本库；样本库支撑规则优化和模型评测，形成持续改进循环。

### 3.2 三个基础底座

所有场景的公共依赖，必须在场景功能之前建设：

#### 底座1：AI调用与治理底座

- **模型网关**：统一模型调用入口，支持多模型注册、版本管理、灰度切量
- **Prompt模板管理**：版本化Prompt模板，与模型版本绑定
- **调用审计**：所有模型输入输出必须审计留痕，含模型版本、Prompt版本、耗时、成本
- **成本限额**：每条Span的AI检测Token上限、每事件的AI研判Token上限、月度预算告警阈值
- **降级策略**：模型超时/错误时的降级行为（跳过AI/纯规则结果/重试）
- **熔断器**：连续N次超时/错误后自动熔断并告警，切回规则引擎
- **评测机制**：攻击样本集、正常业务样本集、回归测试、模型版本对比、上线门禁

#### 底座2：证据与数据安全底座

**模型输入分级策略：**

| 数据级别 | 内容 | AI调用策略 |
|---|---|---|
| L0 公开 | 脱敏后的结构化摘要 | 可传外部模型 |
| L1 内部 | 脱敏证据文本、风险标签 | 可传私有化模型，外部模型需审批 |
| L2 敏感 | 含PII的Prompt原文、Raw证据 | 仅传私有化模型，禁止传外部API |
| L3 机密 | 完整用户输入、未脱敏原始数据 | 仅本地模型，禁止任何外部传输 |

- **证据引用机制**：AI调用默认传脱敏证据引用（trace_id/span_id/字段路径），不传Raw原文
- **Raw访问审批**：高敏Raw调用必须走审批流程，记录访问人、审批编号、用途
- **租户隔离**：模型调用日志按租户隔离，跨租户不可见

#### 底座3：反馈与样本底座

- **样本采集**：误报标记、确认命中、漏报补充自动进入样本库
- **人工标注**：支持标注样本的风险类型、严重程度、是否为边界案例
- **回放评估**：规则/模型变更前，用历史样本集回放验证效果
- **反馈回流**：人工确认/修正AI研判后，反馈自动回流样本库，标注采纳/修正/拒绝状态
- **评估集管理**：维护攻击样本集、正常业务样本集、边界样本集，支撑模型评测

**样本集分类与流转规则：**

| 样本集类型 | 用途 | 来源 | 流转规则 |
|---|---|---|---|
| **候选集** | 新采集样本的暂存区 | 误报标记、确认命中、漏报补充、人工修正 | 人工修正样本先入候选集，经复核后可进入其他集 |
| **训练集** | 模型微调训练 | 从候选集经复核后转入 | 仅限模型微调使用，不可用于验收评测 |
| **评测集（固定）** | 模型版本上线门禁 | 从候选集经复核+固定后转入 | 固定后不可修改，用于上线门禁FPR/FNR验收 |
| **回归集** | 规则/模型变更后的回放验证 | 从候选集经复核后转入 | 变更前回放，验证不退化 |
| **争议集** | 人工与AI判断不一致的边界样本 | 人工修正/拒绝的样本 | 优先进入下一轮模型评测，不进入固定评测集 |

**关键约束：** 人工修正样本不可直接进入固定评测集，必须先入候选集经复核后转入，防止污染评测结果。

## 4. 场景1：风险识别增强

### 4.1 场景目标

将风险识别从"纯规则匹配"升级为"规则+大模型语义检测"双引擎模式，覆盖规则无法识别的语义级风险。

### 4.2 功能需求

#### 4.2.1 检测三级架构

风险识别必须按延迟和可靠性要求拆为三级：

| 级别 | 检测方式 | 延迟要求 | 适用场景 | 降级行为 |
|---|---|---|---|---|
| **同步硬规则** | 关键词/正则/条件表达式 | <50ms | 已知攻击模式、硬阻断场景 | 不可降级，规则引擎是基线 |
| **近同步语义判定** | 轻量分类器/安全专用模型 | <500ms P99 | Prompt注入、越狱识别、敏感内容 | 超时跳过AI，仅取规则结果 |
| **异步复核补充** | 大模型深度分析 | <30s P99 | 复杂攻击链还原、多轮累积判定 | 超时标注`ai_status=timeout`，不阻塞事件创建 |

约束：同步硬规则不可被AI覆盖或跳过；近同步语义判定采用旁路模式，不可用时规则引擎正常运行；异步复核结果通过事件更新接口追加，不阻塞主链路。

**AI调用状态枚举（`ai_status`）：**

| 状态值 | 含义 |
|---|---|
| `not_configured` | 该检测点未配置AI检测 |
| `pending` | AI检测已触发，等待结果 |
| `success` | AI检测成功完成 |
| `timeout` | AI检测超时未返回 |
| `error` | AI检测调用出错 |
| `circuit_open` | 熔断器打开，AI检测暂停 |
| `skipped_by_policy` | 策略配置跳过AI检测（如低风险场景） |

#### 4.2.2 大模型语义检测增强

- **需求描述：** 在现有规则引擎基础上，引入大模型对输入/输出进行语义级安全检测
- **检测场景：**
  - Prompt注入检测：覆盖直接/间接/上下文/多轮累积注入
  - 越狱攻击识别：覆盖角色扮演、编码绕过、多轮诱导、指令覆盖
  - 敏感内容识别：对模型输出进行语义级敏感分类（个人隐私/商业秘密/合规违规/有害内容/内部泄露）
  - 工具边界判定：分析工具调用意图与声明范围的匹配度，识别意图偏移、参数篡改、级联越权
- **输出（结构化，非JSON blob）：** 风险标签 + 置信度 + 攻击类型 + 攻击片段定位 + 命中片段原文引用（证据Span引用） + 判断理由 + 反例提示 + 模型版本 + Prompt模板版本
- **约束：** 大模型检测采用旁路模式，不可用时不影响规则引擎运行；所有模型输入输出必须审计留痕；模型结果必须可解释、可追溯、可覆盖（具体化要求见§4.2.5）

#### 4.2.3 多轮累积风险识别（会话内）

- **需求描述：** 识别同一会话内多轮低风险行为的累积升级
- **范围边界：** 本场景仅负责**会话内**的风险累积识别；**跨会话/跨应用/跨时间窗口**的主体风险画像归入场景4
- **输出：** 累积风险评分、关键转折点、累积风险等级
- **约束：** 需关联同一用户的会话上下文，跨Span聚合分析

#### 4.2.4 风险评分融合（异步合并机制）

- **需求描述：** 规则引擎和大模型检测结果融合输出综合风险评分
- **异步融合机制：**
  1. 规则引擎同步产生初始风险评分，创建风险线索
  2. AI旁路检测完成后，通过事件更新接口异步追加AI检测结果
  3. 重新计算综合评分：若AI结果导致等级上升，触发二次告警
  4. 若AI结果在超时阈值内未返回，综合评分仅取规则评分，记录标注`ai_status=timeout`
- **输出：** 综合风险评分、各检测源评分、融合策略标识、`ai_status`状态
- **约束：** P0仅支持最小版（规则优先+AI追加），权重/投票/取高等高级策略后续扩展；"取高"仅在AI置信度>阈值时生效，防止误报爆炸；"投票"需奇数个源，双源场景不适用

#### 4.2.5 "可解释、可追溯、可覆盖"具体化要求

AI检测结果必须包含以下可验证输出，不接受无法复核的纯文本：

| 要求 | 具体输出 |
|---|---|
| 可解释 | 命中片段原文引用、证据Span ID、判断理由、反例提示（为什么不是其他类型） |
| 可追溯 | 模型版本号、Prompt模板版本号、调用时间、输入证据引用（非原文） |
| 可覆盖 | 人工可修正AI标签、可降级为规则结果、修正后标注修正原因和修正人 |

### 4.3 数据模型影响

| 现有实体 | 新增字段 | 说明 |
|---|---|---|
| `span_observation` | `ai_detection_result_id` (FK) | 关联AI检测结果实体（替代JSON blob） |
| `risk_clue` | `detection_source` (enum) | 检测来源：rule / ai_model / rule_and_ai |
| `risk_clue` | `ai_status` (enum) | AI检测状态：not_configured / pending / success / timeout / error / circuit_open / skipped_by_policy |

**新增实体（替代JSON blob）：**

- `ai_inference_record`：inference_id、关联对象类型(risk_clue/risk_event)、关联对象ID、模型版本、Prompt模板版本、输入证据引用列表、输出结构（风险标签/置信度/攻击类型/命中片段/判断理由/反例提示）、耗时ms、Token消耗、成本、调用状态(成功/超时/错误/熔断)、创建时间
- `model_call_log`：call_id、inference_id、模型ID、模型版本、Prompt模板版本、输入token数、输出token数、耗时ms、调用状态、错误信息、数据级别(L0-L3)、创建时间

**实体边界说明：** `model_call_log`记录一次物理模型调用；`ai_inference_record`记录一次业务推理结果。一个推理可能包含多次模型调用（如主模型+分类器）、RAG检索、重试或降级，即1个inference_record对应N个model_call_log。

### 4.4 原型图改造

| 改造类型 | 页面 | 改造内容 |
|---|---|---|
| **改造** | 内容安全策略 | 每条策略增加检测方式标签（规则/AI），详情弹窗增加"AI检测配置"Tab（开关、置信度阈值、模型选择、检测超时、降级策略）；策略中心顶部增加"检测融合设置"入口 |
| **改造** | 高级规则项 | 规则实现方式新增"AI增强"类型（与现有正则/阈值/关键词并列），选择AI增强时展开AI配置字段 |

| **新增** | 会话风险追踪页 | 安全监控下新增，展示会话内跨轮次风险累积曲线和关键转折点 |

## 5. 场景2：风险研判增强

### 5.1 场景目标

从"纯人工研判"升级为"AI辅助研判+人工确认+反馈回流"模式，提升研判效率和准确性，同时建立持续改进的反馈闭环。

### 5.2 功能需求

#### 5.2.1 AI智能研判摘要

- **需求描述：** 基于Trace/Span证据自动生成风险研判摘要
- **输出（结构化）：** 攻击手法分析 + 影响面评估 + 相似历史事件关联 + 处置优先级建议 + 判断理由与依据引用 + **不确定性表达**（置信等级/缺失证据/需人工补充的问题） + 模型版本 + Prompt模板版本
- **不确定性表达要求：** 安全研判中"哪里不确定"比一段顺滑摘要更有价值。AI研判必须输出：(1)置信等级（高/中/低，低置信必须人工复核）；(2)缺失证据列表（哪些关键证据未获取，影响判断完整性）；(3)需人工补充的问题（AI无法判定的开放问题）
- **约束：** 研判摘要为建议性质，安全运营可确认/修正/补充；高危事件必须人工确认后才可采纳；研判过程和结果必须审计留痕

#### 5.2.2 攻击链自动还原

- **需求描述：** 基于完整Span序列自动还原攻击链路
- **输出：** 攻击链路图、攻击阶段标注、意图推断、关键转折点
- **约束：** 自动还原结果为辅助展示，不改变任何数据状态

#### 5.2.3 知识检索辅助研判

- **需求描述：** 研判时可检索知识库中的攻击手法、历史案例、处置预案
- **调用契约：** 向量相似检索为主，关键词检索为辅；同步RAG（研判场景需要即时结果）；检索结果先过内容安全扫描再注入Prompt，结果内容与系统提示词隔离（角色分离）
- **输出：** 知识检索结果列表、相关性评分、知识来源引用、可信度元数据（来源等级/有效期/冲突状态）
- **约束：** 仅检索展示，不修改知识库内容

#### 5.2.4 相似历史事件关联

- **需求描述：** 自动关联历史相似事件，辅助研判决策
- **输出：** 相似事件列表、相似度评分、关键相似点标注
- **约束：** 关联结果为参考性质，不自动继承处置结论

#### 5.2.5 反馈闭环机制

- **需求描述：** 人工确认/修正AI研判后，反馈必须回流样本库
- **反馈类型：** 采纳（AI研判正确，样本标注为"确认命中"）、修正（部分正确，标注修正内容和原因）、拒绝（AI研判错误，标注为"误报"并记录原因）

- **约束：** 反馈自动收集，不需手动触发；修正和拒绝的样本优先进入下一轮模型评测

## 6. 场景3：处置响应增强

### 6.1 场景目标

从"纯人工处置"升级为"AI建议+受限自动响应+人工审批"模式，提升处置效率同时确保安全可控。

### 6.2 功能需求

#### 6.2.1 AI处置建议

- **需求描述：** 基于风险类型、影响面、历史处置效果自动生成处置建议
- **输出：** 推荐动作类型、建议范围、TTL建议、影响评估、审批级别推荐
- **约束：** 建议性质，高危处置必须人工确认和审批

#### 6.2.2 自动响应（四级动作分级）

| 级别 | 动作类型 | 可否自动执行 | 审批要求 | TTL | 灰度 | 回滚 | 最大影响范围 |
|---|---|---|---|---|---|---|---|
| **L1 通知类** | 告警通知、消息推送 | 可自动 | 规则审批后启用 | 默认带TTL | 支持 | 无需回滚 | 单人 |
| **L2 观察类** | 标记观察、升级关注、加入监控名单 | 可自动 | 规则审批后启用 | 默认带TTL | 支持 | 移除标记 | 单会话 |
| **L3 软限制类** | 会话TTL限制、频率降级、工具调用次数限制 | 可自动（需白名单） | 规则审批+业务确认 | 必须 | 必须 | 自动恢复 | 单Agent/单应用 |
| **L4 强控制类** | 应用降级、工具禁用、主体阻断、策略变更 | **不可自动** | 必须人工审批+MFA | 必须 | 必须 | 必须支持 | 多应用/全局 |

约束：L3软限制类必须有白名单机制和熔断机制（影响超过N个会话则暂停）；所有自动执行动作必须写入审计日志；自动响应动作默认带TTL到期自动恢复；自动响应规则需审批后启用支持灰度模式；执行失败必须告警并转人工

**人工撤销与紧急停止机制：**

| 操作 | 作用范围 | 触发方式 | 效果 |
|---|---|---|---|
| **全局急停** | 所有自动响应规则 | 管理界面一键急停按钮 | 所有自动响应规则暂停，已执行动作按TTL自然恢复 |
| **单规则暂停** | 指定自动响应规则 | 规则详情页暂停按钮 | 该规则暂停，已执行动作按TTL自然恢复 |
| **单租户暂停** | 指定租户的所有自动响应 | 租户管理页暂停按钮 | 该租户自动响应暂停 |
| **手动提前恢复** | 单个已执行的自动动作 | 动作台账手动恢复按钮 | 立即恢复，不等待TTL到期 |
| **急停后批量恢复可逆动作** | L2标记/L3频率降级等可逆动作 | 急停页面批量恢复按钮 | 立即恢复所有可逆动作，L1通知无需恢复 |

约束：全局急停操作必须审计留痕；急停后需人工重新启用自动响应规则，不可自动恢复；急停后可选择立即恢复可逆动作（L2标记移除、L3限制解除），也可选择按TTL自然恢复

#### 6.2.3 AI规则优化建议

- **需求描述：** 分析误报/命中样本，自动生成规则调整建议
- **前置条件：** 样本采集与标注闭环已建立（底座3），有足够的确认样本和误报样本
- **输出：** 条件修改建议、阈值调整建议、新增规则建议
- **约束：** 建议性质，支持干跑验证闭环；规则变更必须走正式审批流程；建议必须经过历史流量回放和影响面估算

### 6.3 数据模型影响

| 现有实体 | 新增字段 | 说明 |
|---|---|---|
| `event_action` | `ai_suggested` (bool) | 是否来自AI建议 |
| `event_action` | `action_level` (enum) | 动作级别：L1/L2/L3/L4 |
| `rule` | `ai_optimized` (bool) | 是否经AI优化 |

**新增实体：**

- `auto_response_execution`：execution_id、rule_id、event_id、动作级别、执行动作、执行结果、执行时间、是否自动恢复、TTL剩余

## 8. 场景5：知识库安全能力

### 8.1 场景目标

引入知识库并构建安全防护体系，同时建设知识库自身安全能力，防范知识投毒和RAG注入等新型风险。

### 8.2 功能需求

#### 8.2.1 知识库引入目的

1. 安全运营知识检索（攻击手法库、处置预案库、合规要求库）
2. AI研判领域知识支撑（安全知识增强研判准确性）
3. 规则优化样本库（误报/命中/攻击样本）
4. 策略配置最佳实践库（策略模板、场景化配置）

#### 8.2.2 知识库自身安全

- **知识内容安全：** 入库前安全审核、知识版本管理、来源可信验证、过期与失效管理
- **知识访问安全：** 知识分级访问控制、检索审计、导出控制、防泄露（脱敏展示）
- **知识更新安全：** 变更审批、AI生成知识审核、冲突检测、影响面评估

#### 8.2.3 知识库赋能安全

- **安全知识检索增强研判：** 安全运营调查时可检索相关攻击手法、历史案例、处置预案
- **RAG增强AI检测与研判：** 安全知识库作为RAG外部知识源，增强大模型检测和研判准确性
- **样本库支撑规则优化：** 误报样本库、命中样本库、攻击样本库，支持AI辅助样本标注
- **策略模板库加速治理：** 场景化策略模板、行业最佳实践库、合规要求映射库
- **知识驱动安全问答：** 自然语言提问获取安全知识、处置指引、历史案例，支持知识缺口识别

#### 8.2.4 知识库集成接口契约

| 调用场景 | 检索方式 | 调用模式 | 结果注入方式 |
|---|---|---|---|
| 场景2 研判辅助 | 向量相似检索+关键词 | 同步RAG | 检索结果先过内容安全扫描，再注入Prompt；与系统提示词角色分离 |
| 场景3 处置建议 | 预案模板匹配+向量检索 | 同步 | 匹配结果作为建议参考，不直接注入Prompt |
| 场景5 安全问答 | 向量相似检索+全文 | 同步 | 返回给用户展示，含可信度元数据 |

#### 8.2.5 检索可信度链路

知识检索结果必须返回以下可信度元数据，不可仅返回内容：

| 元数据 | 说明 |
|---|---|
| 来源等级 | 人工审核/AI生成/外部导入，对应信任等级 |
| 适用范围 | 该知识适用的攻击类型/行业/场景 |
| 有效期 | 知识的有效截止日期，过期自动降级 |
| 引用次数 | 被AI研判引用的次数，高频引用需重点审核 |
| 冲突状态 | 是否与其他知识条目冲突，冲突需人工裁决 |
| 是否可用于模型上下文 | 标记该条目是否允许注入LLM Prompt |

#### 8.2.6 RAG Prompt安全沙箱

- 检索结果先过内容安全扫描再注入Prompt
- 检索结果内容与系统提示词隔离（角色分离：系统指令和知识内容分不同角色）
- 知识内容不可覆盖系统指令
- 检索结果标注来源，AI输出必须引用知识来源

#### 8.2.7 知识库安全风险防护

| 风险类型 | 描述 | 防护措施 |
|---|---|---|
| 知识投毒 | 恶意知识条目影响AI判断 | 入库审核+AI内容安全检测+信任等级分级 |
| 知识泄露 | 敏感知识被未授权访问 | 分级访问控制+检索审计+脱敏展示 |
| 知识过时 | 过期知识导致错误判断 | 有效期管理+自动降级+定期审核 |
| 知识冲突 | 矛盾知识导致判断不一致 | 冲突检测+优先级排序+人工裁决 |
| RAG注入 | 通过知识库间接注入AI | 知识内容安全扫描+检索结果过滤+来源可信验证 |
| RAG Prompt注入 | 检索结果被植入恶意指令后注入最终Prompt | 内容安全扫描+角色分离+内容不可覆盖系统指令 |
| 依赖失效 | 知识变更导致依赖规则/策略失效 | 影响面评估+变更审批+灰度发布 |
| 知识投毒/过期召回 | 已入库的投毒或过期知识已被AI引用 | 条目下架+引用影响面分析+已生成AI结论追溯标记 |

#### 8.2.8 知识条目下架与召回机制

- **下架操作：** 发现知识投毒或过期错误时，支持将条目状态设为"下架"，下架后不可被检索和引用
- **引用影响面分析：** 下架时自动分析该条目被哪些AI研判/检测引用，生成影响面报告
- **已生成AI结论追溯标记：** 对引用了下架知识的AI研判结果标注`knowledge_recalled=true`，提示人工复核
- **召回审批：** 下架操作需安全管理员审批，记录下架原因和影响面
- **恢复机制：** 下架条目经修正审核后可恢复上架，版本号+1

### 8.3 数据模型影响

**新增实体：**

- `knowledge_base`：kb_id、名称、类型、状态、条目数
- `knowledge_entry`：entry_id、kb_id、标题、内容、嵌入向量、来源类型、信任等级、敏感级别、状态(draft/pending_review/active/suspended/recalled/archived)、有效期、冲突状态、是否可用于模型上下文、引用次数、版本号、下架原因、下架时间、恢复时间
- `knowledge_version`：version_id、entry_id、版本号、内容快照、变更说明、发布人、发布时间
- `knowledge_access_log`：access_id、entry_id、访问人、访问动作、访问时间、访问原因
- `sample_entry`：sample_id、类型（误报/命中/攻击/边界）、关联规则ID、关联事件ID、样本内容、标注状态、标注人、反馈来源（人工确认/修正/拒绝）、所属样本集（候选集/训练集/评测集固定/回归集/争议集）、复核状态（待复核/已复核）、复核人、复核时间

## 13. 跨场景技术约束

### 13.1 大模型接入架构

```text
规则引擎(同步) ──┐
AI旁路检测(近同步) ──┼── 风险评分融合引擎 ──→ 现有业务服务层
AI异步研判(异步) ────┘
         ↑
    检索结果过滤层 ←── 知识库RAG检索
```

- 模型调用采用**旁路模式**，不可用时不影响规则引擎运行
- 近同步检测延迟需满足实时要求，异步研判允许1-5s
- 所有模型输入输出必须审计留痕
- 模型结果必须可解释、可追溯、可覆盖（具体化要求见§4.2.5）
- 模型版本管理纳入策略版本体系
- 检索结果过滤层：知识库检索结果先过内容安全扫描，再注入Prompt

### 13.2 智能体分层架构与运行控制面

| 层级 | 定位 | 覆盖场景 | 运行控制要求 |
|---|---|---|---|
| L1 分析辅助 | 任务驱动的分析辅助 | 场景2（证据分析、攻击链还原、知识检索） | 最大步数限制、只读工具权限、结果需人工确认 |
| L2 处置响应 | 事件驱动的自动响应 | 场景3（处置建议、受限自动响应） | 动作级别限制(L1-L3)、预算限制、审批点、失败转人工 |
| L3 自主运营 | 长周期自主安全运营 | 场景4/6（风险巡检、策略评估、报告生成） | 任务定义、最大步数、预算、审批点、失败恢复、人工接管、执行快照、复盘记录 |

**L3自主运营边界约束：** L3 Agent仅可生成报告和建议，**不可修改策略**。策略变更必须走正式审批流程，与Agent自动化无关。

**智能体安全约束（10项）：**

1. 动作边界约束 — 明确可执行/不可执行动作
2. 审批前置约束 — 高危动作必须人工审批
3. TTL约束 — 自动动作默认带过期时间
4. 灰度约束 — 新规则/策略先灰度后全量
5. 审计约束 — 所有Agent动作必须审计留痕
6. 回滚约束 — 自动动作必须支持回滚
7. 失败约束 — 执行失败必须告警并转人工
8. 降级约束 — Agent不可用时降级为人工流程
9. 预算约束 — 每次执行设定Token/步数上限
10. 快照约束 — 执行关键步骤保存快照，支持复盘

### 13.3 模型治理与评测

- **模型版本管理**：支持多版本并行注册，灰度切量（10%/30%/100%）
- **模型效果评估看板**：实时显示各模型的TP/FP/TN/FN统计，支持时间窗口对比
- **模型A/B测试**：同一检测点可配置两个模型并行，人工标注后统计胜出版本
- **模型熔断器**：连续N次超时/错误后自动熔断并告警，切回规则引擎
- **上线门禁**：新模型版本上线前必须通过评测集评估，FPR/FNR达标方可发布
- **持续评估**：上线后持续监控模型效果，准确率下降超过阈值自动告警

### 15.3 风险与注意事项

1. **模型幻觉风险** — AI研判和处置建议可能产生错误结论，必须保留人工确认环节
2. **模型延迟风险** — 大模型调用增加检测延迟，需设定超时降级策略和熔断机制
3. **知识投毒风险** — 知识库可能被恶意内容污染，需建立入库审核、RAG安全沙箱和定期巡检机制
4. **智能体失控风险** — Agent自动执行可能产生意外动作，需严格动作边界约束、审批前置和运行控制面
5. **数据隐私风险** — 模型调用需传输证据数据，需按数据分级策略（L0-L3）严格管控，国内数据不出境
6. **成本控制** — 大模型调用产生Token成本，需设定调用频率限制、租户配额和月度预算告警
