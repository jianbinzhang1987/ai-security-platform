# 智能化改造概要设计 — 数据分级与脱敏策略

## 1. 设计背景与目标

### 1.1 问题分析

概要设计中多处引用数据分级 L0-L3，但存在以下缺口：

- `02-§2.1` 定义了 L0-L3 的分级策略和 AI 调用约束，但**无前端管理入口**定义分级规则
- `02-§2.4` 定义了脱敏框架和默认规则，但**无脱敏规则配置页面**
- `content-security.html` 的"数据级别限制"仅展示只读标签，分级定义来源不明
- `model_registry.max_data_level` 引用 L0-L3，但分级判定逻辑未配置化
- 外部集成（Syslog/Webhook）需按数据级别控制可发送内容，依赖分级定义

### 1.2 设计目标

1. **数据分级可定义可配置**：L0-L3 的分级标准、判定规则、字段映射可管理
2. **脱敏规则可配置可审计**：脱敏策略按字段/级别配置，脱敏执行可追溯
3. **分级访问控制可执行**：模型调用、外部集成、页面展示均按分级自动过滤
4. **Raw 访问需审批可追溯**：L2/L3 数据的原始访问走审批流，全量审计

### 1.3 设计原则

- 数据分级是全局基础设施，所有模块（模型网关、外部集成、页面展示）统一消费
- 脱敏在模型网关内部执行，业务服务不感知脱敏过程（与 02-§2.4.2 一致）
- L2/L3 数据禁止传外部 API（与 02-§2.2 决策表一致）
- 脱敏规则变更需审批，变更后自动标注版本号

## 2. 数据分级管理

### 2.1 分级定义

复用 `02-§2.1` 的四级分级体系，增加可配置的判定规则：

| 数据级别 | 内容定义 | AI 调用策略 | 脱敏要求 | 判定规则（可配置） |
|---|---|---|---|---|
| **L0 公开** | 脱敏后的结构化摘要、聚合统计 | 可传外部模型 | 否 | 风险等级标签、检测来源、统计指标 |
| **L1 内部** | 脱敏证据文本、风险标签、事件摘要 | 可传私有化模型，外部需审批 | 是 | 事件摘要、证据引用、研判结论 |
| **L2 敏感** | 含 PII 的 Prompt 原文、Raw 证据 | 仅传私有化模型，禁止外部 API | 是 | 用户输入原文、响应原文、工具参数 |
| **L3 机密** | 完整用户输入、未脱敏原始数据、密钥 | 仅本地模型，禁止任何外部传输 | 是 | 身份证号、银行卡号、未脱敏 PII |

### 2.2 页面结构

**数据分级管理页** (`pages/system/data-classification.html`)

```text
页面布局:
├── 分级概览卡 (4 个):
│   ├── L0 公开: 数据项数 / 今日访问量
│   ├── L1 内部: 数据项数 / 今日访问量
│   ├── L2 敏感: 数据项数 / 今日访问量 / 审批待处理
│   └── L3 机密: 数据项数 / 今日访问量 / 审批待处理
├── 分级规则配置 Tab:
│   ├── 字段分级映射表:
│   │   ├── 数据对象 (span_observation / risk_event / ai_inference_record / ...)
│   │   ├── 字段路径 (prompt.content / response.content / user_id / ...)
│   │   ├── 默认级别 (L0-L3)
│   │   ├── 判定条件 (可选, 如 "含正则匹配身份证号 → L3")
│   │   └── 操作: [编辑]
│   └── 新增映射弹窗:
│       ├── 数据对象选择
│       ├── 字段路径输入
│       ├── 默认级别选择
│       └── 判定条件 (可选, 规则表达式)
├── 数据级别 × 部署模式决策表 (只读展示, 与 02-§2.2 一致):
│   ┌──────────┬──────────┬──────────┬──────────┬──────────┐
│   │ 数据级别  │ 私有化    │ 云服务    │ 公有云API │ 需审批    │
│   ├──────────┼──────────┼──────────┼──────────┼──────────┤
│   │ L0       │ ✅       │ ✅       │ ✅       │ 否       │
│   │ L1       │ ✅       │ ✅(审批) │ ❌       │ 云需审批  │
│   │ L2       │ ✅       │ ❌       │ ❌       │ 是       │
│   │ L3       │ ✅(本地) │ ❌       │ ❌       │ 是+MFA   │
│   └──────────┴──────────┴──────────┴──────────┴──────────┘
└── Raw 访问审批 Tab:
    ├── 待审批列表
    ├── 审批操作 (通过/拒绝)
    └── 审批历史
```

### 2.3 数据模型

#### 2.3.1 新增实体

```text
data_classification_rule:
  1. rule_id               — 规则唯一标识
  2. target_object         — 数据对象 (span_observation/risk_event/ai_inference_record/...)
  3. field_path            — 字段路径 (prompt.content/response.content/user_id/...)
  4. default_level         — 默认数据级别 (L0/L1/L2/L3)
  5. condition_expression  — 判定条件 (可选, 规则表达式)
     示例: "regex_match(prompt.content, '\\d{17}[\\dXx]') → L3"
  6. condition_description — 判定条件描述 (人工可读)
  7. priority              — 优先级 (数值越大越优先, 默认 0)
  8. enabled               — 启用状态
  9. version               — 规则版本号
  10. created_by/updated_by
  11. created_at/updated_at
```

**判定逻辑：**

```text
字段数据级别判定流程:
1. 按 target_object + field_path 查找匹配规则
2. 按 priority 降序排列
3. 依次评估 condition_expression:
   - 首个匹配的规则 → 返回其 default_level
   - 无条件匹配 → 返回最高优先级规则的 default_level
4. 无任何规则 → 默认 L1 (内部, 保守策略)
```

## 3. 脱敏策略管理

### 3.1 脱敏规则配置

复用 `02-§2.4.1` 的脱敏规则，增加可配置管理界面：

| 脱敏字段 | 默认规则 | 可配置选项 | 优先级 |
|---|---|---|---|
| 用户标识 | 哈希替换 | 哈希替换 / 掩码替换 / 不脱敏 | 1 |
| IP 地址 | 掩码替换 | 掩码替换(192.168.*.*) / 不脱敏 | 2 |
| 手机号 | 掩码替换 | 掩码替换(138****1234) / 哈希替换 / 不脱敏 | 3 |
| 证件号 | 掩码替换 | 掩码替换 / 哈希替换 / 不脱敏 | 4 |
| 姓名 | 哈希替换 | 哈希替换 / 掩码替换 / 不脱敏 | 5 |
| Prompt 中 PII | 正则匹配+掩码 | 正则规则可自定义 | 6 |

### 3.2 页面结构

**脱敏策略管理** (数据分级管理页内 Tab)

```text
页面布局:
├── 脱敏规则列表:
│   ├── 规则名称
│   ├── 匹配字段 (用户标识/IP/手机号/证件号/姓名/Prompt PII)
│   ├── 匹配模式 (正则表达式)
│   ├── 脱敏方式 (哈希替换/掩码替换/删除/自定义)
│   ├── 掩码模板 (如 138****1234, 192.168.*.*)
│   ├── 优先级
│   ├── 启用状态
│   └── 操作: [编辑] [禁用]
├── 新增脱敏规则弹窗:
│   ├── 规则名称
│   ├── 匹配字段选择
│   ├── 匹配模式 (正则, 预置常用模式: 手机号/身份证/邮箱/银行卡)
│   ├── 脱敏方式选择
│   ├── 掩码模板 (脱敏方式=掩码时)
│   └── 优先级
├── 脱敏效果预览:
│   ├── 输入原文示例
│   └── 脱敏后输出预览
└── 脱敏审计统计:
    ├── 今日脱敏执行次数
    ├── 今日脱敏命中字段数
    └── 脱敏命中率趋势 (近 7 天)
```

### 3.3 数据模型

#### 3.3.1 新增实体

```text
desensitization_rule:
  1. rule_id               — 规则唯一标识
  2. rule_name             — 规则名称
  3. match_field           — 匹配字段 (user_id/ip/phone/id_card/name/prompt_pii/custom)
  4. match_pattern         — 匹配正则表达式
  5. action_type           — 脱敏方式 (hash/mask/delete/custom)
  6. mask_template         — 掩码模板 (如 "138****1234", 哈希时为 null)
  7. custom_action         — 自定义脱敏逻辑 (可选, JSON 描述)
  8. priority              — 优先级 (数值越大越优先)
  9. enabled               — 启用状态
  10. version              — 规则版本号
  11. created_by/updated_by
  12. created_at/updated_at
```

**脱敏执行流程（复用 02-§2.4.2，增加规则查询步骤）：**

```text
模型网关内部脱敏层:
1. 读取数据的分级标记 (来自 data_classification_rule 判定)
2. 若级别 >= L1, 查询 desensitization_rule (按 priority 降序)
3. 依次匹配 match_pattern:
   - 命中 → 执行对应 action_type 脱敏
   - 未命中 → 保留原文
4. 记录脱敏审计日志 (脱敏字段数/命中率)
5. 传递脱敏后内容给模型
```

## 4. Raw 访问审批

### 4.1 审批流程

复用 `02-§2.3.2` 的 Raw 访问审批流，增加前端审批界面：

```text
AI 需访问 L2-L3 级别 Raw 证据
→ 创建 Raw 访问审批单 (approval_order, type=raw_evidence_access)
  审批单字段:
  - 申请原因
  - 目标数据对象 + 字段路径
  - 数据级别 (L2/L3)
  - 关联推理记录 ID
  - 申请时间
→ 安全管理员审批
  审批操作:
  - 通过: approval_status → approved, 有效期可设 (单次/1小时/24小时)
  - 拒绝: approval_status → rejected, 填写拒绝原因
→ 审批通过后:
  - 调用记录标注 approval_id
  - 执行 Raw 数据读取 (加密存储)
  - 读取结果注入模型调用
  - 写入 sensitive_access_log (06-§2.2.4)
```

### 4.2 页面结构

**Raw 访问审批** (数据分级管理页内 Tab，或独立页面)

```text
页面布局:
├── 筛选: 审批状态 / 数据级别 / 申请人 / 时间范围
├── 待审批列表 (默认视图):
│   ├── 申请编号
│   ├── 申请人 / 申请角色
│   ├── 目标数据 (对象+字段)
│   ├── 数据级别 (L2/L3)
│   ├── 申请原因
│   ├── 关联推理记录
│   ├── 申请时间
│   └── 操作: [通过] [拒绝]
├── 审批历史 Tab:
│   ├── 审批编号
│   ├── 申请人
│   ├── 审批人
│   ├── 审批结果 (通过/拒绝)
│   ├── 数据级别
│   ├── 有效期
│   ├── 审批时间
│   └── 操作: [查看详情]
└── 审批详情弹窗:
    ├── 申请信息
    ├── 审批信息
    ├── 访问记录 (关联 sensitive_access_log)
    └── 数据影响分析 (该审批关联的推理结果列表)
```

## 8. 安全约束

| 约束 | 说明 |
|---|---|
| 无规则字段默认 L1 | 未配置分级规则的字段默认为 L1（内部），保守策略 |
| 脱敏规则变更需审批 | 修改脱敏规则需安全负责人审批，变更后版本号+1 |
| L3 访问需 MFA | 审批 L3 数据访问时审批人需 MFA 验证 |
| 脱敏不可逆 | 脱敏后数据不可还原，原文仅加密存储于对象存储 |
| 分级规则优先级冲突检测 | 新增规则时自动检测与已有规则的字段路径冲突 |
