# 智能化改造概要设计 — 场景1：风险识别增强

## 1. 场景目标

将风险识别从"纯规则匹配"升级为"规则+大模型语义检测"双引擎模式，覆盖规则无法识别的语义级风险。

## 2. 检测三级架构

### 2.1 架构图

```text
标准化数据输入
    ↓
┌─────────────────────────────────────────────┐
│ 同步硬规则（<50ms，不可降级）                  │
│ 关键词/正则/条件表达式 → 初始风险评分+风险线索    │
└──────────────┬──────────────────────────────┘
               ↓（旁路，不阻塞）
┌─────────────────────────────────────────────┐
│ 近同步语义判定（<500ms P99，可降级跳过）         │
│ 轻量分类器/安全专用模型 → AI风险标签+置信度      │
│ 超时 → 跳过AI，仅取规则结果                     │
└──────────────┬──────────────────────────────┘
               ↓（异步，不阻塞事件创建）
┌─────────────────────────────────────────────┐
│ 异步复核补充（<30s P99）                        │
│ 大模型深度分析 → 复杂攻击链还原/多轮累积判定     │
│ 超时 → ai_status=timeout，不阻塞               │
└──────────────┬──────────────────────────────┘
               ↓
┌─────────────────────────────────────────────┐
│ 评分融合引擎                                   │
│ P0：规则优先+AI追加                             │
│ 规则评分同步产出 → AI评分异步追加               │
│ AI导致等级上升 → 触发二次告警                    │
│ AI超时 → 仅取规则评分                           │
└─────────────────────────────────────────────┘
```

### 2.2 三级对比

| 级别 | 检测方式 | 延迟要求 | 适用场景 | 降级行为 |
|---|---|---|---|---|
| 同步硬规则 | 关键词/正则/条件表达式 | <50ms | 已知攻击模式、硬阻断场景 | 不可降级，规则引擎是基线 |
| 近同步语义判定 | 轻量分类器/安全专用模型 | <500ms P99 | Prompt注入、越狱识别、敏感内容 | 超时跳过AI，仅取规则结果 |
| 异步复核补充 | 大模型深度分析 | <30s P99 | 复杂攻击链还原、多轮累积判定 | 超时标注ai_status=timeout，不阻塞事件创建 |

### 2.3 AI调用状态枚举

| ai_status | 含义 | 触发条件 |
|---|---|---|
| `not_configured` | 未配置AI检测 | 该检测点无AI配置 |
| `pending` | AI检测已触发，等待结果 | AI调用已发出 |
| `success` | AI检测成功完成 | AI返回有效结果 |
| `timeout` | AI检测超时未返回 | 超过超时阈值(近同步3s/异步60s) |
| `error` | AI检测调用出错 | 模型返回错误 |
| `circuit_open` | 熔断器打开，AI检测暂停 | 连续5次超时或错误率>20% |
| `skipped_by_policy` | 策略配置跳过AI检测 | 低风险场景策略配置跳过 |

## 3. 大模型语义检测增强

### 3.1 检测场景与模型路由

| 检测场景 | 检测级别 | 推荐模型类型 | 输出 |
|---|---|---|---|
| Prompt注入检测 | 近同步 | 轻量分类器/安全专用模型 | 风险标签+置信度+攻击类型+命中片段+判断理由+反例提示 |
| 越狱攻击识别 | 近同步 | 轻量分类器/安全专用模型 | 同上 |
| 敏感内容识别 | 近同步 | 分类模型 | 敏感类别(5类)+置信度+命中片段 |
| 工具边界判定 | 近同步/异步 | 大模型 | 意图偏移/参数篡改/级联越权+置信度+判断理由 |
| 多轮累积风险 | 异步 | 大模型 | 累积风险评分+关键转折点+累积风险等级 |

### 3.2 AI检测结果结构

AI检测结果写入`ai_inference_record`，结构化输出字段：

```text
ai_inference_record:
  推理输出结构:
    - risk_labels: 风险标签列表
    - confidence: 置信度(0-1)
    - attack_type: 攻击类型(直接注入/间接注入/上下文注入/多轮累积/角色扮演/编码绕过/...)
    - hit_fragments: 命中片段列表
        - span_id: 证据Span ID
        - field_path: 字段路径
        - offset_start/end: 偏移量
        - original_text_ref: 命中片段原文引用（引用，非原文）
    - reasoning: 判断理由
    - counter_example: 反例提示（为什么不是其他类型）
    - model_version: 模型版本号
    - prompt_template_version: Prompt模板版本号
```

### 3.3 "可解释、可追溯、可覆盖"具体化

| 要求 | 具体输出 |
|---|---|
| 可解释 | 命中片段原文引用、证据Span ID、判断理由、反例提示（为什么不是其他类型） |
| 可追溯 | 模型版本号、Prompt模板版本号、调用时间、输入证据引用（非原文） |
| 可覆盖 | 人工可修正AI标签、可降级为规则结果、修正后标注修正原因和修正人 |

## 4. 多轮累积风险识别（会话内）

### 4.1 范围边界

- 本场景仅负责**会话内**的风险累积识别
- **跨会话/跨应用/跨时间窗口**的主体风险画像归入场景4

### 4.2 实现方案

```text
同一会话内的多个Span
→ 按时间排序构建会话上下文
→ 大模型分析多轮交互的累积风险
→ 输出：
    - accumulated_risk_score: 累积风险评分
    - key_turning_points: 关键转折点
    - accumulated_risk_level: 累积风险等级
约束：需关联同一用户的会话上下文，跨Span聚合分析
```

## 5. 风险评分融合

### 5.1 P0最小版融合策略

```text
规则优先+AI追加：
1. 规则引擎同步产出初始风险评分 → 创建风险线索
2. AI旁路检测完成后，通过事件更新接口异步追加AI检测结果
3. 重新计算综合评分：
   - 若AI结果导致等级上升 → 触发二次告警
   - 若AI结果在超时阈值内未返回 → 仅取规则评分，标注ai_status=timeout
4. 综合评分 = max(规则评分, AI评分)（仅当AI置信度>阈值时取AI评分）
```

### 5.2 后续扩展策略（P1+）

| 策略 | 说明 | 适用条件 |
|---|---|---|
| 规则优先+AI追加 | P0默认策略 | 双源场景 |
| 取高策略 | 取规则和AI中较高评分 | AI置信度>阈值时生效，防止误报爆炸 |
| 加权融合 | 规则权重×规则评分+AI权重×AI评分 | 需校准权重，P1+ |
| 投票策略 | 奇数个源投票 | 需≥3个检测源，双源不适用 |

### 5.3 融合输出

```text
综合评分输出：
  - composite_risk_score: 综合风险评分
  - rule_risk_score: 规则评分
  - ai_risk_score: AI评分（可能为空）
  - fusion_strategy: 融合策略标识(rule_priority_ai_append/max/weighted/voting)
  - ai_status: AI检测状态
  - detection_source: 检测来源(rule/ai_model/rule_and_ai)
```

## 6. 数据模型影响

| 现有实体 | 新增字段 | 说明 |
|---|---|---|
| `span_observation` | `ai_detection_result_id` (FK) | 关联AI检测结果实体（替代JSON blob） |
| `risk_clue` | `detection_source` (enum) | 检测来源：rule / ai_model / rule_and_ai |
| `risk_clue` | `ai_status` (enum) | AI检测状态枚举（见§2.3） |

**新增实体：**

- `ai_inference_record`：AI推理结果（结构化，非JSON blob）
- `model_call_log`：模型调用审计日志

**实体边界：** `model_call_log`记录一次物理模型调用；`ai_inference_record`记录一次业务推理结果。一个推理可能包含多次模型调用（主模型+分类器、RAG检索、重试或降级），即1个inference_record对应N个model_call_log。
