# 智能化改造概要设计 — 外部集成与数据输出

## 1. 设计背景与目标

### 1.1 问题分析

当前系统缺少与外部系统的集成能力：

- 有 API Key 管理但无集成配置页面（与 SIEM/SOC 等对接的配置管理）
- 无 Syslog 发送配置，无法向上级安全系统推送数据
- 无 Webhook 回调配置，无法向企业微信/飞书/Slack 等推送通知
- 无数据输出范围控制，无法按数据级别限制对外提供的数据内容
- 通知渠道管理（`notify-channel.html`）仅管理内部通知通道，不覆盖外部系统集成

### 1.2 设计目标

1. **Syslog 标准输出**：支持 RFC 5424 / RFC 3164 格式向上级系统发送结构化数据
2. **Webhook 回调**：支持 HTTP POST 回调到外部系统，含签名验证
3. **数据范围按分级控制**：每个集成通道配置允许发送的最高数据级别，系统自动按级别过滤字段
4. **集成状态可监控**：发送成功率、延迟、最近发送时间可查看

### 1.3 设计原则

- 数据输出必须受数据分级（L0-L3）约束，与 09-数据分级与脱敏策略设计一致
- Syslog/Webhook 发送为异步操作，不阻塞主业务流程
- 发送失败自动重试（最多 3 次），重试间隔递增（1s/5s/30s）
- 所有外部数据输出写入审计日志

## 2. Syslog 集成设计

### 2.1 功能说明

配置 Syslog 发送通道，将平台风险事件、审计日志、统计指标等数据以结构化格式发送到上级安全系统（如 SIEM、SOC 平台、监管态势大屏）。

### 2.2 协议支持

| 协议 | 格式 | 传输方式 | 适用场景 |
|---|---|---|---|
| RFC 5424 | 结构化数据 (SD-PARAMS) | TCP/TLS | 现代 SIEM (Splunk/QRadar/ELK) |
| RFC 3164 (BSD) | 传统格式 | UDP/TCP | 传统 Syslog 服务器 |
| JSON over TCP | JSON 行协议 | TCP/TLS | 自研接收端 |

### 2.3 数据输出范围

按数据级别控制可发送的内容，与 09-数据分级设计对齐：

| 数据级别 | 可发送内容 | 典型接收方 | Syslog Facility/Severity |
|---|---|---|---|
| **L0 公开** | 聚合统计指标：事件总数、风险等级分布、检测来源分布、处置率 | 上级监管态势大屏 | facility=local0, severity=info |
| **L1 内部** | 事件摘要：事件ID、风险类型、等级、时间、应用名、检测来源、处置状态、AI研判摘要（脱敏后） | SIEM/SOC 平台 | facility=local1, severity=warning~err |
| **L2 敏感** | 事件详情 + 证据片段：含命中文本（脱敏后）、AI研判结论、会话上下文摘要 | 内部安全运营平台 | facility=local2, severity=err~crit |
| **L3 机密** | 完整原始内容：未脱敏 Prompt/Response | 仅限同级安全系统 | facility=local3, severity=crit~emerg |

**L3 数据发送约束：**
- 仅允许发送到经审批的内部安全系统
- 目标地址必须在白名单内
- 发送前需脱敏策略确认
- 每次发送写入 `sensitive_access_log`

### 2.4 Syslog 消息格式示例

**RFC 5424 格式（L1 级别事件摘要）：**

```text
<141>1 2026-04-30T09:30:00.000Z platform ai-security-platform 12345 -
  [event@32473 id="evt_001" type="prompt_injection" level="high"
   app="app_copilot_service" source="rule_and_ai"
   ai_status="success" action="blocked"]
  Prompt injection detected in app_copilot_service
```

**JSON over TCP 格式（L1 级别）：**

```json
{
  "timestamp": "2026-04-30T09:30:00.000Z",
  "source": "ai-security-platform",
  "data_level": "L1",
  "event_type": "risk_event",
  "event_id": "evt_001",
  "risk_type": "prompt_injection",
  "risk_level": "high",
  "app_id": "app_copilot_service",
  "detection_source": "rule_and_ai",
  "ai_status": "success",
  "action_taken": "blocked",
  "summary": "AI检测到Prompt注入攻击，规则+AI联合检出"
}
```

## 3. Webhook 集成设计

### 3.1 功能说明

配置 HTTP POST 回调通道，将平台事件推送到外部系统（企业微信/飞书/Slack/自研系统）。

### 3.2 Webhook 协议

```text
请求:
  POST {target_url}
  Headers:
    Content-Type: application/json
    X-Platform-Signature: sha256={hmac_sha256(payload, secret)}
    X-Platform-Event: risk_event / audit_log / statistics
    X-Platform-Delivery: {delivery_id} (幂等键)

响应:
  2xx → 发送成功
  非 2xx → 发送失败, 进入重试队列

重试策略:
  最多 3 次, 间隔 1s → 5s → 30s
  超过 3 次标记为 failed, 告警通知
```

### 3.3 页面结构

**Webhook 通道配置** (外部集成配置页内，与 Syslog 同列表)

```text
新建 Webhook 通道弹窗:
├── 通道名称
├── 目标 URL
├── 签名密钥 (自动生成或手动输入, 展示时脱敏)
├── 最高数据级别 (L0-L3)
├── 数据内容选择 (同 Syslog)
├── 过滤条件 (同 Syslog)
├── 发送频率 (实时/批量)
├── 自定义 Header (可选, JSON 编辑器)
└── 超时设置 (默认 10s)
```

## 4. 数据输出过滤机制

### 4.1 过滤流程

```text
事件/日志产生
→ 查询匹配的集成通道 (按过滤条件匹配)
→ 读取通道的最高数据级别 (max_data_level)
→ 从 data_classification_rule 获取各字段的数据级别
→ 字段级别 > max_data_level → 脱敏或移除
→ 字段级别 <= max_data_level → 保留
→ 构造发送内容 (按通道格式)
→ 异步发送 (Syslog/Webhook)
→ 写入 external_delivery_log
```

### 4.2 字段过滤规则

| 字段 | L0 可发送 | L1 可发送 | L2 可发送 | L3 可发送 |
|---|---|---|---|---|
| 事件ID | ✅ | ✅ | ✅ | ✅ |
| 风险类型 | ✅ | ✅ | ✅ | ✅ |
| 风险等级 | ✅ | ✅ | ✅ | ✅ |
| 时间 | ✅ | ✅ | ✅ | ✅ |
| 应用名 | ✅ | ✅ | ✅ | ✅ |
| 检测来源 | ✅ | ✅ | ✅ | ✅ |
| 处置状态 | ✅ | ✅ | ✅ | ✅ |
| 用户标识 | ❌ | 脱敏后 | 脱敏后 | ✅ |
| AI研判摘要 | ❌ | ✅ | ✅ | ✅ |
| 命中片段 | ❌ | ❌ | 脱敏后 | ✅ |
| Prompt 原文 | ❌ | ❌ | ❌ | ✅ |
| Response 原文 | ❌ | ❌ | ❌ | ✅ |
| 统计指标 | ✅ | ✅ | ✅ | ✅ |

## 5. 数据模型

### 5.1 新增实体

```text
integration_channel:
  1. channel_id            — 通道唯一标识
  2. channel_name          — 通道名称
  3. channel_type          — 通道类型 (syslog/webhook)
  4. protocol              — 协议 (rfc5424/rfc3164/json_tcp / http_post)
  5. transport             — 传输方式 (udp/tcp/tls)
  6. target_address        — 目标地址 (IP/域名/URL)
  7. port                  — 端口号
  8. tls_config            — TLS 配置 (JSON: {cert_ref, ca_ref}, 可选)
  9. auth_secret           — 签名密钥 (加密存储, 展示时脱敏)
  10. max_data_level       — 最高数据级别 (L0-L3)
  11. data_content         — 数据内容选择 (JSON: [event_summary/audit_log/statistics/ai_result])
  12. filter_conditions    — 过滤条件 (JSON: {risk_level, detection_source, app_scope})
  13. send_frequency       — 发送频率 (realtime/batch_5m/batch_15m)
  14. custom_headers       — 自定义 Header (JSON, Webhook 时可选)
  15. timeout_seconds      — 超时设置 (默认 10)
  16. enabled              — 启用状态
  17. last_sent_at         — 最近发送时间
  18. today_sent_count     — 今日发送量
  19. today_success_rate   — 今日发送成功率
  20. created_by/updated_by
  21. created_at/updated_at

external_delivery_log:
  1. delivery_id           — 投递唯一标识
  2. channel_id            — 关联通道
  3. data_level            — 实际发送数据级别
  4. event_type            — 事件类型 (risk_event/audit_log/statistics)
  5. source_id             — 源对象ID (事件ID/日志ID)
  6. payload_hash          — 发送内容哈希 (用于审计比对)
  7. send_status           — 发送状态 (success/failed/retrying)
  8. retry_count           — 重试次数
  9. response_code         — 响应码 (Webhook 时)
  10. error_message        — 错误信息
  11. latency_ms           — 发送延迟
  12. sent_at              — 发送时间
```

**索引建议：** (channel_id), (send_status), (sent_at), (event_type)

## 9. 安全约束

| 约束 | 说明 |
|---|---|
| 数据级别硬约束 | 发送内容严格按通道 max_data_level 过滤，不可绕过 |
| L3 发送白名单 | L3 数据仅发送到经安全负责人审批的白名单地址 |
| 签名验证 | Webhook 发送必须携带 HMAC-SHA256 签名 |
| TLS 强制 | L2/L3 数据必须通过 TLS 传输，禁止明文 |
| 审计全量记录 | 所有外部数据输出写入 external_delivery_log |
| 失败告警 | 连续 3 次发送失败触发告警通知 |
