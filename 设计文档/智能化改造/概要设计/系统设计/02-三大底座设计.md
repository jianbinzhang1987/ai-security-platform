# 智能化改造概要设计 — 三大底座设计

## 1. 底座1：AI调用与治理底座

### 1.1 模型网关

#### 1.1.1 定位

统一模型调用入口，所有AI能力的模型调用必须经过模型网关，禁止业务服务直连模型API。

#### 1.1.2 核心能力

| 能力 | 说明 |
|---|---|
| 多模型注册 | 支持注册多个模型（不同厂商/不同版本），每个模型配置endpoint、鉴权、数据级别限制 |
| 版本管理 | 模型版本化注册，支持灰度切量（10%→30%→100%） |
| 路由策略 | 按检测点配置路由到指定模型版本，支持A/B测试路由 |
| 调用审计 | 所有模型输入输出写入`model_call_log`，含模型版本、Prompt版本、耗时、成本 |
| 成本限额 | 每条Span AI检测Token上限(2048+512)、每事件研判上限(8192)、月度预算告警 |
| 降级策略 | 模型超时/错误时降级行为可配置（跳过AI/纯规则结果/重试） |
| 熔断器 | 连续5次超时或错误率>20%自动熔断，冷却期5分钟+探测请求成功后渐进恢复 |

#### 1.1.3 模型网关架构

```text
业务服务调用
    ↓
模型网关（ai-model-service）
    ├── 路由层：按检测点配置路由到模型版本
    ├── 限流层：租户日调用量上限(10000次/天)、频率限制(100次/秒/租户)
    ├── 熔断层：连续5次超时/错误率>20% → 熔断 → 切回规则引擎
    ├── 脱敏层：按数据级别(L0-L3)执行脱敏策略
    ├── 审计层：写入model_call_log
    └── 降级层：超时/错误时执行降级策略
    ↓
模型服务（私有化/云服务/本地模型）
```

#### 1.1.4 模型注册数据结构

```text
model_registry:
  - model_id: 模型唯一标识
  - model_name: 模型名称
  - model_type: 模型类型(classifier/llm/embedding)
  - provider: 提供商
  - endpoint: 调用地址
  - auth_ref: 鉴权信息引用
  - max_data_level: 允许的最高数据级别(L0-L3)
  - deployment_mode: 部署模式(private/cloud/local)
  - status: 模型状态(registered/testing/online/offline)

model_version:
  - version_id: 版本唯一标识
  - model_id: 关联模型
  - version_number: 版本号
  - config: 模型配置(temperature/max_tokens等)
  - evaluation_result: 评测结果摘要(FPR/FNR)
  - gate_status: 上线门禁状态(pending/passed/failed)
  - status: 版本状态(draft/testing/canary/production)
  - traffic_percent: 流量百分比
```

### 1.2 Prompt模板管理

#### 1.2.1 设计方案

| 能力 | 说明 |
|---|---|
| 版本化模板 | 每个Prompt模板支持多版本，与模型版本绑定 |
| 模板分类 | 按场景分类：检测类(注入/越狱/敏感/工具边界)、研判类、处置建议类、报告生成类 |
| 变量注入 | 支持变量占位符，运行时注入证据引用、风险上下文、知识检索结果 |
| 角色分离 | 系统指令与知识内容分不同角色，知识内容不可覆盖系统指令 |
| 审计绑定 | 每次AI调用记录Prompt模板版本号，可追溯 |

#### 1.2.2 Prompt模板数据结构

```text
prompt_template:
  - template_id: 模板唯一标识
  - template_name: 模板名称
  - category: 分类(detection/judgement/remediation/report)
  - sub_category: 子分类(prompt_injection/jailbreak/sensitive/tool_boundary/...)
  - system_prompt: 系统提示词
  - user_prompt_template: 用户提示词模板(含变量占位符)
  - variables: 变量定义列表(名称/类型/描述/是否必须)
  - output_schema: 期望输出结构(JSON Schema)
  - current_version: 当前版本号

prompt_template_version:
  - version_id: 版本唯一标识
  - template_id: 关联模板
  - version_number: 版本号
  - system_prompt: 系统提示词快照
  - user_prompt_template: 用户提示词模板快照
  - output_schema: 输出结构快照
  - change_note: 变更说明
  - publisher: 发布人
  - publish_time: 发布时间
```

### 1.3 评测机制

#### 1.3.1 评测流程

```text
模型版本注册
→ 评测集选取(攻击样本集+正常业务样本集+边界样本集)
→ 自动化评测执行
→ 计算FPR/FNR指标
→ 与门禁值对比
    ├── 通过 → 可进入灰度发布
    └── 未通过 → 不可上线，返回优化
→ 上线后持续监控(准确率下降>阈值自动告警)
```

#### 1.3.2 评测门禁

| 检测类型 | 目标FPR | 目标FNR | 基准集规模 |
|---|---|---|---|
| Prompt注入检测 | <5% | <10% | 攻击≥200+正常≥1000 |
| 越狱攻击识别 | <8% | <15% | 攻击≥150+正常≥800 |
| 敏感内容识别 | <5% | <10% | 攻击≥100+正常≥500 |
| 工具边界判定 | <10% | <10% | 攻击≥80+正常≥400 |

### 1.4 熔断器设计

```text
状态机：CLOSED → OPEN → HALF_OPEN → CLOSED

CLOSED（正常）:
  - 正常转发模型调用
  - 记录成功/失败计数

OPEN（熔断）:
  - 停止转发，直接返回降级结果
  - 标注ai_status=circuit_open
  - 发送告警
  - 进入冷却期(5分钟)

HALF_OPEN（探测）:
  - 发送探测请求
  - 成功 → 转CLOSED，渐进恢复流量(10%→30%→100%)
  - 失败 → 转OPEN，重新冷却

触发条件：
  - 连续5次超时 或
  - 滑动窗口(1分钟)内错误率>20%
```

### 1.5 成本控制

| 约束项 | 默认门槛 | 说明 |
|---|---|---|
| 单条Span AI检测最大输入长度 | 4096 tokens | 超长输入截断并标注 |
| 单条Span AI检测Token上限 | 2048(输入)+512(输出) | 防止单条Span消耗过大 |
| 每事件AI研判Token上限 | 8192(含研判+知识检索+相似事件) | 限制单事件上下文条数 |
| 每事件AI研判最大上下文条数 | 20条证据/Span | 超出部分仅传引用 |
| 租户日调用量上限 | 10000次/天（可按租户配置） | 防止突发调用 |
| 月度Token预算 | 默认按租户配置，80%告警，100%限流 | 限流后仅规则引擎运行 |
| 模型调用频率限制 | 100次/秒/租户（可配置） | 防止突发流量冲击 |

约束：所有成本门槛默认值可按租户配置，但**不得为空**，禁止无限额调用。

## 2. 底座2：证据与数据安全底座

### 2.1 数据分级策略

| 数据级别 | 内容 | AI调用策略 | 脱敏要求 |
|---|---|---|---|
| L0 公开 | 脱敏后的结构化摘要 | 可传外部模型 | 否 |
| L1 内部 | 脱敏证据文本、风险标签 | 可传私有化模型，外部需审批 | 是 |
| L2 敏感 | 含PII的Prompt原文、Raw证据 | 仅传私有化模型，禁止外部API | 是 |
| L3 机密 | 完整用户输入、未脱敏原始数据 | 仅本地模型，禁止任何外部传输 | 是 |

### 2.2 数据级别×部署模式决策表

| 数据级别 | 私有化模型 | 满足驻留的云服务 | 公有云API | 是否必须脱敏 | 是否允许落日志 | 是否需审批 |
|---|---|---|---|---|---|---|
| L0 公开 | ✅ 允许 | ✅ 允许 | ✅ 允许 | 否 | 是 | 否 |
| L1 内部 | ✅ 允许 | ✅ 允许（需审批） | ❌ 禁止 | 是 | 是 | 云服务需审批 |
| L2 敏感 | ✅ 允许 | ❌ 禁止 | ❌ 禁止 | 是 | 是（加密存储） | 是 |
| L3 机密 | ✅ 仅本地模型 | ❌ 禁止 | ❌ 禁止 | 是 | 是（加密+审批） | 是+MFA |

### 2.3 证据引用机制

#### 2.3.1 设计方案

AI调用默认传脱敏证据引用（trace_id/span_id/字段路径），不传Raw原文：

```text
AI调用输入构造流程：
1. 从span_observation提取证据引用列表
2. 按数据级别执行脱敏策略
3. 构造Prompt输入（引用+脱敏摘要，非Raw原文）
4. 记录输入证据引用列表到ai_inference_record
```

#### 2.3.2 Raw访问审批流

```text
AI需访问L2-L3级别Raw证据
→ 创建Raw访问审批单(approval_order, type=raw_evidence_access)
→ 安全管理员审批
→ 审批通过后，调用记录标注审批编号
→ 执行Raw数据读取（加密存储，审计留痕）
→ 读取结果注入模型调用
```

### 2.4 脱敏框架

#### 2.4.1 脱敏规则配置

| 脱敏字段 | 默认规则 | 可配置 |
|---|---|---|
| 用户标识 | 哈希替换 | 是 |
| IP地址 | 掩码替换(192.168.*.*) | 是 |
| 手机号 | 掩码替换(138****1234) | 是 |
| 证件号 | 掩码替换 | 是 |
| 姓名 | 哈希替换 | 是 |
| Prompt中PII | 正则匹配+掩码 | 是 |

#### 2.4.2 脱敏执行点

```text
模型网关内部脱敏层：
1. 读取数据级别标记
2. 匹配脱敏规则配置
3. 执行脱敏替换
4. 记录脱敏审计日志（脱敏字段数/命中率）
5. 传递脱敏后内容给模型
```

### 2.5 租户隔离

- 模型调用日志(`model_call_log`)按租户隔离，跨租户不可见
- AI推理结果(`ai_inference_record`)按租户隔离
- 样本库(`sample_entry`)按租户隔离
- 知识库(`knowledge_base`/`knowledge_entry`)支持租户级和共享级

### 2.6 数据流向审计

- 所有调用外部模型的数据需记录数据流向：源对象ID→数据级别→目标模型→调用时间
- 数据流向记录纳入合规审计，支持按租户/时间范围查询
- 数据驻留要求：国内数据不出境，跨境需审批

## 3. 底座3：反馈与样本底座

### 3.1 样本集分类与流转

| 样本集类型 | 用途 | 来源 | 流转规则 |
|---|---|---|---|
| 候选集 | 新采集样本暂存区 | 误报标记、确认命中、漏报补充、人工修正 | 人工修正样本先入候选集，经复核后可进入其他集 |
| 训练集 | 模型微调训练 | 从候选集经复核后转入 | 仅限模型微调使用，不可用于验收评测 |
| 评测集（固定） | 模型版本上线门禁 | 从候选集经复核+固定后转入 | 固定后不可修改，用于上线门禁FPR/FNR验收 |
| 回归集 | 规则/模型变更后回放验证 | 从候选集经复核后转入 | 变更前回放，验证不退化 |
| 争议集 | 人工与AI判断不一致的边界样本 | 人工修正/拒绝的样本 | 优先进入下一轮模型评测，不进入固定评测集 |

**关键约束：** 人工修正样本不可直接进入固定评测集，必须先入候选集经复核后转入，防止污染评测结果。

### 3.2 反馈回流机制

```text
人工确认AI研判
├── 采纳 → 样本标注"确认命中" → 候选集
├── 修正 → 标注修正内容和原因 → 候选集（优先进入下一轮评测）
└── 拒绝 → 标注"误报"+原因 → 候选集 → 争议集

反馈自动收集，不需手动触发
修正和拒绝的样本优先进入下一轮模型评测
```

### 3.3 回放评估

```text
规则/模型变更前
→ 选取回归集样本
→ 用新规则/模型回放执行
→ 对比回放结果与标注结果
→ 计算FPR/FNR变化
→ 验证不退化后方可发布
```

### 3.4 人工标注

- 支持标注样本的风险类型、严重程度、是否为边界案例
- AI辅助标注：对未标注样本提供AI标注建议，人工确认后生效
- 标注结果写入`sample_entry`的annotation_status/annotator字段

### 3.5 评估集管理

```text
候选集样本
→ 人工复核（review_status: pending_review → reviewed）
→ 按用途分流：
    ├── 训练集 ← 复核通过+适合训练
    ├── 评测集(固定) ← 复核通过+固定后不可修改
    ├── 回归集 ← 复核通过+用于变更回放
    └── 争议集 ← 人工与AI判断不一致

评估集使用：
- 评测集(固定)：模型版本上线门禁，FPR/FNR达标方可发布
- 回归集：规则/模型变更前回放验证
- 训练集：模型微调训练
- 争议集：优先进入下一轮模型评测
```
