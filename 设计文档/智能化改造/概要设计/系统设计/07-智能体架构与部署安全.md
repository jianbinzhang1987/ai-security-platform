# 智能化改造概要设计 — 智能体架构与部署安全

## 1. 智能体分层架构

### 1.1 三层架构定义

| 层级 | 定位 | 覆盖场景 | 运行控制要求 | 期次 |
|---|---|---|---|---|
| **L1 分析辅助** | 任务驱动的分析辅助 | 场景2（证据分析、攻击链还原、知识检索） | 最大步数限制、只读工具权限、结果需人工确认 | **P4** |
| **L2 处置响应** | 事件驱动的自动响应 | 场景3（处置建议、受限自动响应L1-L3） | 动作级别限制(L1-L3)、预算限制、审批点、失败转人工 | **P4** |
| **L3 自主运营** | 长周期安全运营任务 | 场景4-6（巡检、基线计算、报告生成、知识维护） | 预算限制、人工确认点、结果审核、可随时暂停 | **P4** |

**期次策略说明：**
- **P0-P3 阶段**：场景内直接使用AI能力（如研判摘要、自动响应），**不经过Agent编排层**
- **P4 阶段**：引入 `agent-service` 统一编排，将P0-P3已验证的场景能力封装为可编排的Agent
- **策略**：先验证场景能力，再建设Agent平台，避免过早抽象导致平台与场景脱节

### 1.2 运行控制面

```text
智能体运行控制面:
├── 步数限制
│   ├── L1: 最大10步
│   ├── L2: 最大5步
│   └── L3: 最大20步
├── 预算限制
│   ├── 单次执行Token上限
│   ├── 单日执行次数上限
│   └── 月度Token预算
├── 工具权限
│   ├── L1: 只读工具（查询/检索/分析）
│   ├── L2: 限制性写工具（L1-L3动作+策略查询）
│   └── L3: 审核性写工具（知识维护+报告生成+基线计算）
├── 审批点
│   ├── L1: 结果需人工确认
│   ├── L2: L3动作需审批、L4不可执行
│   └── L3: 关键结果需人工审核
├── 失败处理
│   ├── 自动重试(最多2次)
│   ├── 失败转人工
│   └── 部分成功可提交
└── 暂停与恢复
    ├── 人工可随时暂停
    ├── 暂停后可恢复
    └── 超时自动暂停
```

### 1.3 智能体安全约束

| 约束 | 说明 |
|---|---|
| **不可执行L4动作** | 智能体最高可执行L3动作，L4必须人工审批+MFA |
| **不可修改系统指令** | 智能体不可修改Prompt模板中的系统提示词 |
| **不可访问L3数据** | 智能体最高可访问L2数据，L3需人工审批 |
| **不可删除数据** | 智能体不可删除事件/证据/样本/知识条目，仅可标记状态 |
| **不可绕过审批** | 智能体不可绕过审批流程，需审批的操作必须等待审批结果 |
| **执行日志全量记录** | 智能体每步执行写入agent_execution_log |
| **可随时人工暂停** | 任何人在任何时间可暂停智能体执行 |

### 1.4 智能体数据模型

```text
agent_definition:
  - agent_id: 智能体唯一标识
  - agent_name: 智能体名称
  - agent_level: 层级(L1/L2/L3)
  - description: 描述
  - capabilities: 能力声明列表
  - tool_permissions: 工具权限列表
  - max_steps: 最大步数
  - budget_limits: 预算限制(JSON: {single_execution_tokens, daily_execution_count, monthly_token_budget})
  - approval_points: 审批点配置(JSON: [{step_type, approval_required}])
  - status: 状态(draft/testing/active/suspended)
  - tenant_id: 租户ID

agent_execution_log:
  - execution_id: 执行唯一标识
  - agent_id: 关联智能体
  - task_type: 任务类型
  - trigger_event_id: 触发事件ID
  - step_number: 步骤序号
  - step_type: 步骤类型(tool_call/decision/approval_wait/result_submit)
  - tool_name: 工具名称
  - tool_input: 工具输入（脱敏后）
  - tool_output: 工具输出（脱敏后）
  - execution_result: 执行结果(success/failed/pending_approval/paused)
  - token_consumed: Token消耗
  - execution_time: 执行时间
  - paused_by: 暂停人
  - paused_at: 暂停时间
```

## 2. 部署架构

### 2.1 部署模式

| 组件 | 部署模式 | 说明 |
|---|---|---|
| 业务服务集群 | 容器化部署 | 现有9服务域+新增4服务域=13服务域，可按负载独立扩缩 |
| AI模型网关 | 容器化部署 | ai-model-service独立部署，支持水平扩展 |
| 模型服务 | 多模式 | 私有化部署/云服务API/本地模型，按数据级别选择 |
| 向量数据库 | 容器化/独立部署 | Milvus/Qdrant，P1引入 |
| 知识库服务 | 容器化部署 | knowledge-service独立部署 |
| Collector集群 | 现有不变 | — |
| 前端管理端 | 现有不变 | — |
| 消息队列 | 现有不变 | — |

### 2.2 部署拓扑

```text
                    ┌── 前端管理端
                    ↓
                API网关
                    ↓
    ┌───────────────┼───────────────┐
    ↓               ↓               ↓
业务服务集群    AI模型网关       知识库服务
(8服务)        (ai-model-svc)   (knowledge-svc)
    ↓               ↓               ↓
    ├── 业务DB      ├── 模型服务     ├── 向量DB
    ├── 检索库      │   ├── 私有化   ├── 业务DB
    ├── 分析库      │   ├── 云服务   └── 对象存储
    ├── 对象存储    │   └── 本地模型
    └── 缓存        └── AI推理结果库
```

### 2.3 部署原则

1. AI模型网关与业务服务分离部署，避免AI调用延迟影响业务链路
2. 向量数据库独立部署，避免影响业务库性能
3. 模型服务按数据级别选择部署模式（L2/L3仅私有化/本地）
4. AI推理结果库与业务库可共用关系型数据库实例，逻辑隔离
5. 知识库服务独立部署，支持水平扩展

## 3. 安全与合规设计

### 3.1 AI安全约束

| 约束类型 | 具体要求 |
|---|---|
| **模型输入安全** | 按数据级别L0-L3分级管控，L2/L3禁止传外部API |
| **模型输出安全** | AI输出不可直接执行L4动作，必须经人工确认或审批 |
| **Prompt注入防护** | 系统指令与用户输入/知识内容角色分离，知识内容不可覆盖系统指令 |
| **RAG注入防护** | 知识检索结果先过内容安全扫描再注入Prompt |
| **模型调用审计** | 所有模型调用写入model_call_log，含输入输出摘要 |
| **成本控制** | Token限额、月度预算、限流策略，防止成本失控 |
| **熔断降级** | 模型连续超时/错误自动熔断，切回规则引擎 |

### 3.2 数据安全

| 安全要求 | 实现方式 |
|---|---|
| **数据分级** | L0-L3四级分类，按级别限制AI调用和数据流转 |
| **脱敏框架** | 模型网关内置脱敏层，按规则配置自动脱敏 |
| **Raw访问审批** | L2/L3数据访问需审批，审批记录关联调用记录 |
| **租户隔离** | 模型调用日志、AI推理结果、样本库按租户隔离 |
| **数据驻留** | 国内数据不出境，跨境需审批 |
| **加密存储** | L2/L3数据加密存储，对象存储访问必须授权 |
| **导出审计** | 所有导出行为必须审计留痕 |

### 3.3 审计与追溯

| 审计对象 | 审计内容 | 存储位置 |
|---|---|---|
| 模型调用 | 输入/输出摘要、耗时、成本、数据级别 | model_call_log |
| AI推理结果 | 推理类型、命中片段、判断理由、模型版本 | ai_inference_record |
| AI研判反馈 | 采纳/修正/拒绝、修正内容、修正人 | ai_judgement_result |
| 知识访问 | 访问人、访问动作、访问原因 | knowledge_access_log |
| 数据流向 | 源对象→数据级别→目标模型→调用时间 | model_call_log |
| 自动响应 | 规则触发、动作执行、TTL恢复 | auto_response_execution |
| 智能体执行 | 每步工具调用、Token消耗、执行结果 | agent_execution_log |
| Raw访问 | 访问人、审批单ID、访问原因 | sensitive_access_log |

### 3.5 验收矩阵工程实现

#### 3.5.1 评测集来源与构成

| 评测集类型 | 来源 | 构成比例 | 审核要求 | 期次 |
|---|---|---|---|---|
| **攻击样本** | 公开数据集(CVE/攻击样本库) + 红队生成 | 攻击样本的60% | 安全专家审核标注 | P0 |
| **正常样本** | 生产环境脱敏数据 + 合成数据 | 攻击样本的4-5倍 | 业务负责人确认无风险 | P0 |
| **边界样本** | 争议集(人工修正/拒绝的样本) | 攻击样本的10% | 安全+业务联合审核 | P1 |
| **对抗样本** | 红队持续生成 + 对抗测试 | 攻击样本的20% | 渗透测试团队验证 | P1.5 |

#### 3.5.2 评测集冻结机制

```
候选集样本
  ↓ 人工复核（review_status: reviewed）
  ↓ 质量门禁（标注完整度100%、边界清晰）
冻结流程：
  1. 安全负责人提交冻结申请
  2. 评测集版本号生成（v1.0.0）
  3. 样本内容快照存入对象存储（只读）
  4. 评测集状态设为frozen（不可修改、不可删除）
  5. 与模型版本绑定（model_version.evaluation_set_id）

解冻条件：
  - 发现样本标注错误 → 走修正流程 → 版本号+1（v1.0.1）
  - 业务场景重大变化 → 重新采集 → 新版本（v2.0.0）
```

#### 3.5.3 自动化评测流程

```
模型版本提交上线申请
  ↓
ai-model-service 触发自动化评测
  ↓
从 sample_entry 提取 fixed_evaluation_set 样本
  ↓
批量调用模型（按检测点路由）
  ↓
收集推理结果（ai_inference_record）
  ↓
计算指标：
  - FPR = 正常样本误报数 / 正常样本总数
  - FNR = 攻击样本漏报数 / 攻击样本总数
  - 准确率 = (真正例 + 真负例) / 总数
  ↓
与门禁值对比（target_fpr/target_fnr）
  ├─ 通过 → gate_status=passed，可进入灰度
  └─ 未通过 → gate_status=failed，阻断发布，返回优化
```

#### 3.5.4 门禁失败后的发布阻断

| 门禁检查点 | 阻断机制 | 人工 override |
|---|---|---|
| **FPR/FNR 未达标** | model_version.gate_status=failed，禁止流量切换 | 技术负责人+安全负责人双签可强制通过（需留痕） |
| **评测集规模不足** | 禁止发起上线申请 | 不可 override，必须先补充样本 |
| **样本标注错误率>5%** | 冻结评测集，暂停评测 | 修正后重新冻结 |
| **回归集验证失败** | 阻断发布，提示"变更退化" | 技术负责人评估后决定 |

#### 3.5.5 验收数据留存

- 每次评测生成完整报告：评测集版本、模型版本、FPR/FNR、混淆矩阵、失败样本列表
- 报告存入对象存储，保存期≥3年
- 门禁失败记录必须包含失败原因分析和改进建议

## 4. 非功能需求设计

### 4.1 性能与延迟

**性能指标分层定义：**
- **P95**：95%请求满足该延迟，用于日常监控
- **P99**：99%请求满足该延迟，用于压测验收
- **最大超时**：超过该阈值触发降级/熔断，保证系统稳定

| 指标 | P95 | P99 | 最大超时 | 说明 |
|---|---|---|---|---|
| 规则引擎同步检测 | <30ms | <50ms | 100ms | 不可降级，超时直接失败 |
| AI旁路近同步检测 | <300ms | <500ms | 3s | 可降级跳过，超时ai_status=timeout |
| AI异步复核 | <10s | <30s | 60s | 不阻塞事件创建，超时ai_status=timeout |
| AI研判摘要生成 | <5s | <30s | 60s | 异步生成，超时ai_analysis_status=timeout |
| 知识检索(RAG) | <1s | <2s | 5s | 同步检索，超时可降级为关键词检索 |
| 评分融合计算 | <50ms | <100ms | 500ms | 规则评分同步+AI异步追加 |

**降级触发条件：**
- AI旁路检测：>3s未返回 → 跳过AI，仅取规则评分
- AI异步复核：>60s未返回 → ai_status=timeout，不阻塞事件创建
- AI研判：>60s未返回 → ai_analysis_status=timeout，提示"研判超时"
- 熔断器：连续5次超时或1分钟错误率>20% → circuit_open

### 4.2 可用性

| 指标 | 要求 | 说明 |
|---|---|---|
| 规则引擎可用性 | 99.9% | 不可降级 |
| AI检测可用性 | 99% | 可降级，降级后仅规则引擎运行 |
| 模型网关可用性 | 99.9% | 熔断后自动降级 |
| 知识库可用性 | 99% | 不可用时研判无知识辅助，不影响核心链路 |

### 4.3 可观测性（新增指标）

| 指标 | 说明 |
|---|---|
| AI检测P99延迟 | 按检测点分维度 |
| AI检测成功率 | 按检测点分维度 |
| 熔断器状态 | 各模型版本熔断状态 |
| 模型调用量/成本 | 按租户/模型/检测点分维度 |
| AI研判采纳率 | 确认/修正/拒绝比例 |
| 知识检索命中率 | 检索结果被引用的比例 |
| 样本库规模 | 各样本集条目数 |
| 自动响应执行数 | 按动作级别分维度 |

## 6. 关键依赖与风险

### 6.1 关键依赖

| 依赖 | 影响场景 | 缓解措施 |
|---|---|---|---|
| 模型服务可用性 | 所有AI场景 | 熔断降级+旁路模式 |
| 向量数据库可用性 | 知识检索 | 降级为关键词检索 |
| 样本数据积累 | 评测/规则优化 | P0先建框架，P1积累数据 |
| 身份归一数据 | SOC分析 | P1前置建设 |
| 行为基线数据 | SOC分析 | P1前置建设 |

### 6.2 主要风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| AI误报爆炸 | 运营效率下降 | FPR门禁+规则优先+人工可覆盖 |
| 模型成本失控 | 预算超支 | Token限额+月度预算+限流策略 |
| 知识投毒 | AI研判准确性下降 | 入库审核+安全扫描+下架召回 |
| RAG注入 | AI输出被操控 | 安全沙箱+角色分离+内容扫描 |
| 数据泄露 | 合规风险 | 数据分级+脱敏框架+访问审批 |
