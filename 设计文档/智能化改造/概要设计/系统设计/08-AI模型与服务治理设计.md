# 智能化改造概要设计 — AI模型与服务治理

## 1. 设计背景与目标

### 1.1 问题分析

当前概要设计中，AI模型是整个智能化改造的基石——P0.5a 的检测、研判、反馈回流均依赖模型网关，但**缺少模型管理的前端入口**：

- `content-security.html` 的"检测模型"下拉无数据来源，无法配置使用哪个模型
- 高级规则项引用"Prompt 模板"，但无独立管理页面
- 模型网关的熔断/降级状态无可视化监控
- Token 消耗与成本无看板，月度预算告警无处查看
- 模型版本灰度发布无操作界面

### 1.2 设计目标

1. **模型全生命周期可管理**：注册 → 版本管理 → 灰度发布 → 上线门禁 → 下线
2. **Prompt 模板版本化可追溯**：创建 → 版本快照 → 变量注入 → 审计绑定
3. **模型运行状态可视化**：延迟/成功率/Token消耗/熔断状态/成本趋势
4. **成本可控可预警**：月度预算、日调用量、单条限制的配置与告警

### 1.3 设计原则

- 所有模型调用必须经过模型网关，禁止业务服务直连模型 API（与 02-§1.1.1 一致）
- 模型版本上线必须通过评测门禁（P1 启用，P0 仅记录）
- Prompt 模板系统提示词与知识内容角色分离（与 02-§1.2.1 一致）
- 成本限额不得为空，禁止无限额调用（与 02-§1.5 一致）

## 2. 功能模块设计

### 2.1 模型注册管理

#### 2.1.1 功能说明

管理平台接入的所有 AI 模型，提供模型注册、状态管理、数据级别限制配置。

#### 2.1.2 页面结构

**模型列表页** (`pages/system/model-registry.html`)

```text
页面布局:
├── 搜索栏: 模型名称 / 模型类型(classifier/llm/embedding) / 部署模式 / 状态
├── 统计卡: 模型总数 | 在线数 | 离线数 | 今日调用量
├── 数据表:
│   ├── 模型名称
│   ├── 模型类型 (classifier/llm/embedding)
│   ├── 提供商
│   ├── 部署模式 (private/cloud/local)
│   ├── 最高数据级别 (L0-L3)
│   ├── 当前生产版本
│   ├── 状态 (registered/testing/online/offline)
│   └── 操作: [查看版本] [编辑] [上线/下线]
└── 新建模型弹窗:
    ├── 基础信息: 名称/类型/提供商/描述
    ├── 连接配置: endpoint/auth_ref(密钥引用)
    ├── 安全配置: 部署模式/最高数据级别
    └── 状态: registered(默认)
```

#### 2.1.3 数据结构

复用 `06-§2.2.1` 的 `model_registry` 实体，无需扩展。

#### 2.1.4 关键交互

| 操作 | 前置条件 | 后续动作 |
|---|---|---|
| 注册新模型 | 无 | 状态=registered，需至少注册一个版本后才能 testing |
| 模型上线 | 至少一个版本 gate_status=passed | 状态→online，灰度切量从 0% 开始 |
| 模型下线 | 无正在执行的推理任务 | 状态→offline，路由层停止转发 |
| 编辑连接配置 | 模型状态≠online | 修改 endpoint/auth_ref 需审批 |

### 2.2 模型版本管理

#### 2.2.1 功能说明

管理同一模型的多个版本，支持灰度发布、评测门禁、流量切分。

#### 2.2.2 页面结构

**模型版本列表** (模型详情页内 Tab)

```text
页面布局（模型详情 → "版本管理" Tab）:
├── 版本列表:
│   ├── 版本号
│   ├── 版本状态 (draft/testing/canary/production)
│   ├── 流量百分比 (0-100%)
│   ├── 评测结果 (FPR/FNR 摘要)
│   ├── 门禁状态 (pending/passed/failed)
│   ├── 发布人 / 发布时间
│   └── 操作: [灰度切量] [设为生产] [下线]
├── 新建版本弹窗:
│   ├── 版本号 (自动递增或手动)
│   ├── 模型配置: temperature/max_tokens 等 (JSON 编辑器)
│   └── 变更说明
└── 灰度切量弹窗:
    ├── 当前流量百分比
    ├── 目标流量百分比 (10%→30%→100% 渐进)
    ├── 确认按钮 (需二次确认)
    └── 约束提示: "灰度切量需观察至少 30 分钟后再扩大"
```

#### 2.2.3 数据结构

复用 `06-§2.2.2` 的 `model_version` 实体，无需扩展。

#### 2.2.4 灰度发布流程

```text
新建版本 (draft)
→ 提交评测 (testing)
→ 评测门禁通过 (gate_status=passed)
→ 灰度发布 (canary, 流量 10%)
→ 观察 30 分钟，指标正常
→ 扩大灰度 (30%)
→ 观察 30 分钟，指标正常
→ 全量发布 (production, 流量 100%)
→ 旧版本自动降级为 canary → draft
```

**P0 约束：** 评测门禁仅记录不阻断（`gate_status` 字段存在但不强制），P1 启用门禁阻断。

### 2.3 Prompt 模板管理

#### 2.3.1 功能说明

管理所有 AI 调用使用的 Prompt 模板，支持版本化、变量注入、分类管理。

#### 2.3.2 页面结构

**Prompt 模板列表页** (`pages/system/prompt-template.html`)

```text
页面布局:
├── 搜索栏: 模板名称 / 分类 / 子分类 / 状态
├── 分类筛选 Tab: 全部 | 检测类 | 研判类 | 处置建议类 | 报告生成类
├── 数据表:
│   ├── 模板名称
│   ├── 分类 (detection/judgement/remediation/report)
│   ├── 子分类 (prompt_injection/jailbreak/sensitive/tool_boundary/...)
│   ├── 当前版本号
│   ├── 变量数量
│   ├── 关联模型数
│   ├── 更新时间
│   └── 操作: [查看版本] [编辑] [发布新版本]
└── 新建模板弹窗 (多步):
    Step 1 - 基础信息:
      ├── 模板名称
      ├── 分类 + 子分类
      └── 描述
    Step 2 - 提示词编辑:
      ├── 系统提示词 (system_prompt, 只读区域标注)
      ├── 用户提示词模板 (user_prompt_template, 含变量占位符 {{variable}})
      └── 变量定义列表 (名称/类型/描述/是否必须)
    Step 3 - 输出规范:
      └── 期望输出结构 (JSON Schema 编辑器)
```

**Prompt 模板版本列表** (模板详情页内 Tab)

```text
页面布局:
├── 版本列表:
│   ├── 版本号
│   ├── 变更说明
│   ├── 发布人 / 发布时间
│   └── 操作: [查看快照] [回滚]
└── 版本对比:
    ├── 左: 旧版本快照
    └── 右: 新版本快照
    └── 差异高亮
```

#### 2.3.3 数据结构

复用 `02-§1.2.2` 的 `prompt_template` + `prompt_template_version` 实体，无需扩展。

#### 2.3.4 角色分离约束

```text
Prompt 构造规范:
1. system_prompt: 系统指令（角色=system）
   - 定义任务目标、输出格式、安全约束
   - 知识内容不可覆盖此区域
   - 修改需安全负责人审批

2. user_prompt_template: 用户提示词模板（角色=user）
   - 含变量占位符 {{evidence_refs}} / {{risk_context}} / {{knowledge_results}}
   - 知识检索结果注入此区域
   - 变量注入时自动转义，防止 Prompt 注入

3. 角色分离执行:
   - 模型网关在构造 Prompt 时强制 system/user 分离
   - 知识内容仅注入 user 角色
   - 禁止在 user_prompt_template 中包含覆盖系统指令的指令
```

### 2.4 AI 服务健康监控

#### 2.4.1 功能说明

实时监控各 AI 模型服务的运行状态、性能指标、熔断状态，提供运维决策依据。

#### 2.4.2 页面结构

**AI 服务监控页** (`pages/ops/ai-service-monitor.html`)

```text
页面布局:
├── 全局概览卡:
│   ├── 在线模型数 / 总模型数
│   ├── 今日总调用量
│   ├── 全局 P95 延迟
│   ├── 全局成功率
│   ├── 当前熔断模型数
│   └── 本月 Token 消耗 / 月度预算 (进度条)
├── 模型状态矩阵:
│   ┌──────────┬────────┬─────────┬──────────┬──────────┐
│   │ 模型名称  │ 状态   │ P95延迟  │ 成功率   │ 熔断状态  │
│   ├──────────┼────────┼─────────┼──────────┼──────────┤
│   │ 注入检测  │ 🟢在线 │ 210ms   │ 99.2%   │ CLOSED   │
│   │ 越狱识别  │ 🟢在线 │ 280ms   │ 98.7%   │ CLOSED   │
│   │ 研判摘要  │ 🟢在线 │ 4.2s    │ 97.1%   │ CLOSED   │
│   │ 敏感识别  │ 🟡探测 │ 450ms   │ 85.3%   │ HALF_OPEN│
│   │ 工具判定  │ 🔴熔断 │ —       │ —       │ OPEN     │
│   └──────────┴────────┴─────────┴──────────┴──────────┘
├── 延迟趋势图 (近 1h/6h/24h 切换):
│   ├── P95 折线
│   ├── P99 折线
│   └── 最大超时阈值线 (虚线)
├── 成功率趋势图 (近 1h/6h/24h 切换)
├── 熔断器状态面板:
│   ├── 当前状态 (CLOSED/OPEN/HALF_OPEN)
│   ├── 最近熔断时间
│   ├── 熔断原因 (连续超时/错误率)
│   ├── 冷却剩余时间
│   └── 操作: [手动恢复] [强制熔断]
└── 最近调用日志 (快速查看, 链接到 model_call_log 审计页)
```

#### 2.4.3 数据来源

| 指标 | 数据来源 | 计算方式 |
|---|---|---|
| P95/P99 延迟 | `model_call_log.latency_ms` | 滑动窗口 5 分钟聚合 |
| 成功率 | `model_call_log.call_status` | success / total × 100% |
| 熔断状态 | 模型网关内存状态 | 实时推送或轮询 |
| Token 消耗 | `model_call_log.input_token_count + output_token_count` | 按日/月聚合 |
| 调用量 | `model_call_log` 按模型版本分组计数 | 按日聚合 |

#### 2.4.4 告警规则

| 告警 | 条件 | 级别 | 动作 |
|---|---|---|---|
| 延迟告警 | P99 > 最大超时阈值 × 80% | warning | 通知运维 |
| 成功率下降 | 1 分钟窗口成功率 < 95% | warning | 通知运维 |
| 熔断触发 | 熔断器状态变为 OPEN | critical | 通知运维 + 安全负责人 |
| 预算告警 | 月度 Token 消耗 > 80% 预算 | warning | 通知运维 |
| 预算耗尽 | 月度 Token 消耗 > 100% 预算 | critical | 限流，仅规则引擎运行 |

### 2.5 成本看板

#### 2.5.1 功能说明

展示 AI 调用的 Token 消耗和成本趋势，支撑预算管理和成本优化决策。

#### 2.5.2 页面结构

**成本看板** (AI 服务监控页内 Tab 或独立区域)

```text
页面布局:
├── 预算概览:
│   ├── 本月预算总额
│   ├── 已消耗金额 (进度条, 80% 黄色, 100% 红色)
│   ├── 预计月末消耗 (基于趋势外推)
│   └── 剩余可用天数估算
├── 消耗趋势图 (日粒度):
│   ├── Token 消耗折线 (输入/输出分色)
│   ├── 成本折线
│   └── 预算线 (虚线)
├── 按模型消耗 Top5 (饼图)
├── 按检测点消耗分布 (柱状图):
│   ├── Prompt 注入检测
│   ├── 越狱攻击识别
│   ├── AI 研判摘要
│   ├── 敏感内容识别
│   └── 工具边界判定
└── 按数据级别消耗分布:
    ├── L0 调用量 / Token
    ├── L1 调用量 / Token
    ├── L2 调用量 / Token
    └── L3 调用量 / Token
```

#### 2.5.3 成本计算模型

```text
单次调用成本 = (input_token_count × 输入单价 + output_token_count × 输出单价) / 1000

模型版本级单价配置:
model_version:
  - input_price_per_1k: 输入每千 Token 单价
  - output_price_per_1k: 输出每千 Token 单价
  - currency: 币种 (CNY/USD)

月度预算配置:
budget_config:
  - monthly_token_budget: 月度 Token 总预算
  - monthly_cost_budget: 月度成本总预算 (可选, 与 Token 预算二选一)
  - warning_threshold: 告警阈值 (默认 80%)
  - hard_limit_threshold: 硬限阈值 (默认 100%)
  - hard_limit_action: 硬限动作 (rate_limit / rule_only)
```

## 3. 数据模型扩展

### 3.1 新增实体

| 实体 | 说明 | 期次 |
|---|---|---|
| `budget_config` | 月度预算配置 | P0 |
| `model_alert_rule` | 模型告警规则 | P0 |

#### 3.1.1 `budget_config` — 月度预算配置

```text
budget_config:
  1. config_id             — 配置唯一标识
  2. scope_type            — 范围类型(global/model_version/detection_point)
  3. scope_id              — 范围对象ID (global时为null)
  4. monthly_token_budget  — 月度 Token 总预算
  5. monthly_cost_budget   — 月度成本总预算 (可选)
  6. currency              — 币种 (CNY/USD)
  7. warning_threshold     — 告警阈值百分比 (默认 80)
  8. hard_limit_threshold  — 硬限阈值百分比 (默认 100)
  9. hard_limit_action     — 硬限动作 (rate_limit/rule_only)
  10. effective_month      — 生效月份 (YYYY-MM)
  11. created_at/updated_at
```

#### 3.1.2 `model_alert_rule` — 模型告警规则

```text
model_alert_rule:
  1. rule_id               — 规则唯一标识
  2. model_id              — 关联模型ID (null=全局)
  3. alert_type            — 告警类型 (latency/success_rate/circuit_open/budget)
  4. condition             — 触发条件 (JSON: {metric, operator, threshold, window})
  5. severity              — 严重级别 (warning/critical)
  6. notify_channels       — 通知渠道 (JSON: [channel_id])
  7. enabled               — 启用状态
  8. last_triggered_at     — 最近触发时间
  9. created_at/updated_at
```

### 3.2 现有实体字段扩展

| 现有实体 | 新增字段 | 类型 | 说明 |
|---|---|---|---|
| `model_version` | `input_price_per_1k` | decimal | 输入每千 Token 单价 |
| `model_version` | `output_price_per_1k` | decimal | 输出每千 Token 单价 |
| `model_version` | `currency` | enum | 币种 CNY/USD |

| 高级规则项关联 Prompt | AI 增强实现方式关联 Prompt 模板 | P0 Prompt 模板 |

## 7. 安全约束

| 约束 | 说明 |
|---|---|
| 模型 endpoint 密钥不落前端 | `auth_ref` 仅存储引用，前端展示脱敏后值 |
| Prompt 系统提示词修改需审批 | 修改 system_prompt 需安全负责人审批 |
| 灰度切量需二次确认 | 扩大流量百分比操作需弹窗二次确认 |
| 熔断器手动操作需审计 | 手动恢复/强制熔断操作写入审计日志 |
| 预算硬限不可绕过 | 硬限触发后仅规则引擎运行，不可通过 API 绕过 |
