# 智能化改造概要设计 — 场景4-6：SOC分析、知识库与报告增强

## 1. 场景4：安全运营增强（高级SOC分析）

### 1.1 场景目标

将分析维度从单条Trace/Span扩展到人员、组织、时序、关联和行为基线五个维度。

### 1.2 前置数据条件（P2之前必须建设）

| 前置能力 | 说明 | 建设时机 |
|---|---|---|
| **身份归一与实体解析** | 统一用户标识（跨应用/跨会话的用户ID映射），建立用户→部门→业务线的组织映射 | P1 |
| **行为基线数据准备** | 积累足够的历史行为数据（调用频率/工具使用/Prompt模式），支撑基线计算 | P1 |
| **拓扑关系可信度** | 应用/Agent/工具/资源的拓扑关系需持续维护和验证，确保关联分析基于可信拓扑 | P1 |

### 1.3 五维分析架构

```text
                    ┌── 人员维度 ─── 用户风险画像/行为基线/跨会话累积/高风险排行
                    ├── 组织维度 ─── 业务线风险态势/租户级聚合/风险热点
数据分析引擎 ──────├── 时序维度 ─── 趋势预测/攻击周期识别/风险演化追踪
                    ├── 关联维度 ─── 跨应用风险关联/工具传播链/攻击链路关联
                    └── 基线维度 ─── 应用/Agent行为基线/全局异常检测
```

### 1.4 人员维度分析

#### 1.4.1 用户风险画像

```text
聚合同一用户标识下所有风险事件/线索/命中记录
→ 计算用户总风险评分
→ 识别风险趋势(ascending/stable/descending)
→ 输出：user_risk_profile
```

#### 1.4.2 用户行为基线

```text
积累历史行为数据（调用频率/工具使用/Prompt模式）
→ 统计计算基线指标（均值/标准差/分位数）
→ 检测偏离（偏离度>2σ自动标记）
→ 输出：user_behavior_baseline
```

#### 1.4.3 跨会话风险累积

```text
识别跨会话/跨应用/跨时间窗口的主体风险累积
（与会话内累积分层，会话内累积归入场景1§4.2.3）
→ 输出：user_risk_accumulation
    - accumulation_type: session_cross/application_cross/time_window
    - accumulated_score: 累积评分
    - key_turning_points: 关键转折点
    - risk_level: 累积风险等级
```

#### 1.4.4 P2首批可交付指标

| 指标 | 定义 | 交付标准 |
|---|---|---|
| 高风险用户TopN | 按风险评分排序的用户列表 | 支持Top10/50/100，可下钻查看用户风险详情 |
| 异常工具调用 | 工具调用偏离基线的用户/Agent | 偏离度>2σ自动标记，可查看偏离详情 |
| 跨应用同主体风险 | 同一用户在不同应用的风险聚合 | 支持跨应用风险视图，展示风险传播路径 |
| 共享高危工具传播链 | 高风险工具被多Agent/应用调用的传播图 | 可视化传播链，标注风险等级和影响范围 |

### 1.5 组织/业务线维度分析

```text
业务线风险态势：按业务线聚合应用风险、事件数量、处置效率
租户级风险聚合：按租户聚合全量风险数据，识别跨应用风险传播
组织内风险热点：识别风险集中应用和高风险Agent/工具
→ 输出：org_risk_profile
```

### 1.6 时序与趋势分析

```text
风险趋势预测：基于历史数据预测未来趋势，识别拐点和季节性模式
攻击周期识别：识别周期性攻击模式
风险演化追踪：追踪风险类型从出现到爆发的演化过程
```

### 1.7 关联与传播分析

```text
跨应用风险关联：识别共享工具/资源/模型的应用间风险传播
工具/资源风险传播：追踪高风险工具被多Agent/应用调用的风险扩散
攻击链路关联：将分散在不同Trace中的攻击行为关联为完整攻击链
```

### 1.8 行为基线与异常检测

```text
应用行为基线：建立应用级正常行为基线，检测偏离
Agent行为基线：建立Agent级正常行为基线，检测行为偏移
全局异常检测：统计模型检测全局异常模式
```

### 1.9 数据模型

```text
user_risk_profile:
  - profile_id, user_identifier, department, business_line
  - total_risk_score, risk_event_count, high_risk_event_count
  - last_risk_time, risk_trend(ascending/stable/descending)

user_behavior_baseline:
  - baseline_id, user_identifier, baseline_type(app/agent)
  - target_id, metric_name, metric_value(均值/标准差/分位数)
  - calculation_window, last_calculated

user_risk_accumulation:
  - accumulation_id, user_identifier, session_id
  - accumulation_type(session_cross/application_cross/time_window)
  - accumulated_score, key_turning_points, risk_level, calculation_time

org_risk_profile:
  - org_id, org_type(业务线/部门/租户), org_identifier
  - total_risk_score, app_risk_summary
  - hotspot_apps, hotspot_agents, last_calculated
```

| **新增** | 组织风险态势页 | 业务线风险聚合/租户级风险/风险热点图 | P2b |

## 2. 场景5：知识库安全能力

### 2.1 场景目标

引入知识库并构建安全防护体系，同时建设知识库自身安全能力，防范知识投毒和RAG注入等新型风险。

### 2.2 知识库引入目的

1. 安全运营知识检索（攻击手法库、处置预案库、合规要求库）
2. AI研判领域知识支撑（安全知识增强研判准确性）
3. 规则优化样本库（误报/命中/攻击样本）
4. 策略配置最佳实践库（策略模板、场景化配置）

### 2.3 知识库架构

```text
knowledge-service
    ├── 知识库管理
    │   ├── 知识条目CRUD
    │   ├── 版本管理(knowledge_version)
    │   ├── 入库审核流程
    │   ├── 分级访问控制
    │   └── 变更审批
    ├── RAG检索引擎
    │   ├── 向量相似检索（向量数据库）
    │   ├── 关键词检索（检索索引库）
    │   ├── 检索结果安全扫描
    │   └── 可信度元数据附加
    ├── 样本库管理
    │   ├── 样本采集与标注
    │   ├── 评估集管理(候选/训练/评测/回归/争议)
    │   └── 回放评估
    └── 安全问答
        ├── 自然语言问答
        └── 知识缺口识别
```

### 2.4 知识条目生命周期

```text
创建(draft) → 提交审核(pending_review) → 审核通过(active) / 审核驳回(draft)
    ↑                                    ↓
    │                              变更审批 → 版本号+1
    │                                    ↓
    │                           暂停(suspended) / 下架(recalled)
    │                                    ↓
    │                           修正审核 → 恢复上架(active)，版本号+1
    └────────────────────────────────────┘
                              过期/归档(archived)
```

### 2.5 知识库集成接口契约

| 调用场景 | 检索方式 | 调用模式 | 结果注入方式 |
|---|---|---|---|
| 场景2 研判辅助 | 向量相似检索+关键词 | 同步RAG | 检索结果先过内容安全扫描，再注入Prompt；与系统提示词角色分离 |
| 场景3 处置建议 | 预案模板匹配+向量检索 | 同步 | 匹配结果作为建议参考，不直接注入Prompt |
| 场景5 安全问答 | 向量相似检索+全文 | 同步 | 返回给用户展示，含可信度元数据 |

### 2.6 检索可信度链路

知识检索结果必须返回以下可信度元数据，不可仅返回内容：

| 元数据 | 说明 |
|---|---|
| 来源等级 | 人工审核/AI生成/外部导入，对应信任等级 |
| 适用范围 | 该知识适用的攻击类型/行业/场景 |
| 有效期 | 知识的有效截止日期，过期自动降级 |
| 引用次数 | 被AI研判引用的次数，高频引用需重点审核 |
| 冲突状态 | 是否与其他知识条目冲突，冲突需人工裁决 |
| 是否可用于模型上下文 | 标记该条目是否允许注入LLM Prompt |

### 2.7 RAG Prompt安全沙箱

```text
检索结果先过内容安全扫描再注入Prompt
检索结果内容与系统提示词隔离（角色分离：系统指令和知识内容分不同角色）
知识内容不可覆盖系统指令
检索结果标注来源，AI输出必须引用知识来源
```

### 2.8 知识库安全风险防护

| 风险类型 | 防护措施 |
|---|---|
| 知识投毒 | 入库审核+AI内容安全检测+信任等级分级 |
| 知识泄露 | 分级访问控制+检索审计+脱敏展示 |
| 知识过时 | 有效期管理+自动降级+定期审核 |
| 知识冲突 | 冲突检测+优先级排序+人工裁决 |
| RAG注入 | 知识内容安全扫描+检索结果过滤+来源可信验证 |
| RAG Prompt注入 | 内容安全扫描+角色分离+内容不可覆盖系统指令 |
| 依赖失效 | 影响面评估+变更审批+灰度发布 |
| 知识投毒/过期召回 | 条目下架+引用影响面分析+已生成AI结论追溯标记 |

### 2.9 知识条目下架与召回机制

```text
发现知识投毒或过期错误
→ 将条目状态设为"下架"(recalled)
→ 自动分析该条目被哪些AI研判/检测引用（影响面报告）
→ 对引用了下架知识的AI研判结果标注knowledge_recalled=true
→ 提示人工复核受影响的AI研判
→ 下架操作需安全管理员审批
→ 修正审核后可恢复上架，版本号+1
```

### 2.10 数据模型

```text
knowledge_base:
  - kb_id, name, type(攻击手法/处置预案/合规要求/策略模板/样本)
  - status, entry_count, tenant_id(共享知识库tenant_id=null)

knowledge_entry:
  - entry_id, kb_id, title, content
  - embedding_vector_ref: 嵌入向量引用（实际向量存向量数据库）
  - source_type(manual/ai_generated/external_import)
  - trust_level(verified/ai_reviewed/external)
  - sensitivity_level(L0-L3)
  - status(draft/pending_review/active/suspended/recalled/archived)
  - valid_until, conflict_status(none/detected/resolved)
  - model_context_allowed(bool), reference_count
  - version_number, recall_reason, recalled_at, restored_at

  - version_id, entry_id, version_number
```

## 3. 场景6：安全报告增强

### 3.1 场景目标

从"人工编写报告"升级为"AI自动生成报告+人工审核"模式。

### 3.2 安全报告自动生成

#### 3.2.1 生成流程

```text
触发条件：定时(周报/月报) 或 手动创建
→ 收集事件数据、风险趋势、处置记录
→ 选择报告模板
→ AI生成报告内容
→ 人工审核
→ 发布

约束：
- 报告发布前需人工审核
- 支持自定义模板
- AI生成内容标注来源
```

#### 3.2.2 报告类型

| 报告类型 | 说明 | 约束 |
|---|---|---|
| 安全周报/月报 | 基于事件数据、风险趋势、处置记录自动生成 | 发布前人工审核 |
| 风险巡检报告 | 定时自动扫描全量风险数据，生成巡检报告 | 仅报告建议，不自动执行变更 |
| 策略效果评估报告 | 策略发布后定时评估命中效果、误报率、覆盖率 | 评估建议性质，策略变更走正式审批 |

### 3.3 原型图改造

| 改造类型 | 页面 | 改造内容 | 期次 |
|---|---|---|---|
| **改造** | 安全报告列表 | 增加"AI自动生成"入口，报告来源标注，增加审核状态 | P3 |
| **改造** | 自定义报告 | 增加AI生成模板选择，支持AI填充报告内容 | P3 |
