## 二、统一策略中心需要完成的策略清单（建议）

建议把策略分成两层：**通用策略层** + **执行面适配层**。

### A. 通用策略层（平台统一定义，一份策略多处执行）
1. **内容安全策略**
   - Prompt 注入、越狱、敏感词、涉政/涉黄/暴恐、PII 泄露
2. **数据防泄漏策略（DLP）**
   - 输入/输出脱敏、命中后拦截/掩码/告警
3. **模型行为约束策略（Guardrail）**
   - 回答边界、拒答模板、系统指令保护
4. **工具调用安全策略**
   - 工具白名单、参数约束、调用频次限制、高危工具审批
5. **访问控制策略**
   - 租户/应用/用户/角色维度授权，策略可见域
6. **流量与速率策略**
   - QPS、并发、Token 消耗限额、预算阈值
7. **风险评分与处置策略**
   - 风险分级（低中高）、动作编排（放行/拦截/降级/人工复核）
8. **告警与通知策略**
   - 告警阈值、聚合去重、升级路径、通知渠道
9. **审计留痕策略**
   - 命中日志保留、证据链、合规报表字段
10. **策略生命周期治理**
   - 草稿/发布/灰度/全量/回滚/废弃、审批流、版本比较

### B. 执行面适配层（下发到探针与网关）
#### 1) 探针策略（侧重应用内部与链路细粒度）
- 会话级上下文检测（多轮对话）
- Tool 调用前后校验
- RAG 检索结果注入风险检测
- 模型输出后置审查与二次处置
- 本地缓存策略（离线兜底）

#### 2) 网关策略（侧重入口防护与统一流控）
- 请求鉴权、签名、IP/UA 风控
- 路由级限流熔断
- 请求/响应内容快速规则检测（低延迟）
- 租户级配额与计费联动
- 黑白名单与封禁策略

## 三、对当前策略功能的优化调整建议

## 1）信息架构升级：从“规则列表”到“策略中心”

建议菜单重构为：

- **统一策略中心**
  - 策略目录（按类型）
  - 策略编排（条件、优先级、动作）
  - 发布管理（版本、灰度、回滚）
  - 下发管理（探针/网关状态）
  - 命中分析（效果评估）
- **告警中心**
  - 告警规则
  - 通知渠道
  - 升级与抑制

> 这样“检测规则配置”不再孤立，而成为统一策略的一部分。

## 2）策略模型统一（最关键）

建立统一策略对象（逻辑上）：

- `policy_id / name / type / scope`
- `target`（probe | gateway | both）
- `match_conditions`
- `actions`（allow/block/mask/challenge/review）
- `priority`
- `version`
- `status`（draft/published）
- `rollout`（tenant/app/env 百分比）
- `audit`（creator, approver, changelog）

这能解决“同类规则多处重复配置、行为不一致”的问题。

## 3）下发机制标准化

增加“策略发布流水线”：

1. 语法与冲突校验  
2. 仿真回放（历史流量样本）  
3. 灰度发布（先少量应用/租户）  
4. 观测指标（误拦截率、命中率、延迟）  
5. 一键回滚  

并对探针/网关都维护“**期望版本 vs 实际版本**”。

## 4）冲突与优先级机制显式化

给出统一规则：
- 优先级数字越小越先执行（或反之，但要全局统一）
- 默认“阻断类”优先于“告警类”
- 同级冲突按“最严格动作优先”
- 支持策略互斥组与依赖关系

## 5）可运营能力增强

当前“告警规则”建议补充：
- 告警聚合（相同指纹 N 分钟合并）
- 抑制窗口（维护期静默）
- 多级升级（IM→短信→电话）
- 告警闭环（确认、误报标记、规则反哺）

## 6）性能与可用性设计（探针/网关差异化）

- 网关策略：强调低延迟，尽量使用可编译快速匹配规则
- 探针策略：允许更重检测（上下文、语义、工具参数）
- 下发采用增量更新 + 本地缓存 + TTL
- 控制面不可用时，数据面“最后可用策略”继续生效

## 四、落地优先级（建议 P0/P1）

### P0（先做，确保统一下发闭环）
1. 统一策略模型（含 target=probe/gateway）
2. 检测规则配置升级为“策略目录+策略编辑”
3. 发布管理（版本、灰度、回滚）
4. 下发状态面板（探针/网关在线与版本）
5. 告警规则 + 通知渠道打通（最小可用）

### P1（增强）
1. 自定义 Guardrail 可视化编排
2. 策略冲突检测与仿真回放
3. 命中效果分析（误报/漏报反馈闭环）
4. 多租户分层策略（全局/租户/应用继承）
