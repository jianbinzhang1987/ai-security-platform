基于对原型图 (`E:\code\大模型安全监测平台\设计文档\原型图-claude\index.html` 以及 `policy` 目录下的规则列表) 和需求文档中的分析，目前原型中的策略中心主要围绕检测规则和告警规则，缺少针对不同防御节点（探针端侧防御和网关集中防御）的细粒度下发和配置能力。

要实现一个 **统一策略中心** ，下发探针（Agent/SDK）的安全策略和网关（Gateway）的安全策略，我们需要梳理和完善以下策略体系并对现有功能进行优化调整：

### 一、 统一策略中心需要完善的策略全景梳��

从防御纵深和生效节点的角度，策略应分为三大类：

#### 1. 探针端侧安全策略 (Agent/SDK 侧生效)

这类策略在应用本地执行，以极低的延迟拦截最明显的风险或保护敏感数据出境。

* **端侧凭证防泄露策略：** 检测和拦截硬编码在 Prompt 中发往外部大模型的敏感凭证（如 AK/SK、密码、Token）。
* **端侧数据脱敏/打码策略 (PII 脱敏)：** 定义哪些类型的敏感信息（如手机号、身份证、邮箱）在发送给 LLM 之前需要在端侧进行脱敏替换。
* **端侧熔断/限流策略：** 针对异常的高频请求、异常流量行为进行端侧熔断。
* **探针采集控制策略：** 决定探针采集数据的范围、采样率、黑白名单（哪些请求不采集）、本地缓存限制等。

#### 2. 网关集中防御策略 (Gateway 侧生效)

这类策略在统一的大模型安全网关执行，利用更强的算力和安全模型进行深度防御。

* **Prompt 注入防御策略：** 拦截各类越狱（Jailbreak）、提示词泄露（Prompt Leaking）攻击。
* **敏感/违规内容过滤策略：** 检测和拦截涉政、涉黄、暴力等不合规内容（输入和输出双向）。
* **意图偏离检测策略：** 检测大模型输出是否偏离了预设的 System Prompt 意图或发生幻觉。
* **工具调用越界拦截策略：** 限制和拦截大模型未授权或危险的外部工具（Tool/Function）调用请求。
* **全局频控与配额策略：** 基于租户、应用、User 的全局限流策略。

#### 3. 平台响应与告警策略 (Console/SOC 侧生效)

（目前原型中已有基础轮廓，需进一步深化）

* **风险检测与定级规则（已在原型中）：** 定义触发阈值、置信度、风险定级。
* **告警聚合与通知规则（已在原型中）：** 告警聚合窗口、分发渠道（企微、短信）。
* **自动化响应与阻断联动规则：** 当检测到高危风险时，自动下发阻断指令给网关或探针（如封禁某IP或用户）。

### 二、 当前策略功能的优化调整方案

为了支撑上述统一策略体系，建议对现有的原型和功能设计进行如下优化：

#### 1. 菜单层级的重构与扩展

将原有的“规则策略”升级为真正的“ **统一策略中心** ”，拆分防御节点维度：

* **统一策略中心**
  * **网关安全策略（Gateway 防护）** ：管理 Prompt 注入、内容合规、意图管控等深度防御策略。
  * **探针安全策略（Agent 防护）** ：管理端侧脱敏、凭证拦截、采集采样等本地策略。
  * **规则引擎配置（自定义检测）** ：保留现有的 `policy-list.html`，用于编写高阶检测表达式（如 `tool.declared=false AND span_kind=tool`）。
  * **告警与响应规则** ：保留并增强现有的 `alert-rules.html`，增加自动化阻断动作。

#### 2. 策略配置表单的改造 (针对 `policy-list.html`)

当前的“检测规则配置”页面偏向于事后的告警检测，需要增加“阻断/拦截”的配置项，使其成为真正的防护策略：

* **增加“生效节点”选项：** 在新增策略时，需选择该策略下发至 `探针 (Agent)` 还是 `网关 (Gateway)`，或者是 `仅旁路分析 (Observer)`。
* **增加“处置动作”选项：** 除了目前的风险定级，必须增加：`放行 (Monitor)`、`阻断 (Block)`、`脱敏 (Mask)`、`替换 (Rewrite)`。
* **增强“绑定应用”的精细度：** 目前只能选应用，建议支持按“环境（测试/生产）”、“模型渠道（如仅针对公有云模型生效）”进行细粒度绑定。

#### 3. 策略下发与同步机制的UI体现

策略配置不仅是存入数据库，核心是 **下发** 。UI 上需要体现策略的同步状态：

* **下发状态指示器：** 在规则列表中增加一列“下发状态”（如：已同步、下发中、部分失败）。
* **版本控制与回滚：** 强化现有的版本列，支持查看历史版本、一键回滚到上一个安全策略版本。
* **策略冲突检测：** 当探针策略和网关策略在同一个应用上产生逻辑冲突时，控制台在保存时应提供“冲突预警”。

#### 4. 增强“干跑验证 (Dry-Run)”功能

原型中的 `dryRunModal` 非常好，但需要扩展：

* 在干跑时，明确展示如果是阻断模式，该请求在**哪个节点（网关还是探针）**被拦截。
* 提供“改写后/脱敏后”的 Payload 对比预览，而不仅仅是输出“是否命中”。

### 总结

核心优化思路是 **从“事后检测与告警”向“事前/事中防御管控”演进** 。在 UI 和逻辑模型上，明确区分“Agent 探针”和“Gateway 网关”的职责边界，使管理员能在一个界面统一编排边缘和中心的防御防线。
