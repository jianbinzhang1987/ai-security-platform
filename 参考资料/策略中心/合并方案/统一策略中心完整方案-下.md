## 10. 共享规则库

### 10.1 定义

共享规则库是策略中心的公共校验资源，封装关键词、正则、LLM评分等检测能力。区别于原设计中Guardrail仅作为网关防护策略的一种type，共享规则库**显式化为独立菜单项**，供网关和探针策略共同引用。

### 10.2 共享规则库结构

| 字段 | 说明 |
|---|---|
| rule_id | 唯一标识 |
| name | 规则库名称 |
| type | keyword/regex/llm_score/composite |
| content | 规则内容（关键词列表/正则列表/评分配置） |
| version | 版本号 |
| ref_count_gateway | 被网关策略引用次数 |
| ref_count_probe | 被探针策略引用次数 |
| last_updated | 最后更新时间 |

### 10.3 交互

- 共享规则库作为独立菜单项管理，有独立的列表和编辑页面
- 列表展示"被引用次数"列，区分网关引用和探针引用
- 修改时弹窗提示影响范围："此规则库被3条网关策略、2条探针策略引用，修改后将触发所有引用策略的版本更新"
- 删除时若被策略引用，需确认影响范围
- 修改后引用该规则库的策略自动创建新draft版本，需重新发布才生效

### 10.4 与Guardrail的关系

- **P0**：Guardrail仍作为网关防护策略的一种type（type=guardrail），检测能力内嵌
- **P1**：Guardrail的检测能力抽取为共享规则库，策略通过ref_guardrail_id引用
- **P2**：共享规则库支持版本管理、灰度发布、跨执行面协同

## 11. 告警策略配置

### 11.1 定义

策略actions包含alert时，在策略编辑表单内配置告警的聚合、通知和升级规则。告警配置合入策略编辑表单的动作配置区，通知渠道保留为独立全局资源。

### 11.2 告警配置结构

| 字段 | 说明 |
|---|---|
| aggregation_window | 聚合窗口（分钟），相同指纹的事件合并 |
| aggregation_key | 聚合键（risk_type/app_id/tool_name等） |
| suppress_duration | 抑制窗口（分钟），维护期静默 |
| notification_channels | 通知渠道列表（飞书/钉钉/企微/邮件/短信/SIEM） |
| escalation_rules | 升级规则（15min未确认→短信；30min→电话） |
| auto_actions | 自动响应动作（高危时自动下发阻断指令） |

### 11.3 双端策略的告警配置

target=both的策略，告警配置在策略级别统一设置（不按执行面分区），因为告警是策略的输出行为。告警事件中自动标注来源执行面，让运维人员知道是网关还是探针触发。

## 12. 策略发布状态机

### 12.1 状态定义

```text
                    ┌──────────┐
                    │  draft   │ ← 创建/编辑后保存
                    └────┬─────┘
                         │ 点击"发布"
                    ┌────▼─────┐
                    │validating│ ← 语法校验+冲突检测
                    └────┬─────┘
                    ┌────┴─────┐
               ┌────▼────┐     └────► draft（校验失败）
               │  canary  │ ← 灰度发布
               └────┬─────┘
                    │ 点击"全量发布"
               ┌────▼─────┐
               │published │ ← 全量生效
               └────┬─────┘
                    │ 废弃或被新版本替代
               ┌────▼─────┐
               │deprecated│ ← 已废弃
               └──────────┘
```

| 状态 | 说明 | 可执行操作 |
|---|---|---|
| draft | 草稿，未下发 | 编辑、删除、发布 |
| validating | 校验中 | 等待（自动流转） |
| canary | 灰度中 | 全量发布、回滚、查看灰度指标 |
| published | 全量生效 | 编辑（创建新draft版本）、废弃 |
| deprecated | 已废弃 | 查看历史、恢复（创建新draft） |

### 12.2 版本管理

- 每次draft→published，version自增
- 同一policy_id仅一个版本为published
- 新版本published时，旧版本自动deprecated
- 支持查看历史版本和diff对比

### 12.3 双端策略的发布

target=both的策略发布时，网关侧和探针侧**同步发布**。若一侧下发失败，另一侧自动回滚，保证双端策略一致性。

## 14. 策略冲突检测

### 14.1 冲突类型

| 冲突类型 | 示例 | 严重度 |
|---|---|---|
| 动作矛盾 | 同一Hook Point上，策略A=block，策略B=allow | 高 |
| 执行面矛盾 | 网关策略=allow，探针策略=block（同应用） | 中 |
| 条件重叠 | 两条策略条件重叠且动作不同 | 低 |
| 优先级循环 | 互斥组内优先级设置导致执行顺序不确定 | 高 |

### 14.2 冲突解决规则

- 阻断类优先于告警类
- 同级冲突：block > mask > alert > allow
- 执行面矛盾时以最严格动作为准，记录裁决来源执行面
- 支持策略互斥组声明

### 14.3 统一列表下冲突检测增强

合并为统一列表后，网关和探针策略同列可见，**冲突检测优先级应提升**。策略保存时自动检测冲突，弹出预警弹窗。

### 16.3 核心原则

**合并的是管理视图，不是执行逻辑。** 用户在一个地方管理所有策略，但每条策略的执行面、Hook Point、动作仍然严格区分——这是防止混淆的根本。
