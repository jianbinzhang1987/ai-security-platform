## 1. 方案结论

本次策略模块原型不再沿用“按单条策略类型逐条配置，再给策略配置作用范围”的主模型，而统一切换为：

**规则项 + 策略包 + 接入应用绑定**

核心原因：

- 旧模型更适合“平台按类型维护规则”，不适合回答“某个接入应用当前到底生效了哪些策略”
- 接入应用视角缺少可读性，无法直观看到当前生效内容、版本和差异
- 后续要支持“同一个策略的不同版本下发给不同应用”，旧模型很难解释清楚

因此，本方案的最终方向是：

- `规则项` 作为原子能力维护
- `策略包` 作为真正的可发布、可下发对象
- `接入应用` 作为唯一绑定目标
- `应用详情页` 只读展示当前绑定策略包和版本，不直接编辑

## 2. 已确认口径

以下内容已确认，不再作为待决策项：

| 事项 | 确认结果 |
|---|---|
| 下发对象 | `策略包` |
| 目标对象 | 统一为“接入应用”，不再区分应用和服务 |
| 应用详情页策略区 | 只读展示为主，不直接编辑 |
| 主版本视角 | 以 `策略包版本` 为主 |
| 规则项版本 | 可保留，但不作为主界面重点 |
| 视觉风格 | 与现有后台风格一致，不使用 emoji 图标 |

视觉表达统一要求：

- 使用现有页面的 `page-header`、`stat-lite`、`data-table`、`tag`、`modal` 体系
- 执行面区分通过文字 + 颜色标签实现
- 不使用 emoji、拟人化图标、夸张插画或过度彩色装饰

## 3. 数据模型建议

### 3.1 规则项

规则项是原子能力，按类型维护。

建议字段：

| 字段 | 说明 |
|---|---|
| `rule_id` | 规则项唯一标识 |
| `name` | 规则项名称 |
| `type` | 内容安全 / 数据防泄露 / 工具管控 / 访问控制 / 频控与配额 / 采集控制 |
| `target` | 网关 / 探针 |
| `hook_point` | 执行点 |
| `match_condition` | 匹配条件 |
| `action` | 动作 |
| `priority` | 优先级 |
| `status` | 启用 / 停用 |

### 3.2 策略包

策略包是可发布、可下发对象，可同时包含多种类型规则项。

建议字段：

| 字段 | 说明 |
|---|---|
| `package_id` | 策略包唯一标识 |
| `name` | 策略包名称 |
| `description` | 策略包说明 |
| `rule_refs` | 包内规则项集合 |
| `current_version` | 当前版本 |
| `status` | 草稿 / 已发布 / 已废弃 |

### 3.3 策略包版本

策略包版本是不可变快照。

建议字段：

| 字段 | 说明 |
|---|---|
| `package_id` | 所属策略包 |
| `version` | 版本号 |
| `rule_snapshot` | 规则项快照 |
| `created_at` | 创建时间 |
| `created_by` | 创建人 |
| `change_log` | 变更说明 |
| `publish_status` | 草稿 / 灰度 / 已发布 |

### 3.4 接入应用绑定

绑定对象统一为原型中的“接入应用”。

建议字段：

| 字段 | 说明 |
|---|---|
| `app_id` | 接入应用 ID |
| `package_id` | 绑定的策略包 |
| `package_version` | 当前生效版本 |
| `bind_status` | 已绑定 / 灰度 / 已下发 / 部分失败 |
| `last_sync_at` | 最近同步时间 |

## 4. 页面职责重组

### 4.1 总体页面结构

策略模块建议收敛为 3 条主线：

```text
统一策略中心
  ├─ 策略包管理
  ├─ 规则项管理（可选开放）
  ├─ 通知渠道管理
  └─ 绑定与下发

接入应用详情
  └─ 当前生效策略（只读）
```

### 4.2 页面职责说明

| 页面 | 主职责 |
|---|---|
| 策略包管理 | 创建、编辑、发布策略包；查看包内规则项和版本历史 |
| 规则项管理 | 维护原子规则项，按类型分类管理 |
| 绑定与下发 | 查看每个接入应用绑定了哪个策略包版本，并控制下发 |
| 接入应用详情 | 只读查看当前绑定策略包、当前版本、下发状态和最近变更 |

### 4.3 关键原则

- 策略中心负责“配置和发布”
- 接入应用详情负责“查看和确认”
- 接入应用详情默认不开放策略包内容编辑
- 如需调整内容，统一回到策略中心处理

## 6. 各文件详细修改规格

### 6.1 `index.html`

**目标**：统一策略中心不再按“网关策略 / 探针策略”分裂展示，改为按对象职责展示。

建议导航结构：

```text
统一策略中心
  ├─ 策略包管理
  ├─ 通知渠道管理
  └─ 绑定与下发
```

若本轮开放规则项管理，则补充：

```text
  ├─ 规则项管理
```

说明：

- `alert-rules.html` 不再作为策略中心菜单项
- 原 `gateway-policies.html`、`probe-policies.html`、`policy-list.html`、`guardrails.html` 不再出现在主导航

### 6.2 `unified-protection.html`

**新定位**：策略包管理主页面。  
不再以“单条策略记录”为主，而以“策略包”为主。

**面包屑**：

```text
统一策略中心 > 策略包管理
```

#### 6.2.1 页面结构

```text
页面顶部
  ├─ page-header（标题 + 新建策略包按钮）
  ├─ 统计卡片区
  └─ 搜索筛选区

主体区
  └─ 策略包列表

弹窗 / 抽屉
  ├─ 策略包编辑
  ├─ 包内规则项选择器
  ├─ 版本历史
  └─ 绑定应用列表
```

#### 6.2.2 列表字段

| 列名 | 说明 |
|---|---|
| 策略包名称 | 主名称 + package_id |
| 包含规则类型 | 例如：内容安全 / 数据防泄露 / 工具管控 |
| 规则数 | 包含规则项数量 |
| 当前版本 | 例如 v3 |
| 绑定应用数 | 当前有多少接入应用绑定 |
| 发布状态 | 草稿 / 灰度 / 已发布 |
| 下发状态 | 已同步 / 下发中 / 部分失败 |
| 操作 | 编辑 / 查看版本 / 查看绑定 / 发布 |

#### 6.2.3 详情展开内容

点击策略包后，建议展示：

- 基础信息
- 包内规则项列表
- 网关规则和探针规则分组
- 版本历史
- 已绑定接入应用列表

#### 6.2.4 编辑逻辑

编辑策略包时：

- 可同时选择多种规则类型
- 规则项仍保持原子结构，不允许在包内临时改造规则结构
- 保存后生成新的策略包版本

### 6.3 `shared-rules.html`

**新定位**：规则项管理。  
不再强调“共享规则库”概念，而强调原子规则项的维护。

**面包屑**：

```text
统一策略中心 > 规则项管理
```

#### 6.3.1 列表字段

| 列名 | 说明 |
|---|---|
| 规则项名称 | 主名称 + rule_id |
| 类型 | 内容安全 / 数据防泄露 / 工具管控 / 访问控制 / 采集控制 |
| 执行面 | 网关 / 探针 |
| Hook Point | 执行点 |
| 动作 | block / mask / alert / challenge 等 |
| 状态 | 启用 / 停用 |
| 被策略包引用数 | 被多少个策略包引用 |
| 操作 | 编辑 / 查看引用 |

#### 6.3.2 作用

- 为策略包管理提供规则项来源
- 平台管理员统一维护原子能力
- 普通查看用户不一定需要进入该页

### 6.4 `distribution-status.html`

**新定位**：绑定与下发。  
页面主视角从“策略对象”逐渐切换为“接入应用绑定结果”。

**面包屑**：

```text
统一策略中心 > 绑定与下发
```

#### 6.4.1 页面结构

```text
页面顶部
  ├─ page-header
  ├─ 统计卡片区
  └─ 搜索筛选区

主体区
  └─ 接入应用绑定列表

详情弹窗
  └─ 查看该应用当前绑定策略包版本及节点下发状态
```

#### 6.4.2 列表字段

| 列名 | 说明 |
|---|---|
| 接入应用 | 应用名称 + app_id |
| 当前策略包 | 例如“基础安全包” |
| 当前版本 | 例如 v2 |
| 发布时间 | 当前版本发布时间 |
| 下发状态 | 已同步 / 下发中 / 部分失败 |
| 最近同步时间 | 最后回执时间 |
| 操作 | 查看详情 / 更换绑定版本 |

#### 6.4.3 更换绑定版本

该页允许的轻操作是：

- 为接入应用切换绑定的策略包版本
- 不允许在该页修改策略包内容本身

### 6.5 `pages/assets/app-detail.html`

**新增内容**：在接入应用详情中加入“当前生效策略”只读区。

建议区块内容：

| 字段 | 说明 |
|---|---|
| 当前策略包 | 当前绑定的策略包名称 |
| 当前版本 | 当前生效版本 |
| 包含规则类型 | 内容安全 / 数据防泄露 / 工具管控等 |
| 规则数 | 包内规则数量 |
| 发布状态 | 草稿 / 已发布 / 灰度 |
| 下发状态 | 已同步 / 部分失败 |
| 最近变更 | 版本发布时间和变更摘要 |

建议操作：

- 查看版本历史
- 跳转到策略中心查看详情

不建议操作：

- 直接在接入应用详情中编辑策略包
- 在应用详情中直接增删包内规则项

### 6.6 `notify-channel.html`

定位不变，继续作为全局资源页。

要求：

- 保留现有结构
- 去除不专业口语
- 统一面包屑和命名
- 作为策略包告警动作和平台运维告警的共享通知资源

### 6.7 `alert-rules.html`

**新定位**：平台运维告警。

说明：

- 不再承载业务策略告警规则配置
- 业务告警配置应并入策略包版本或策略包编辑中的告警配置区
- 本页只保留 Collector、存储链路、通知通道等基础设施自监控告警

## 8. 版本与绑定设计

### 8.1 主版本视角

主界面统一突出：

- `策略包版本`

不在主界面强调：

- 规则项内部版本

### 8.2 版本管理原则

- 每次修改策略包内容，都生成新版本
- 历史版本不可变
- 接入应用可绑定不同版本

示例：

```text
接入应用 A -> 基础安全包 v2
接入应用 B -> 基础安全包 v3
接入应用 C -> 增强审计包 v1
```

### 8.3 原型中必须体现的能力

- 查看策略包版本历史
- 查看某个版本的变更说明
- 查看哪些接入应用绑定了哪个版本
- 在“绑定与下发”页更换绑定版本

---

## 9. 交互原则

### 9.1 策略包管理页

- 新建策略包时，先填写基础信息
- 再从规则项列表中选择要纳入的规则项
- 保存生成版本
- 发布后才能进入绑定和下发

### 9.2 接入应用详情页

- 默认只读
- 用户重点看到“现在生效什么”
- 不承担策略编辑职责

### 9.3 绑定与下发页

- 更适合做“应用维度”的配置确认和版本切换
- 不承担包内规则细节维护职责

## 10. 实施顺序

```text
阶段 1：模型和口径统一
  ├─ 统一文档口径：规则项 / 策略包 / 接入应用绑定
  └─ 调整导航和页面命名

阶段 2：核心页面重构
  ├─ `unified-protection.html` 改为策略包管理
  ├─ `distribution-status.html` 改为绑定与下发
  └─ `app-detail.html` 增加只读策略区

阶段 3：辅助页面调整
  ├─ `shared-rules.html` 改为规则项管理
  ├─ `notify-channel.html` 统一文案
  └─ `alert-rules.html` 迁出策略中心

阶段 4：遗留页面收口
  ├─ 旧策略页继续保留文件
  └─ 从主导航和主流程中移出
```
