## 1. 设计背景与目标

### 1.1 现状问题

- 检测规则与告警规则割裂，策略无统一模型
- 策略无执行面区分，未区分网关/探针生效
- 无统一下发机制，策略保存即生效
- 网关与探针策略分离管理，同类规则重复配置

### 1.2 设计目标

- **统一管理视图**：一个策略中心管理所有策略
- **执行面标签化**：视觉标签+智能推荐，清晰区分生效位置
- **策略内分区配置**：双端策略在同一条策略内按执行面分区编辑
- **共享规则库显式化**：公共校验库作为独立资源，修改一次两侧同步
- **纵深防御协同**：网关粗筛+探针精筛，完整防御纵深

## 2. 网关与探针安全扫描的区别与联系

### 2.1 核心区别

| 维度 | 网关安全扫描 | 探针安全扫描 |
|---|---|---|
| 扫描位置 | 网络边界，HTTP请求/响应级别 | 进程内，Agent运行时上下文级别 |
| 可见数据 | HTTP Body/Header/Params | Tool参数、Session上下文、RAG检索结果 |
| 检测时机 | 请求到达时（预防，第一道防线） | 调用发生后（追溯+深化，第二道防线） |
| 延迟约束 | 极低延迟（<<10ms），倾向快速规则匹配 | 可容忍较重检测（语义分析、参数校验） |
| 阻断粒度 | 整请求级别 | 细粒度（拦截单个Tool调用、暂停执行转审批） |
| 脱敏方式 | 网关层内容替换/截断（数据已出进程） | 端侧本地脱敏（数据不出进程，更安全） |
| 流控范围 | 全局限流/配额/ACL（租户/应用维度） | 单实例限流/熔断/死循环中断 |
| 误报风险 | 较低（基于请求结构） | 较高（需要基线，规则需更严谨） |
| 响应速度 | 毫秒级（立即阻断） | 秒级（本地采样后判定） |
| 离线兜底 | 依赖网关服务可用性 | 本地缓存策略，控制面不可用时继续生效 |

### 2.2 核心联系

- 同一风险可能双端触发（如敏感内容过滤）
- 纵深防御互补：网关粗筛+探针精筛
- 网关拦截后探针可免检，节省资源
- 网关放行后探针继续监测执行行为
- 共享检测能力：Guardrail可作为公共校验库被两端引用
- 证据链协同：网关审计日志+探针行为日志=完整溯源链
- 告警统一：汇聚到同一个告警体系

### 2.3 用户认知模型

用户思考顺序："我要管网关的什么"→"我要管探针的什么"→"有没有两侧都要管的"，因此策略创建入口应提供**场景导向**引导。

## 3. 核心设计原则

**分层管理 + 统一下发 + 策略内分区**

- 合并的是**管理视图**，不是**执行逻辑**
- 每条策略的执行面、Hook Point、动作仍然严格区分
- 双端策略在同一条策略内按执行面分区配置，后台按执行面分别下发
- 共享规则库作为独立资源，修改一次两侧同步

## 4. 菜单架构

### 4.1 统一策略中心菜单树

```text
▼ 统一策略中心 /policies
   ├─ 安全防护策略 /policies/protection
   │    ├─ 全部策略 (默认视图)
   │    ├─ 🟢 网关防护策略 (筛选视图，头部显示同步摘要)
   │    └─ 🔵 探针运行时策略 (筛选视图，头部显示同步摘要)
   ├─ 共享规则库 /policies/shared-rules
   ├─ 通知渠道管理 /policies/channels
   └─ 策略发布与下发 /policies/release
        ├─ 发布管理
        └─ 下发状态
```

### 4.2 与当前原型菜单的映射

| 当前原型菜单 | 统一策略中心菜单 | 变化 |
|---|---|---|
| 检测规则配置 | 安全防护策略>全部/网关/探针 | 统一入口+筛选视图 |
| 告警规则 | 策略编辑表单>动作配置区 | 合入策略表单 |
| 自定义Guardrail | 安全防护策略(type=guardrail)+共享规则库 | 归属网关防护策略+共享规则库复用 |
| 通知渠道 | 通知渠道管理 | 保留为全局资源 |
| （无） | 共享规则库 | 新增 |
| （无） | 策略发布与下发 | 新增 |

## 5. 策略统一模型

### 5.1 策略实体字段

| 字段 | 类型 | 说明 | 必填 |
|---|---|---|---|
| policy_id | string | 唯一标识 | 是 |
| name | string | 策略名称 | 是 |
| type | enum | content_safety/dlp/tool_control/rate_limit/access_control/guardrail/telemetry | 是 |
| target | enum | probe/gateway/both/observer | 是 |
| scope | object | {tenant_id, app_ids, env, model_channels} | 是 |
| priority | int | 数字越小越先执行 | 是 |
| version | int | 每次发布自增 | 自动 |
| status | enum | draft/validating/canary/published/deprecated | 自动 |
| created_by/updated_by | string | 创建人/修改人 | 自动 |
| created_at/updated_at | timestamp | 创建/更新时间 | 自动 |

### 5.2 执行面配置模型

**单执行面策略**（target=gateway或probe）：

```json
{
  "policy_id": "pol-001",
  "name": "Prompt注入防御",
  "type": "content_safety",
  "target": "gateway",
  "hook_point": "gw-request-in",
  "match_conditions": { "ref_guardrail_id": "gr-001", "operator": "any_match" },
  "actions": ["block", "alert"],
  "priority": 50
}
```

**双端策略**（target=both，策略内分区配置）：

```json
{
  "policy_id": "pol-002",
  "name": "敏感内容过滤",
  "type": "content_safety",
  "target": "both",
  "priority": 50,
  "execution_configs": {
    "gateway": {
      "hook_point": "gw-request-in",
      "match_conditions": { "ref_guardrail_id": "gr-001" },
      "actions": ["block", "alert"],
      "block_message": "内容包含敏感信息，已拦截"
    },
    "probe": {
      "hook_point": "probe-llm-before",
      "match_conditions": { "expression": "llm_score > 0.8" },
      "actions": ["mask", "alert"],
      "mask_rules": [{ "field": "phone", "pattern": "(\\d{3})\\d{4}(\\d{4})", "replace": "$1****$2" }]
    },
    "shared": {
      "ref_guardrail_ids": ["gr-001"],
      "shared_rule_version": "v12.5"
    }
  }
}
```

**关键**：target=both时，用户在同一个表单内分区配置，后台按执行面拆分下发，用户视角始终是一条策略。

### 5.3 策略类型与执行面推荐映射

| 策略类型 | 推荐执行面 | 推荐理由 | 允许切换 |
|---|---|---|---|
| Prompt注入防御 | 🟢网关 | 请求入站时快速拦截 | 可切双端 |
| 敏感内容过滤 | 🟡双端 | 网关快速规则+探针深度语义 | 可切单端 |
| 意图偏离检测 | 🟢网关 | 网关层输出偏离检测 | 可切双端 |
| RAG污染防护 | 🔵探针 | 检索结果注入风险检测 | 不建议切网关 |
| 凭证防泄露 | 🔵探针 | 端侧扫描，数据不出进程 | 不建议切网关 |
| PII脱敏 | 🔵探针 | 端侧本地替换更安全 | 可切双端 |
| 工具白黑名单 | 🔵探针 | 探针拦截Tool调用 | 不建议切网关 |
| 工具参数约束 | 🔵探针 | 探针校验Tool入参 | 不建议切网关 |
| 高危操作审批 | 🔵探针 | 探针暂停执行转审批 | 不建议切网关 |
| 工具调用越界 | 🟢网关 | 网关层限制未授权工具调用 | 可切双端 |
| 端侧熔断限流 | 🔵探针 | 单实例限流 | 不建议切网关 |
| 全局频控配额 | 🟢网关 | 全局限流/配额 | 不建议切探针 |
| 访问控制ACL | 🟢网关 | IP/Token/地理位置控制 | 不建议切探针 |
| 安全降级路由 | 🟢网关 | 网关层路由控制 | 不建议切探针 |
| 黑白名单封禁 | 🟢网关 | 全局封禁 | 不建议切探针 |
| Guardrail护栏 | 🟢网关 | 快速关键词/正则匹配 | P1支持双端 |
| 探针采集控制 | 🔵探针 | 探针采集控制 | 不建议切网关 |

**交互**：选择策略类型后，"生效节点"自动填入推荐值并显示理由气泡。切换到不推荐组合时弹出风险提示。

## 6. Hook Point体系

| 执行面 | Hook Point | 触发时机 | 可用动作 |
|---|---|---|---|
| Gateway | gw-request-in | 请求进入网关，转发给LLM前 | block/mask/alert/allow |
| Gateway | gw-response-out | LLM响应返回，转发给客户端前 | block/mask/rewrite/alert/allow |
| Probe | probe-llm-before | Agent发起LLM调用前 | block/mask/alert/allow |
| Probe | probe-llm-after | LLM响应返回Agent后 | mask/alert/allow |
| Probe | probe-tool-before | Agent发起Tool调用前 | block/challenge/alert/allow |
| Probe | probe-tool-after | Tool执行结果返回后 | mask/alert/allow |
| Probe | probe-rag-after | RAG检索结果返回后 | mask/alert/allow |
| Probe | probe-telemetry | 探针采集配置（非拦截型） | allow（仅配置型） |

**交互**：选择执行面后Hook Point下拉自动过滤。target=both时网关侧和探针侧各选一个。

## 7. 匹配条件与动作

### 7.1 匹配条件

- **引用共享规则库**：`{ "ref_guardrail_id": "gr-001", "operator": "any_match" }`
- **自定义表达式**：`{ "expression": "tool.declared = false AND span_kind = 'tool'", "confidence_threshold": 0.8 }`

### 7.2 动作

| 动作 | 说明 | 适用Hook Point | 配置项 |
|---|---|---|---|
| allow | 放行，仅记录 | 全部 | 无 |
| block | 阻断，返回安全回复 | gw-request-in, gw-response-out, probe-llm-before, probe-tool-before | 阻断回复文案、降级路由 |
| mask | 脱敏/打码 | gw-request-in, gw-response-out, probe-llm-before/after, probe-tool-after, probe-rag-after | 脱敏规则、脱敏字段 |
| rewrite | 改写为安全内容 | gw-response-out | 改写模板 |
| challenge | 转人工审批 | probe-tool-before | 审批通知渠道、超时自动动作 |
| alert | 触发告警 | 全部 | 告警配置 |

### 7.3 优先级与冲突规则

- 数字越小越先执行
- 阻断类优先于告警类
- 同级冲突：block > mask > alert > allow
- 同优先级按policy_id升序稳定排序
- 同一Hook Point首个block即终止
- 执行面矛盾时以最严格动作为准，记录裁决来源执行面
